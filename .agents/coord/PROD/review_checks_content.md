# 内容任务（CONTENT-*）合入前审核要点（协调者 10-03 13:22 / 13:26 裁定；开发监督起草）

**审核纪律**：必须先实际读文件、跑命令，再写结论；无法执行的项写 ⚠️ 并说明原因，不计为 ❌。写着「尚未执行 / 尚未核实」的 ❌ 一律无效。

只审下面 5 条，每条给 ✅ / ❌，并附依据（引用文件与行号或小节号）：

1. **内容侧正确**：内容任务本身要做对的部分全部到位。
   - ID 统一：地图对象、事件、Ink、任务、门禁或入口互相引用的 ID 是同一个已登记 ID；不用 quest ID、旗标去冒充 gate ID；动作名大小写与登记表一致。
   - 人物与台词齐全：出场人物都有内容定义，台词都有文本键。
   - 文案完整：无占位、无「待补」。
   - 奖励只发一次：同一物品或奖励只在一个所有者（quest / Ink / 事件）里发放，不重复。
2. **只改负责的文件**：`git diff --stat` 与任务写集一致。
3. **校验命令**：任务提示词「检查」一节的命令，在本地实际执行全部通过。
4. **引擎缺口按交接处理，不判 FAIL**：内容依赖的运行时行为，若对应的引擎功能尚未合入，只要报告同时列明以下两项，就判 ✅，等引擎合入后由验收任务补测：
   - 阻塞的 ENG 任务 ID，例如 ENG-region-gates-data、ENG-event-executor、ENG-19e-m1-order；
   - 交接字段：内容已按什么接口写好、等引擎消费什么。
   缺口包括：Trigger 执行 EventDef 动作、gate / dialogue / loot binding 的数据源、说话人标签、M1 页面流顺序等。
   - 若内容写法与该 ENG 任务的已登记接口不一致，或干脆没在报告里列出阻塞，判 ❌。
5. **报告如实**：
   - 校验结果与实际命令输出一致，删除过期的失败结论；
   - 第 7 节有「需作者确认（附默认）」与交下游（ENG-* / 验收）的字段清单。

**裁定**：
- 1、2、3 任一不成立判 FAIL；
- 4 只在「缺口没列成交接项」或「写法与已登记的引擎接口冲突」时判 FAIL；
- 5 的问题列出并要求返修，但只在报告与改动明显相反时判 FAIL。
- 返修说明只写要补、要改的小项。

**口径**：只有上面写明判 FAIL 的条件是阻断项。审核不得新增判定标准：不评文风，不要求实现引擎功能，不要求超出写集的改动。其他观察只列出，不影响结论。
