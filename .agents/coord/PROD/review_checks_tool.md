# 代码工具任务（TOOL-*）合入前审核要点（协调者，2026-10-01；作者：验收不要太复杂）

**审核纪律**：必须先实际跑命令、看生成物，再写结论；无法执行的项写 ⚠️ 并说明原因，不计为 ❌。写着"尚未执行 / 尚未核实"的 ❌ 一律无效，会被当作审核失败重跑。

只审下面 5 条，每条 ✅ / ❌ 附依据：

1. 命令通过：任务提示词"检查"一节的命令本地实际执行通过（单测、`--check`）；不通过判 ❌。
2. 确定性：同一输入跑两次生成物 sha256 相同（抽 1 个输入核对）；不同判 ❌。
3. 生成物抽查：抽 2 个图标 + 2 个覆盖层（或 1 条预览条带）`view_image`：抠底干净无灰边、尺寸符合规格、形状 / 主色像源物品；明显错判 ❌。
4. 只改负责的文件：`git diff --stat` 与写集一致；没改规格文档与源图；判 ❌。
5. 报告如实：工具用法与实际参数一致；对规格的偏离写明。

裁定：1、2、4 任一不成立判 FAIL；3 明显错判 FAIL；5 只列出。

**口径**：只有上面写明判 FAIL 的条件是阻断项；审核不得新增判定标准，其他观察只列出不影响结论。
