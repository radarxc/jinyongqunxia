## 0. 方向与承接范围

让玩家一直身处江湖：大地图、区域城镇、就地战斗占据整个视口；人物与工具沿边缘排列，读物以册页覆盖世界，行囊像打开木匣。默认墨色 HUD、暖宣纸阅读面、朱砂确认印、旧铜细边。装饰集中在边角和接缝，正文保持清楚。

“始终全屏渲染”指主视窗的几何尺寸与场景连续性，不是后台和菜单下无条件每帧绘制。打开面板不卸载来源场景、不重置相机；暂停时保留最后一帧，见 §3.2、§8。时钟暂停与绘制调度分开，遵守基准 §19。

## 2. 八款界面调研

资料为 §11 的公开截图与发行方展示，访问日期均为 2026-10-03；只评可见布局。没有实际安装这些游戏，字体名称和完整图鉴功能不从截图猜测。“未见”不等于游戏没有；不把续作、MOD、移动版截图冒充原版。调研结论为设计观察，借鉴项属于本作 **（原创扩展）**，不复制纹样、图标或字体文件。

### 2.1 金庸群侠传（1996 DOS）

- 主视窗 / HUD：等距场景占主体，战斗左侧竖向命令、右侧头像与体力 / 生命 / 内力数字；操作直接叠在原场景。
- 菜单 / 物品：短词竖菜单；物品以小图格与选中说明组织，截图不支持把现代彩色稀有度套回原作。图鉴：所见武功清单是已学列表，未证实独立五类图鉴。
- 状态 / 字体 / 材质：头像旁三资源直读；点阵中文、深色半透明块和细框。沉浸来自场景连续与动作语言简短。
- 借鉴：场景不离眼、物品选择就地说明。避开：低分辨率小字、只靠记忆的热键与过小命中域。来源 G1；不采用搜索结果中标“前传”的 MOD。

### 2.2 侠客风云传（PC，发行方截图）

- 主视窗 / HUD：探索保留宽阔场景；战斗六角范围清晰，边缘头像和底部圆形动作入口。菜单 / 工具依情境出现。
- 物品格 / 品阶：本次商店截图集未覆盖完整背包，不据此断言颜色次序；图鉴结构同样未见，已知能力清单不能等同解锁图鉴。
- 状态 / 字体 / 材质：战斗头像附资源，剧情对白有大头画与气泡 / 阅读带；书写式题名与较清楚的正文分层。沉浸来自人物表情与场景同框。
- 借鉴：战斗动作收在边缘，对话立绘与环境联系。避开：把 PC 圆图标直接缩进触屏。来源 G2。

### 2.3 河洛群侠传（PC）

- 主视窗 / HUD：第三人称场景居中，右上圆形地图、底缘工具与人物信息；对话保留场景镜头。
- 物品 / 图鉴：此次官方截图未露完整物品格、品阶图例或独立图鉴分类，留为未核实观察项；本作不继承其未确认机制。
- 状态 / 字体 / 材质：角落头像与细资源条，深透底承载白色正文；材质简化让环境成为视觉主体。
- 借鉴：罗盘、地点与交互对象的空间关系。避开：过小底栏、把截图里的细字作为手机字号依据。来源 G3。

### 2.4 仙剑奇侠传（DOS / 98 柔情篇，商店合集）

- 主视窗 / HUD：探索地图近乎铺满，对话肖像与文本直接进入场景；战斗角色状态和命令集中在边缘。
- 菜单 / 物品：分类文字与选项列表是主要阅读方式；本次截图未证实现代品阶描边，独立五类图鉴也未见。合集含两个版本，不混称单一版本 UI。
- 状态 / 字体 / 材质：像素头像、数值资源、点阵正文、窄边框；沉浸来自对白节奏和人物头像，不靠装饰密度。
- 借鉴：一句对白一个阅读焦点、场景可见。避开：照搬像素文字、模仿原作头像与商用字库。来源 G4。

### 2.5 古剑奇谭（初代，PC）

- 主视窗 / HUD：场景满幅，战斗人物头像沿底边；菜单以暖色整页纸面承载，探索与菜单材质连续。
- 菜单 / 工具：竖分类与侧边项目；物品 / 能力详情采用图像、列表、说明分栏。截图不足以核定全部品阶颜色，不能转译为本作十二品。
- 图鉴 / 状态：发行方展示有资料阅读与地图式分页，未逐页验证收集解锁计数；人物肖像与状态项目组合。书法题名、规整正文、暖纸细饰让菜单像世界内物件。
- 借鉴：主图与阅读栏有不同密度，册页装订感。避开：整页不透明覆盖造成场景脱离，繁复金边。来源 G5。

### 2.6 太吾绘卷（Steam 当前展示，含新版画面）

- 主视窗 / HUD：地图是空间主面，底边功能入口，右侧任务；人物关系图、功法图与战斗使用各自信息画幅。
- 菜单 / 物品：暗青底、多栏分类与密集格阵；物品九品具体配色未在本次截图完整核对，不借其等级体系。图鉴：见关系网络与功法节点式资料组织，未证实统一收集册入口。
- 状态 / 字体 / 材质：头像、条形资源与大量数值；标题书法、正文规整，暗底铜色强调。沉浸来自术语与系统图的连续视觉语法。
- 借鉴：关系与经脉可视化按需展开，状态有来源。避开：一次展示所有细目、雷达图取代精确数值。来源 G6；不将当前截图追溯为 2018 首发 UI。

### 2.7 鬼谷八荒（PC）

- 主视窗 / HUD：水墨大地图，周边功能区；对话双立绘与底部纸卷，环境仍可见。
- 菜单 / 物品：木构边缘与纸面列表，图标格、彩色道具和独立详情。颜色次序未逐件验证；本作仍用黄玄地天。
- 图鉴 / 状态：截图可见册页左侧图目、右侧图文，人物信息为肖像与条目；完整图鉴门类 / 解锁分母未实玩核验。毛笔题名、浅纸与深木形成层级。
- 借鉴：实体书页与立绘同框、物品小图在独立详情中放大。避开：层层大模态框、高饱和宝物光污染。来源 G7。

### 2.8 烟雨江湖（移动端，官方 App Store 展示）

- 主视窗 / HUD：俯视城镇主体与右侧窄工具列，功能短词常驻；所见为横屏截图，不推断竖屏原生布局。
- 菜单 / 物品：侧列入口与人物换装陈列，截图中有成套衣装图块；完整背包与品阶图例未见。图鉴：未取得独立图鉴页，不能声称已有本作式五类册目。
- 状态 / 字体 / 材质：地图信息沿边缘，人物装束大图便于识别，木色侧框与工整正文；角色 / 场景统一比例产生沉浸。
- 借鉴：手机工具入口稳定、短词加轮廓、点击替代复杂拖拽。避开：长期占据地图一整侧的密集入口及活动图标。来源 G8。

结论：借 1996 的场景连续、侠客的战斗边缘组织、河洛的地图方位、仙剑的对话焦点、古剑的册页分栏、太吾的按需系统图、鬼谷的图像资料页、烟雨的稳定触控工具。未核清的商业游戏图鉴 / 品阶仅记录缺口，不作为本作规则输入；本作五类图鉴直接从已归属文档设计。

## 3. 主视窗、HUD 与面板栈

### 3.1 屏幕分区与尺寸

所有数值为 **【建议值】**；沿用 `14` §1.2 触屏 60×60、硬底线 44×44 CSS px，不以缩放整幅 UI 适配手机。主视窗铺满 viewport，安全区仅影响 HUD。世界相机有工具遮挡留白，不改变可达性。

```text
┌ 年号·年月·时辰·节气 ─ 地点 ─ 银两 ───── 罗盘/小地图 ┐
│ 队伍头像 气血/内力/体力     全屏世界                   │
│ 一条任务笺                 大地图 / 区域 / 城镇 / 战斗 │
│                         [选中对象的题签]               │
│        [册页/卷轴/木匣：按需覆盖，边缘露出世界]          │
│ 飘字/获得朱印                    上下文动作 / 对话卷轴 │
└ 行囊 · 武学 · 人物 · 图鉴 · 江湖志 · 系统 ────────────┘
```

| 视口 | HUD 与面板 | 核算 |
|---|---|---|
| 1280×720 | 安全内边 24；顶部 64；底工具 76；面板上 / 下各留 96 / 104；中部左右留 56 | 面板 1168×520；无面板时中央净高 `720−64−76=580` |
| 390×844 | 安全内边 12；顶部 88；底部六键各 60，间距 0；读取面板上留 116、下留 92，外缘留 12 | `6×60=360≤390−24=366`；面板净高 `844−116−92=636`，扣实际安全区 |
| 390 竖屏探索 | 顶部两行信息，队伍折为当前头像 + 队伍按钮；任务只露一行，罗盘缩为方位短签 | 节气 / 银两细项点顶签展开；不能丢失当前地点与关键资源 |
| 矮横屏 / 150% 字号 | 主操作固定，列表 / 详情改同页切换，卷内滚动 | 不压正文，不使确认滚出屏幕；场景仍铺满并保留边缘 |

日期 / 节气来自游戏时间投影；没有节气字段时留空，不用设备日期估算。银两显示沿经济单位格式化，底层仍为文；不可拿金色数字当新币种。当前队员显示三资源，其他头像点开同构摘要，伤势图标按 `06` 投影；队伍上限引用 `18`，不因 HUD 默认只露少数而改上限。

### 3.2 层级、暂停与返回

| 层 | 内容 | 场景 / 时钟与输入 | Esc / 返回 |
|---|---|---|---|
| 0 | SceneHost 世界 | 仅当前场景拥有输入；探索 tick 由宿主控制 | 无候选时开系统页 |
| 1 | HUD、头像、工具、罗盘 | 非交互透明区穿透；装饰不可拾取 | 撤场景候选优先 |
| 2 | 印章获得通知、提示 | 不抢焦点；收据到达后才展示获得 | 先关主动打开的提示 |
| 3 | 对话或一个主面板 | 世界钟暂停；场景留末帧，摄像机与会话保留；背景 inert | 退出预览 → 关详情 → 关主面板，各退一次 |
| 4 | 页内事务确认 | 替换详情，不叠第二确认；锁本事务 | pending 前回草稿，提交后不能假撤销 |
| 5 | 错误 / 恢复 | 纯 DOM；资源缺失时字体与背景均可回退 | 合法重试 / 导出，不绕校验 |

场景全屏且常驻不要求保留多个 renderer：城镇→战斗的场景转换仍按宿主生命周期；只保证打开工具不拆来源画布。完全遮挡面板停 GPU 提交；露出边缘的面板也默认冻结末帧，需重绘时只请求一帧；探索时钟仍暂停。战斗面板只在可暂停决策期打开，自动推进先请求接管，禁止面板本身停 / 改 CT。

面板保存来源触发器、列表锚点、筛选、相机位置；关闭还焦点，条目已消失则还到分类标题。一次最多主面板 + 一层详情，确认替代详情。系统设置从行囊进入时暂存行囊 UI 草稿并替换主面板；返回恢复，不能借此绕过书眠或对话事务。

### 3.3 鼠标、键盘、触屏的共同契约

鼠标左键与单指点击同为选中；确认才发命令。hover 只补解释，所有说明可聚焦 / 点击打开。双指只控制场景相机；面板列表单指纵滚，不穿透到地图。拖拽均有“选中→目标→确认”替代；手势边缘返回仅在无事务草稿时提示退出，不覆盖浏览器手势。

| 意图 | PC 默认【建议值】 | 触屏 |
|---|---|---|
| 行囊 / 武学 / 人物 / 江湖志 / 地图 | B（I 别名）/ K / C / J / M | 底栏与罗盘；地图是场景导航，打开总图不直接旅行 |
| 图鉴 / 系统 | G / Esc | 底栏图鉴 / 系统 |
| 导航 / 确认 | Tab，组内方向键 / Home / End，Enter / Space | 点选、固定确认 |
| 战斗招式 / 探索快捷物品 | 战斗 1–6；探索 1–3，只在对应模式有效 | 招式签 / 快捷物品抽屉 |
| 返回 | Esc；右键只撤候选，不覆盖系统上下文操作 | 每层有返回或关闭，不依赖长按 |

输入框、IME composition、确认框、浏览器组合键优先；keydown.repeat 不重复提交。城镇 WASD / QE 为现有六向移动，战斗 Q/E 可作镜头预设旋转，按场景域路由，不能同时触发。F5 保留浏览器刷新，快速存档用系统页显式按钮。样稿数字 1–6 是六屏浏览快捷键，**不移植进正式游戏全局键位**。

### 3.4 菜单与工具入口

底栏六项为行囊、武学、人物、图鉴、江湖志、系统；罗盘进大地图 / 区域地图；快捷药、队伍另从头像与底角展开。江湖志收任务、门派职责、家业与传承索引；人物收经脉、同伴；图鉴收五类资料并链接门派、成就、传承；系统收存档、设置、教学与退出。未开放功能显示获准线索与禁用原因，永不展示原始内容键或工程报错。

通知统一为小幅朱印 + 物品小图 + 数量 / 去向，点击可开详情；伤害飘字由 render 消费结算事件，HUD 只汇总当前对象。背包满先显示待拾去向；不能用印章动画再触发奖励。对话层详见 §4.4，不与重面板同时争夺输入。

生产回退栈：标题 `"Tianshu Title", "Ma Shan Zheng", "Kaiti SC", KaiTi, "Songti SC", serif`；正文 `"Tianshu Text", "Noto Serif SC", "LXGW WenKai", "Songti SC", "Noto Serif CJK SC", "Kaiti SC", KaiTi, "Microsoft YaHei", serif`。用户姓名和缺字交系统回退；拉丁数字可用系统数字族，不为 0–9 再加载中文粗字重。2026-10-03 实测 Google Fonts CSS2 请求 Ma Shan Zheng 与 Noto Serif SC 返回 200，LXGW WenKai 返回 400；因此样稿不引用该不可用的 Google Fonts 家族，也不从第三方 CDN 补载。

### 6.2 构建管线（交 ENG-ui-kit）

1. 输入为构建后已本地化的 UI 文本、当前内容包剧情 / 名称 / lore、已登记地名 / 穴名及维护的常用字表；不直接把整份策划 Markdown 的代码、ID 与英文说明算成游戏文本。常用字表默认项目维护 3,500 字集合 **【建议值】**，来源 / 版本随构建记录，字表未落地不声称覆盖完成。
2. 去重 Unicode 码点，保留标点、数字、全半角所需符号与变体选择符；不把玩家输入姓名上传服务器生成子集。检查字符 cmap 覆盖，缺字报告具体码点与内容文件，关键界面缺字阻断字体发布。
3. 分为启动标题 T、正文公共 C、章节增量 B：标题只含首屏所需短题；正文公共含常用字与共用界面字；章节集为实际章文字减公共集。公共集按实际 WOFF2 体积再切 ≤260 KiB 的不重叠块 **【建议值】**；每章新增总量目标 ≤500 KiB，超过须拆包而不是静默漏字。
4. 用 fontTools `pyftsubset` 的 `--text-file`、`--flavor=woff2`、`--output-file` 生成；WOFF2 需 Brotli 支持，见 F3。工具版本由 ENG 在环境锁文件固定，本文不杜撰当前版本号。子集后另处理内部名称并保留许可证，检查复合字形、标点与布局表。
5. 自动生成精确 `unicode-range`（不能给每块都写整个汉字区）、CSS、字符清单、hash、字数 / 字节统计和缺字报告；正文 CSS 在第一处阅读界面才挂载。章节包只附其增量 CSS，返回已下载章节可命中缓存。

```sh
# 约定命令示例，输入文件由 ENG 管线生成；本轮未构建生产字体。
pyftsubset title-source.ttf --text-file=title-characters.txt --flavor=woff2 --output-file=title-subset.woff2
pyftsubset body-source.ttf --text-file=chapter-characters.txt --flavor=woff2 --output-file=chapter-subset.woff2
```

### 6.3 载入、体积估算与 PWA

首屏只请求 T，≤40 KiB 目标沿 `14` / `tech/03`；正文就绪前系统楷 / 宋仍可玩。固定短题可用 `font-display:swap`，正文先回退，`document.fonts.load()` 完成后在下一页切换字体，首段不阻塞超过 300 ms，防止对白正在阅读时跳行。`font-display` 自身不保证精确 300 ms，这是应用超时策略。`unicode-range` 只有实际使用该范围字符才触发相应文件下载，见 F4–F6。

估算 **【建议值】（待实测）**：设 WOFF2 平均每字 150–250 B、每文件开销 4 KiB，120 字标题为 `120×(150..250)/1024+4≈21.6..33.3 KiB`；3,500 常用字约 `516.7..858.5 KiB`，需分块，绝不能声称整套正文只有 260 KiB。若首段涉及一块 800 字正文，约 `121.2..199.3 KiB`；章节新增 1,500 字约 `223.7..370.2 KiB`。字形复杂度和压缩共享使估算仅用于预算，最终按生成文件测量。

entry 170 KiB **只算 JS gzip**，字体另计网络与缓存；不能以“不算 JS”为理由首屏拉全字库。假设 1 Mbps 有效吞吐，40 KiB 标题纯传输约 `40×1024×8/1,000,000≈0.33 s`，不含 RTT / 握手，不作为首屏实测承诺。

正式字体同源自托管、内容 hash URL；PWA 外壳预缓存仅标题子集与许可，正文按阅读 / 用户下载书界包进入版本化缓存。更新先下载并校验新字体清单再切版本，保留当前页面所需旧版直到离场；空间不足可淘汰字体，不能删本地存档。Cache API 不自动过期且可能被浏览器清理，离线承诺仅覆盖确已下载内容（F7）。样稿按任务仅用 Google Fonts；不注册 SW、不承诺首次离线有远端字体，下载失败自动回退。

### 7.2 可访问性与低动效

选择簿按 WAI-ARIA APG listbox / 单选规则实现（F8），选项内不塞另一个按钮；复杂详情改普通列表与独立动作。装饰 SVG / 图片 aria-hidden，文本是真实 DOM。自绘卷轴拖杆至少 44 px 命中，触屏用整块列表纵滑；增强脚本失败时恢复浏览器滚动条，不能把滚动彻底禁掉。

`prefers-reduced-motion:reduce` 或游戏减少动效开启，禁卷曲、震屏、墨扩散、缩放落印，改为直接显示或 ≤80 ms opacity；两开关任一为真即生效（F9）。墨晕是贴图显隐，不实时扩散滤镜；展卷是内容层位移，裁剪框尺寸不动画。禁用、空列表、资源失败、命令拒绝、过期预览均给就地文字与返回路径；字体缺失不改变可操作资格。

## 8. 性能与工程约束

### 8.1 渲染、分层与资产

- `packages/ui` 的 Vue 组件只收只读投影、发命令意图；不导入 core 内部状态、不计算命中 / 装备加成 / 可行动资格。`apps/game` 组装 SceneHost、输入与命令桥；`packages/render` 负责已有场景与拾取。新增图鉴投影由 core / content 归属方实现。
- 主视窗 `position:fixed; inset:0`，HUD 与面板 DOM 叠加；穿透区 `pointer-events:none`、控件恢复命中。UI 消费的事件不可再落到地图；关闭面板恢复原焦点与相机锚点，禁止点击穿透导致移动。
- 打开行囊等重菜单时保留同一个场景宿主与末帧，停 world tick 和无效逐帧渲染；不为每个面板创建 Canvas。关闭重面板仍默认卸载其 DOM、清图片与订阅，仅保存轻量 UI 草稿；场景保留不等于面板全量常驻。真正换场景仍按 render 生命周期释放旧资源。页面后台停绘制；恢复 / WebGL 丢失走 `14` §7.3 的低依赖容错。
- 面板代码动态导入，首次打开才加载详情图；只预读当前场景常用工具的轻壳。图片走 manifest URL / public 静态目录，不 `import` 二进制进 JS，不内联大 base64；落库立绘 / 物品图优先复用。
- 框和底纹采用 9-slice 图集与可复用坐标，`ui-art-kit` 给 T/R/B/L 切片边距；图集实现需要按切片裁源或构建期导出切片，不能把整个 atlas URL 直接当单框 border-image。CSS `border-image` 可作独立切片文件回退（F11）。透明边留足采样间隔，禁止邻格串色。

### 8.2 动效与预算

目标 60 fps，即 `1000/60≈16.67 ms/帧`；这是目标而非本轮真机结论。动画仅改 transform / opacity，纸纹、阴影、墨晕均静态资源；禁动画 width / height / blur / shadow、禁常驻粒子与大面积 backdrop-filter。最大同时展开一个主面板，动画完成释放 will-change。滚动列表按 `14` 的窗口化与投影节流要求执行，长图鉴不一次挂载所有立绘。

**硬门禁不变**：`tools/perf/budgets.json` entry ≤170 KiB、render chunk ≤180 KiB、WebGL 合计 ≤350 KiB，口径均为该文件规定的 gzip JS；总量为 `170+180=350`。字体、图集另报网络字节 / 解码内存，不能调大 JS 预算来容纳壳或组件库。静态样稿的内联脚本不是生产 entry 测量结果。

**【建议值】**：工具切换反馈 ≤100 ms；题签按压 80 ms，面板展开 160 ms，落印 180 ms，与 §7.1 一致；同屏只保留一个获得提示队列，连续所得合并计数。触控遵守 `14` §1.2：60×60 CSS px 优先、44×44 硬底线，任何比例缩放后仍满足；safe-area 与动态浏览器栏由 `14` §1.4 承接。390 px 竖屏先重排，不把 1280 px 整体缩成小图。

### 8.3 输入、音效与验证边界

音乐继续由既有音频管线调度；组件只发 hover / press / commit / reject / page-turn / stamp 钩子，静音与系统减少动效优先，hover 音默认关闭。相同一组批量操作只发一次结果音，命令拒绝时不能先播成功音。浏览器首次交互前的声音解锁沿现有工程约定。

真机验证至少覆盖桌面鼠标键盘、iOS Safari、Android Chrome 的竖横屏、软键盘、断网、字体失败与低动效；具体系统 / 浏览器版本由 ENG 验收记录，不在设计稿猜最低版本。UI 样稿可验证布局与交互方向，不能证明游戏 60 fps、内存和首屏时间。
