## 1. 十四书界年代考据

### 1.1 方法与原则

1. **排序原则**（基准 §2）：按**故事主体发生的年代**排序；序幕 / 尾声的年代不改变排序。
2. **证据分级**：
   | 等级 | 含义 | 例 |
   |---|---|---|
   | A 明文 | 书中直接写出年号 / 年份 | 《雪山飞狐》开篇写明乾隆四十五年 |
   | B 史实人物 / 事件 | 书中出现可考的历史人物、战役、制度 | 鹿鼎记：擒鳌拜（1669）、尼布楚条约（1689） |
   | C 门派 / 人物传承 | 与已定年书的人物、门派存在先后关系 | 侠客行：武当派已是大派 ⇒ 晚于倚天 |
   | D 官制 / 地名 / 风物 | 只能粗定朝代 | 连城诀："知府"明清通用 |
   | E 作者说明 | 后记、访谈 | 笑傲后记：本书"没有历史背景"（大意） |
3. **游戏定年** `gameYear`：为书眠过场（"一梦 N 年"）、时代图层选择与跨书彩蛋提供内部年份。历史人物 / 事件只用于锚定范围；表内具体起止年仍是本作采用的推定值，逐字核对项列在相应书界及 §10.4。笑傲、侠客、连城、白马、鸳鸯五部年代不详，给出的具体年份均为**（原创扩展）**安排；UI 加"约"字，书灵采用模糊措辞，不把玩法定年冒充原著事实。
4. **归属边界**：本文只给出各书界的朝代语义和切换年份。历史城市、入口及状态由 `design/11` 定义；NPC 的 `born` / `died`、是否健在与同伴重逢由 `design/18` 定义。

### 2.2 外来与本土的判定

每个武功实例 `SkillInstance` 与装备实例 `EquipInstance` 带一个 `nativeTo: ChapterId`，表示"它属于哪个书界"。武学实例另带 `sourceGrade?: Grade`：缺省等于定义的 `absGrade`；从残承途径新学时记该途径的 `lineageGrade`，且此限制随实例跨界保留，不能靠书眠、强化、《天书现影》或终局自动补全。层数来源上限另用 `sourceCap`，两者不可混用。

| 事件 | `nativeTo` 取值 |
|---|---|
| 在书界 X 习得完整武功 / 获得装备 | X；完整武功 `sourceGrade := absGrade` |
| 在书界 X 从残承途径新学武功 | X；`sourceGrade := lineageGrade`，只取得残承来源品阶 |
| 书眠携带到下一书界 | **不变**（因此在新书界成为外来） |
| 在书界 X 由残篇"忆起"（§5.3） | X（忆起视同本书界习得） |
| 在书界 X 锻造的装备（哪怕用了外来材料） | X |
| 对外来装备做精炼 / 镶嵌 / 附魔（`design/10`） | **不变**（杜绝"精炼洗白"） |
| 印证（完整传承，见下） | 改为当前书界 |
| 器合（同 ID 的原生实例并入，见 §5.8） | 改为当前书界 |
| 藏史取回（§6.6） | 保留寄存前实例原有 `nativeTo`；`depositChapter` 只记录寄存发生在哪个书界，不改变本土归属 |

`isForeign(inst, ch) := inst.nativeTo !== ch.id`。高武书界 `S=0`，外来标记仍然存在，用于 NPC 回响（§6.3）与书眠 UI。

**印证 `attune`**：外来武学在一个"它也原生存在"的书界里重新取得本土身份。

| 类型 | 条件 | 效果 |
|---|---|---|
| 完整传承 `full` | ① 当前书界的再遇表（§5.7）含该武学且类型为 `full`；② 完成该书界配置的印证事件（与原著持有者切磋 / 受其指点 / 读到本书界秘籍原本，三选一，由 chapters/ 文档指定）；③ 满足本书界对该武学的进度门槛（§2.9） | `nativeTo := 当前书界`、`sourceGrade := absGrade`，压制消失；层数上限照旧 |
| 残承 `partial` | 再遇类型为 `partial`，带残承品阶 `lineageGrade` | 不改 `nativeTo`；写入 `attunedGrade = lineageGrade`、`attunedIn = 当前书界`；有效品阶见 §2.3 |

印证不消耗层数、不重置经验；离开该书界后照常成为外来。

### 2.3 品阶压制公式与边界

```
S(tier)       = { HIGH: 0, MID: 2, LOW: 4 }
gSource(inst) = min(inst.absGrade, inst.sourceGrade ?? inst.absGrade)
S_eff(inst)   = design/13 §4.5 的按武学 / 装备分流结果
effGrade(inst, ch):
  if inst.nativeTo == ch.id:                       return gSource(inst)
  base = max(1, gSource(inst) − S_eff(inst))
  if inst.attunedIn == ch.id:                      return max(base, min(inst.absGrade, inst.attunedGrade))
  return base
```

| 边界 | 规则 |
|---|---|
| 下限 | 黄下（1）。玄中（5）及以下带入低武全部变为黄下。 |
| 跨大阶 | 按整数减，不按"大阶"减：天下 10 −2 = 地中 8。 |
| 绝对品阶 | 永不改变；离开压制书界后按新书界重新计算。 |
| 来源品阶 | 残承新学以 `sourceGrade` 为压制前基数；来源限制随实例保留。完整传承才可补到 `absGrade`。 |
| 显示 | UI 显示"天上 → 天下（天道压制 −2）"，原品阶划线、有效品阶用有效品阶主色（基准 §4 色表）。 |
| 永久抵消 | 普通外来实例用 `S_eff=max(ceil(S/2), S-off_kind)`，`off_skill` / `off_equip` 分流；自创武学最高地上 9，压制基数直接取 `ceil(S/2)`，不可再被永久效果降为 0。完整规则见 `design/13` §4.5。 |

### 2.4 层数截断与积蕴

| 项 | 规则 |
|---|---|
| 真实层数 `trueLayer` | 1–10，只增不减；随武功实例一起携带。 |
| 有效层数 `effLayer` | `min(trueLayer, tierCapEff, gateCap(absGrade, displayLevel), special.layerCap ?? 10)`；所有层数相关计算（招式威力、数值被动与通常的解锁）都用有效层数。`tierCapEff` 的本命 / 现影例外见 `design/13`。 |
| 正常修炼 | 只能在 `maxLayer`、`sourceCap`、`gateCap` 与 `tierCapEff` 都允许时提升 `trueLayer`；已练成的更高真实层数不回退。 |
| 修为 / 来源瓶颈 | 尚未达到 `tierCapEff`、但被 `gateCap` 或 `sourceCap` 卡住时，新增武学经验保留为 `sxp`，按 `design/05` §3.3 的一重经验上限暂存，**不转积蕴**。 |
| 积蕴 `latentExp` | `trueLayer` 已达到 `tierCapEff` 后继续获得的该武功修炼经验，才按 **50%** 效率存入积蕴；积蕴上限 = 从该上限升到第 10 重所需经验之和（经验表见 `design/05` §3.2）。 |
| 积蕴释放 | 进入层数上限更高的书界（或终局）时自动注入，逐层提升直至用尽或达到新上限；书眠压制预览（§4.3 第 5 步）会显示"积蕴可破至第 N 重"。 |
| 招式封印 | 通常情况下，招式 `unlockLayer > effLayer` 时封印：UI 灰显加锁，提示"天道所限：需第 N 重"。已装配的封印招式不可施放，但保留在招式栏位。`tsp_05_fate`“封印松动”是唯一例外，依 `design/13` §4.3 执行；它不抬高 `effLayer`，也不绕过修为或来源要求。 |
| 敌人 | 敌人与队友同样受 `layerCap` 约束；Boss 超限只放宽等级、不放宽层数。 |
| 对 `design/05` 的要求 | 核心武功的第一绝招 `unlockLayer≤7`，第二 / 第三绝招默认在 9 / 10 重；逐门数量与职责见 `design/05` §3.5 和统一裁定表。低武通常只开放第一招，中武通常开放前两招，不能把后续绝招改名为普通终式规避数量与共享冷却。 |

层数系数以 `design/05` §3.1 为准：`L(n) = 0.5 + 0.1 × n`，即 L(10)=1.50、L(9)=1.40、L(8)=1.30、L(7)=1.20、L(1)=0.60。本文后续 P 值均按此式复算。

### 2.5 显示等级与真实等级

| 项 | 规则 |
|---|---|

| UI | 角色面板显示"Lv 60 · 宗师（真 68）"；封顶提示为"修为已臻此界之极"，经验栏切换为修为余韵进度，不展示仍可暗中升级的真实等级条。 |

### 2.11 敌人武学品阶分布

**模型**（确定性：品阶骰使用种子流 `rng.stream('grade', encounterId)`）：

```
μ_normal(L, W) = 1 + 7.3 × (0.1 + 0.009 × W) × (L / 70)^0.65     // L = 敌人显示等级
μ_elite        = μ_normal + 1.5
P(g) ∝ exp( −(g − μ)² / (2σ²) ),  g ∈ [1, gmax]，归一化
σ: 普通 1.0，精英 0.9
gmax: 见 §2.1（普通 9/8/7，精英 9/9/8，对应 高/中/低武）
具名 NPC：手工配置（参考中心 μ_normal + 3，可使用本书界原生天级；受 I3 约束）
```

**概率表显示规则（表 B–J）**：先以未舍入权重在 `1..gmax` 内归一化；精确值 `<0.05%` 的格显示为“—”（参与余差计算时按显示值 0.0%），其余格四舍五入到 0.1%；最后把 `100.0% − 已显示合计` 的舍入余差补到该行显示概率最高的一格。这样每行显示合计恒为 100.0%，运行时仍使用未舍入概率，不使用表中显示值反推权重。

- 取到品阶 g 后，从该敌人所属门派/势力的武学池中选 g 品武学；没有则取最近的更低品阶，再没有则取最近的更高品阶（不超过 gmax）。
- 敌人武学层数：普通 `clamp(round(2 + 5 × L / levelCap), 1, layerCap − 2)`；精英 +1；具名 ≤ `layerCap`。
- 武运使同等级的敌人品阶更高：同为 L=45，巅峰书界的普通敌人中心约玄上，衰微书界约黄上（表 A）。

### 2.12 随机掉落品阶分布

掉落 = 固定掉落（任务/Boss/宝箱配置，含全部天级）+ 随机掉落（本节）。随机掉落先掷**品阶骰**，再在书界掉落表中按品阶挑具体物品（秘籍残页、装备、材料、丹药；物品目录见 `design/05`、`design/10`）。

| 池 | ID | 来源 | μ | σ | gmax（高/中/低） | 天级 |
|---|---|---|---|---|---|---|
| 普通 | `pool_common` | 普通敌人、野外箱、采集 | `μ_normal(L_src, W) − 0.5 + luk/200` | 1.1 | 9 / 8 / 7 | 无 |

苏醒地点按以下顺序确定：①休眠地点在下一时代仍安全可达，则取同一稳定地理锚；②该地点消失 / 封闭，则取同区域最近的合法出口；③事件本身为坠落、海漂等位移，则使用事件声明的出口；④仍无合法点时使用目标章节指定的保底开场点。苏醒时间取下一书 `gameYear.start` 与其最前期主线窗，不允许为了方便把玩家投到中后期。地点定义归 `design/11` / chapters，本文只定选择算法。

**低武本土补位（作者决定 P25）**：鹿鼎采用北京白云观全真入门支线；连城、鸳鸯采用游方武当道人支线，均为**（原创扩展）**。本文只确认这些支线可在余韵期完成并参与书眠选择；具体武学池以 `design/catalog/skills-daojia` 为准，任务与 NPC 由相应 chapters/ 文档及 `design/18` 定义。

### 4.2 流程状态机

```
IN_CHAPTER ──取得天书──▶ AFTERGLOW ─▶ SLEEP_EVENT ◀──── 取消（事件提交前）
                                           │ 事件落定
                                           ▼
  BS_SAVE ─▶ BS_REVIEW ─▶ BS_ALLOC ─▶ BS_PICK_3P3 ⇄ BS_CONVERT ⇄ BS_PICK_EQUIP ⇄ BS_PREVIEW ─▶ BS_CONFIRM
                                                                                        │ 长按确认
                                                                                        ▼
                                              IN_CHAPTER(next) ◀─ BS_WAKE ◀─ BS_CINEMATIC ◀─ BS_COMMIT
```

- 休眠事件按剧情保存点处理；进入识海后的 `BS_COMMIT` 之前仍无破坏性，可前进 / 后退，或读取事件前自动档返回余韵。
- `BS_COMMIT` 是唯一的原子写入点；以 `plan.id` 保证幂等（崩溃重进不会重复生成残篇或重复扣除）。
- `BS_COMMIT` 完成后即持久化；若在过场中退出，重进直接到 `BS_WAKE`。

|---|---|---|---|---|

正式书界仍有 13 个相邻转场资产位，但顺序改为 `10→01→02→...→09→11→12→13→14`；数字取稳定 ID。默认鹿鼎后资产播放周游变体而非书眠变体。总目标时长仍为 `13×24=312` 秒。

**书灵推荐** `autoPick`（两遍式）：
1. 武学：对每个候选计算
   `score = P_target × roleW + setΔ + attuneBonus`，其中 `P_target = G(effGrade_target) × L(effLayer_target)`；
   `roleW`：内功 1.2（主运候选），拳脚 1.0，兵器 1.0（若与第 2 遍选出的主武器类别不符则 0.8）；
   `setΔ`：保留成套可得的套装评分（`design/07` 提供 `setScore`）；
   `attuneBonus`：目标书界再遇表为 `full` +0.3，`partial` +0.15。
   同分时绝对品阶高者优先（"携带看绝对品阶"）。每列取前 N。
2. 装备：采用 `design/10` §7.5 的目标书界携带价值 `score = G(effGrade_target) × slotW × Rtarget + uniqueW + setΔ + matchW`；`slotW`：主武器 1.5、衣 1.2、其余 1.0；`Rtarget = 1 + 0.04 × refineEff(target)`；`uniqueW`：目标书界 `effGrade_target≥10` 为 +0.40、地阶保留核心为 +0.20、玄阶减半为 +0.10；`matchW`：主武器类别与已选兵器武学一致 +0.5。天级装备只受 6 件携带上限与 `noCarry` 约束，不计武学获取预算 `playerTianBudget`。取前 6。
3. 回到第 1 遍按选定主武器重算 `roleW`，至多迭代 2 次。
4. 每项推荐附一句理由："绝对品阶最高""下一书界可印证""维持套装 X"。

**撤销**：`BS_COMMIT` 之后不可在当前书眠流程内撤销。能否从标题菜单载入 `save_booksleep_chNN`、每书界可回档次数及禁止条件，均按难度与规则开关执行 `design/13` §9.3；本文不另行保证该检查点可读。

```
commitBookSleep(state, plan):
  if plan.id in state.bookSleepLog: return                      // 幂等
  assert validateSleepEvent(plan.sleepEventId, plan.from)
  assert plan.skills.martial.length <= 3 && plan.skills.inner.length <= 3
  assert validateConversionPartition(state.skills, plan.skills, plan.convert)
  assert validateEquipCarry(plan.equips)                         // 装备数 + 本书界藏史数 ≤ 6（S4）；noCarry
  for s in state.skills:
    if s.id == sk_changshengjue: keep s                           // 不占 3+3，不可遗忘 / 散功
    else if s.instanceId in concat(plan.skills.martial, plan.skills.inner):
      keep s                                                     // nativeTo / trueLayer / latentExp 不变
    else if s.instanceId in plan.convert.forget:
      upsertFragment(state, s); convertNewSxpToEpiphany(state, s) // §5.1–5.2、13 §4.10
    else if s.instanceId in plan.convert.dissipate:
      upsertFragment(state, s); convertNewSxpToTrueEssence(state, s)
    else:
      upsertFragment(state, s)                                   // 只留残篇，不得资源获利
  state.equips   = state.equips.filter(e => e.instanceId in plan.equips)
  archiveChapter(state, plan.from)                                // 结局、天书之力、统计写入 chapterHistory
  applySleepAllocation(state, plan.sleepAlloc)                    // design/03：仅六项；属性原值全保留
  snapshotCompanionsForReunion(state, plan.from)                  // design/18：曾招募标记、离队能力快照
  clear(state.activeCompanions)                                   // 只清活动队伍，不删除同伴历史
  preserveMeridianProgress(state)                                 // design/15：冲穴、周天/九转与永久增益跨界保留
  runBookSleepHooks(state, ['resources', 'livelihood', 'sects'])  // design/16、12：重置当代资产/任职/身份
  clearCurrentEraOrdinaryAssets(state)                            // 金钱、普通物品、当代任务；不触及系统物品
  preserveCrossWorldState(state)                                  // 天书实物、学识、图鉴、永久增益、historyBox
  state.chapter  = plan.to
  switchEraLayerAndWake(state, chapter(plan.to).gameYear)         // design/11：时代图层与苏醒地点
  refreshOpenSects(state, plan.to)                                // design/17：按目标年代查询开放门派矩阵
  state.displayLevel = min(state.realLevel, chapter(plan.to).levelCap)
  releaseLatentExp(state)                                         // 层数上限升高时注入积蕴（§2.4）
  state.bookSleepLog.push(plan.id)                                // 史匣 historyBox 不受影响
```

## 5. 残篇机制

### 5.1 生成规则

| 情形 | 是否生成残篇 |
|---|---|
| 第九层前，苏醒取舍中未保留的武功或内功 | 是；无论选择转化还是只留痕迹，均更新同一条记录 |
| 武功类别 | 拳脚、兵器、轻功、暗器及武艺型杂学均计入 3 门武功；不再因“非核心”自动遗忘 |
| 序章结束 | 否；临时 `sk_yuenvjian` 实例在离开序章时销毁，不进入白马结束时的 3+3 候选，不生成残篇、顿悟、资质或其他永久战斗收益；正式取得方式留给 `DES-prologue-v2` |
| 《长生诀》 | 否；不可遗忘、不可散功且不占 3+3 |
| 九层后的周游 | 否；不再发生苏醒取舍 |
| 书界内主动散功 / 被废武功（若 `design/05` 设计此类机制） | 否（由 `design/05` 自行处理） |
| 已有残篇的武学再次被遗忘 | 更新原记录（不新建） |

| 保留 | 丢弃 |
|---|---|
| 武学 ID、绝对品阶、来源品阶 `sourceGrade`、来源层数上限 `sourceCap`、类别、门派、同源组 | 当前层数、当前经验、积蕴 |
| 历史最高层数、曾解锁招式、绝招是否解锁 | 装配状态、套装进度 |
| 习得 / 遗忘的书界记录、累计施展次数 | `nativeTo`、印证状态 |
| 已发放的感悟值、转化经验高水位 `convertedSxp` | 由该武学提供的被动与 Buff |

`convertedSxp` 随残篇与再次习得记录永久取最大值。再次忆起后若累计修炼经验由 8,000 增至 11,000，下一次只能以新增的 `11,000−8,000=3,000` 为转化基数；未增长时再次遗忘产出 0。这样残篇仍允许按再遇途径忆起，但不能在“忆起 → 遗忘”之间反复兑现同一段经验。

### 5.3 再次习得（忆起 `recall`）

| 项 | 规则 |
|---|---|
| 触发 | 在任一书界"接触"该武学的来源：① 该武学秘籍 / 残页；② 拜师或受原著持有者指点；③ 在战斗中观摩持有者施展 ≥ 3 次且武学常识 `lore` ≥ 40。满足任一即可"忆起"。 |
| 本土性 / 来源 | 忆起视同本书界习得：`nativeTo := 当前书界`，不受外来压制；但恢复残篇保存的 `sourceGrade` / `sourceCap`，未接触完整来源前不得超过该残承限制。 |
| 起始层数 | `startLayer = min(sourceCap, clamp(floor(maxLayer × 0.5), 1, layerCap − 2))` |
| 修炼加速 | 经验 ×2.0，直到有效层数达到 `min(maxLayer, layerCap)`；此后 ×1.0 |
| 门槛 | 属性 / 资质门槛 ×0.8；**进度门槛（§2.9 R3）不降低**，防止天级提前回归 |
| 招式 | `unlockLayer ≤ startLayer` 的招式立即可用；曾解锁的招式不再播放首次解锁演出 |
| 预算 | 忆起的天级计入本书界 `playerTianBudget` |

起始层数速查：

| 历史最高层 | 高武起始 | 中武起始 | 低武起始 |
|---|---|---|---|
| 10 | 5 | 5 | 5 |
| 9 | 4 | 4 | 4 |
| 8 | 4 | 4 | 4 |
| 6 | 3 | 3 | 3 |
| 4 | 2 | 2 | 2 |
| 1–3 | 1 | 1 | 1 |

耗时估算 **【建议值】**：按 `design/05` §3.2 的正式逐层经验表计算，天上品从 1→10 共 26,220 `sxp`，其中 1→5 为 `600+900+1320+1800=4,620`，占 `4,620/26,220≈17.6%`；若残篇从 5 重忆起并以 ×2.0 修炼到 10 重，耗时约为 `(26,220−4,620)/2÷26,220≈41.2%` 的首次全程。不同品阶因同用 `GF(g)` 比例相同，约为 **41%**。

### 5.5 武学感悟 `insight`（永久小加成）

残篇生成时（每个武学 ID 只结算一次，之后若以更高最高层数再次遗忘则**补差**）发放：

`insight = baseByGrade[absGrade] × clamp(maxLayer / 10, 0.3, 1.0)`，且要求 `maxLayer ≥ 3`（防止"学一重就丢"刷感悟）。

### 6.6 藏史（原创扩展，可选机制）

**概念**：在某书界把一件装备（或一份史笺）藏于跨时代存在的"古迹"，后续书界到同一古迹寻回。它是一枚"时间胶囊"，不是第二个背包。

**命名边界（CN-04）**：`rs_*` **仅表示本节古迹**（`RelicSiteDef`）；生产资源一律使用 `design/16` 定义的 `res_<类别>_<阶><品>`，资源点使用 `rp_*`，营生场所使用 `biz_*`。不得以 `rs_*` 表示药材、矿石等生产资源，也不得把 `res_*` 当作藏史地点。

**为何不破坏"6 件携带"规则**：
1. **守恒**：每次书眠经识海进入下一书界的装备仍 ≤ 6（S4 使存入占用的是存入书界的额度，而非额外额度）。
2. **有界**：史匣全局 ≤ 2 件装备，任一书界内外来装备至多 6 + 2 = 8 件，且那 2 件是书界第 3 幕之后才能拿到的。
3. **更弱**：取回物 = 绝对品阶 − 侵蚀 − 压制，恒 ≤ 一路携带的同一件（上表最后一列），只在"跳过中间书界、腾出中间几次携带额度"上有收益。
4. **不越级**：取回物有效品阶 ≤ 12 − S（与一路携带的天上品同一上限），而不变式 I1 保证本书界原生最高品阶 ≥ 12 − S，因此藏史物至多与本地顶级固定掉落同档，相当于"一份提前约好的本地战利品"。
5. **机会成本**：史印每书界 1 枚且只在余韵期可用；寻史需要跑任务、过门禁。

### 9.3 结构与人工验收

1. TypeScript 片段须通过项目格式化 / 类型检查；`Grade` 范围为 1–12，`WorldTierRule` 与 YAML 三档字段一一对应。伪代码不是可直接编译的 TypeScript，不得复制进运行时。

5. 原著事实抽查以三联 / 广州修订版为基线；无法逐字确认的项目只保留 §10.4 的七项，不把玩法定年、原创支线或爱好者推测写成原著事实。
