### 0.1 一句话结论

全作不是十四张彼此无关的地图，而是同一张不可行走的全国导航图，投影到十四个时代图层；玩家在导航图选路线并结算旅程，进入某一全局 `rg_*` 后，才加载可行走的六角场景。地貌与稳定地点尽量跨时代复用，城市名、势力、NPC、门派、资源点和营生状态由当前书界的时代包覆盖。

## 1. 世界结构

### 1.1 四层结构

```text
江湖大地图（全作唯一，导航 UI；不可行走）
└─ 全局玩法区域 rg_*（30 个稳定 ID；跨时代复用基础包）
   ├─ 城市 city_*（189 个稳定地理锚；时代层改名、改地位、改开放）
   ├─ 野外 / 山门 / 岛屿 / 秘境场景 sc_<NN>_*（按需加载）
   └─ 32×32 六角地块 chunk（1,024 个轴坐标槽；渲染与流式单位）

书界 chNN = EraLayer
└─ 覆盖 region/city/scene/sect/resource/business/NPC/route 的当代状态
```

`chapter` 是叙事和成长容器，`rg_*` 是跨时代地理容器；两者不是父子关系。一个书界只开放 6–10 个玩法区域，但同一 `rg_*` 可在多书界复用。一个区域可含多座城市与若干离散场景，不要求把数百公里地理按 1 m 一格连续铺满。

### 1.2 大地图、区域和场景的运行边界

| 层 | 玩家操作 | 数据驻留 | 切换 |
|---|---|---|---|
| 大地图 | 缩放、筛选、选起终点、比较路线、确认出发 | 当前 `jianghu-chNN.svg` 或生产瓦片；开放城市、门派、路线摘要 | 不运行角色移动与遭遇检测 |
| 区域 | 八向表现的自由探索；六角寻路、交互、采集、明雷追逐 | 当前 `RegionDef`、时代差量、当前及相邻场景索引 | 进出区域自动存档；邻区包预取 |
| 场景 | 城镇街区、山道、洞窟、庄园、船、秘境等可行走单元 | 相机周围 3×3 chunk 先构建，其余流式 | 门、路口、渡口或门禁传送 |
| 战场 | 仍在当前场景上行动 | 遭遇点周围实际可用六角 ≤400，`qSpan/rSpan≤20` | 不另加载一张抽象战斗地图 |

探索动画依裁定 C20 使用八方向；规则寻路仍以 `design/08` 的 pointy-top 六邻六角为准。镜头四个 90° 预设只改变表现映射，不改变坐标、邻接或随机结果。

### 1.3 区域和场景规模

| 级别 | 轴槽包围盒 | chunk 数 | 槽位上限 | 典型用途 |
|---|---:|---:|---:|---|
| 微型场景 | ≤64×64 | ≤2×2 = 4 | 4,096 | 客栈、宅院、地牢单层、船甲板 |
| 标准场景 | ≤96×96 | ≤3×3 = 9 | 9,216 | 城镇街区、山门、山谷、普通秘境 |
| 大型场景 | ≤160×160 | ≤5×5 = 25 | 25,600 | 大城、草原、沙漠、连续山地 |
| 压力上限 | ≤256×256 | ≤8×8 = 64 | 65,536 | 极稀疏荒野或性能基准；不得作为常规制作目标 |

- 每 chunk 固定 `32×32=1,024` 个轴坐标槽，来自 `tech/02` §2.2。槽位包含不可走留白，不能把槽位数等同于实际内容格。
- 一个 `rg_*` 可含 3–8 个场景；同一时刻只挂载一个主场景及其必要室内子场景。区域不是一张 256×256 的巨图，也不把真实地理距离换算成格数。
- 标准场景首屏恰为 3×3 chunk；大型场景其余 chunk 每帧最多上传 2 个。单个区域素材块沿用 `tech/03`：mid 典型 ≤20 MB、错误线 25 MB；规则 / 文本单片原始 JSON ≤300 KB，游戏中单次解析 ≤256 KB。
- 大型城若超预算，按章节街区拆 `sc_<NN>_<拼音>`，保持同一 `city_*`，不可伪造第二座城市。山体高差超过 10 级时按 `design/08` §5.1 拆段。
- 上表是玩法内容边界；`tech/02` / `tech/03` 尚需以 30 区结构复核 256×256 压力场景、区域包和切换峰值，见 §15。

### 1.4 区域连接

| 连接 | 数据来源 | 可见与通行 | 旅行结算 |
|---|---|---|---|
| 官道 / 山道 | `routes.yaml` 的陆路线 | 起终城市开放且入口未封锁；候选 `via` 关闭时不可停靠 | 徒步、坐骑、车马；路上可触发暗雷 |
| 河运 / 海运 | `routes.yaml` 的水路与码头 | 码头开放、班次和天气允许 | 客船 / 货船；不得在未列端点的沿途城市停靠 |
| 区域边界 | `RegionDef.neighbors` + 场景出口 | 玩家已到达出口；门禁读 `design/08` `GateExpr` | 短途步行，通常不回全国图也可确认 |
| 驿站快行 | `post_*` | 当前与目标驿站已登记；主线封锁可暂停 | 付费并推进时间，跳过普通暗雷 |
| 图外专线 | 三个 `offmap_*` | 只经权威专线；每线两端、无中继 | 完整转场，途中不可下船 / 下车 |
| 书眠切层 | `design/02` 书眠提交 | 不是地理路线；只在书眠流程执行 | 原子切换时代后于下界苏醒点进入 |

`routes.yaml.geometry` 是绘图折线，`from/to` 是必达端，`via` 只是候选停靠点；本文不从折线长度反推实际里程。若某 `via` 在当前时代关闭，路线外观不变但该点不能停靠。

### 1.5 门禁与解锁节奏

1. 区域开放有三层：`discovered`（地图已知）、`routeOpen`（至少一条入口可用）、`entered`（已实际进入）。显示不等于可达。
2. 每书界开局开放 2–3 个相邻区域；第一幕结束时达到 3–4 区，中点前达到预算的约 70%，终幕前主线所需区域全开；余韵期保留所有已开区域。
3. 区域主入口不得只靠轻功；轻功可提供捷径、支线和秘境。主线轻功上限与出现进度完全引用 `design/08` §6.5。
4. 所有主线门禁必须有替代解；单向落点必须能回到安全点。身份、任务、时辰、船、坐骑、技艺等门禁表达式均引用 `design/08` §6.1–6.7。
5. 普通门禁靠近后显示需求；`intent:hidden` 永不显示图标、轮廓或格坐标。临近书眠只由书灵提示仍有哪个区域存在“遗珠”，落实 P52。
6. 关闭区域不等于抹去地理：地图可显示淡墨轮廓与历史题签，但入口不可选，且不下载区域时代包。
7. 开放城市不自动开放整区所有场景；城市入口、山门、秘境、季节通道各自有状态，防止一条剧情旗标穿透全部门禁。

### 1.6 时代图层与书眠切换

`EraLayer` 是当前 `chNN` 对稳定地理数据的稀疏覆盖，不复制基础地形。权威读序为：

1. 加载 `rg_*` 基础几何、地形、稳定古迹与入口骨架；
2. 读取 `cities.yaml.eras[chNN]`，确定名称、地位、注记与 `open`；
3. 读取 `design/17` §3 / `sects.yaml.availability[chNN]`，投影门派 `O/H/P/M/N/D` 状态；
4. 合并本时代的区域势力、NPC、资源点、营生、路线、天气气候与剧情动态旗标；
5. 动态旗标只覆盖当前存档事实，不能篡改权威坐标和历史名称。

书眠依 `design/02` §4 原子执行。`BS_COMMIT` 后先卸载旧时代状态，再装载目标时代公共状态和苏醒区域；目标区域挂载成功、玩家位置合法、天气与 NPC 日程推进到目标起点后才写 `save_wake_chNN`。若下载或校验失败，保持书眠等待页，不允许出现“旧朝 NPC 站在新朝城市”的半切层状态。

时代切换重置：本时代资源点归属、家丁任用、普通库存、营生任职、门派身份 / 职级和临时路线封锁；其跨书例外只读 `design/02`、`13`、`16`、`18` 的白名单。保留：稳定地理发现史、图鉴、跨时代古迹记录与上游明确保留的永久状态。玩家在新界第一次打开大地图时，仅显示该时代本来可知的公共地理，加上已保留的“曾到此处”淡墨记忆；记忆不能绕过新入口条件。

### 3.3 城市入口与状态叠加

城市最终可进入条件按以下顺序合并，后项只能收紧、不能把历史关闭点强行改为普通城市：

1. `cities.yaml.eras[chNN].open` 为历史 / 小说锚基础开关；
2. `EraRegionState.openCities` 选择本书界实际制作的城市入口，未选中的开放城仍可作地图题签和路线中继；
3. 任务旗标将入口设为 `open/guarded/blocked/ruined/hidden`；
4. 天灾、宵禁和战事只产生有起止条件的临时覆盖；
5. 门派、资源点、营生、NPC 各自再读自己的时代状态，不能因“城开”自动全开。

每书界“开放城市数”统计 `EraRegionState.openCities` 中可实际进入至少一个场景的去重 `city_*`，不是 `cities.yaml` 中所有 `eras[chNN].open=true` 的地图题签数。后者目前为 149–178 个（十四章依次为 149、156、156、169、167、170、169、177、172、172、177、177、178、178），若全做可玩城市会突破 8–15 小时和区域包预算。

### 3.4 营生场所随城登记

- `cities.yaml.businesses[]` 是允许实例化的类别白名单；它目前覆盖客栈、市场、赌场、镖局、山庄、驿站、港口等，不代表每个时代都必然营业。
- 实例 ID 为 `biz_<city短名>_<类别>_<nn>`；同城同类从 `01` 起编号，跨时代复用物理建筑时 ID 稳定、状态随层变化。
- 本文预算只计 AR-06 的可任职赌场 / 镖局 / 山庄；客栈、市场、驿站和港口是通用设施，不计“营生场所数”。
- 赌场 / 镖局 / 山庄每个实例必须绑定一个 `city_*`、入口 POI 和 `openChapters`；具体职位、收入、结算周期、客卿全局唯一和日程冲突见 `design/16`。

## 4. 区域探索

### 4.1 探索循环与移动

区域内的最小循环为“观察 → 选路 → 移动 / 轻功 → 交互 → 获得线索或资源 → 决定继续或休整”，目标用时 3–12 分钟；城市或区域的一次连续会话为 45–120 分钟，承接 `design/01` §5 的节奏。

| 输入 / 状态 | 规则 |
|---|---|
| 步行 | 点地寻路或虚拟摇杆；规则路径沿六邻，表现动画用八方向；默认避开危险格、门禁和会触发敌意的视野锥 |
| 疾行 | 持续消耗 `sta=2/秒`；脚步噪声 +1 级；体力为 0 时禁用，恢复至 20% 后可再用 |
| 轻功 | 纵跃、跨沟、攀崖、踏水、树梢、一苇渡江等动作及体力、熟练折扣完全引用 `design/08` §4–§6 |
| 骑乘 | 只在 `design/08` §6.8 允许的地形；骑行中不能施展轻功，入不可骑格自动下马 |
| 潜行 | 读取地形 `noise/hidden`、昼夜、天气和 NPC 视听；本文只给世界状态，隐身 Buff 与战斗判定见 `design/06/08/09` |
| 自动寻路 | 只到已揭示 POI 或已知出口；遇新门禁、敌对明雷、危险天气边界即暂停并请求确认 |
| 失败回退 | 沿用 `design/08` AF5–AF6：探索失败至多损失 10% `hpMax` + 1 时辰；书灵可“引路”回最近安全点，见 §9.5 |

### 4.2 交互物与状态

| 类别 | ID / 状态 | 交互 | 持久化 |
|---|---|---|---|
| 门、闸、吊桥 | `poi_*` + `door/gate` | 开锁、机关、身份、任务或破坏 | 关键门按任务；普通门离场复位 |
| 容器 / 宝箱 | `poi_*` + `chest` | 开启、撬锁、拆机关；任务物保底 | `opened=true` 永久；周目重置 |
| 采集点 | `rp_*` 或 `poi_*` + `gather` | 采药、采矿、伐木、捕鱼、拾取 | 普通点按日再生；资源点归 `design/16` |
| 调查点 | `poi_*` + `inspect` | 读碑、听声、看痕、嗅毒、问路 | 发现线索永久；可改变任务状态 |
| 休整点 | `poi_*` + `rest` | 打坐、扎营、等待、书灵引路目标 | 营地可一次性或常驻 |
| 眺望点 | `poi_*` + `vista` | 读 `design/08` 视野 ×1.5，揭示地图 | 首次奖励，后续只看景 |
| 机关 / 危险物 | `tr_jiguan` 或 `poi_*` + `hazard` | 识破、拆除、绕行或承受结果 | 剧情机关持久；普通机关 1 时辰复位 |
| 告示 / 路标 | `poi_*` + `sign` | 揭示城市、路线、悬赏和公开设施 | 只写地图知识，不直接完成任务 |

所有交互物需给 `verb`、短反馈、前置、成功 / 失败后果和可重复性；纯装饰不得挂交互高亮。需要技艺的操作用 `design/03` §8 的统一门槛和概率，不另造一套“探索技能等级”。

### 4.3 资源点的地图分布与数量

资源点 `rp_*` 是可占领和派家丁管理的长期节点，普通采集点不算资源点。经营规则、四阶九品、家丁、产出与维护归 `design/16`；本文定位置与密度：

1. 每个开放玩法区域至少 1 个、通常 1–3 个资源点；内容密集的首区 / 枢纽区可到 4 个，但全界仍须守 §10 总预算。九区大书界通常 18–22 个，六区短书界 10–14 个。
2. 至少 60% 位于城外，避免玩家只在菜单收租；至多 40% 受门派 / 势力控制；至少 25% 有两种取得路径（战斗与任务 / 购买 / 门派授予之一）。
3. 同类资源点的最近两个节点不得都在同一区域；每书界至少覆盖药材、木 / 矿、粮 / 畜、商贸四大供给面，具体资源类别仍由 `design/16` 定。
4. 一区最多 1 个高稀缺节点；它必须有地图线索，不能仅靠贴墙扫描。高阶奖励的采集门槛、敌人和天气风险要能由本书界正常成长达到。
5. 资源点绑定 `rg_*`，可选绑定最近 `city_*`，并写六角场景坐标；时代切换时 ID 可稳定复用，但所有权、产出品阶和是否存在由时代状态覆盖。
6. `rp_<region短名>_<类别>_<nn>` 为全局 ID；若只存在于一书界，在状态里限定 `openChapters`，不把 `chNN` 塞入全局地理 ID。

### 4.4 宝箱、秘境与探索奖励预算

| 内容 | 每标准区 | 每书界目标 | 奖励约束 |
|---|---:|---:|---|
| 普通容器 | 8–16 | 72–120 | 银两、消耗品、普通材料；同场景不连续堆箱 |
| 锁箱 / 机关箱 | 2–4 | 18–30 | 至少两种开启法；任务钥匙不被消耗品替代 |
| 地标 / 眺望点 | 2–3 | 14–22 | 揭图、传说、少量见闻 / 资质经验 |
| 小秘境 | 1–2 | 8–14 | 10–25 分钟；谜题、战斗、移动至少两种玩法 |
| 大秘境 | 全书 1–2 | 1–2 | 30–60 分钟；可承载武学、名器或 Boss，不与主线必经地重复计数 |
| 隐藏奇遇入口 | 0–1 | 3–6 | 服从 §5；隐藏轮廓不显示，P52 |

探索内容按标准流程“完成约 70%”设计，不能要求全清才能达到等级、银两或基础轻功主线。单书界**开放内容时长**按总时长的 35% 配置，承接 `design/01` §5；这不是成长资源份额。该时段内的探索奖励价值点建议按物品 / 银两 / 材料 45%、武学与资质成长 25%、剧情 / 羁绊 / 声望 20%、外观与图鉴 10% 分配 **【建议值】**。百分比是价值点而非掉落件数，章节可在不突破永久上限的前提下 ±5 个百分点。

每个小秘境最多投放 1 件固定地级或更高核心奖励；天级武学 / 神兵必须同时受 `design/02` 与 `design/10` 的书界池、互斥和单周目预算约束。随机箱不能产出天级完整传承，也不能绕过唯一物品。

### 4.5 地图迷雾、发现与标记

| 状态 | 地图表现 | 获得方式 |
|---|---|---|
| `unknown` | 宣纸留白，不显示路线与 POI | 初始 |
| `rumored` | 淡墨区域 / 问号，位置误差半径 6–20 格 | 对话、告示、地图物品、前世记忆 |
| `charted` | 地形与公共路线清晰，隐藏内容不显 | 走近、眺望、购买舆图 |
| `visited` | POI 具名并显示最近访问时辰 | 实际进入 |
| `resolved` | 已清、已取、已占领等状态图标 | 完成内容 |

- 玩家可放最多 40 个自定义标记；标记含图标、8 字短注**【建议值】**、区域 / 场景 / 六角坐标，不随时代自动移动。上限正式接收 `design/14` §7.2 的 DOM 节点预算；短注长度仍待 UI 实测。
- NPC 传闻给的是区域或模糊圈，不应泄露隐藏秘境格坐标。`intent:hidden` 门禁即使已擦过边缘也不生成“待解之处”。
- 眺望点揭示同场景视线连通部分与邻近公开 POI，不穿墙、不解谜、不揭开室内。高山眺望可在全国图新增邻区传闻，但不解锁旅行。
- 书眠后保留 `visited` 的历史淡墨层，但当代可达性重新判断；已毁桥、未建城和不同山门不会因前世地图直接开放。

### 4.6 探索内容质量闸门

每个玩法区域至少包含：1 个具名聚落或安全据点、1 个主线 / 派系入口、3 种地貌、1 条可回访捷径、1 个资源点、1 个秘境或奇遇、1 个昼夜 / 天气差异。至少三分之一普通冲突提供免战或缩短战斗路径，正式采纳 `design/01` D01-02；可用口才、身份、贿赂、潜行、驱兽、环境机关或绕路实现。

## 5. 奇遇系统

### 5.1 定义与 ID

奇遇是非主线、非固定告示任务的条件事件，允许玩家因福缘、时间、地点、品德、行为或前置组合获得独特经历。任务 ID 固定为 `q_NN_qiyu_NN`；编号是章节局部两位数。新建前必须全仓搜索，已被图鉴占用的编号即使仍是占位也不可复用为另一事件。

天龙已占用 `q_01_qiyu_71`–`74`、`81`、`82`、`91`，本文示例只引用这些，不另占天龙编号。其他书界也须先检查现有 70–99 段。

### 5.2 触发条件与福缘

```text
eligible = 地点与时代开放
        && 时间 / 天气窗口满足
        && 品德 / 声望 / 门派 / 前置旗标满足
        && 未完成、未互斥、冷却结束

qiyuMul = 0.5 + luk / 100                    // design/03 §2.3
pFinal  = clamp(pBase × qiyuMul × pityMul, 0, pCap)
```

| 参数 | 默认 | 说明 |
|---|---:|---|
| `pBase` | 5%–25% | 每次合法“机会点”检查；不得每个 10 Hz tick 重掷 |
| `qiyuMul` | 0.51–1.70 | 永久 `luk=1..120`；50 点为 1.0 |
| `pityMul` | `min(2, 1+0.25×misses)` | 同一奇遇合法未触发后累计；离开窗口不清，成功清零 |
| `pCap` | 80% | 保留不确定性；关键奇遇改用保底，不把上限写 100% |
| 检查时点 | 进入 POI、跨时辰、完成前置、天气开始 | 相同 `worldTick` 同一奇遇只检查一次 |
| 保底 | 关键奖励 3 次合法未触发后，第 4 次触发 | 只对标记 `pityGuaranteed=true` 的事件 |

例：`luk=70`，`pBase=20%`，连续失败 2 次，则 `qiyuMul=0.5+70/100=1.2`、`pityMul=1+0.25×2=1.5`，第三次 `pFinal=20%×1.2×1.5=36%`。随机只使用存档确定性 RNG；读档不得重掷同一机会点。

### 5.3 奇遇类型

| 类型 | 典型条件 | 典型奖励 | 设计要求 |
|---|---|---|---|
| 地貌 | 坠崖、瀑布后、孤岛、雪夜 | 秘境、武学残篇、捷径 | 坠崖奇遇每书界 ≤2，出口见 `design/08` |
| 人物 | 地点 + 时辰 + NPC 在世 / 在场 | 指点、羁绊、招募线索 | NPC 可用性读取 `design/18` |
| 德行 | `morality` 区间、过往选择 | 声望、称号、正邪分支 | 不用单次善恶行为永久锁全界 |
| 福缘 | `luk` 概率、重复经过 | 宝物、免灾、罕见商人 | 必须有失败反馈或无打扰静默策略 |
| 天候 | 雷暴、雪后、月夜、退潮 | 稀有材料、路径、场景变化 | 天气窗口至少持续 1 时辰 |
| 技艺 | 医毒、奇门、音律、棋、书画 | 技艺经验、配方、解法 | 统一使用 `design/03` 门槛 |
| 江湖传闻 | 声望、门派、区域敌对 | 挑战、救援、赏金 | 普通冲突至少有一条非战解 |
| 连锁 | 已完成另一奇遇 / 持有史笺 | 跨时代回响 | 持久化和书眠规则见 `design/02/13` |

### 5.4 数量与可错过性

- §10 的 10–18 个预算指**完整奇遇链**，不是区域机会点：一条完整链可以在多个地点 / 阶段各登记一个具名 `opportunityId`，但同一机会点不可重复凑数。
- 每个开放区域另须满足 `design/02` §2.10 的奇遇触点下限 `floor(1 + W/25)`；小型环境演出只有进入 `QiyuDef.opportunityIds` 并具备有效触发条件时才计触点。完整链与触点分别验收。
- 至少 60% 的完整奇遇链在取得天书后的余韵期仍可触发。
- 时间限定奇遇不超过 30%；永久错过者在不可逆选择前给叙事提示，但不泄露隐藏坐标。
- 同一入口不叠超过 3 个随机奇遇；优先级为主线安全事件 > 已到保底的奇遇 > 限时奇遇 > 普通随机。未选中的候选不算失败。
- 同一奇遇可有多阶段，但只计一个预算；若其流程超过 30 分钟或有 3 个以上任务节点，应转为支线。

### 5.5 永久奖励上限

`design/03` D-13 给全程奇遇 / 丹药永久先天约 `+50`；`design/10` 已把物品部分锁为 `+20`，故本文把奇遇与非物品剧情合计锁为 **全程最多 +30 点先天**。分配为高武每界 3、中武每界 3、低武每界 1：`4×3 + 6×3 + 4×1 = 34` 会超限，故采用下表节奏：

| 书界类型 | 书界数 | 单界上限 | 小计 |
|---|---:|---:|---:|
| 高武 | 4 | +3 | +12 |
| 中武前段（笑傲、侠客、碧血） | 3 | +2 | +6 |
| 低武 | 4 | +1 | +4 |
| 中武后段（书剑、飞狐、雪山） | 3 | +2 / +3 / +3 | +8 |
| **合计** | **14** | — | **+30** |

其他永久奖励硬限：

- 奇遇与物品合计每书界 `breakCap ≤2`；其中物品最多 1，故奇遇可给 0–2，但若物品已占 1 则奇遇最多 1。每项先天 `breakCount≤4`、最终上限 120。
- 奇遇不得另投永久 `hpMax/mpMax` 百分比，除非占用 `design/10` §8.5 的物品 / 传功共同账本；全程总上限仍为 `hpMax +30%`、`mpMax +40%`。
- 抗性永久增益仍受每项 +15pp 的物品账本；永久免疫全作只允许莽牯朱蛤既有一例。
- 一次奇遇最多给 `+2` 先天，且只能选一项或从两项各 +1；达到书界 / 全程上限后转换为非永久奖励，不吞掉事件。
- 天级完整武学、神兵、名器、坐骑必须计入各自上游投放池；“奇遇获得”不是额外预算。

## 6. 世界时钟、昼夜、季节与天气

### 6.1 时间基准

世界时钟只在探索态运行，固定对齐 10 Hz 逻辑步；渲染帧率、设备墙钟和联网时间都不能成为玩法时间来源。下列玩法换算与 `tech/05` §3.1 的确定性单步契约一致：

```text
TICK_HZ              = 10
TICK_MS              = 100
10 world ticks       = 1 game minute
600 world ticks      = 1 game hour
1,200 world ticks    = 1 shichen（2 game hours）
14,400 world ticks   = 1 game day

gameMinute  = floor(worldTick / 10)
dayIndex    = floor(gameMinute / 1,440)
minuteOfDay = gameMinute mod 1,440
```

因此正常 1× 探索时，现实 1 秒推进游戏 1 分钟，完整游戏日约 24 分钟。`worldTick` 必须用至少 64 位无符号整数或安全整数保存；暂停、后台、加载、全屏菜单、对话和战斗不推进。页面从后台恢复时不补跑积压 tick，沿用 `tech/01` §6.2 的 `MAX_CATCHUP` 防死亡螺旋规则。

| 操作 | 时间推进 | 实现约束 |
|---|---:|---|
| 站立、步行、疾行、区域探索 | 每 100 ms 1 tick | 只由单步 API `core.tick()` 推进 |
| 对话、背包、图鉴、大地图选路 | 0 | 剧情要耗时必须显式发 `advanceWorldMinutes` |
| 战斗 | 0 | 开战快照时辰与天气；战斗中世界部分的 `core.tick()` 为空操作 |
| 等待、打坐、休息 | 指定分钟数 | 按事件边界批量推进，不循环模拟每个 tick |
| 大地图旅行 | 依 §7 公式 | 逐路段批量推进，仍依序处理时辰、日界与 Buff 事件 |
| 剧情蒙太奇 | 章节显式给分钟数 | 必须写入日志；不得读取真实日期替代 |

批量推进时按“当前分钟后的定时事件 → 时辰边界天气 / 日程 → 日界 / 日历 → 到达事件”的顺序处理；同一时间戳再按稳定 ID 排序。这样一次推进三日与逐 tick 运行三日得到相同的天气、跨战 Buff、任务期限和 NPC 位置。`advanceWorldMinutes` 必须在 `design/12` 已解析的 `deadlineAt` 处切段，先发 `timeAdvanced(fromMinute,toMinute)`，再由任务系统按稳定任务 ID 处理到期，不可一次跳到终点后倒推失败。`design/13` §5.2 的 `tj_shi` 只在任务系统把相对时限解析成 `deadlineAt` 时将时长缩短 25%；本文不重复乘倍率，绝对时限、软失败与主线出口仍归 `design/12`。

日历同时提供不绑定节令名称的稳定事件键。含三尸脑神丹内容的时代包必须配置年度键 `sanshi_annual`；批量或逐 tick 推进跨过该边界时，统一发送 `onCalendar({calendarKey: 'sanshi_annual', year, worldDay})`，同一游戏年恰一次。该键只表示“本年度解药期限”，具体月、日与节令须由章节在《笑傲江湖》三联 / 广州修订版考据后映射；考据完成前 UI 只写“年度期限”，不得硬编码为端午。

| 巳 | 09:00–10:59 | `day` | 常规日程 |

月相只压成 `bright/dark` 两档以满足地形接口：默认农历初八至廿二为 `bright`，其余为 `dark` **（原创扩展）**。章节若未配置可考日期，以 `lunarDay=15` 开局；日期本身只服务日程、节令和天气，不据此杜撰原著精确发生日。

### 6.3 NPC 日程与时间门禁

每个可活动 NPC 由 `design/18` 给身份与时空可用性，区域时代层只登记当代地点日程：

```text
ScheduleBlock = [startMinute, endMinute, poiId, activity, access]
```

1. 日程按半开区间 `[start,end)` 匹配，跨午夜拆成两段；重叠时取 `quest override > emergency > personal > fallback`。
2. NPC 不在相机视野内才可跨 POI 瞬移；在视野内则沿六角路径离场。找不到合法路时停在原地并记录警告，不穿门、不穿墙。
3. 商铺、衙署、门派院堂、渡口班次由入口状态读取日程。关门前已在室内的玩家可正常离开，不因时辰切换被困。
4. 主线目标若仅在某时辰出现，必须提供“等待到该时辰”；等待点须安全，最长一次跳至下一有效窗口，不让玩家手动空站。
5. 普通 NPC 的夜间缺席不删除其任务；地图目标改指住处、值夜点或“翌日再访”。不可逆限时事件必须在任务文本显示截止时辰。
6. 宵禁只收紧城门、巡逻和潜行，不应把客栈、主线出口、书灵引路目标同时锁死。

### 6.4 季节与气候

`season` 为 `spring/summer/autumn/winter`。章节用自己的历日初始化，不因一本书界仅玩 8–15 小时就强行轮完四季；长时间游历跨过季界时再自然切换。每个区域基础包登记 `climateProfile`，时代包可因战乱、灾年或剧情覆写天气权重，但不能改地理气候类别。

| 气候 | 主要区域示例 | 常见天气 | 禁止 / 罕见规则 |
|---|---|---|---|
| `temperate` 温带季风 | 中原、齐鲁、江淮 | 晴、阴、雨、雾；冬季雪 | 盛夏自然暴雪为 0 |
| `humid_south` 湿润南方 | 江南、福建、岭南、湖湘 | 阴、雨、雷暴、雾 | 平地自然雪为 0；高山实例另配 |
| `plateau` 高原山地 | 青藏、川西、天山高处 | 晴、阴、雪、暴雪、雾 | 雷暴仅暖季；昼夜温差高 |
| `arid` 荒漠绿洲 | 西夏、河西、南疆 | 晴、阴、沙暴 | 连续雨最多 1 时辰；暴雪仅指定高地 |
| `steppe` 草原 | 漠南、漠北、北疆 | 晴、阴、雨、雪、劲风 | 沙暴需沙地子区 |
| `coastal` 海岸岛屿 | 东海、南海、辽东海线 | 晴、阴、雨、雷暴、雾 | 沙暴为 0；风力决定停航 |

地形季节变化与天然替代钥匙仍见 `design/08` §8.5：例如冬季浅水冰封可替代踏水，但急流不冻；章节必须保留另一条不依赖玩家等数十日的主线路。

### 6.5 世界天气状态

合法天气枚举固定为 `clear/cloudy/rain/storm/snow/blizzard/fog/sandstorm`；另有 `wind.angle: 0..359`、`wind.force: 0..3`、`temp: hot/mild/cold/freezing` 与 `moon: bright/dark`。天气是“区域 × 时代”的状态，不是一张全国共享的雨云。

| 天气 | 最短持续 | 世界层影响 | 战斗衔接 |
|---|---:|---|---|
| `clear` 晴 | 1 时辰 | 正常旅行；夏季午时可为 `hot` | 见 `design/08` §8.2 |
| `cloudy` 阴 | 1 时辰 | 无硬门禁；可向雨雪过渡 | 同上 |
| `rain` 雨 | 1 时辰 | 路程 ×1.15；渡口照常，泥泞累积 | 同上 |
| `storm` 雷暴 | 1 时辰 | 陆路 ×1.50；小舟和海船暂停出发 | 同上；雷击只作剧情事件 |
| `snow` 雪 | 1 时辰 | 非雪路 ×1.25；积雪按 08 累积 | 同上 |
| `blizzard` 暴雪 | 1 时辰 | 无向导的野外路线暂停；已在途转入庇护事件 | 同上 |
| `fog` 雾 | 1 时辰 | 陆路 ×1.10、水路 ×1.25；迷雾揭示半径减半 | 同上 |
| `sandstorm` 沙暴 | 1 时辰 | 沙漠商队 ×1.50；无向导不可出发 | 同上 |

- 自然天气只在时辰边界转移；持续未满 1 时辰时保持。任务脚本可立即开始 / 结束，但必须记录 `source=script` 和结束条件。
- 每 20 个探索 tick（2 秒，即 2 游戏分钟）更新降雨、积雪、干燥等累积量；批量旅行按分钟差直接积分。达到 `design/08` §8.2 门槛时才改地表。
- 新区域首次载入时，用 `saveSeed + eraId + regionId + shichenIndex` 生成确定性天气链；读档不能重掷。邻区可给同类天气转移权重 +25% **（原创扩展）**，但每区仍独立。
- 只维护当前区、相邻区和已规划旅行路段的精确天气；其他区保存最近边界和种子，按需快进，避免 30 区每 tick 全模拟。
- 开战时复制完整天气、风、温度、月相和地表累积结果；战斗中不自然转天、不换天气，剧情脚本例外。战后回到同一 `worldTick`，再继续世界时钟。

### 6.6 天气可达性与防锁死

天气只允许制造“晚些走 / 换工具 / 换路线”的选择，不得永久封死主线：

- 每个主线气候门禁至少有等待至下一合法时辰、付费向导 / 车船、或一条全天候替代路。
- 船已离岸后遇雷暴，不把玩家悬在不可操作状态；转为靠泊、避风或旅途事件，时间照算。
- 暴雪、沙暴导致路线暂停时，大地图必须显示原因、预计最早复查时辰与可用替代路线；隐藏内容仍遵守 P52，不泄露位置。
- 天气脚本结束后必须恢复区域气候链，而不是永久固定晴天；调试器需显示脚本覆盖来源和剩余时间。
- 地表变化可能封路时，关卡校验按 `design/08` 的季节 / 天气可达集检查安全点与出口。

## 7. 旅行与快速移动

### 7.1 两种尺度

区域内移动按六角、体力与地形实时运行；跨区域旅行在全国导航图选择一条 `routes.yaml` 路线后结算。两者共享地点和时间，却不把经纬度折线变成六角距离。玩家必须先实地到过区域出口、城市驿站或码头，才能从该点发起相应路线。

| 方式 | 使用尺度 | 可中断 | 遭遇 | 到达点 |
|---|---|---|---|---|
| 徒步 / 疾行 | 区域内 | 随时 | 明雷、暗雷 | 当前六角 / 场景出口 |
| 轻功动作 | 区域内 | 动作结束后 | 不在动作中随机开战 | 门禁落点 |
| 骑乘 | 区域内 + 大地图陆路 | 区域内随时；大地图按路段 | 降低普通暗雷，不免剧情遭遇 | 马厩、出口或路段节点 |
| 车马 / 商队 | 大地图陆路 | 候选 `via` | 护送、劫道、盘查 | 开放中继或终点 |
| 客船 / 货船 | 大地图水路 | 开放码头；专船除外 | 风浪、水贼、船上剧情 | 码头 / 专线终点 |
| 驿站快行 | 大地图 | 登记驿站 | 跳过普通暗雷 | 目标 `post_*` 所在城市 |
| 区域内传送点 | 同一区域 | 否 | 无 | 已激活安全 `poi_*` |
| 书灵引路 | 当前区域救济 | 否 | 无 | 最近安全点 |

### 7.2 区域内速度与体力

`staMax = 100 + 0.5×con + 0.5×Ld + Σflat_staMax`，沿用 `design/03` §5.3。疾行速度为步行 ×1.6、消耗 `2 sta/秒`；地形、轻功动作、熟练折扣、坐骑可骑地形与 `staMul` 一律读取 `design/08` / `10`，本文不复制动作表。

- 体力支出只在实际移动 / 动作时间结算；打开地图、对话和卡顿不扣。
- 2 秒未消耗体力后，每秒回复 `staMax×4%`；`sta=0` 获 `bf_pibei`，恢复到 `ceil(0.20×staMax)` 才解除，完全采用裁定 C11。
- 骑行中不能用纵跃、踏水等轻功；下马用 1 秒。敌人追上时自动下马，坐骑移到战场外安全格，不作为战斗单位。
- 自动寻路估算体力后若预计会在安全点前耗尽，默认改成步行或停下警告；不能替玩家自动服药。

### 7.3 大地图旅行耗时

`routes.yaml.duration_days` 是普通步行 / 常规班次的基准日数。按路段计算、最后向上取到半个时辰（1 游戏小时）：

```text
durationHours = baseDays × 24
              × modeMul × mount.travelMul
              × weatherMul × roadStateMul × escortMul

chargedHours = ceil(durationHours)
```

没有坐骑时 `mount.travelMul=1`；车船方式已包含在 `modeMul`，不得再套坐骑。建议倍率：

| 方式 | `modeMul` | 普通暗雷机会 | 说明 |
|---|---:|---:|---|
| 徒步 | 1.00 | 100% | 基准；无需票价 |
| 车马 | 0.80 | 50% | 需城市车行 / 官道；付费 |
| 商队 | 1.10 | 40% | 慢但安全，可接护送或营生任务 |
| 驿站快马 | 0.55 | 0 | 需两个 `post_*` 已登记并付费；剧情遭遇仍可发生 |
| 河船 / 运河船 | 1.00 | 35% | `duration_days` 已是水路基准，倍率不再提速 |
| 海船 / 剧情专船 | 1.00 | 脚本 | 受班次、风力与剧情锁定 |

陆路坐骑的权威倍率来自 `design/10` §11.4：

| 坐骑 | `travelMul` | 算例：6 日燕汴官道（晴、路况 1） |
|---|---:|---:|
| 毛驴 | 0.90 | `6×24×0.90=129.6` → 130 小时 |
| 驽马 | 0.80 | 116 小时 |
| 川马 | 0.75 | 108 小时 |
| 骆驼 | 0.80 | 116 小时；沙漠适性另由 08 处理 |
| 蒙古马 | 0.70 | `100.8` → 101 小时 |
| 大宛良驹 | 0.60 | `86.4` → 87 小时 |
| 白马 | 0.55 | `79.2` → 80 小时 |
| 小红马 | 0.45 | `64.8` → 65 小时 |

天气倍率见 §6.5；`roadStateMul` 默认平安 1.00、泥泞 / 战乱 1.20、断路不可选；`escortMul` 默认 1.00，剧情护送慢行可为 1.10–1.25。路线显示基准、修正和最终到达时辰，避免玩家误以为地理距离被动态改变。

### 7.4 旅行体力、口粮与队伍

大地图旅行不逐秒扣 `sta`，每一自然日视为包含行走、进食和宿营：无跨战减益时到达 `sta=staMax`；若路段中断进入遭遇，则开战体力为 `max(ceil(0.60×staMax), staBeforeTravel)`，不会因数日折叠计算变成 0。

- 徒步 / 骑乘每人每日消耗 1 份口粮，车船含基础食宿则减为每两日 1 份；终值与价格由 `design/10/12` 定。口粮不足不致死，改为时长 ×1.25，且抵达时全队带 `bf_pibei`。
- `bf_judu` 等禁止奔跑的世界态会关闭驿站快马和个人骑乘，但允许客车 / 船；跨战 Buff 的途中结算完全按 `design/06` §5.4.2。
- 同行人数不得改变路线几何；若载具容量不足，必须换更大载具或拆成剧情队伍，不能把队友静默遗留在旧时代。
- 旅行事件每段最多 2 个普通事件 + 1 个剧情事件；事件后的绕路、伤病与等待更新剩余时长。

### 7.5 车船、班次与停航

常规路线只允许在 `from/to` 和当代开放的 `via` 停靠。`via` 关闭时可经过但不能下车 / 下船；图内剧情专船按 `routes.yaml` 直达，图外专线严格 `via=[]` 且 `no_intermediate_stops=true`。

| 服务 | 默认班次 | 误班处理 | 天气停运 |
|---|---|---|---|
| 官道车马 / 商队 | 卯、午各一班 | 等下一班或徒步 | 暴雪 / 沙暴停；雷暴延误 |
| 河船 / 运河船 | 辰、未各一班 | 可在码头等待 | 河道封冻、洪水脚本停 |
| 普通海船 | 每日辰时一班 | 次日再发 | `storm` 或风力 3 停 |
| 剧情 / 图外专线 | 任务约定 | 按任务处理 | 可延误，不擅自取消锚点 |

等待班次会推进世界时钟并结算 Buff；若等待可能使主线截止，确认框必须明确提示。费用只使用 `routes.yaml.fee_tier` 六档，银两终值由 `design/12` 给出。

### 7.6 驿站快行与区域内传送点

驿站不是无条件传送：必须亲自到访并登记当前和目标 `post_*`，路线在当前 `chNN` 开放，且中间没有剧情封锁。快行仍推进 §7.3 算出的时间、扣费用 / 口粮并结算日程，只跳过普通随机遭遇；悬赏追捕、护送目标、特殊伤病或不可离开队友可临时禁用。

区域内传送点只连接同一 `rg_*` 中已经亲自抵达的客栈、门派前庭、城市门、码头和常驻营地；不跨区域、不跨未解门禁、不在敌人警觉或追逐中使用。使用时推进 10 游戏分钟，保持天气和 NPC 日程连续。秘境深处只可单向回安全点，不能从安全点反向直达未解深处。

### 7.7 书灵“引路”救济

战斗外、非追逐、非剧情封闭状态下可请求引路，回到当前区域最近的客栈 / 门派前庭 / 营地：

- 推进 1 时辰（2 游戏小时），不会绕过城市、门派或区域入口门禁；
- 失去本次未结算采集连击和正在追踪的普通猎物，不丢任务物品；
- 气血不因传送自动回复，抵达后再由玩家选择打坐 / 休息；
- 单向坠崖或关卡错误没有正常出口时免费引路，并写诊断事件，不惩罚玩家。

## 8. 遭遇与就地开战

### 8.1 明雷、暗雷与剧情遭遇

| 类型 | 地图表现 | 触发方式 | 可规避性 |
|---|---|---|---|
| 明雷 `visible` | 敌人 / 队伍实体与警觉圈 | 视野、听觉、碰撞、追逐 | 可潜行、绕路、交涉或抢先手 |
| 暗雷 `hidden` | 不显示敌人；危险地带有环境提示 | 跨机会边、旅途分段检查 | 可用侦察、向导、低噪声与路线选择降率 |
| 剧情 `scripted` | 任务预警或演出 | 旗标 / 到达 / 截止时辰 | 是否可避由章节明确；不计随机密度 |
| 追猎 `pursuit` | 红色追踪标记 | 通缉、仇恨、护送失败 | 离开警戒、换装、付代价或迎战 |

暗雷不能按每个 10 Hz tick 抽取。区域场景预先布置“机会边”，玩家跨入新危险片区、连续移动 90 游戏分钟或大地图经过一个路段节点时才检查；同一机会 ID 在同一时辰最多一次。

### 8.2 遭遇密度预算

| 区域类型 | 明雷同时活动 | 暗雷基率 / 合法机会 | 每 30 分钟目标战斗数 |
|---|---:|---:|---:|
| 城市 / 门派安全区 | 0–2（多为可交涉） | 0–2% | 0–1 |
| 官道 / 农田 | 2–4 | 5–10% | 1–2 |
| 山林 / 湿地 | 3–6 | 10–18% | 2–3 |
| 沙漠 / 雪原 / 边关 | 3–6 | 12–20% | 2–3 |
| 敌营 / 地牢 | 5–8 | 0；用固定巡逻 | 3–5 |
| 秘境核心 | 2–5 | 0；手工布置 | 2–4 |

密度还要服从 `design/01` 的时间构成：普通区域至少三分之一冲突存在非战、绕行或缩短战斗路径；低武书界突出潜行、口才、易容、医毒、奇门和人情。击败同一生态敌群后，其刷新冷却至少 3 游戏日；任务敌不自然刷新。连续两场战斗后 10 分钟内普通暗雷率乘 0.25，防止出门连战。

可重复刷新的遭遇点必须有稳定 `spawnPointId`，并在时代状态中保存 `dailyClearCount[worldDay]`，不得把同一个 `EncounterDef` 在不同地点的战斗混成一个计数。该点当日第 1–3 次胜利输出 `repeatExpMul=1`，第 4–7 次输出 `0.5`，第 8 次起输出 `0.2`；算式即 `n≤3 ? 1 : n≤7 ? 0.5 : 0.2`。这里只定义刷新点事实和倍率，角色经验的乘法位置、定点舍入与其他系数仍见 `design/13` §2.4.1。逃跑 / 战败本就不给经验，不增加 `dailyClearCount`；一次性剧情战和更换了 `spawnPointId` 的势力事件不套重复衰减。计数随游戏日换日归零、读档不重掷，并在书眠切换时代状态时卸载。

### 8.3 暗雷概率

```text
pEncounter = clamp(baseRate
                   × dangerMul
                   × noiseMul
                   × timeMul
                   × weatherMul
                   × travelMul, 0, 0.35)
```

| 因子 | 默认 | 说明 |
|---|---:|---|
| `dangerMul` | 0.5 / 1 / 1.5 | 安全、普通、危险子区 |
| `noiseMul` | 0.6 / 1 / 1.4 | 潜行 / 常态 / 疾行或重载 |
| `timeMul` | 白昼 1、夜晚 1.25 | 城市宵禁巡逻可独立覆写 |
| `weatherMul` | 晴 1、雾 0.8、恶劣 0.6 | 少遇敌不等于少危险；环境事件另判 |
| `travelMul` | 见 §7.3 | 徒步 1、车马 0.5、商队 0.4、驿站 0 |

例：山林基率 12%、危险子区、夜间疾行，晴天徒步：`12%×1.5×1.4×1.25=31.5%`，低于 35% 上限。若同条件潜行且有雾：`12%×1.5×0.6×1.25×0.8=10.8%`。随机使用稳定机会 ID 与存档 RNG，读档不得重掷。

### 8.4 区域等级带与动态变化

每书界敌人总边界来自 `design/02`；每个开放区域配置 `enemyBand: [min,max]`。普通敌人不得随玩家逐级贴身缩放：

1. 区域首次进入时，以章节幕进度从 `enemyBand` 取一个 4–8 级宽的当前子带；只在新幕或重大势力变化时更新。
2. 普通敌人等级落在子带内，精英可 `+2`、头目 `+4`；Boss 用章节明表，但仍受书界超限规则。

### 8.5 就地开战

遭遇触发后冻结探索输入并由 `design/09` 建立战斗。截取规则完全服从基准 §8 与 `design/08` §7.1：以触发点为中心选实际可用六角不超过 400，且轴坐标跨度 `qSpan≤20`、`rSpan≤20`；靠近场景边缘时平移窗口，室内不足 400 格就使用合法室内范围。

- 玩家、明雷敌人、可交互掩体、地表状态、高度与危险物原位进入战斗；暗雷按入口方向放置敌群，不能凭空夹在不可达墙后。
- 天气、风、气温、月相和昼夜相位取 §6 开战快照；战斗中固定，剧情脚本例外。
- 载具和坐骑停在战场外；船甲板本身可作战场。无合法部署区时遭遇延迟到下一机会点，不把单位叠在同格。
- 战斗后的燃烧、冰封和可破坏物写回规则见 `design/08` §7.1；敌群结果、处置与奖励见 `design/09`。
- 玩家成功脱离后，明雷保留警戒并有 10 秒追击冷却；同一敌群不可在出口黑屏后立刻重新开战。

## 9. 休整与战后恢复

### 9.1 D-11 定稿结论

本文正式接收 `design/03` D-11，但减益清理以高优先级裁定 C08 和 `design/06` §5.4.2 为准，不能再使用“品阶 ≤3 的伤毒一律清除”的旧占位。客栈、门派静室和营地等完整休整统一发出 `onRest(restType)`；战后调息、探索自然恢复与打坐不触发完整 `onRest`，不得各自写一套驱散逻辑。

`restSpot` 是安全点上的独立布尔标志，只表示 `design/13` §9.2 所需的宗师 / 天劫手动存档许可，不等于“可免费长休”，也不自动等于 `allowsMeditation`。客栈、开放驿站、门派居所和合法营火应标 `restSpot=true`；普通观景点、临时剧情落点与仅可打坐的安全格默认 false。存档系统只消费该事实，费用、开放权限和难度规则仍分别归 `design/12`、`design/13`。

| 情形 | 时间 | `hp` | `mp` | `sta` | 减益与代价 |
|---|---:|---|---|---|---|
| 战后调息 | 0 | `+floor(0.10×新 hpMax)` | `+floor(0.30×mpMax)` | 不变 | 每步向下取整；先完成 C08 的跨战转换与倒地伤势，再回复并封顶 |
| 探索自然恢复 | 实时 | 不回 | 每 10 秒 `+5%×mpMax` | 2 秒未消耗后每秒 `+4%×staMax` | 受 Buff 的回复修正；不清减益 |
| 打坐 | 1 游戏小时 | 提到至少 50% | 全满 | 全满 | 不移除 `injury/poison/gu`；需安全点 |
| 客栈 | 1 夜 = 8 游戏小时 | 全满 | 全满 | 全满 | 发 `onRest(inn)`，由 06 逐效果处理；付费 |
| 门派静室 | 8 游戏小时 | 全满 | 全满 | 全满 | 发 `onRest(sect)`；需权限，可免费或耗贡献 |
| 常驻营地 | 8 游戏小时 | 全满 | 全满 | 全满 | 发 `onRest(camp)`；需营地安全且消耗 1 份露营物资 **【建议值】** |
| 临时扎营 | 8 游戏小时 | 全满 | 全满 | 全满 | 同营地，但有守夜检查；危险子区禁用 |

“战后调息”精确顺序沿用 C08 / `design/09` §7.4：`onBattleEnd → 清非 persist → 跨战实例转 world → 倒地者伤势 +1，并令 hp=floor(0.10×新 hpMax) → hp+=floor(0.10×新 hpMax)、mp+=floor(0.30×mpMax) → 各自封顶 → 奖励`。每个百分比步骤独立向下取整；未倒地角色也获得调息，`sta` 不在战后凭空补满。例如新 `hpMax=7,176`、`mpMax=4,697` 时，调息分别增加 `floor(717.6)=717` 与 `floor(1,409.1)=1,409`。

### 9.2 打坐

打坐可在没有敌人警觉、没有持续环境伤害且队伍站在合法地面的安全点开始。它将时钟推进 60 游戏分钟，故可能改变 NPC 日程、天气和任务窗口。

- `hp < 50%` 时设为 `ceil(0.50×hpMax)`；已高于 50% 不降低也不额外回复。
- `mp=mpMax`、`sta=staMax`；跨战毒、蛊、内伤、伤势按自然世界时间结算，但不触发一次“休息”清理。
- 打坐中若有确定会致危殆的世界态，确认框显示预估结果；不允许玩家无提示跳过发作时刻。
- 城市街心、敌营、深水、移动载具和恶劣天气露天格不可打坐；可进入客栈 / 营地或先引路。

#### 9.2.1 冲穴对安全点与时钟的消费接口

`design/15` §5 的“冲穴打坐”只消费本文的地点、时钟与打断框架，不属于上表的普通打坐恢复。安全点配置须明确 `allowsMeditation`；允许盘坐时再由 `design/12` 可选给出 `meditationQuality=0/1/2`，缺字段按 `allowsMeditation=false`、品质 0 处理。每次冲穴 session 在开始前必须同时满足：当前点允许盘坐、没有敌人警觉 / 持续环境伤害 / 强制剧情 / 移动状态，且从当前时刻到未来 60 游戏分钟内没有不可延迟的预定世界事件。

合法 session 原子推进 `60×10=600 ticks`（1 游戏小时），按 §6.1 的事件边界逐段结算；到点事件在本小时成功提交后触发。该推进不得同时执行普通打坐的 `hp` 至少 50%、`mp/sta` 回满，也不得触发完整休整的 `onRest`。若预检查发现不可延迟事件则本次不扣时间、不开始；连续冲穴每小时重新检查，不能以一次六小时批处理越过事件。冲穴进度、内力成本、失败与走火仍全部归 `design/15`，本文不重定义。

### 9.3 客栈、门派与营地

一次完整休息默认推进 8 小时；夜间入住至少休至下一卯时，例如亥时入住则次日卯时醒来；白昼入住推进整 8 小时，不为迁就卯时而反向拨钟。客栈费用和门派贡献价格归 `design/12`，物资归 `design/10`。

`design/06` 的效果表为唯一清理规则，当前关键口径为：

- 中毒地阶起跨战：休息时品阶 ≤8 清除，否则减 3 层；
- 剧毒全部跨战：每次休息只降 1 品；
- 内伤玄阶起跨战：休息减 3 层；
- `bf_shangshi` 按 09：1 级休息清除、2 级降 1、3 级连续休息也只能先降到 2；
- 寒毒、异种真气、走火、情花毒、蛊和受制读取各自专属解法，不因住店一夜全清。

若特殊状态禁止回复（例如发作中的某些蛊），先计算状态效果再钳制资源；UI 必须解释“为何没有回满”，不能只播放休息成功。

### 9.4 守夜、中断与存档

客栈和正式门派静室默认安全，不抽普通袭击。野外临时扎营先做一次守夜检查：普通区 5%、危险区 12%、剧情追猎另算；队伍有两名以上可行动角色时可指定守夜者使概率 ×0.5，但守夜者醒来 `sta=80%×staMax`。

休整被打断时，只推进已经经过的整游戏分钟：打坐按比例恢复 `mp/sta`，不提前拿到 50% 气血保底；长休在完成 4 小时前不触发 `onRest`，4 小时后被打断则恢复 HP/MP/STA 至 60% 下限、仍不触发完整减益清理。休整开始前和完成后各写一次自动存档；遭袭使用开始后的临时快照，防读档重掷守夜 RNG。

### 9.5 战败与引路后的状态

普通遭遇认败按 `design/09` §7.6：最近安全点醒来、推进 1 日、`hp=30%`，并结算银两 / 物品代价。书灵引路本身只移动和耗 1 时辰，不恢复资源；二者不可叠加成“战败后再免费回满”。最近安全点必须在当前时代开放且不会因日程关闭出口；没有合法点时用该区域的强制救济营地并记录关卡错误。

### 10.3 难度与内容比例核算

每个区域最少配置：1 个主线或核心支线入口、3 个普通支线节点、1 个回访门禁、2 个探索奖励、1 个安全点；资源点按 `229/103≈2.22` 个 / 时代区域，营生按 `280/232≈1.21` 个 / 实际开放城市。不是每座地图题签都制作街区，也不是每区强塞同样数量。

## 12. 数据结构与 JSON-compatible YAML 示例

本节给玩法语义和跨表引用，序列化、严格键、目录及 Zod 实现仍归 `tech/04`。示例禁止锚点、别名、自定义标签、重复键和隐式日期；百分比写 0–1 小数，时刻写整数分钟 / tick。示例中的稳定地理对象可直接登记；`rp_*` / `biz_*` 在本文只占地图位置与时代实例预算，经营字段分别引用 `design/16` §14.2 的 `ResourcePointDef` 与 §14.3 的 `BusinessDef`。

### 12.1 `RegionDef`：稳定区域基础

```yaml
schemaVersion: open_world_region.v1
id: rg_dali_cangshan
name: 大理苍山
kind: land
climateProfile: plateau
baseScenes:
  - sc_01_wuliangyidao
  - sc_01_jianhugong
  - sc_01_langhuanfudi
  - sc_01_wanjiangu
neighbors:
  - rg_bashu
  - rg_guangxi
  - rg_yundian_qianzhong
  - rg_qingzang
packageKey: region-rg_dali_cangshan
sourceRefs:
  - docs/design/map/cities.yaml
  - docs/design/map/regions.yaml
```

- `kind` 只取 `land/island/coastal/offmap`；区域内水域、城市和室内是场景，不另冒充全局区域。
- `baseScenes` 是跨时代稳定场景；建筑、NPC 与入口状态由时代包覆盖。`neighbors` 必须双向，跨海 / 图外专线不写入邻接，改读 `routes.yaml`。
- `packageKey=region-<完整 rg_id>` 是 `tech/06` §3.5 / §4.1 的区域基础 `PackId`；例如本区为 `region-rg_dali_cangshan`。物理分包、清单和预算只引用 `tech/06`，本文不再定义第二套逻辑键。

`kind` 至少覆盖 `entrance/safePoint/vista/inspect/gather/chest/secret/transfer/resourcePoint/business`。`cell` 使用 Tiled 转换后的 pointy-top 轴坐标，必须落在有效六角；`gate` 仅实例化 `design/08` §6 的 `GateExpr`，不在本文发明第二套条件语言。`scope` 取 `save/era/globalKnowledge`：地理见闻可跨书保留，容器、采集和经营状态默认只在当前时代保存。`kind=safePoint` 时必须显式给 `restSpot: boolean` 与 `allowsMeditation: boolean`；两者互不蕴含。可盘坐点可附 `meditationQuality: 0|1|2`，数值含义与投放由 `design/12`、冲穴消费见 `design/15`，本文只提供位置许可。

```yaml

chapterId: ch01_tianlong

packageKey: era-ch01

      - {id: route_chengdu_dali, state: storyLocked}

```

`entryState` 取 `open/guarded/blocked/hidden/closed`；运行时再与玩家的 `discovered/routeOpen/entered` 合成。`openCities` 必须是本区城市、在 `cities.yaml.eras[chNN]` 可开且至少有一个实际入口。门派 `state` 直接复制 17 的矩阵，不能由本层改写。`factions` 是地区影响力，不代表可加入门派；`routes` 只能覆写既有路线的当代通行状态。

跨年代传承遗迹只能引用既有 `regionId/cityId/sceneId/poiId`，并在时代层覆写入口的 `hidden/open/blocked/resolved` 状态；本文与 `design/19` 提供位置及可达性，不决定传承源消隐、出现概率、残本 / 信物掉落或全本合成，这些规则统一见已落稿的 `design/20`。遗迹专属 schema 或投放 ID 也只能由 `design/20` 登记。

完整时代层必须恰含 §10 预算数量的开放区域、城市、资源点和营生；关闭的 21 个天龙区域不必列空对象。基础包 `region-<完整 rg_id>` 可跨十四界复用，`era-chNN` 的 `state-<rg_id>` 块只含本书 NPC / 势力 / 名称 / 入口 / 资源 / 营生差量；物理结构见 `tech/06` §4，书眠原子切换过程见 §1.6。
