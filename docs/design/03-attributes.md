## 0. 约定与符号

### 0.1 通用符号

| 符号 | 含义 |
|---|---|
| `Lr` / `Ld` | 旧档真实 / 显示等级；AR-19 后只允许迁移和旧节奏表对照，不是人物成长概念 |
| `Cb` / `Ce` | 派生 / 当界有效修为档 1–70；由武功 / 经脉快照即时求出，`Ce` 再受时代档位上限约束；二者都不存经验、不升级 |
| `g` | 品阶 1–12（基准 §4）；`g_eff` = 经天道压制后的有效品阶 |
| `G(g)` | 基准 §4 的品阶系数（1.00 … 3.50） |
| `layer` | 武功既有层数 1–10；AR-19 资源熟练 `practiceLayer=min(trueLayer,9)`，第 10 重仍保留既有圆满解锁 |
| `con` `str` `agi` `wis` `wil` `luk` `cha` `bre` | 八项先天属性的**最终值**（含临时加值，见 §2.1）；`bre` 为内息 |
| `x⁺` | `max(0, x)` |
| `clamp(x, a, b)` | 截断到 [a, b] |
| `⌊x⌋` | 向下取整 |
| `Σflat_S` / `Σpct_S` / `Σpp_S` | 属性 S 的全部"固定加值 / 百分比加值 / 百分点加值"之和（§11） |
| `HP_LV(L)` `MP_LV(L)` `ATK_LV(L)` `DEF_LV(L)` | 旧节奏校准曲线（§3.1）；生产角色以 `Cb` 选行，禁止把人物等级作为成长源 |
| `STD(Ce)` | 标准主角兼容模型（§3.5），供伤害公式与敌人模板校准；不生成真实资源 |
| `MPREF(Ce)` | 耗内兼容基准（§3.5），design/05 招式耗内的乘数；不等于真实 `mpMax` |
| `P_actual` | 实际招式威力指数 = `G(g_eff) × L(layer_eff) × move.power × Mod_armed × Mod_special`（04 §4.1） |
| `P_ref(Ce, tier)` | 有效修为档期望威力指数（§3.5）；04 的 Z1 只除一次 |
| `【建议值】` | 本文替下游文档给出的暂定数，下游定稿后以下游为准 |

### 0.2 属性的数值形态

每个属性属于且只属于一种形态，形态决定它能接受哪些修饰（§11.2）。

| 形态 | 代码 | 说明 | 允许的修饰 | 例 |
|---|---|---|---|---|
| 先天 | `INN` | 1–100 的人物底子，永久值 + 临时加值 | 仅 `flat` | `con` |
| 资源 | `RES` | 有当前值与上限的池 | 上限按 `MAG` 处理；当前值只由结算改变 | `hp`/`hpMax` |
| 量值 | `MAG` | 随有效修为档兼容曲线放大的绝对量，参与比值运算 | `flat` `flatLv` `pct` `mult` | `atkOut` |
| 评级 | `RAT` | 与对手的对应评级做**差值**比较的点数，不随修为档放大太多 | `flat` `pct` | `hit` vs `eva` |
| 百分点 | `PCT` | 直接就是百分数（单位 pp），只做加法 | `pp` | `resPoison`、`counter` |
| 标志 | `FLAG` / `ENUM` | 布尔、整数等级或枚举 | 规则派生（不进入数值型 `StatModifier`） | `dualWield`、`swimLevel`、`mpNature` |

> 例："攻击 +10%"是属性修饰（`atkOut` 的 `pct`）；"伤害 +10%"**不是属性**，是基准 §9 的 Z3 增伤。两者乘区不同，数据中必须区分。

### 0.3 取整与确定性

- 属性管线内部保留精度，**面板属性在最终边界四舍五入为整数**；百分点配置转换为整数万分点（`BP=10000`）后进入战斗核心。`design/04` 的 Z1–Z10 每个乘区结束向下取整，概率最终向下取整并钳制；资源回复和伤害等结算量按其归属公式向下取整。
- `MPREF` 与招式资源成本按非负数四舍五入；正成本最低 1，显式零成本保持 0。实现统一用 half-up，不依赖语言默认的 bankers rounding。
- 同一属性的修饰按 `(sourceType, sourceId, modifierId)` 字典序求和；三元组在一次属性快照内必须唯一，保证一项来源可合法提供多个修饰且跨平台结果一致（玩法核心为确定性，基准 §19）。

- ①→④ 是**战斗链**：每次重算都从先天属性开始向下推导（§11.4）。
- ⑤⑥⑦ 是**成长链**：不随兼容校准曲线缩放，不受天道压制（§9），跨书界完整保留（`fame` 例外，见 §8.4；`swimLevel` 的行为定义只引用 08 §4.2.3）。

### 1.2 计算顺序（有向无环，必须按此顺序求值）

| 步 | 求值对象 | 依赖 |
|---|---|---|
| S0 | `Cb`、境界参数（layerCap、suppress） | 武功 / 经脉永久快照、当前书界；`Cb` 不存档 |
| S1 | 先天最终值（8 项） | 初眠底值、沉睡分配、修炼永久加成、奇遇、临时加值 |
| S2 | 武功资源项、经脉 / 穴位资源项；内功 `attrs/mpRegen/stats` 与主运派生项 | 全部已学武功的 `absGrade/resourceLayer`；15 的同版本永久进度；装配内功 |
| S3 | `hpMax` `mpMax` `staMax` | S2、装备、Buff；`hpMax/mpMax` 不读人物等级，`staMax` 暂读 `Ce` 兼容档 |
| S4 | `atkIn` `defIn` `atkOut` `defOut` | S1、`Aref/Dref` 与静态内功 / 装备修饰 |
| S5 | `qinggong` | S1、`apLight`、轻功武学、主运内功、装备 |
| S6 | `hit` `eva`（依赖 `qinggong`） `parry` `pierce`（依赖 `lore`） `crit` `tough` `effHit` `effRes` | S1、S5 |
| S7 | `spd` `mov` `jump` | `spd` 直接依赖 S1 的 `agi`、所修轻功有效品阶 / 层数 `g/n`、`design/21` 输出的 `correspondingStrengthAmpBp`；`mov` 由 09 消费最终 `spd`，`jump` 由 S5 的探索 `qinggong/qgTier` 给出 |
| S8 | 百分点类：`critDmg` `counter` `combo` `seal` `healPower` `healRecv`、8 项抗性、次级属性 | S1、技艺、资质 |
| S9 | `shieldMax` | S3 |

> 任何修饰器不得引用"同步或更晚"步骤的属性作为自身的输入（例如 Buff "按闪避的 10% 提升攻击"不被允许，因 `eva` 在 S6、`atkOut` 在 S4）。若确需此类效果，由 design/06 以"战斗中快照值"实现，不进入面板计算链。
> protocol 4 的战斗 `spd` 与探索 `qinggong` 是两条独立链：前者不得读取 S5 输出，后者也不得反推或覆盖 `spd`；两者只共享 S1 的 `agi` 与同一门轻功的武学事实。

## 2. 先天属性与创角

### 2.1 先天属性的构成

```
perm_X  = create_X + origin_X + talent_X + Σ realmAlloc_X[r | r 已由 Cb 解锁] + Σ permBonus_X(奇遇/丹药/天书之力)
perm_X  = clamp(perm_X, 1, cap_X)            cap_X = 100 + 5 × breakCount_X   （breakCount ≤ 4 → cap ≤ 120）
temp_X  = Σ flat_X(内功贡献 attrs、装备词条、内功特有被动、套装、Buff)   （可为负）
X       = clamp(perm_X + temp_X, 1, 120)     ← 公式中使用的"最终值"（基准 §6：先天上限 120）
```

| 规则 | 说明 |
|---|---|
| 只接受 `flat` | 先天属性**不接受百分比修饰**，避免"根骨 +10%"式滚雪球 |
| 突破上限 | 只有标记 `breakCap: true` 的奇遇/丹药能让某项 `cap_X` +5（每项最多 4 次）；每书界此类资源 ≤ 2 个【建议值：10 已落实丹药份额，奇遇投放待 11】 |
| 临时值可超 100 | 例：根骨永久 100 + 内功 `attrs` +8 + 装备 +7 → 115 参与计算；最终上限 120（与基准 §6、design/05 §5.5 一致），超出部分无效并在面板显示为灰色 |
| 负值保护 | 最终值 ≥ 1；所有含 `(X − 50)` 的乘法项另有下限（见各公式） |

#### 2.4.1 沉睡六项配点（AR-26 / AR-27）

可配集合固定为 `A={str,con,bre,wis,agi,wil}`；`luk/cha` 新档各 50，由身份/天赋、奇遇、事件和装束改变，默认不参与配点**（待作者确认）**。点数是永久、可留存的 `sleepPoints`，书眠事务不得清零。

**初眠（长白山雪崩）**：

```text
六项初值 = 35
初眠预算 = 90
初眠后六项总和 = 6×35+90 = 300（均值 50）
初眠单项范围 = 20..80
```

允许降到 20，每降 1 返 1 点；确认前可撤销。均衡分配为六项各 50；专精示例为 `wis=80`、其余五项各 44，总和仍为 300。创角的身份/天赋在初眠确认后叠加，不消耗点数。

**后续书眠**：令下一本正式书的顺序为 `s∈[2,14]`（AR-26 新序：白马为 1），沉睡时派生修为档为 `Cb`：

```text
gain(s,Cb) = 4 + floor((s-1)/4) + floor(Cb/20)
sleepPoints' = sleepPoints + gain
```

书序项在 `s=2..4/5..8/9..12/13..14` 分别为 `0/1/2/3`；修为项通常为 0–3。它把点数来源绑定“走过多少书界 + 已有武功/经脉事实”，不恢复人物等级。未分配点可跨书眠留存；九层后不再书眠时，每完成一书仍在周游结算页按同式发放。

| 路线锚点 | `s` / `Cb` | 单次获得 | 累计后续点 |
|---|---:|---:|---:|
| 天龙前 | 2 / 10 | `4+0+0=4` | 4 |
| 神雕前 | 4 / 35 | `4+0+1=5` | 14 |
| 笑傲前 | 6 / 55 | `4+1+2=7` | 28 |
| 鹿鼎前 | 9 / 65 | `4+2+3=9` | 52 |
| 雪山前 | 14 / 69 | `4+3+3=10` | 99（标准 `Cb` 路线核算） |

上表累计逐次代入标准 `Cb=[10,25,35,45,55,58,62,65,65,66,67,68,69]`，得 `4+5+5+7+7+7+8+9+9+9+9+10+10=99`；逐次累计为 `[4,9,14,21,28,35,43,52,61,70,79,89,99]`。实际 `Cb` 不同会在每次边界产生 ±1；CI 以函数本身为准，不把 99 写成固定奖励。

**上限**：永久值仍先钳 1–100；只有明确标 `breakCap:true` 的奇遇/天书/九转可把对应永久值抬至 120。普通沉睡点和修炼加成都不能把永久值从 100 推到 101；超过部分拒绝分配而非吞点。临时装备/Buff 在永久值后结算，最终仍 ≤120。

**悟性满值可达性**：初眠 `wis=80`；白马、天龙、射雕、神雕结束后的获得依次为 `4/5/5/7`。把前三次全投悟性得 94，再从第四次投 6 点，即在倚天入场前达到 100，四次共 21 点仅余 1 点补短板；这是重投入路线。若延后，至鹿鼎入场累计已有 52 点，最晚规划检查点仍为**鹿鼎入场前**；届时只需其中任意 20 点投入悟性，余 32 点可补其他五项。初眠其余五项总和仍为 `220`（均值 44），均衡路线不会自然满悟性。

### 3.1 旧节奏基准曲线（以 `Ce` 选行）

```
B(L, k)   = k × (L − 1) × max(0, 1 − (L − 1) / 34)        // 新手补偿项：Lv2–34 为正，Lv1/Lv35+ 为 0
HP_LV(L)  = 300 + 4.10 × (L − 1)² + B(L, 20)
MP_LV(L)  = 200 + 2.45 × (L − 1)² + B(L, 12)
ATK_LV(L) = 0.20 × MP_LV(L)                                // 外内同源：裸装标准人 atkOut ≡ atkIn
DEF_LV(L) = 0.15 × MP_LV(L)                                // = 0.75 × ATK_LV
```

设计要点：
1. **二次曲线**贴合基准 §5 的三个锚点（纯幂函数拟合指数 ≈ 2.02）。
2. 纯二次曲线在前 10 级几乎不涨（Lv1→2 仅 +4 气血），所以叠加补偿项 `B`：它在 Lv1 与 Lv35 严格为 0，**不改变任何锚点**，只让新手期每级有 +8%~10% 的体感成长。
3. `ATK_LV`、`DEF_LV` 直接取自 `MP_LV`，使"内力深厚"与"攻防成长"同源；裸装时 `atkOut : atkIn : defOut : defIn` 的比例在全等级段恒定；典型配装下也只在小幅区间漂移（见 §3.5 比例列），伤害公式配合 `P_ref` 归一后只需一组常数即可覆盖 1–70 级。

## 4. 战斗属性派生公式

> 通式（§11.2）：`S = (Base_S + Σflat_S) × max(floor_S, 1 + Σpct_S) × Πmult_S`，然后 `clamp` 到 S 的范围。下面只写各属性的 `Base_S`、专属项、下限与范围。`floor_S` 缺省：MAG 取 0.2，RAT 取 0.2。

### 4.1 攻防四项（MAG）

> **AR-27 现行口径**：下表旧 `ATK_LV/mpMax` 派生只供 v1 回放和敌模板迁移。生产攻击按招式动态求“硬功 + 外放”，攻击面板仅作中性投影；防御面板则是 Z2 使用的静态终值，不能再由 04 按 `wOut/wIn` 加权第二次。

定义 `Aref=ATK_LV(Ce)`、`Dref=DEF_LV(Ce)`；`wOutBp+wInBp=10000`。每个招式的经脉运转系数 `operationBp∈[6500,22000]` 由 `design/21` §4.4.1 / 本任务新增 §4.4.4 给出，中性为 10000：

```text
hardAttack    = floor(Aref × str × wOutBp / (50×10000))
outwardAttack = floor(Aref × bre × wInBp × operationBp / (50×10000²))
ATK_mix       = max(1, hardAttack + outwardAttack)

hardDefenseBase  = floor(Dref × con / 50)
innerDefenseBase = floor(Dref × bre / 50)
hardDefense  = roundHalfUp((hardDefenseBase + Σflat_defOut)
                 × max(0.2, 1 + Σpct_defOut) × Πmult_defOut)
innerDefense = roundHalfUp((innerDefenseBase + Σflat_defIn)
                 × max(0.2, 1 + Σpct_defIn) × Πmult_defIn)
```

- `wOut` 是“武功硬功”，表示筋骨/兵刃直接发力所占比例；`wIn` 是“武功外放”，表示以内息经经脉推出的比例。沿用字段、无数据迁移；只把旧“外/内权重”语义收窄为这两支。`projection:true` 仍决定 21 选普通或外放曲线，不另造第三比例。
- `operationBp` 已兑现经脉强度与路线完成度；Z5M 在 rules protocol 4 起固定 10000，避免既在本式又在 Z5M 双算。旧录像仍按原 Z5M 回放。
- protocol 4 面板：`atkOut=floor(Aref×str/50)`、`atkIn=floor(Aref×bre/50)`，分别显示“硬功基准/外放基准（中性经脉）”；04 生产输入直接传 `hardAttack/outwardAttack/ATK_mix`。`defOut=hardDefense`、`defIn=innerDefense`。
- `Σflat/Σpct/Πmult` 严格使用 §11.2 的静态属性管线；内功的 `inner.contribution.stats.defIn`、内功特有被动与装备内衬均在这里展开为 `defIn` 修饰。硬功防御由根骨、护甲及金钟罩/横练的根骨或 `defOut` 修饰驱动。
- `innerDefense` **不读取**当前内力、`mpMax` 或任何战斗路线结果。21 的 `meridianDefenseBp` 不是面板修饰，只允许 04 在 Z4M 消费一次；命中区在途气只进入 04 的 Z4 / settle，不得回写 `innerDefense`。定力只管心志、稳定与走火，不替代两类防御。

**中性核算**：`Aref=1000,str=60,bre=55,wOut/wIn=6500/3500,operation=10000`，则硬功 `floor(1000×60×6500/500000)=780`，外放 `floor(1000×55×3500×10000/5e9)=385`，`ATK_mix=1165`。若强路线 `operation=12000`，外放变 462，总攻击 1242；只增加外放支。

| 属性 | `Base` | 专属 flat 来源 | 范围 |
|---|---|---|---|
| `atkOut` | protocol≤3：`ATK_LV(Ce) × max(0.5, 1 + 0.010 × (str − 50))` | 主手兵器主属性、副手副兵器 | ≥ 1 |
| `atkIn` | protocol≤3：`0.20 × mpMax` | 少数饰品/Buff | ≥ 1 |
| `defOut` | protocol≤3：`DEF_LV(Ce) × max(0.5, 1 + 0.006 × (con − 50) + 0.002 × (str − 50))`；protocol 4 见上式 | 衣、头、护手、腰带、鞋、盾 | ≥ 0 |
| `defIn` | protocol≤3：`0.15 × mpMax`；protocol 4 见上式 | 内功、衣（内衬）、特定饰品 | ≥ 0 |

- 上表的 `mpMax` 映射只供 protocol≤3 回放；protocol 4 的攻击 / 防御均按本节分支式，不得把 `mpMax` 再映射为第二份攻防。
- 当前内力 `mp` 不影响 `atkIn`；"内力不足时招式威力下降"如需实现，归 design/04（Z1）或 05。

```
ATK_mix = (1 − r_in) × atkOut + r_in × atkIn
DEF_mix = (1 − r_in) × defOut + r_in × defIn        // 守方按攻方招式的 r_in 取防御
```

上框仅用于 `rulesProtocol≤3`。新协议防御仍按攻击两支分别求减免后相加，精确式见 `design/04` §4.2。

### 4.3 速度 `spd` 与集气接口

> **AR-27 覆盖公式（rules protocol 4）**：速度只由“身法 × 轻功基本系数 × 对应经脉强度增幅”形成；旧常数式仅供旧录像。

轻功基本系数使用整数 bp，来自当前装配轻功的有效品阶与有效层数；没有装配轻功时按黄下 0 重底值 7000 bp：

```text
qgBaseBp(g,n) = clamp(7000 + 180×g + 120×n, 7000, 10360)
meridianQinggongBp = design/21 correspondingStrengthAmpBp，范围 6500..13500，中性 10000
spdRaw = floor(agi × qgBaseBp × meridianQinggongBp / 10000²)
spd = clamp(floor((spdRaw+Σflat_spd)×max(2000,10000+Σpct_spdBp)/10000
                  ×ΠmultBp/10000^k),30,300)
```

轻功武学 3/6/9 重分别通过 `trainingAttrs` 永久给 `agi +1/+1/+1`（轻灵名功可 `+1/+2/+2`，单门仍受 §11.7 上限），因此“升级本身提升身法”在属性快照前兑现；`qgBaseBp` 同时随层数增长，但两项来源在 trace 中分列。

| 时期 | 输入 | 基本系数 | 经脉增幅 | `spd` 核算 |
|---|---|---:|---:|---:|
| 早期白马 | `agi=50,g=2,n=3` | `7000+360+360=7720` | 9500 | `floor(50×7720×9500/1e8)=36` |
| 中期神雕 | `agi=65,g=7,n=7` | `7000+1260+840=9100` | 11000 | `floor(65×9100×11000/1e8)=65` |
| 后期雪山 | `agi=85,g=10,n=9` | `7000+1800+1080=9880` | 12500 | `floor(85×9880×12500/1e8)=104` |

早期 36 仍高于 CT 硬下限 30；标准中期约 65、后期专精约 104。若顶配 `agi=120,g=12,n=10,meridian=13500`，结果 `floor(120×10360×13500/1e8)=167`，远低于 300 硬顶，给 Buff 留空间。`meridianQinggongBp` 来自 21 对应轻功经脉的静态/运行强度，不再把旧 `meridianSpeedBp` 乘第二遍；擒拿由 06 / 09 独立结算。

探索 `qinggong` 与境界阈值继续由 §4.5 计算，供 08 门禁；战斗 `spd` 使用本节新式。二者都读取同一轻功武学与身法，但经脉增幅只影响战斗速度/移动预算，不能抬探索境界。

**旧协议公式**：

```
Base_spd = 72 + 0.30 × agi + 0.10 × Ce + 0.14 × qinggong
spd      = clamp(⌊(Base_spd + Σflat_spd) × max(0.2, 1 + Σpct_spd) × Πmult_spd⌋, 30, 300)
```

`qinggong` 已包含身法、`Ce` 兼容档、轻功武学、轻功资质、鞋、主运内功与负重；上式仍给 `agi` / `Ce` 较小的独立权重，以免脱卸轻功后速度完全坍缩，但**不得**再把 `Q_skill` 或 `Q_agi/Q_ce` 分项重复加入。速度修饰通过 `flat` / `pct` / `mult` 管线进入；完整乘算后只在末尾向下取整。“停止集气”不把速度改成 0，而由 09 冻结时间轴。

protocol 4 中，本文输出的 `spd` 已消费 `correspondingStrengthAmpBp`，是战斗速度唯一真值。09 在开战快照冻结它作为首轮与 CT 输入，并据此映射移动预算；21 不得再读取 `baseSpd` 后乘任何经脉倍率。点穴、胀损或调息改变对应强度时，先重算本式，再由 09 在下一次 CT 推进 / 行动开始读取；不回溯首轮或已积累 CT。

protocol≤3 的旧录像仍按旧常数式产生 `baseSpd=91/106/126`，再由 21 的历史 `projectSpeed` 生成 `openingQinggong/spd/move/evadeRatingDelta`。这些字段与 `meridianSpeedBp/moveDelta` 只存在于旧回放分支，不得进入 protocol 4 存档、属性快照或新 golden。

### 4.4 移动力 `mov` 与跳跃 `jump`

```
jump = clamp(qgTier(qinggong) + Σflat_jump, 0, 6)
qgTier(q) = 0 (q<20) | 1 (≥20) | 2 (≥50) | 3 (≥90) | 4 (≥140) | 5 (≥200)      // 基准 §11
```

`mov` 是 09 在行动开始时由最终 `spd`、`qinggong/qgTier`、`sta/staMax`、`Q_load`、装备与 Buff 移动修饰映射并钳于 1–10 的六角移动点结果。本文不再给方格时代的基础公式或 1–8 上限；六邻距离、地形消耗、移动点钳制和覆写优先级见 `design/09`。这也意味着 `agi` 只能经 `spd` / `qinggong` 进入移动预算，不能再独立增加移动点。

- `jump` 只决定**六角战斗地图中单步可跃上的高度差**与**可跨越的沟宽**；平面距离一律用六角距离。台阶、坡道类地形不受 `jump` 限制；下跳免伤高度、跨越消耗等由 `design/08` 定义。
- 探索中的地形门禁判 `qgTier(qinggong)`（**含** `qinggong` 的临时加值——丹药/Buff 是合法钥匙，见 §11.5）；`jump` 自身的 flat 加值只在战斗网格中生效。
- 08 的 20 / 50 / 90 / 140 / 200 门禁、`qgTier`、`jump` 与逐格地形成本始终读取本节探索 `qinggong`，不能靠临时行气越级；protocol≤3 的 `openingQinggong` 也不得反推探索资格。

### 4.5 轻功值 `qinggong`（完整公式）

`qinggong` 现行职责收窄为探索境界、跳跃、地形资格与轻功 UI；它不再代入新 `spd`。公式保留以维持 20/50/90/140/200 门禁可达，`Q_skill` 的层数收益与 `trainingAttrs.agi` 永久加成分别计一次。

```
qinggong = clamp((Q_agi + Q_ce + Q_skill + Q_ap + Q_eq + Q_inner + Σflat_qinggong − Q_load)
                  × max(0.2, 1 + Σpct_qinggong), 0, 300)

Q_agi   = 0.25 × (agi − 30)⁺                       // 身法 50→5，80→12.5，100→17.5，120→22.5
Q_ce    = 0.30 × Ce                                // Ce 35→10.5，50→15，70→21
Q_skill = QS(g_eff) × (0.40 + 0.06 × layer_eff)     // 装配中的轻功武学（轻功栏 1 格，基准 §20）
Q_ap    = 0.15 × apLight                           // 0–15
Q_eq    = Σ 装备 qinggong（鞋主属性 2.5 × g_eff + 词条）
Q_inner = 3.0 × G(g_eff,主运) × layer_eff,主运 / 10  // 仅主运内功，0–10.5
Q_load  = 装备负重惩罚（10 §3.2、§3.4：重甲 10、heavy 重兵 15，可合计 25；背包物品无重量）
```

旧字段名 `Q_lv` 只准在 v2 回放中映射为同值 `Q_ce`；v3 快照与公式不再输出 `Q_lv`。

| g | 1 黄下 | 2 黄中 | 3 黄上 | 4 玄下 | 5 玄中 | 6 玄上 | 7 地下 | 8 地中 | 9 地上 | 10 天下 | 11 天中 | 12 天上 |

## 5. 资源规则

### 5.1 气血 `hp` 与上限

AR-19 后人物资源只读武功 1–9 熟练层与经脉强弱。定义 `grade∈[1,12]`、穴 / 脉 `strengthLayer∈[1,9]`，只统计已学武功和已开穴；所有中间量均为整数：

```text
skillHp = Σ_{已学非内功}(30 + 4×absGrade)×resourceLayer
innerHp = Σ_{已学内功}(20 + 3×absGrade)×resourceLayer
innerMp = Σ_{已学内功}(28 + 5×absGrade)×resourceLayer
openedCount = |MeridianProgress.opened|
meridianScore = Σ_{MeridianProgress.meridianStats}(grade×strengthLayer)
acupointScore = Σ_{已开穴}(grade×strengthLayer)

hpRoot = 300 + skillHp + innerHp + 8×openedCount + 6×meridianScore
         + 2×acupointScore + legacyHpCredit
mpRoot = 200 + innerMp + 6×openedCount + 8×meridianScore
         + 3×acupointScore + legacyMpCredit
breMpBp = clamp(10000 + 60×(bre−50), 7000, 14200)
hpMax = max(1, floor((hpRoot+Σflat_hpMax)×max(2000,10000+Σpct_hpMaxBp)/10000
                     ×ΠmultBp/10000^k))
mpMax = max(1, floor((mpRoot+Σflat_mpMax)×breMpBp/10000
                     ×max(2000,10000+Σpct_mpMaxBp)/10000
                     ×ΠmultBp/10000^k))
```

其中 `resourceLayer=min(trueLayer,9)`；武功使用不受临时书界压制回退的绝对品阶 `absGrade`，脉 / 穴品阶和强度层均来自 15 的同一版永久快照。未开的穴不计 `acupointScore`；一条脉首次开穴时由 15 建立其强度项，此前不计 `meridianScore`。`fluxCap` 是宽度，**不**重复进入资源根值。`legacyHpCredit/legacyMpCredit` 仅由 v2→v3 迁移器一次性写入，新档固定为 0。

这是唯一资源根公式；`bre` 是唯一先天容量修饰，50 为中性点，20/100/120 分别为 `8200/13000/14200 bp`；`con/wil` 不再暗中乘资源。装备、Buff、天书等显式 `flat/pct/mult` 仍在其后按 §11.2 结算；第 10 重不再增加本公式，但保留 05 已有圆满能力。

复算例：已学一门 6 品外功 5 层、一门 6 品内功 5 层；一脉为 6 品 / 强度 4，并开 9 穴，每穴均 6 品 / 强度 3；其余 19 脉先不计示例项。则 `skillHp=(30+24)×5=270`、`innerHp=190`、`innerMp=290`、`openedCount=9`、`meridianScore=6×4=24`、`acupointScore=9×6×3=162`。无其他修饰且 `bre=50` 时 `hpMax=300+270+190+72+144+324=1300`，`mpRoot=200+290+54+192+486=1222`、`breMpBp=10000`，故 `mpMax=1222`；若 `bre=80`，则 `breMpBp=11800`、`mpMax=floor(1222×11800/10000)=1441`。

- `Σpct_hpMaxBp` 可含内功特有被动、装备、套装、Buff、永久创伤与天书之力；旧 `innerHpPct/innerMpPct` 基础贡献已由上式的武功层逐门替代，禁止再算一次。
- AR-19 药材 / 丹药永久强化改走 15 `MeridianTemperEffect`：提高脉 / 穴 `fluxCap` 或强度经验，再由本公式自然提高资源。旧直接永久 `hpMax/mpMax pct` 一次性迁成 `legacyResourceCredit`；物品名称、品阶与投放仍归 10 §8。
- 上限变化时的当前值规则：

| 场景 | 当前值处理 |
|---|---|
| 战斗中上限提高 Δ（Buff） | 当前值 +Δ |
| 战斗中上限降低 | 当前值 = min(当前值, 新上限)；Buff 结束恢复上限时**不**返还 |
| 战斗外换装、武功层数或经脉强度变化 | 保持比例：`cur_new=floor(cur_old×max_new/max(1,max_old))`，旧值满则新值满 |
| 书眠醒来 | 全满（`hp`、`mp`、`sta`），`rage`、`shield` = 0 |

### 5.2 内力 `mp` 与内力性质 `mpNature`

**性质来源**（机制本体归 design/05 §5.1–5.4，本文只定义它对属性的影响）：
- 每门内功带 `nature ∈ {yang, yin, harmony}`（按 05 §5.3 的主修经脉计票规则，逐门现值见图鉴；代表：先天功/龙象/蛤蟆功/葵花为阳，玉女心经/寒冰真气为阴，易筋经/九阴总纲/太玄经/小无相功/九阳/吸星为调和——均为游戏化判定，**（原创扩展）**）。
- `mpNature` = 主运内功的 `nature`；标记 `natureFollowAux` 的内功（乾坤大挪移、斗转星移类）作主运时取品阶最高辅运的性质（05 §5.7）。
- 未装配主运内功：视为调和但**无任何性质加成**（05 相性矩阵"未装配内功"行全为 0）。

| 性质 | 本文的属性效果 | 05 负责的效果 |
|---|---|---|
| `yang` 阳 | `resCold +15pp` | Z5 相性（阳招 +12%/阴招 −12%）、辅运比例、相冲 |
| `yin` 阴 | `resHeat +15pp` | 同上（方向相反） |
| `harmony` 调和 | `resCold +8pp`、`resHeat +8pp` | 调和招 +12%、阴阳招各 +6%（`12%×1/2`）；桥接，见 05 §5.3 |

**获得"调和"**的途径（均由 05 定义，本文列出以便查阅）：① 主运一门调和内功；② `natureFollowAux` 内功搭配调和辅运。"阴阳相冲"的消解靠**桥接**（装配调和且品阶 ≥ 7 的内功，或 `inner.bridge: true`，05 §5.4），不改变 `mpNature`。

**切换**：战斗外自由调整主/辅运（`mp` 按比例保留，§5.1）；战斗中使用 05 §5.6 的行动**"易运"**（主运与一门辅运互换，占用本次行动、收招 800、3 回合限 1 次、当前内力不超过新上限）。易运后本文按 §11.4 立即重算 `mpNature`、性质抗性、`mpRegen`、`Q_inner`、`resGrade` 下限；§5.1 的武功资源项统计**全部已学武功**，不会因换主辅运重复增减。

**内力回复**：每次自身行动开始时 `mp += floor(真实 mpMax × mpRegen / 100)`，不超过 `mpMax`（§4.8）；封内等暂停回复的状态由 `design/06` 定义。“运功调息”行动的调息分支已由 `design/09` §4.8.4 定稿：立即恢复 15% `mpMax`，本行动未移动再恢复 5%。

**永久强化迁移**：AR-19 起丹药与传功不再直接写永久 `mpMax pct`；统一投影为 15 `MeridianTemperEffect`，由品阶 / 强度 / 宽度自然进入资源与运气模型。旧档已有百分比按迁移前后资源差转为 `legacyResourceCredit`，不接受新写入。

**给经脉模拟的属性接口**：21 只读取结算后的 `mpMax/currentMp` 供护体内劲支付，并读取性质、轻功、速度及检定属性。宽度只读 15 的 `fluxCap`，丹田产气与运气速度只读 05 的主运投影；`mpMax` 不再换算节点宽度、起始气或逐段注水。护体内劲仍按 21 §4.8 的 `1 内力抵 2 伤害` 实扣 `currentMp`，其结果发生在护体真气之后、既有 `mpGuard` 之前，不能回写 `mpMax` 或 `atkIn/defIn`。

### 5.3 体力 `sta`

```
staMax = 100 + 0.5 × con + 0.5 × Ce + Σflat_staMax          // 兼容 STD：Ce1 126，Ce35 147，Ce70 170
```

**消耗（探索，design/08 §4.3 已采纳）**：

| 行为 | 所需境界 | 消耗 |
|---|---|---|
| 疾行（奔跑） | — | 2 / 秒 |
| 纵跃（上高差 / 跨沟），每次 | qg1+ | 4 × 高差级数（或沟宽格数） |
| 攀崖，每级高差 | qg3+ | 5 |
| 踏水，每格 | qg3+ | 4 |
| 树梢移动，每格 | qg3+ | 2 |
| 雪/沙/冰/沼 | qg4+ | 0（被动无减速） |
| 一苇渡江（大江湖面），每格 | qg5 | 3 |
| 云海栈道，每格 | qg5 | 3 |

- **熟练折扣**：`cost × max(0.5, 1 − (qinggong − 该动作所需阈值) / 200)`。例：qinggong 190 踏水（阈值 90）→ ×0.5。
- 这让高阶门禁同时考验"境界"与"续航"：渡 40 格大湖需 120 体力（qg5 刚达标时几乎无折扣），兼容 STD `Ce60` 的 `staMax` 163 可一次渡过；55 格以上的大江需在中途设置落脚点（沙洲、船只，08 配置）。

**恢复**：

| 情形 | 恢复 |
|---|---|
| 探索中 2 秒未消耗 | 每秒 `staMax × staRegen%`（默认 4%，≈6/秒） |
| 打坐（任意安全点，游戏内 1 小时） | 全满 |
| 客栈 / 门派 / 营地 | 全满 |
| 干粮 / 药膳（10 定） | +20 ~ +80 |
| 战斗中每次自身行动开始 | +10 |

**疲惫**：`sta` 降至 0 时获得 `bf_pibei`；恢复到 `sta ≥ ceil(0.20 × staMax)` 时移除。疲惫期间 `eva` flat −15、向 `design/09` 提供 `mov` flat −1（仍受其移动下限约束），禁止疾行、纵跃和所有需要轻功境界的动作；不再额外修改 `spd` 或开场 CT。普通招式**不**消耗体力。Buff 实例、标签和解除事件归 `design/06`，地形动作归 `design/08`。

### 5.4 气势 `rage`（0–100）

| 事件 | 获得 | 备注 |
|---|---|---|
| 自身行动开始 | +3 | |
| 本次行动的招式命中 ≥ 1 个目标 | +8 | 每次行动只计一次 |
| 每多命中一个目标（范围招式） | +2 | 此项上限 +8 |
| 本次行动出现暴击 | +4 | 每次行动只计一次 |
| 受到伤害（含被护体吸收部分） | `+4 + ⌊20 × 伤害 / hpMax⌋` | 单次上限 +15；持续伤害（DoT）不计 |
| 被暴击 | 额外 +4 | |
| 闪避成功 | +5 | |
| 招架成功 | +10 | 基准 §8 |

### 5.5 护体真气 `shield`

| 项 | 规则 |
|---|---|
| 上限 | `shieldMax = hpMax × (0.25 + Σpct_shieldMax)`，总系数不超过 0.50 |
| 来源 ① 开场护体 | 主运/辅运内功的**特有被动**"护体真气 X% `hpMax`"（05/图鉴），战斗开始时一次性获得，多门相加后受上限截断 |
| 来源 ② 运功护体 | "运功调息"行动的一个分支（09 定义行动本体）：消耗内力 `m` 点，获得 `shield += m × 1.0 × (1 + 0.005 × (wil − 50))` |
| 来源 ③ Buff | 标签 `guard` 的效果（06） |
| 来源 ④ 装备 | 词条（10），如"开场获得 5% `hpMax` 护体" |
| 衰减 | 默认不衰减；战斗结束清零 |
| 结算 | 基准 §9 settle：伤害先扣 `shield` 再扣 `hp`；"破罡"类效果可无视或加倍削减护体（06/04） |
| 与减益的关系（04 §6.2 已定稿） | 一次攻击若被护体**完全吸收**，该次攻击附带的 `injury`、`bleed` 标签效果不施加；其他标签照常判定 |

### 5.6 战后与休息的资源恢复接口

本文只定义 `hp`、`mp`、`sta` 的增减接口；哪些 Buff 跨战、休息降低多少层或品阶、哪些状态只能走专用解法，唯一引用 `design/06` §5.4.2，不在属性文档维护第二张清理表。地点与时间推进由 `design/11`、`design/16` 定义。

| 入口事件 | 本文处理的资源 | 状态处理接口 |
|---|---|---|
| 战斗结束 | 战后调息 `hp += floor(0.10×hpMax)`、`mp += floor(0.30×mpMax)`，均不超过上限；`sta` 不变 | 由 `design/09` §7.4 调度，逐项调用 `design/06` §5.4.2 |
| 探索中自然恢复 | `mp` 每 10 秒 +5% `mpMax`；`sta` 按 §5.3 | 不触发休息清理；见 `design/11` §9.1 |
| 打坐（游戏内 1 小时） | `hp` 恢复至至少 50%，`mp`、`sta` 全满 | 只结算自然世界时间，不触发完整 `onRest`；见 `design/11` §9.2 |
| 客栈 / 门派 / 营地休息 | `hp`、`mp`、`sta` 全满 | 发出同一 `onRest(restType)`，不按地点另写清理规则；见 `design/11` §9.1–§9.3 |
| 医治（`med`，§8.2） | 治疗量走 `design/04` | 发出带医术与药物参数的治疗事件；解除门槛见 `design/06` |

战末阶段的固定顺序为 `onBattleEnd → 清除非 persist 实例 → 跨战实例转 world → 倒地者先结算伤势 bf_shangshi 造成的新 hpMax、再恢复该上限的 10%（同场多次倒地也只增 1 层伤势）→ 战后资源调息 hp+10% / mp+30% → 按 unitIndex 完成 21 战后经脉调息 / 深度清理 → 销毁战斗经脉实例 → 奖励`；`bf_shangshi` 的层数、惩罚与解除只引用 `design/06` §5.4.2，经脉步骤只引用 `design/21` §10.2，执行权威仍是 `design/09` §7.4。资源恢复与经脉清理是两个步骤，后者不再重复发放 hp / mp；所有百分比回复在各自步骤向下取整并封顶。

### 6.1 计算

```
res_X = clamp( innateTerm_X + natureTerm_X + Σpp_X , −50, 75 )          // 单位 pp（百分点）
```

### 6.2 上下限与"免疫"的区别

| 项 | 值 | 说明 |
|---|---|---|
| 下限 | −50pp | 负抗性使效果更易施加、更强（06 按 `1 − res` 计算即自然放大） |
| 上限 | **75pp** | 任何来源叠加都不超过 75；超出部分溢出无效（UI 显示灰色溢出值，便于配装） |
| 免疫 | 不属于抗性 | "免疫中毒""免疫中蛊"是**机制类 Buff**（`mechanic`，基准 §10），由 design/06 定义；免疫同样受 Buff 品阶对抗约束 |

### 6.3 抗性品阶 `resGrade` 与 Buff 品阶对抗接口

基准 §10 规定"抵抗只对品阶 ≤ 自身品阶的效果完全生效"。抗性是多来源之和，本身没有品阶，因此为每个抗性标签定义**抵抗品阶**（design/06 §3.5.2 已写明"若 03 另行定义 `resGrade`，以 03 为准"；本文定义与 06 的建议式兼容，只增加 5pp 门槛）：

```
resGrade(tag) = max( g_eff(主运内功) − 3,                                        // 内功护体的底子（06 同式）
                     max{ grade(src) | src 对 res_tag 的贡献 ≥ 5pp },            // 小于 5pp 的零碎来源不抬品阶
                     1 )
  grade(src)：武学被动 / 装备 / 套装 / Buff / 丹药 = 其 g_eff；
              解毒专属项（0.15·antidote 等）= gMax(antidote) = ⌊(antidote + 4) / 8⌋（§8.1）；
              内力性质项（寒/热）= 主运内功 g_eff；先天项不单独计品阶（由"主运 − 3"与下限 1 覆盖）
```

对品阶为 `g_e` 的效果（`Δr = g_e − resGrade`），穿透系数 `ρ(Δ)` **采用 design/06 §3.5.0**（Δ≤0 → 0；Δ≥1 → `min(0.90, 0.15 + 0.15Δ)`，即 0.30/0.45/0.60/0.75/0.90）：

```
res_eff = res_X                         若 res_X ≤ 0（负抗性对任何品阶都全额生效）
res_eff = res_X × (1 − ρ(Δr))           否则
```

- 施加概率采用 design/04 §3.1 的正式式：`P_apply = clamp(baseChance × clamp(1 + (effHit − effRes)/100, 0.3, 2.0) × (1 − res_eff/100) × extraFactor, 0, 1)`；本节 `res_eff` 以百分数表示。
- 持续伤害减免：`resPart = 1 − clamp(res_eff, −50, 75)/100`（06 §5.3.2）。
- "免疫"是机制类 Buff，走 06 §3.5.1 的免疫穿透，不经过本节。
- UI：抗性页每项显示"数值 / 品阶色"，例如"抗毒 36%（地中）"；受穿透时 Tooltip 显示"被〈天中·某毒〉穿透 60%"。

### 6.4 示例

主角 Lv50：`con` 60、`antidote` 40；主运内功地中（g8）且其特有被动"抗毒 +20pp"；佩饰"抗毒 +8pp"（地下 g7）。

| 项 | 值 | 品阶 |
|---|---|---|
| 先天项 `0.2×(60−50)` | 2pp | 不计 |
| 解毒项 `0.15×40` | 6pp | `gMax(40)` = 5 |
| 内功特有被动 | 20pp | 8 |
| 佩饰 | 8pp | 7 |
| 主运底子 | — | 8 − 3 = 5 |
| **合计 / resGrade** | **36pp / 8（地中）** | |

| 来袭毒效果品阶 | Δr | ρ | `res_eff` | `P_apply`（baseChance 60%、effHit = effRes） |
|---|---|---|---|---|
| 地中（8）及以下 | ≤ 0 | 0 | 36.0 | 38.4% |
| 地上（9） | 1 | 0.30 | 25.2 | 44.9% |
| 天下（10） | 2 | 0.45 | 19.8 | 48.1% |
| 天中（11） | 3 | 0.60 | 14.4 | 51.4% |
| 天上（12） | 4 | 0.75 | 9.0 | 54.6% |

## 7. 武学资质

### 7.0 类别熟练度、顿悟点数与真元（AR-26 承接资源）

现有 `ap*` **保留并改名为“资质”**：它描述学习效率、类型天赋和 Z5 技法适配，仍为 0–100；不与可消费经验合并。新增两类跨书界资源**（原创扩展）**：

| 资源 | 存档字段 | 计量 | 获得与用途 |
|---|---|---|---|
| 类别熟练度（武功经验） | `masteryXp[MasteryCategory]` | 非负整数 XP | 正常使用/修炼积累；可投入同类新武功 `sxp` |
| 顿悟点数 | `epiphany` | 非负整数 XP | 遗忘武功所得的未分配钱包；可 1:1 分配给任一 `masteryXp` |
| 真元（内功经验） | `trueEssenceByNature[InnerNature]` | 非负整数 XP | 按来源内功性质分账；正常内功修炼沉淀或散功所得，可投入可修炼内功 `sxp` |

`MasteryCategory` 固定为 `fist/finger/leg/grapple/sword/blade/staff/spear/whip/exotic/hidden/movement`；武艺型杂学转化口径见 `design/25` §8，落入最贴近的上述类别，非武艺杂学继续走技艺。`InnerNature` 的 `yang/yin/harmony` 值集及目标内功性质只引用 `design/05` §5.3。每笔真元入账必须按来源内功的静态 `nature` 写入对应分账；显示总量 `trueEssence=sum(trueEssenceByNature[n])` 只读，不得单独持久化或写入。

`epiphany/masteryXp[*]/trueEssenceByNature[*]` 均无玩法配置上限、可跨书暂存；实现须用非负 int64，且三份真元分账之和也不得超过 `INT64_MAX=9,223,372,036,854,775,807`。顿悟点分配到类别、真元投入内功均按 1:1 XP，不得互换或二次打折；真元不得投入《长生诀》（见 `design/25` §1、§8）。单门每层由这些资源补入不得超过该层 `ExpToNext` 的 50%，其余必须来自正常修炼。

真元投放以《长生诀》层数作门控（层效果只引用 `design/25` §2）：`changshengLayer<7` 时，`spendByNature` 只能扣目标内功同性质分账；`changshengLayer>=7` 时可组合扣除任意性质分账，`sum(spendByNature)` 按 1:1 加入目标 `sxp`，无额外损耗。客户端必须提交逐性质扣款明细；服务端以目标卡 `nature` 重验，不接受只报总额的请求。

书眠转化的基数、60%–72% 层率、高水位与原子提交只引用 `design/13` §4.10；`design/25` §8 允许当场分配或暂存。事务顺序固定为“逐门求转化 → 增加钱包 → 扣钱包并增加目标经验”，任一步失败则全回滚。

迁移：

1. 旧 `apXP_k` 原值保留，继续只用于资质升点；不得转换为可消费熟练度。
2. 旧档每门累计合法使用次数按 `masteryXp[cat] += 2×uses + 20×max(0,trueLayer-1)` 给予一次性补偿；缺使用次数时只计层数项。
3. 旧内功按 `trueEssenceByNature[skill.nature] += 25×max(0,trueLayer-1)` 逐门补偿；`skill.nature` 取同版 `design/05` §5.3 静态字段。迁移补偿不是散功，不触发 60%。
4. 忘记/散功的原始经验、向 60% 转化和 3+3 保留事务归 `design/13`；本文只定义接收资源与消费边界。

```

获得：apXP_k += raw × trainWis × talentMul             // trainWis = 0.6 + 0.008·wis（§2.3）；天赋 tal_wuchi ×1.2
```

| 途径 `raw` | 数量 | 限制 |
|---|---|---|
| 战斗中施放 k 类招式（命中或未命中均计） | +1 / 次；绝招 +3 | 每场战斗每类最多 +6 |
| k 类武功层数突破到第 n 重 | +3 × n | 1→10 重合计 +162 |
| 拜师指点 / 研读典籍 / 奇遇 | 事件定义（05/11/12） | — |
| 轻功 `apLight` 额外 | 探索中每次成功使用 qg3+ 地形动作 +1 | 每游戏日最多 +10 |
| 内功 `apInner` 额外 | 每次"运功调息"或打坐 +1 | 每场战斗最多 +3 |

累计经验对照：

| 从 25 升到 | 40 | 60 | 80 | 100 |
|---|---|---|---|---|
| 累计 `apXP` | 630 | 1,820 | 3,410 | 5,400 |

预期曲线（主修类别，悟性 55）：天龙末 ≈ 40，射雕末 ≈ 52，倚天末 ≈ 66，全书末 ≈ 85–95（受 `apCap` 限制）。兼容 STD 采用 `25 + 0.6 × (Ce − 1)`；`Ce` 只选回归行，真实资质仍由上表的行为与突破累计。时代档位封顶后资质仍持续成长，是横向成长维度之一。

### 7.3 上限

`apCap = min(100, 70 + 0.3 × wis)`（悟性 50 → 85，悟性 100 → 100）；奇遇"开窍"类可 +5（每类最多 2 次，不超过 100）。资质**跨书界完整保留，不受天道压制**。

### 7.4 对伤害的影响（伤害乘区 Z5 的"资质"部分）

```
apFactor(ap) = 0.80 + 0.004 × ap                       // 0→0.80，25→0.90，50→1.00，75→1.10，100→1.20
A_ap(move)   = (1 − r_in) × apFactor(ap_cat(move)) + r_in × apFactor(apInner)
```

| 招式类别 | `ap_cat` |
|---|---|
| 拳掌/指/腿/擒拿 | `apFist`/`apFinger`/`apLeg`/`apGrapple` |
| 剑/刀/棍杖/枪/鞭索/奇门 | 对应兵器资质 |
| 暗器 | `apHidden` |
| 内功自带招式（若 05 设计） | `apInner`（此时 `A_ap = apFactor(apInner)`） |
| 杂学主动（医/毒/蛊/阵/音律/书画/棋/易容/驭兽/心神） | 无资质，改用 05 §2.3 映射的技艺（或属性）：`artFactor = 0.80 + 0.004 × value`，`value` 取 `med`/`poi`/`formation`/`music`/`art`/`chess`/`cha`/`wil`（**本文确认 05 §2.3 的映射**，含其修炼速度以 `wis` 当资质的约定） |
| 音功 `sonic` | `apInner`（与 05 §2.3 一致），`music` 只作辅助效果强度 |

- `r_in` 为招式内劲比例（§4.1），让"内劲为主"的招式更吃 `apInner`：例如 `r_in = 0.7` 的掌法，`apFist` 40 / `apInner` 80 → `A_ap = 0.3×0.96 + 0.7×1.12 = 1.072`。
- Z5 已由 design/04 §4.5 定稿：`Z5 = A_ap × (1 + 相性加算项 + 破 X 加算项 + 三运同源等)`。design/05 §5.3 提供相性与“破 X”加算项，资质系数 `A_ap` 是 Z5 内的独立乘子。
- STD 参考：Lv1 ≈ 0.90，Lv35 ≈ 0.98，Lv70 ≈ 1.06。

### 7.5 对修炼速度的影响（design/05 引用）

```
trainMul(k) = (0.5 + 0.01 × ap_k) × trainWis            // trainWis = 0.6 + 0.008 × wis
```

| `ap_k` \ `wis` | 30 | 50 | 70 | 100 |
|---|---|---|---|---|
| 20 | 0.59 | 0.70 | 0.81 | 0.98 |
| 50 | 0.84 | 1.00 | 1.16 | 1.40 |
| 80 | 1.09 | 1.30 | 1.51 | 1.82 |
| 100 | 1.26 | 1.50 | 1.74 | 2.10 |

`trainMul` 乘在武功修炼经验上（修炼经验来源与各重所需经验归 05）。学习门槛由 05 §7.3 按武功逐门定义；其已采纳的配表基准为 `X = 5 × g − 5`（允许按武功在 ±10 内浮动，天上基准 55）。

## 9. 天道压制对属性的影响

> 压制规则本体（何为外来、携带数量、残篇）归 design/02；本节只规定**属性如何重算**。

### 9.1 重算清单（进入书界、或 `Cb` / 装配变化时）

先求当前规则参数，再进入属性 DAG：

```text
S_base(HIGH/MID/LOW) = 0 / 2 / 4
Ce_normal             = min(Cb, chapterBandCap)
Ce_capExemptBoss      = min(Cb, 70, chapterBandCap + delta)
delta(HIGH/MID/LOW)   = 3 / 4 / 6
```

`capExempt` 每书界至多登记 2 名 Boss，且只改变该单位的有效校准档上限；不豁免武学品阶、层数、修为门槛或来源限制。旧洪安通回放仍可得到 `min(50,70,44+6)=50`，其中 50 是内容构建从其武功 / 经脉模板派生的 `Cb`，不是等级。

| 对象 | 处理 | 影响的属性 |
|---|---|---|
| 有效校准档 | 普通单位 `min(Cb,chapterBandCap)`；`capExempt` Boss 用上式 | 所有仍待迁移的 `*_LV(Ce)` 攻防项、`flatLv` 装备值、评级中的档位项、`qinggong` 的 `Q_ce`、`staMax`，以及 04 的 Z8；**不含 `hpMax/mpMax`** |
| 修为突破分配 | 只计已经由 `Cb` 解锁的永久 `realmAlloc[r]` | 先天 → 全部派生；跨时代不回退 |
| 武功层数 | `layer_eff = min(layer, layerCap)`（10/9/8） | 内功贡献（05 §5.5）与特有被动、`Q_skill`、`Q_inner`、`mpRegen`、`resInjury`；招式威力（04） |
| 外来武功品阶 | `g_eff = max(1, g − suppress)`（0/2/4） | `G(g_eff)` 进入以上所有被动；Buff 品阶（06）；套装品阶（07）；抗性品阶（§6.3） |
| 外来装备品阶 | `g_eff = max(1, g − suppress)` | 装备主属性（`0.30×G(g_eff)×ATK_LV` 等）、鞋 `2.5×g_eff`、词条（10） |
| **不变** | 永久先天（突破分配除外）、资质、技艺、`lore`、`morality`、天赋、丹药永久加成、天书之力（13 另定） | — |
| 当前值 | 书眠醒来全满（§5.1） | `hp` `mp` `sta` |

天书之力只把 `design/13` §4.5 已算出的武学 / 装备 `g_eff` 与本命 `layerCap_eff` 交给本文，不改 `Cb/Ce`、修为门槛、真实层数或来源限制。`bf_tsp_xianying`“天书现影”才会限时令品阶压制为 0、书界层数上限为 10（仍检查修为、真实层数和来源）；`bf_tsp_weiguang`“天书微光”只抵消 1 小品且仍受 `ceil(S/2)` 下限，不解层数封印。终局 `bf_tsp_xianying_fin` 只进入 Z3/Z4，不生成属性 `mult`；三者定义与计时均见 `design/06` §5.4、`design/13` §4.6。

自愿规则同样只覆写明确字段：`tj_tiandao` 自第 6 重起把中 / 低武的基础压制改为 3 / 5；互斥的 `rule_wutiandao` 关闭品阶压制并把书界层数上限设为 10。二者都保留 `Cb/Ce`、修为门槛、真实层数、武学特殊上限和来源约束，具体开关与成就后果见 `design/13` §5.2–§5.3。

UI：被压制的武功/装备在图标上显示"天道"角标，品阶色按 `g_eff` 着色，Tooltip 显示"倚天剑 天阶上品 → 地阶中品（中武 −2 … 低武 −4）"；属性面板被压低的数值旁显示向下箭头，悬停可见未压制值。

#### 10.2.1 武学型 Boss 发布构建闸门

`STD_E` 只提供数值基线，不能替代实际武学配装。所有武学型 Boss / 首领在发布前逐单位执行 `design/21` §11.9.1 的闸门：

1. 内功恰为 **1 门主运 + 2 门辅运**；两门辅运必须是玄 / 黄阶基础内功。主运须达到当章“本界精英默认”给出的最低目标 `G` 与人物地位下限，并能由同一主运解析 `effGrade / effLayer / innerNature`；七项经脉参数与路线均须完整。
2. 外功为 **3–5 门**，至少 1 门有效品阶 `≥G`；若人物的主要战斗身份横跨两类外功（如拳掌兼兵器），至少 2 门外功 `≥G`。具体可共享性、来源与补位顺序只引用 21 §11.9.1。
3. “地位下限兜底 / 缺专属主运”标记只允许离线节奏估算工具 `boss_pacing.py` 读取，且输出必须带 `estimateOnly=true`、不得进入发布 IR。正式生产构建若仍见任一标记，或七参只有 `effGrade / effLayer / innerNature` 而没有可解析的主运 `sk_*` 外键，一律按 `tech/04` 的 `TS-CONTENT-BOSS-021` 以 **error 阻断**，不降为 warning，也不得因节奏超窗而降档。其他资料缺失同样不得静默回退为 `1 / 1 / harmony`。
4. 纯落石、火场、门闩等没有武学行动的机关 / 环境物可豁免内外功和经脉实例；武学型机关若低于目标或豁免，必须在遭遇数据中写明例外类型、叙事 / 机制理由与实际目标值。

多人首领组仍逐单位通过以上配装闸门；这不表示每个单位各自获得一份完整 Boss 耐久，节奏验收统一见 §10.8。

### 10.5 书界难度修正

采用 **design/02 §3.3** 的 `enemyStatMul(D) = 0.85 + 0.05 × D`（D3 → 1.00 … D10 → 1.35；局部难度 `localDifficulty` 可覆盖）。它**只乘 `hpMax` 与 `atkOut`/`atkIn`**，不乘防御与评级（防御再乘会与 Z2 的比值型减伤重复放大，评级另有模板加值）；design/13 §5.1 已确认难度模式的 `dm_hp`/`dm_atk` 与之独立相乘，评级另加 `dm_rat`。

### 10.6 模板敌人的威力归一（design/04 §4.1、§9 已采纳）

模板敌人的招式在 Z1 中**不用自身品阶的 `G × L(n)`**，而是：

```
P_enemy = P_ref(Ce_敌, tier) × tmplPower          // §3.5；tmplPower 见 §10.3
```

理由：02 的品阶骰让杂兵/精英的武学品阶普遍低于同级主角；模板法若直接使用随机所得 `G×L(n)`，其基础伤害会和属性模板重复降档。替换后，品阶仍决定附带 Buff 品阶、特效、掉落与招式池，模板攻击节奏由 `tmplPower` 与遭遇参数控制。`full` NPC 不做这项**模板替换**，而是使用真实 `P_actual`；两种方式都必须在 Z1 除且只除一次 `P_ref`。正式公式与模拟见 `design/04` §4.1、§9。

### 11.2 叠加管线："基础值 → 加值 → 百分比 → 最终值"

对每个属性 S（按 §1.2 的步骤顺序逐个求值）：

| 步 | 名称 | 规则 |
|---|---|---|
| ① | 基础值 `Base_S` | 资源按 §5.1；其余兼容属性由 `Ce` 曲线 × 先天系数 + 固有常数给出 |
| ② | 加值 `Σflat_S` | 所有 `flat` 与 `flatLv`（后者先按兼容档 `Ce` 解析为数值）**相加** |
| ③ | 百分比 `Σpct_S` | 所有 `pct` **相加**（同属性的加成彼此加法，不连乘）；负值（减益）同池相加 |
| ④ | 独立乘数 `Πmult_S` | 仅限归属文档明确标注 `mult` 的系统层来源；当前已定来源只有敌人模板/流派/难度。`tianshu`、`title`、`meridian` 与 `terrain` 不得自行进入本乘区 |
| ⑤ | 合成 | `S = (Base_S + Σflat_S) × max(floor_S, 1 + Σpct_S) × Πmult_S` |
| ⑥ | 百分点 | PCT 形态属性：`S = Base_S + Σpp_S`（没有②–④） |
| ⑦ | 截断 | `clamp(S, min_S, max_S)`（§12 汇总各属性范围） |
| ⑧ | 覆写 | 机制类 `override`（如"`resCC` 视为 75"、"`hpMax` 锁定为施加时的值"）最后生效，多个覆写取最新施加者；"停止集气"不用覆写实现（§11.5 #3） |

- `floor_S`：MAG/RAT 为 0.2（即任何减益叠加最多把属性压到 20%）；资源上限 `hpMax`/`mpMax` 同为 0.2。
- 与伤害乘区的关系：本管线产出的是**面板属性**。"伤害 +X%"进 Z3、"受到伤害 −X%"进 Z4、"对某类兵器伤害"进 Z5，均**不是属性修饰**。protocol 4 的 `operationBp` 只由 21 输出并在 §4.1 外放支消费，`meridianDefenseBp` 只进 04 的 Z4M，Z5M 固定 10000；旧 `meridianAttackBp` 仅供 protocol≤3。
- **实例唯一**：以 `(sourceType, sourceId, modifierId)` 为修饰器唯一键；同键重复输入只生效一次，不同 `modifierId` 可让同一装备、武学或 Buff 合法修改多个属性。Buff 的刷新/叠层/独立/取高由 design/06 在展开修饰器前处理。

示例（`atkOut`，`Ce=50`，`str=70`）：

| 步 | 内容 | 值 |
|---|---|---|
| ① | `ATK_LV(50) × (1 + 0.01×20)` = 1,216.49 × 1.2 | 1,459.79 |
| ② | 地中剑 `0.30 × 2.2 × 1,216.49` = 802.88；词条 +50 | +852.88 |
| ③ | 某内功特有被动 +10%、套装 +8%、减益"筋骨酸软" −15% | Σ = +3% |
| ⑤ | `(1,459.79 + 852.88) × 1.03 = 2,382.05`；面板 half-up | **2,382** |

### 11.4 重算时机

| 触发 | 范围 |
|---|---|
| 武功习得 / 层数变化、开穴 / 强度变化、书眠进入新书界、装配 / 装备或修为分配变化 | 先从同一永久快照重算 `Cb/Ce` 与 §5.1 资源根值，再全量重算 |
| 战斗中 Buff 施加/移除/叠层变化 | 标脏受影响属性及其下游（按 §1.2 DAG），在**下一次读取前**增量重算 |
| 属性重算导致 `mpMax/mpNature/qinggong/spd` 改变 | 先完成属性快照，再标脏 21 的护体支付；经脉运行态变化则先重算对应强度与本文 `spd`。节点宽度仍只读 15 `fluxCap`，并保留在途气、迟滞、堆积、胀损和点穴 |
| 条件修饰（`cond`，如"气血低于 30% 时 +20% 攻击"） | 在每次自身行动开始、每次受击结算后重新求值条件 |
| 伤害结算 | 读取**招式开始结算那一刻**的属性快照；同一招式多段伤害共用该快照 |

### 11.5 边界情况

| # | 情况 | 规则 |
|---|---|---|
| 1 | 先天极低（如根骨 1） | 含 `(X−50)` 的乘法项各有下限 0.5（§3、§4.1、§5.1），`hpMax` 不会低于曲线值的一半 |
| 2 | 减益叠满 | `1 + Σpct` 下限 0.2；PCT 属性按各自范围截断（抗性 −50） |
| 3 | "停止集气"类控制（冰封、定身） | 由 design/09 冻结 CT 实现，**不**把 `spd` 改为 0；`spd` 始终在 [30, 300] |

| 5 | 临时 Buff 提升 `qinggong` 跨过门禁 | 探索门禁判定**包含** `qinggong` 的临时加值（丹药/Buff 是合法钥匙）；但 `jump` 自身的 flat 加值只在战斗中生效（§4.4） |
| 6 | `apCap` 因悟性下降而低于当前资质 | 资质不回退，只停止成长 |
| 7 | 空手 | 兵器栏不可用（基准 §20），`P_wpn = 0`，`atkOut` 无兵器 flat；拳脚武学仍按 `atkOut`/`atkIn` 合成 |
| 8 | 未装配主运内功 | `mpNature` 视为调和但无任何性质加成（05 相性矩阵"未装配内功"行全 0），`mpRegen = 1`，`Q_inner = 0`，无 `resInjury` 主运项，`resGrade` 下限 1 |
| 9 | 战斗中武功或经脉成长 | 永久成长只在结算事务提交；当前战斗继续使用创建时快照，新值从下一战生效 |
| 10 | 达到当前书界时代上限 | `Ce` 不再提高，但武功真实层、经脉 / 穴位、资质等永久事实可继续成长；`hpMax/mpMax` 不因 `Ce` 封顶停长 |
| 11 | 敌人 `flatLv` | 按敌人自身 `Ce` 解析 |
| 12 | 同伴 | 与主角、具名 NPC 同走 `full` 管线；武功 / 经脉快照、本土归属及跨界成长由 `design/18` 输入。健在同伴重逢时真实能力只增不减，兼容战斗表按当前 `Ce`、来源和压制重算 |
| 13 | 同一套装由外来件与原生件混搭 | 各件按自身 `g_eff` 参与 design/07 的档位判定 |
| 14 | 数值溢出 | `hpMax` 等整数存档字段用 32 位有符号整数；本文合法 STD 与现有终局模板量级远低于 `2^31−1`。任何新增 `mult` 来源或上限突破须先枚举合法组合、以 64 位中间值验算，再决定是否调整存档字段 |

### 11.7 武功修炼永久属性加成（AR-27）

`SkillDef.trainingAttrs` 是已学武功达到真实熟练层时写入人物永久账本的奖励，不要求当前装配，不随外来压制回退。字段与预算由 `design/05` §2.1、§3.7 定义；本文规定聚合：

```text
grant(skill,attr) = Σ milestone.points, milestone.layer<=min(trueLayer,9)
skillGrantTotal <= 12
characterTrainingAttrTotal = Σ全部武功全部属性 grant <= 48
permAttr = clamp(base + sleepAlloc + acceptedTrainingGrant + events, 1, cap)
```

里程碑只能在 3/6/9 重，每个里程碑 1–4 点；第 10 重不给永久属性。达到总上限 48 后，新奖励转为等量该门类别熟练度（内功转真元），不吞奖励。单项来自修炼的累计上限 24，防止只学同源武学把一项灌满。

| 源流 / 小说表现 | 默认里程碑 | 单门总量 | 配表边界 |
|---|---|---:|---|
| 一般拳剑刀枪 | 主属性 `+1/+1/+1` | 3 | 无明确炼体/身法描写不加副属性 |
| 轻功 | `agi +1/+1/+1` | 3 | 顶尖轻灵可 `+1/+2/+2=5` |
| 硬功横练 | `con +1/+2/+2` | 5 | 金钟罩、铁布衫类；可另 `wil +1`，总量仍≤6 |
| 内功吐纳 | `bre +1/+2/+2` | 5 | 稳心型可把至多 2 点改为 `wil` |
| 刚猛外功 | `str +1/+2/+1` | 4 | 若兼横练，最多再 `con +2` |
| 巧思/悟理名功 | `wis +1/+1/+1` | 3 | 只用于明确以悟理为核心者 |

原著只证明“偏向”，不证明数值。名录依据应写人物/源流/情节梗概；无把握标（待考），原创归类标（原创扩展）。同一武功不得仅因“强”而同时加三项；总量 7–12 只给有明确多维锻炼且需手配的名功。
