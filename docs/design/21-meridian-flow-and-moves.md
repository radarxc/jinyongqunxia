## 0. 结论先行与阅读顺序

1. 作者所称“大招”正式采用武侠语境中的“**绝招**”；程序继续使用 `MoveDef.ultimate`，不建立第二套能量或 ID。
2. `design/15` 的 20 脉 / 180 穴是静态拓扑与永久修炼事实；本文只在战斗实例里投影节点状态，不改变冲穴进度，也不拿战斗调息冒充冲穴。
3. 每个可独立行动单位各有一个 `MeridianFlowModule`：我方人物、普通敌人、精英、Boss、召唤物，以及确实需要独立出手的环境行动者均不共享实例。
4. 路线长度 `n` 的理论加成上限为 `floor(1200n/(n+6)) bp`：1 / 2 / 6 / 10 / 18 段分别为 171 / 300 / 600 / 750 / 900 bp，严格递增但永远小于 1200 bp。
5. 实际路线加成同时受逐穴充盈率和有效流畅度约束，落入 `design/04` Z3 `dmgUp` 加算池；不新增乘区，不绕过 Z3 总上限。
6. 长路线不是白送伤害：每尝试一段增加 CT；熟练不足、节点迟滞或点穴会卡住，未通过之气形成堆积，超过动态阈值则胀损并封路。
7. 擒拿是外功严重度 1–9，点穴是内功对具体穴位的严重度 1–9；二者由后续 `design/06` 注册承载 Buff，与旧麻、定身、封穴做兼容映射而非同义替换。
8. 调息合并进 `design/09` 已有 `yunjin mode:tiaoxi`：既保留其回内 / 防护，又增加理顺迟滞、卸除堆积、修复胀损与尝试解穴。
9. Python 参考实现与固定黄金数据分别位于 `tools/balance/meridian_flow_sim.py`、`meridian_flow_golden.json`；它们是后续 TypeScript Core 的独立慢模型与逐字段对齐基准。
10. 当前黄金对同一组 04 锚点的接入前 / 后行动数是普通 `5→5`、精英 `9→8`、Boss `22→21`，仍在 3–5 / 6–10 / 12–25 目标内。

| 编号 | 目标 | 验收口径 |

## 1. 术语、命名与唯一归属边界

### 1.1 “大招”命名论证

| 候选 | 武侠语感 | 问题 | 结论 |
|---|---|---|---|
| 绝招 | 简短、通行，既可指压轴招式也可指制胜一手 | 日常用法稍泛 | **采用** |
| 绝技 | 常指整门稀有技艺，如“少林绝技”，易与武学本体混淆 | 粒度偏大 | 不采用 |
| 杀招 | 强调杀伤，不适合治疗、护体、擒拿型压轴招 | 语义过窄 | 不采用 |
| 看家本领 | 口语形象，但不像稳定数据术语 | 太长 | 仅用于对白 |
| 压箱底功夫 | 有江湖味，但偏俗语且更像保留手段 | 太长 | 仅用于对白 |

因此 UI、策划正文均称“绝招”，数据继续沿用 `ultimate: true` 与气势 100 的既有定义（见 `design/05` §4.8、`design/09`）。本文只补“绝招也有经脉路线且通常较长”，不改绝招预算、解锁层、霸体或演出规则。小说中的某一招是否是人物“最强一击”，若原著没有明说，不以本文配置反推原著事实。

### 1.4 三层事实与生命周期

```text
永久成长层（design/15）
  已开穴、通脉、小/大周天、十二经周流、九转
       │ 战斗初始化时只读投影
       ▼
单位经脉实例（本文）
  capacity / flowBp / stagnationBp / backlog / ruptureDamage / sealLevel
       │ 每次出手、调息、tick 更新；随战斗快照保存
       ▼
一次攻击结果（本文 → design/04）
  routeZ3Bp / flowCt / blockedAt / trace
```

- 永久成长层不会因战斗卡住、点穴或胀损而回退；战斗实例也不能直接把节点标为永久开通。
- 战斗结束时：`water=0`；临时点穴和擒拿按 Buff 生命周期清除；普通迟滞 / 堆积按战后调息归零；胀损默认转为一次战后深度调息后清零，不形成新的永久伤势。剧情若要留下伤势，应走 09 的战后伤势系统，不能直接保存本文数值。
- 中途存档或录像检查点必须保存全部实例状态；重新开战则从永久层重新初始化。

### 1.5 设计不变量

1. 一单位一实例，一实例只属于一个 `unitId`；任何引用共享可变 `nodes` 都是错误。
2. 路线只能引用已开通穴位；未开通、9 级点穴或已胀损节点使整条路线在选招阶段不可用。
3. `preview` 不修改状态、不消费任何 RNG；`commit` 成功事务才消费战斗 RNG。
4. 每个被实际尝试的节点恰消费一次卡住随机；预检失败与未走到的后段不消费。
5. 数组按路线顺序，映射按穴位 ID ASCII 升序；不得依赖对象插入顺序。
6. 所有比例用整数 bp；所有除法按本节标出的点向下取整。
7. `routeZ3Bp ≥ 0` 且不超过路线理论上限；Z3 的全局钳制仍由 04 执行。
8. 卡住只能减少本次路线贡献；不能因为堆积反而增加本次伤害。
9. 无路线的旧内容迁移为 2 段默认短路线，不允许得到 0 成本满加成。
10. Boss 也按同样流动公式；其抗点穴 / 抗擒拿来自 06 的抵抗与递减，不来自跳过模块。

## 2. 经脉运行的河流模型

### 2.1 概念映射

AR-14 要求“以河流为模型”。这里把它收敛为可测试状态机，不把比喻当医学论断：

| 河流意象 | 运行时对象 | 游戏含义 |
|---|---|---|
| 水源 | 起始气量 `Q0` | 一招启动时可送入路线的气 |
| 支流注水 | 节点增量 `ΔQ` | 每经过一穴继续聚气 |
| 河道宽度 | `capacity` | 节点安全承载与吞吐基准 |
| 河床顺畅 | `flowBp` | 开通、内功与周天带来的基础通行效率 |
| 淤塞 | `stagnationBp` | 受伤、强催、点穴后的临时阻力 |
| 上游积水 | `backlog` | 本次未通过而残留的气量 |
| 涨裂河堤 | `ruptureDamage` | 超过动态阈值后的胀损；大于 0 即封路 |
| 疏浚 | 调息 | 按优先级清迟滞、堆积、胀损和点穴 |

“穴位为节点、经脉段为河道”在数据上表现为：路线的每一个 `RouteStep` 引用一个 `ap_*`，并携带从上一个节点流入该节点的 `segmentCt` 与固有风险 `riskBp`。路线第一个节点也算一段，代表丹田 / 起势至首穴的启动河道。

### 2.2 节点运行时状态

| 字段 | 单位 / 范围 | 初始化 | 更新与清理 |
|---|---|---|---|
| `opened` | bool | 读取 15 的永久开启状态 | 战斗内只读 |
| `water` | 气量整数，≥0 | 0 | 每段写实际通过量；每 tick 清 0 |
| `capacity` | 气量整数，600–2600 | §2.3 公式 | 战斗内通常不变；明确 Buff 可重算 |
| `flowBp` | 3000–10000 bp | §2.4 公式 | 基础值不变，结算时叠迟滞 / 点穴惩罚 |
| `stagnationBp` | 0–9500 bp | 0 或模板伤势 | 卡住 / 堆积增加；调息减少 |
| `backlog` | 气量整数，≥0 | 0 | 未通过量累积；调息与 tick 减少 |
| `ruptureDamage` | 损伤整数，≥0 | 0 | 越阈产生；调息修复；大于 0 封路 |
| `sealLevel` | 0–9 | 0 | 点穴取较高值；解穴 / 调息递减 |

状态必须逐穴保存，而不是只保存“整条经脉堵塞”。这样点中 `ap_shoutaiyin_taiyuan` 只会影响确实经过太渊的招式；另一条绕行路线仍可用。为避免 UI 噪音，运行时可以精确到穴，界面默认聚合到经脉和招式路线。

### 2.3 容量来源与公式

令有效品阶 `g∈[1,12]`、有效层数 `n∈[1,10]`，`Gbp(g)` 是基准 §4 的品阶系数乘 10000，`mpRatioBp = floor(mpMax / 同级STD.mpMax × 10000)` 并钳至 5000–20000。

```text
depthBp = floor(sqrt(clamp(mpRatioBp, 5000, 20000) × 10000))
capBase = 700 + floor(Gbp(g)/50) + 25n
          + 100·allMeridians + 50·smallCycle
          + 100·greatCycle + 100·twelveCycle + 20·turns
capacity = clamp(floor(capBase × depthBp / 10000), 600, 2600)
```

其中 `allMeridians` 表示目标穴所在经脉已通，`turns∈[0,9]`；“小 / 大周天、十二经周流、九转”的完成事实只从 15 读取。不同穴可乘配表 `capacityBp`，默认 10000；敌人模板也只允许通过这一整体比例派生，不逐穴手配 180 次。

容量设计为“内力深度的平方根”而非线性：内力翻倍只给约 `sqrt(2)=1.414` 倍容量，避免后期 `mpMax` 同时放大内攻、续航和路线加成。平方根必须用整数 `isqrt`；禁止浮点。

### 2.4 流畅度来源与阴阳相性

```text
flowBaseBp = 4500 + floor(Gbp(g)/10) + 250n
             + 400·allMeridians + 200·smallCycle
             + 400·greatCycle + 400·twelveCycle + 100·turns
flowBp = clamp(floor(flowBaseBp × affinityBp / 10000), 3000, 10000)
```

| 主运性质 → 路线性质 | 同性阴 / 阴、阳 / 阳 | 调和主运 → 阴 / 阳 | 任意 → 调和 | 阴 ↔ 阳异性 |
|---|---:|---:|---:|---:|
| `affinityBp` | 11000 | 10500 | 10000（调和→调和为11000） | 8800 |

路线性质由其节点所属经脉的多数决定；阴、阳段数相同或含任督 / 奇经混合方案时取 `harmony`。这只是 AR-02 在战斗流动上的投影；`design/05` 的招式 Z5 相性仍独立存在，二者不能合并为一次倍率。

### 2.5 起始气量与逐段注水

```text
Q0 = 120 + floor(Gbp(g)/50) + 10n
ΔQ = 30 + floor(Gbp(g)/500) + 3n
incoming[0] = Q0 + ΔQ
incoming[i] = passed[i-1] + ΔQ
```

每个节点只增加一次 `ΔQ`。因此长路线会逐段积聚更大的潜在气量，但上一段吞吐不足会真实传递到下一段，而不是凭空恢复满额。招式 `mpCost` 仍只按 05 在行动开始支付；`Q0/ΔQ/water` 是内力运转的无量纲战斗单位，不能再次从 `mp` 扣除。

若招式多段命中，整招路线只运行一次并形成同一 `routeZ3Bp`；04 再把 `power/hits` 拆成伤害段。反击、追击、左右互搏里的每一招都是独立路线提交，但同一单位共享当时节点状态，因此连续强催会积累风险。

### 2.6 初始化输入优先级

节点初始化按下列固定顺序合成：

1. 读取 `design/15` 的穴位是否开启、所属经脉性质、通脉 / 周天 / 九转；
2. 读取 `design/05` 当前主运内功的有效品阶、有效层数与 `nature`；
3. 读取 `design/03` 当前 `mpMax` 相对同级 `STD.mpMax` 的比例；
4. 应用敌人模板的整体容量 / 流畅修正；
5. 应用装备与 Buff 的显式 `meridianCapacityBp` / `meridianFlowBp` 修饰；
6. 把开战前伤势投影为初始迟滞，最后钳制；
7. 所有动态值置零；实例持有 battle 流中为本单位预留的子状态 / 游标，不创建第六条全局随机流。

同一字段的多个修饰先按 `(sourceType, sourceId, modifierId)` 排序后加算，再乘算一次并钳制，沿用 03 / tech/05 的确定性约定。没有主运内功时按黄下 1 品、1 重、`harmony` 计算，允许普通攻击短路线，但不得借此获得阴阳同性增益。

### 2.7 非自然节点与未开通路线

- 内容配表不得为了某招新造穴位；只能从 15 的 180 个 `ap_*` 取值。
- 路线不能重复同一穴位，否则环路可无限注水；构建期直接失败。
- 未开通节点令该路线不可选，UI 指向经脉页；不在战斗中临时冲穴。
- 敌人模板可声明“按武学需要开放路线并集”，这是敌人生成输入，不会写入玩家成长状态。
- 召唤物若没有内力设定，使用黄下 1 品 / 1 重短路线模板；纯机关、落石等不走武功伤害的环境事件可不实例化。若环境行动者实际施展武学并计算攻击，则必须实例化。

## 3. 整数公式、卡住与胀损

### 3.1 单节点有效流畅与吞吐

设点穴等级为 `s`，查 §9 的 `sealPenaltyBp[s]`：

```text
effectiveFlowBp = floor(flowBp × max(0, 10000-stagnationBp-sealPenaltyBp[s]) / 10000)
throughput       = floor(capacity × effectiveFlowBp / 10000)
normalPass       = min(incoming, throughput)
```

计算顺序很重要：先从 10000 中合并迟滞与点穴惩罚，再乘基础流畅；若分别连乘，会让两个减益互相稀释。`effectiveFlowBp=0` 时仍完成卡住判定，但可通过量为 0。

### 3.2 卡住概率

```text
loadBp       = ceil(incoming × 10000 / capacity)
overloadBp   = floor(max(0, loadBp-9000) / 4)
jamChanceBp  = clamp(
  riskBp
  + floor((10000-practiceBp)/8)
  + floor(stagnationBp/4)
  + overloadBp
  + 350×sealLevel,
  0, 8500)
jammed       = battleRollBp < jamChanceBp
```

`practiceBp` 是招式熟练投影，基础值来自武学有效层数与招式使用熟练：

```text
practiceBp = clamp(3500 + 500×effLayer + movePracticeBp/4, 3500, 9800)
```

其中 `movePracticeBp` 为 0–10000；图鉴尚未存该字段时取 `200×累计合法使用次数`，上限 10000 **【建议值】**。路线 `riskBp` 是节点固有转折风险，直行 0–150、换脉 200–500、逆行 / 强催 600–1200。每个实际尝试节点按顺序抽一次 `battle` 流，`roll∈[0,9999]` 且 `roll<chance` 即卡住。

### 3.3 卡住、堆积与胀损

```text
passed = jammed ? floor(normalPass × 4000 / 10000) : normalPass
excess = max(0, incoming-passed)
backlog' = backlog + excess
stagnationBp' = clamp(
  stagnationBp + ceil(excess×2500/capacity) + (jammed ? 1000 : 0),
  0, 9500)
ruptureThreshold = floor(capacity × (12000-min(stagnationBp',6000)/2) / 10000)
if backlog' >= ruptureThreshold:
  ruptureDamage' = max(oldDamage, floor(capacity/2)+backlog'-ruptureThreshold)
```

卡住或新生胀损时立即停止后续路线。该节点已实际通过的 40% 不计入“完成段”，因为招式劲路已断；但其气量会进入日志和状态。胀损阈值随迟滞从容量 120% 降到最低 90%，表达淤塞后更易撑坏。`ruptureDamage>0` 的节点在下一次选招预检时直接封路，直至调息修到 0。

### 3.4 每段质量与路线实际加成

仅完整通过的节点产生质量：

```text
fillBp[i]    = min(10000, floor(passed[i]×10000/capacity[i]))
qualityBp[i] = floor(fillBp[i]×effectiveFlowBp[i]/10000)
routeCapBp(n)= floor(1200n/(n+6))
routeZ3Bp    = floor(routeCapBp(routeLength)
                     × ΣqualityBp(completed) / (routeLength×10000))
```

分母始终用**配置总段数**，不是已完成段数。因此在第 4 / 10 段卡住时只拿前三段质量，不能把短残段重新归一化成满加成。所有除法在所示位置向下取整；`routeZ3Bp` 作为一个来源加入 04 的 `ΣdmgUp`。

### 3.5 上限曲线与时间成本

| 段数 n | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 | 12 | 18 | 趋近值 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 上限 bp | 171 | 300 | 400 | 480 | 545 | 600 | 685 | 750 | 800 | 900 | `<1200` |

`routeCap(n+1)>routeCap(n)` 至少验证到 64 段；生产路线硬上限 18 段。实际收益存在递减：2→6 段多 300 bp，6→10 只多 150 bp，10→18 也只多 150 bp。

```text
flowCt = Σ segmentCt[实际尝试段]
effectiveRecovery = MoveDef.recovery + flowCt + 擒拿附加收招
```

`segmentCt` 合法范围 40–120，普通转折建议 60–90，强催 / 逆行 90–120。它直接加到 09 的收招值，不作为另一次行动，也不改变首轮固定排序。若预检已发现未开通 / 胀损 / 9 级点穴，动作不可提交且 `flowCt=0`；若途中卡住，已经尝试的段仍计时。

### 3.6 tick 与自然消退

每次 09 的战斗 tick：所有节点 `water=0`；`backlog=max(0,backlog-1)`，迟滞与胀损不自然消退。该每 tick 的 1 点卸压只是避免极小残量永久滞留，不能代替调息。点穴 / 擒拿的持续与递减由 06 的自身行动计数驱动；模块 `tick` 接收其 `remaining` 投影结果（投影 0 才清除本地镜像，未传则保持），不维护第二个 Buff 时钟。

## 4. 招式路线、路线加成与绝招

### 4.1 路线是招式的扩展，而非新招式

每个造成武功伤害的 `MoveDef` 增加一个 `meridianRouteRef`，引用本文拟登记的路线对象。路线不改变招式的名称、品阶、`power`、范围、命中段数或来源：

```text
SkillDef sk_* ──包含──► MoveDef mv_* ──引用──► MeridianRoute mfr_*
                                  │
                                  └─ ultimate:true 表示绝招
```

同一路线可被同源招式复用，但只有动作、发力方向和内功性质都相近时才允许；不能为了减少数据量把所有掌法指向一条万能路线。纯架势 / 治疗也可有路线，但 `routeZ3Bp` 应投向其效果强度接口，由其归属文档另行定稿；本稿和参考实现只验直接伤害。

### 4.2 普通攻击与武学品阶

`mv_basic_strike` 默认使用 2 段短路线，单段 70 CT，理论上限 300 bp；若没有主运或所需穴位未开，生成器从已开穴中选同侧两个基础节点。普通攻击因此也能从通畅经脉得到小幅增伤，但绝不超过长路线绝招。

招式数量继续服从 `design/05` §3.5，不在本文重写：

| 大阶 | 05 的普通招式总数 | 05 的绝招数 | 路线建议 |
|---|---:|---:|---|
| 黄 | 2–3 | 0 | 2–4 段，单经为主 |
| 玄 | 3–5 | 0–1 | 3–6 段，可有一次换脉 |
| 地 | 4–7 | 1 | 4–9 段，绝招 8–12 段 |
| 天 | 5–10 | 1–2 | 5–12 段，绝招 10–18 段 |

原著有定数的武学仍按 05 例外收全招名；招式栏不变。高阶“多个招式”由现有 `moves[]` 实现，本文只要求每个已上场招式有明确路线。

### 4.3 绝招的路线约束

1. 绝招仍由气势 100、`ultimate:true`、默认收招 1200 与 05 的预算控制。
2. 地 / 天阶第一记绝招路线建议不少于 8 / 10 段；不是硬性伤害保证，支援型绝招可短但须说明。
3. 绝招路线可以跨经脉，换脉节点提高 `riskBp`；长路线的时间与堵塞风险是其高上限的对价。
4. 绝招卡住时仍消耗已支付内力与气势，伤害按完成质量结算；若预检即发现硬封路，则按钮禁用、不扣资源。
5. 05 的绝招 `power` 与本文路线 Z3 分属不同位置，不能把路线加成预先乘回 `power`。

### 4.4 接入 Z0–Z10 的时点

```text
P1 整招快照 / 支付资源
  → MeridianFlow.preview（UI / AI，可选）
  → MeridianFlow.commit（路线注水、卡住、状态写入）
  → 把 routeZ3Bp 放入该招所有直接伤害段的 Z3 来源
  → 04 的 Z0–Z10 逐段伤害
  → 06 附加效果与结算后事件
  → 09 以 MoveDef.recovery + flowCt 扣 CT
```

Z3 来源键建议为 `(sourceType:'meridianRoute', sourceId:routeId)`；与留力、蓄力、战阵、情缘等先加总，再受 04 的 `[-5000,+10000] bp` 钳制。路线卡住不会使整招自动未命中；它降低 `routeZ3Bp`，严重时可能只有原 `power` 的基础伤害。只有预检硬封路才禁止使用。

### 4.5 反击、合击、多段与改招

| 情形 | 路线提交次数 | 规则 |
|---|---:|---|
| 多段 / 范围 | 1 | 同一整招共享一次路线结果，所有伤害段共享 `routeZ3Bp` |
| 反击 / 追击 | 每次触发 1 | 独立提交；会加重同一单位节点状态 |
| 左右互搏 | 两招各 1 | 按 09 定序；第一招状态会影响第二招 |
| 合击 | 每名真实参与者各 1 | 各自实例、各自路线；虚拟阵位无实例 |
| 自动组选式 | 最终解析招式 1 | 先解析 `mv_*` 再取得路线，不能为每个候选消耗 RNG |
| AI 预览多个候选 | 0 | 全部 `preview`；只对最终成功命令 `commit` |
| 招式中途被反应作废 | 0 或回滚 | 与 Core 命令事务同生共灭，不能留下半条堵塞 |

### 4.6 路线合法性与迁移

构建器检查：ID 为拟议 `mfr_*`；节点 1–18 个且不重复；每个 `ap_*` 已由 15 登记；`segmentCt` / `riskBp` 数组等长；CT 40–120；风险 0–1200；招式性质与路线性质冲突必须显式 `allowOpposedNature:true`。

旧存档 / 旧内容没有 `meridianRouteRef` 时：运行时按武学性质与已开穴确定一条 2 段迁移短路，并在下一次内容迁移写回稳定路线引用。迁移不得使用地图的 `route_*` 前缀，也不得根据本地化显示名生成 ID。

## 8. 擒拿 1–9 级（外功）

### 8.1 定义与逐级效果

擒拿严重度使用拟议 `qnl_*` 档案，表示关节、筋骨和姿态受制的程度。它是外功效果：施加主检定以 `apGrapple`、臂力和身法为主，不直接堵塞经脉节点。以下倍率都乘当前有效值并向下取整；收招附加是受擒者下一次行动的 `recovery` 增量。

9 级是硬控，并非可长期维持的数值减益；进入 06 的硬控互斥、坚毅和 Boss 控制递减。1–8 级不是硬控；其中 7–8 级的兵器锁定只禁用需要武器的招式，不会把装备从背包移除。等级 1 明确不降移动，落实作者“酸软”而不把最轻级变成定身。

### 8.2 施加与对抗检定

擒拿类招式必须来自 `subType:grapple` 或显式 `tags:[grapple]`。先按 04 做命中，再按效果命中 / 抵抗；通过后确定基础级：

```text
attackScore = source.apGrapple + floor(source.str/2) + floor(source.agi/4)
defendScore = target.apGrapple + floor(target.str/3) + floor(target.agi/2)
gradeEdge   = clamp(source.effGrade-target.resGrade(cc.bind), -3, 3)
baseLevel   = clamp(move.grappleLevel + floor((attackScore-defendScore)/20)
                    + sign(gradeEdge), 1, 9)
```

这一步没有第二次随机；随机只在 04 的效果命中。普通招式建议 `grappleLevel` 1–4，地阶重招 4–6，绝招 6–8；9 级只允许 8 级状态再次成功升级，或剧情 / Boss 专属条件，避免一击硬锁。

### 8.3 持续、叠加与升级

- 默认持续 2 次受擒者自身行动；精英持续减 1（最低 1），Boss 的 1–8 级持续固定 1。
- 同来源同目标再次成功：若新基础级 > 当前，取新级；否则当前级 +1，上限 9，并刷新持续至两者较大值。
- 不同来源只保留最高级和最长剩余持续，不相加为 18；来源列表只供解除 / 日志追溯。
- 9 级结束后获得 06 的 `bf_jianyi` 对 `cc.bind.hard` 免疫 1 回合；Boss 还走 `ccCount` 递减。
- 目标受单次 `hpMax×8%` 以上伤害时，擒拿降 2 级；施加者倒地、离场或与目标距离超过招式保持距离时立即解除“维持型”擒拿。

### 8.4 挣脱

09 的 `struggle` 行动，收招 800；成功率：

```text
escapeBp = clamp(
  5000 + 40×[(target.str+target.agi)-(source.str+source.apGrapple)]
  + 150×target.mainInnerEffGrade + 500×failedAttempts - 650×level,
  500, 9500)
```

成功完全解除；失败持续不刷新但记 `failedAttempts+1`，所以每次失败提高 5 个百分点。队友对施加者造成位移、眩晕或缴械，也可按招式描述直接解除。内功在此提供抗制与爆发，不把擒拿变成点穴。

### 8.5 与既有控制的兼容映射

| 旧状态 / Buff | 与擒拿关系 | 迁移或并存 |
|---|---|---|
| 麻 `bf_mabi` | 麻是中毒 / 神经性失力，有概率失去行动；擒拿是外力制关节 | 可并存；臂力倍率同池取更不利值，不连乘 |
| 定身 `bf_dingshen` | 只禁移动 / 跳跃；擒拿 1–8 是渐进减益 | 可并存；移动取最严限制 |
| 缠绕 `bf_chanrao` | 语义最接近 | 旧缠绕迁移为擒拿 4 的显示投影；原 Buff 仍由 06 读旧 |
| 缴械 `bf_jiaoxie` | 兵器离手；擒拿 7–9 只令兵器招不可用 | 可并存；擒拿解除不自动拾回兵器 |
| 眩晕 / 昏迷 | 硬控 | 9 级与其进入同一硬控互斥组，不叠加跳过次数 |
| Boss 首领 `bf_shouling` | 受制 / bind 默认免疫 | 普通 Boss 最高只到 6 级数值减益；脚本明确可擒者才允许 7–9，并走递减 |

## 9. 点穴 1–9 级（内功）

### 9.1 节点级效果

点穴严重度使用拟议 `dxl_*` 档案，并必须绑定一个已存在 `ap_*`。它是内功效果：先由招式命中，再以 04 的 `seal`、`effHit` 对 `resSeal`、`effRes` 与抗性品阶判定。成功后节点 `sealLevel=max(old,new)`。

| 级 | 武侠表现 | 流畅惩罚 | 招式耗内附加 | 路线 / 运劲限制 |
|---:|---|---:|---:|---|
| 1 | 气息受阻 | 500 bp | +300 bp | 路线仍可用 |
| 2 | 气行不畅 | 1000 bp | +600 bp | 路线仍可用 |
| 3 | 穴络滞涩 | 1600 bp | +900 bp | 经过该穴的预估标黄 |
| 4 | 经气壅塞 | 2300 bp | +1200 bp | 卡住风险明显上升 |
| 5 | 一脉牵滞 | 3200 bp | +1600 bp | 调息触及数 −1（最低 1） |
| 6 | 真气难续 | 4300 bp | +2000 bp | 不可使用逆催路线 |
| 7 | 数脉受牵 | 5700 bp | +2500 bp | 经过节点的绝招禁用 |
| 8 | 内功受封 | 7500 bp | +3000 bp | 禁内功招 / 护体 / 蓄力；仍可求援解穴 |
| 9 | 经脉迟滞，无法运气 | 10000 bp | — | 经过节点的路线禁用；禁所有运劲和自行调息 |

耗内附加是相对该招原 `mpCost` 的 bp，例如原耗内 1000、5 级点穴经过一个节点，则 `ceil(1000×11600/10000)=1160`；多穴被点只取路线中最高等级对应的耗内附加，不逐穴相乘。若最高为 9，预检直接不可用，不扣内力。

### 9.2 命中穴位与传播

- 招式必须显式给 `targetAcupoint` 或按姿态 / 方向从候选穴列表确定；不能随机命中未登记字符串。
- 同一次招式命中多个穴时，每个穴各走效果命中，但按穴位 ID 排序消费 RNG。
- 1–4 级只影响该节点；5–6 级让同经脉相邻节点各获得 `floor(level/2)×300 bp` 临时迟滞；7–9 级仍不自动封整条经脉，避免一次命中废掉全部招式。
- 路线经过受点节点时按 §3.1 降流畅；没有经过则不受影响。由此产生真实的“封路—换招—换路线”选择。

### 9.3 持续与升级

- 默认持续：1–3 级 2 次目标行动，4–6 级 2 次，7–8 级 1 次，9 级 1 次并进入硬控规则。具体 Buff 回合仍归 06。
- 同穴再次成功：新等级较高则替换；否则等级 +1，上限 9，并刷新至较长持续。
- 不同穴各自保存；全身同时有效点穴节点上限 3。第四个成功时，替换“等级最低→剩余最短→穴位 ID 最小”的节点。
- 9 级与旧 `bf_fengxue` 的跳过行动不能叠加；硬控组只保留一个，结束后触发坚毅。
- Boss：1–6 级作为数值减益正常；7–8 级的禁绝招 / 内功降为对应类别 `flowBp -3000`；9 级走硬控递减，失败时退化为 6 级 1 回合。终局守卷人免疫 9 级硬控但不免疫 1–6 级数值阻流。

### 9.4 解穴的四条路

| 方法 | 条件 | 代价 / 规则 |
|---|---|---|
| 自行冲穴 | 等级 ≤8，未禁运劲 | 用 09 `yunjin:tiaoxi`；每次至多使一个穴位 −1 级 |
| 内功调息 | 有调息档案 | 品阶 + 层数达到阈值时，按 §10 使所触节点 −1 |
| 队友解穴 | 相邻队友有指法 / 擒拿 `seal` 招式 | 沿用 09 `unseal`，收招 900；可一次削品 / 解除 |
| 道具 | 10 登记的合法药物 | 由道具写驱散强度；9 级不得用普通药直接清空 |

解穴成功率沿用 04 的效果体系；用于平衡 / 参考实现的确定式预估为：

```text
releaseBp = clamp(3500 + 250×healerGrade + 100×healerLayer
                  + 20×medical + 10×target.wil + methodBonusBp
                  - 700×sealLevel, 500, 9500)
```

正式提交仍用 battle RNG。9 级禁止“自行调息”，但允许队友解穴、特定道具或剧情效果，保证存在反制。

### 9.5 与旧封穴的兼容映射

| 旧状态 | 本文解释 | 迁移 / 合并规则 |
|---|---|---|
| `bf_fengxue` 点穴（封穴） | 旧版“一回合跳过行动”的总体硬控 | 读档时映射为目标主要路线关键穴 9 级、持续 1；仍保留旧 ID 供 06 迁移 |
| `bf_fengnei` 封内力 | 禁内力类行动 | 映射为一个关键穴 8 级；若来源无穴位，按目标当前主运路线首个未封穴确定 |
| `bf_fengjingmai` 封经脉 | 禁某类 / 某脉招式 | 映射为该经脉中最常用路线节点 7 级；不一次封所有穴 |
| 麻 `bf_mabi` | 力量 / 速度减益及概率跳行动 | 与点穴可并存；点穴不再额外产生麻 |
| 眩晕 / 昏迷 | 其他硬控子类 | 9 级点穴与其互斥，不叠加持续 |

兼容选择贯彻“旧档不变强”：旧一回合 `bf_fengxue` 迁移后仍至多跳过一次；新 1–8 级点穴主要改变路线，不免费追加跳行动。

### 9.6 拟新增 Buff 规格（交 `design/06` 登记）

| 名称 | 类 / 标签 | 核心字段 | 持续 / 解法 | 备注 |
|---|---|---|---|---|
| 穴位受封 | 效果负；`seal.point.node` | `acupointId`、`level:1..9`；效果见 §9.1 | 1–2 次自身行动；调息 / 解穴 / 道具 | 新 `bf_*` ID 由 06 创建 |
| 经气迟滞 | 数值负；`injury.qi.stagnation` | 指向节点，投影 `stagnationBp` | 调息 | 可不设 Buff，直接作为模块状态；由 06 / tech/05 决定 |
| 经脉胀损 | 机制负；`injury.qi.rupture` | 指向节点，`ruptureDamage>0` 即封路 | 调息修至 0 | 战斗结束不自动变永久伤势 |

## 10. 调息

### 10.1 与既有“运功调息”的关系

本文**合并**而不新增行动：仍使用 `design/09` 的 `{t:yunjin, mode:tiaoxi}`，基础收招 1000、基础回内 15% `mpMax`，本行动未移动再 +5%，并施加其既有调息防护。本文在同一事务中追加经脉处理；旧 `meditate` 仍只作为 09 的读档别名。

顺序固定为：动作校验 → 09 的回内 / 防护 → 本文经脉调息 → 写事件 → 扣收招。9 级点穴禁止自行调息时，整个 `yunjin:tiaoxi` 不可用；队友解穴仍可用。调息被打断则命令事务回滚：不回内、不修经脉、不扣完整收招；具体打断窗口与已支付成本沿用 09。

### 10.2 调息档案

每门内功生成一份拟议 `txp_*` 调息档案：

```text
reliefBp = clamp(floor((500 + 100g + 80n) × natureBp / 10000), 500, 2500)
repairUnits = floor((120 + 24g + 18n) × natureBp / 10000)
scope = 默认 3 个节点
natureBp = 调和 10500；其他 10000
```

选择节点的全序是：胀损优先 → 点穴等级高 → 迟滞高 → 堆积高 → 穴位 ID ASCII 小。每个所选节点：

```text
stagnation' = max(0, stagnation-reliefBp)
backlog'    = max(0, backlog-floor(capacity×reliefBp/10000))
rupture'    = max(0, ruptureDamage-repairUnits)
sealLevel'  = sealLevel-1，若 g+n >= sealLevel+6；否则不变
water'      = 0
```

战斗外 `reliefBp` 与 `repairUnits` 均 ×15000 bp 后向下取整；可以连续结算直到状态清空，不占 CT。战后默认至少自动执行一次当前主运档案，然后再决定是否在客栈 / 大地图继续恢复。

### 10.3 不同品阶与性质

| 档 | 示例输入 | `reliefBp` | `repairUnits` | `scope` | 定位 |
|---|---|---:|---:|---:|---|
| 黄下 1 重 | g1 / n1 / 非调和 | 680 | 162 | 1 | 无主运兜底，只能缓解 |
| 玄上 6 重 | g6 / n6 / 非调和 | 1580 | 372 | 2 | 中期常规调息 |
| 地上 8 重 | g9 / n8 / 非调和 | 2040 | 480 | 3 | 能稳定修轻度胀损 |
| 天上 10 重 | g12 / n10 / 调和 | 2500（钳制） | 617 | 3 | 顶级理顺与修复 |

`scope` 是档案字段，不直接由品阶公式推导；默认黄 1、玄 2、地 / 天 3。专精内功可以把 scope 提至 4，但不能提高 2500 bp 上限。

### 10.4 代表内功差异（只引用已有武学）

| 内功 | 品阶 / 性质 | 建议调息特色（原创扩展） | 代价 / 边界 |
|---|---|---|---|
| 易筋经 `sk_yijinjing` | 12 天上 / 调和 | scope 4；修复量 +20%；优先胀损 | 不额外解毒，仍走 09 逼毒 |
| 九阳神功 `sk_jiuyang` | 12 天上 / 阳 | 阳路线迟滞再 −500 bp；修复量 +10% | 对阴路线无额外加成 |
| 九阴真经 `sk_jiuyin` | 12 天上 / 调和 | 每次可额外把一个 1–6 级点穴 −1 | 不绕过 9 级自调息禁用 |
| 北冥神功 `sk_beiming` | 12 天上 / 阴 | backlog 卸除 +30%；scope 3 | 胀损修复不加成 |
| 枯荣禅功 `sk_kurongchangong` | 9 地上 / 调和 | 可选“枯”：清迟滞更快；“荣”：修复更快 | 二选一，不同时获益 |
| 逆转经脉 `sk_nizhuanjingmai` | 7 地下 / 阴 | 可越过一个 7 级封穴节点调息 | 每次自增 1000 bp 迟滞，不能越过 8–9 级 |
| 蛤蟆功 `sk_hama` | 10 天下 / 阳 | 蓄势后一次性卸 backlog +40% | 调息 CT +200，受击打断风险更高 |

这些参数须由后续 05 在各内功数据中登记，本文只给默认接口；未登记的内功使用通用公式。性质特色不能再同时加到 Z5，避免双重奖励。

### 10.5 调息 UI 与可中断性

- 行动按钮沿用“运劲”，展开后显示“调息”；有堵塞时在按钮角标显示最严重状态。
- 确认层只显示预计触及的 1–4 个穴、迟滞下降、胀损修复、解穴概率和收招 1000，不展示公式墙。
- 可被 09 定义的硬控 / 打断打断；预览明确提示“若中断，本次无收益”。
- AI 与玩家看到同一 `previewRegulateBreath` 输出，不允许 AI 偷看未来随机解穴结果。
- 战斗外界面可选“一次调息”或“调至通畅”；后一项是多个确定步骤的批处理，逐步写日志以便中断 / 读档。

## 11. 经脉模拟模块

### 11.1 模块名、职责与实例粒度

生产模块建议名 `MeridianFlowModule`，位于 gameplay core 的 battle 域。职责只有五类：由成长事实初始化节点；预估 / 提交招式路线；接受点穴 / 擒拿；执行调息与 tick；生成 / 恢复确定性快照。它不负责动画、UI、武学解锁、伤害公式或永久冲穴。

每个**可独立行动单位**一个实例：

| 单位类型 | 是否实例化 | 初始化方式 |
|---|:---:|---|
| 玩家主角 | 是 | 角色 15 进度 + 装配内功 + 当前属性 |
| 我方同伴 | 是 | 各自角色进度；不可借主角经脉 |
| 普通敌人 | 是 | 敌人模板 + 当前武学需要的路线并集 |
| 精英 | 是 | 模板 + 精英修正 + 专属弱点 |
| Boss | 是 | 模板 + 阶段修正；仍走相同流动公式 |
| 召唤物 | 按需 | 能独立施展武学则是；纯投影 / 阵位则否 |
| 环境行动者 | 按需 | 会以武学攻击则是；纯地形伤害则否 |

实例所有权键为战斗中的稳定 `unitIndex` / `unitId`；同模板生成的十名敌人也必须有十份动态状态，并持有 battle 流按稳定单位顺序分派的独立子状态 / 游标。任何“敌人共用一个 180 节点数组”的优化均不合法。

### 11.2 实例状态

```text
MeridianFlowRuntime
├─ unitId, kind, rulesProtocol
├─ cultivation: effGrade, effLayer, mpRatioBp, nature, practiceBp
├─ nodes: Map<AcupointId, NodeRuntime>
│  └─ opened, water, capacity, flowBp, stagnationBp, backlog,
│     ruptureDamage, sealLevel
├─ grappleLevel, grappleSource, grappleRemaining
├─ tickNo
└─ battleRngState[4]
```

生产态只需实例化“单位全部可用招式路线节点的并集 + 当前点穴目标”。玩家经脉页仍从 15 的永久数据绘制完整 180 节点；战斗模块缺省节点可按只读基底即时派生。对有 12 条路线、每条 10 穴且 40% 重合的单位，约需 72 个活跃节点，而非总是 180 个。

### 11.3 初始化流程

1. 收集当前装配 / 敌人行动表会用到的 `meridianRouteRef`，展开并去重 `ap_*`；
2. 对玩家 / 同伴读取 15 的永久开通状态；敌人按模板的 `openPolicy` 生成；
3. 以当前有效品阶 / 层数而非真实未压制值计算容量、流畅与熟练；
4. 加入 `mpMax / STD.mpMax`、内功性质、周天 / 九转、装备与 Buff；
5. 由 Core 以 battle 流和稳定 `unitIndex` 派生 / 分派单位子状态；具体算法随 M2-P03 交 tech/05 定稿，禁止简单 `battleSeed+unitIndex` 或新建流名；
6. 节点按穴位 ID 排序，动态状态置零，完成可序列化快照。

敌人 `openPolicy` 三档：`routeOnly` 只开行动表路线并集（普通）；`schoolCore` 再开门派核心脉（精英）；`fullTemplate` 按 Boss 配置开额外脉。它只减少配表量，不改变玩家能否点穴或封路。

### 11.4 每次出手的固定流程

```text
F0 validate move / target / resources / route hard blocks
F1 snapshot attacker stats and route node references
F2 pay move costs inside command transaction
F3 for each route step in listed order:
     inject qi → derive effective flow → draw one jam roll
     → pass / backlog → stagnation → rupture → stop if blocked
F4 aggregate completed qualities → routeZ3Bp
F5 append routeZ3Bp to design/04 Z3 inputs; resolve damage segments
F6 apply 06 effects, point / grapple results and reactions
F7 persist node states; recovery += flowCt; emit trace
F8 commit RNG and state together, or roll everything back
```

预检硬封路发生在 F0，不消费资源 / RNG。途中卡住是合法已提交结果，保留成本、尝试段 CT 与节点伤势。攻击未命中仍已运气，因此 F3 的状态与 CT 不回滚；只有命令本身非法、引擎异常或被 P1 前反应作废时整体回滚。

### 11.5 对外接口语义

| 接口 | 是否改状态 / RNG | 输入 | 输出 / 保证 |
|---|---|---|---|
| `initialize` | 创建 | 单位、成长、装配、模板、种子 | 独立实例；全部派生值已钳制 |
| `preview` | 否 / 否 | 路线、可选安全分位 | 预计 Z3、CT、风险节点；不承诺随机结果 |
| `commit` | 是 / 是 | 路线、命令 token | 唯一 `FlowResult`；事务提交 |
| `applyAcupointSeal` | 是 / 由 04 已消费 | 穴位、等级、来源 | 同穴取高 / 升级，返回变更 |
| `applyGrapple` | 是 / 由 04 已消费 | 等级、来源、持续 | 取高 / 升级，返回行动限制 |
| `regulateBreath` | 是 / 解穴时是 | 调息档案、战内 / 外、来源 | 修复明细；随机只用于解穴 |
| `tick` | 是 / 否 | battleTick、Buff 投影 | 清水量、卸 1 backlog、同步持续 |
| `snapshot` | 否 / 否 | 无 | 规范排序的完整 JSON 值 |
| `restore` | 是 / 否 | 已校验快照 | 原样恢复，包括 RNG；不同单位拒绝 |

`preview` 默认用“不卡住”的安全轨迹展示期望收益，并另外返回每段 `jamChanceBp`、到达概率和最坏封路点。AI 可用这些确定特征算期望值；不得通过反复 preview 偷抽未来 RNG。

### 11.6 Core 与战斗循环挂接

| 上游阶段 | 经脉模块动作 | 下游 |
|---|---|---|
| `createBattle` | 为稳定排序后的每个单位 `initialize` | `BattleState.meridianByUnit` |
| 09 P1 整招快照 | `preview` 供合法性 / UI；命令提交后 `commit` | `DamageInput.z3Sources[]` |
| 04 Z3 | 读 `routeZ3Bp` | 与其他 `dmgUp` 加算、钳制、向下取整 |
| 06 效果结算 | 成功后调用 point / grapple | 更新目标自己的实例 |
| 09 E 段 / CT | 加 `flowCt`，同步 Buff 持续 | 下一次就绪时刻 |
| battle tick | 对所有活动实例按 `unitIndex` 调 `tick` | 可回放状态 |
| 存档 / replay checkpoint | `snapshot` | `GameState` / hash 域 |
| 回滚 | 丢弃候选实例或 `restore` | 命令前状态与 RNG 一致 |

经脉计算必须在伤害 Z3 前完成，但点穴 / 擒拿施加在该次伤害后的 06 阶段，不能反向削弱已经命中的当前招。反击若被触发，使用反击者自己的实例。

### 11.7 确定性细则

1. PRNG 与 tech/05 一致：版本化 `sfc32`，种子经 `splitmix32` 派生，流名仍为 `battle`。
2. 节点卡住是 battle 流的一部分；单位可持有由 Core 分派的独立子状态，但不新开未登记的第六条全局流。Python 参考实现用显式单位种子模拟该边界，生产派生算法由 tech/05 随 M2-P03 定稿。
3. 一段一个 `rollBp = nextU32()%10000`；预检失败、未到达后段、纯数值函数不消费。
4. 多单位同时处理按 `unitIndex`，单实例按路线数组，调息按 §10.2 全序。
5. 所有乘法在除法前使用足够宽整数；TS 推荐 `bigint` 或证明不会越过安全整数。
6. `preview` 必须在调用前后断言 RNG state 与节点 hash 不变。
7. 快照包含 `rulesProtocol`、RNG 四字状态、tick 和节点明细；排序后进入规范 hash。
8. Python fixture 的 `fixtureVersion/rulesProtocol/rngProtocol` 任一变化都要求逐项评审后更新 golden，不能只重录掩盖漂移。

### 11.8 手机端性能预算

经脉模块的热路径只按**实际路线节点**计算，不能每次出手遍历 180 穴。以下为接入 `tech/05` §16 的子预算，属于首轮实现门槛，尚需三档真机验证：

| 场景 | 运算上限 | 时间子预算 | 超限处置 |
|---|---:|---:|---|
| 单次 `commit` | ≤18 节点、≤18 次 RNG、1 次 Z3 汇总 | ≤0.25 ms **【建议值】【待实测】** | 记录 trace；禁止降低规则精度 |
| 单路线 `preview` | ≤18 节点、0 次 RNG | ≤0.15 ms **【建议值】【待实测】** | 复用预分配 scratch |
| 单 AI 的 12 路线候选 | ≤216 节点访问 | ≤2 ms **【建议值】【待实测】** | 超限交 Worker；仍受 tech/05 ≤8 ms 总预测预算 |
| 全场一次 `tick` | ≤全部活动节点 | ≤0.50 ms **【建议值】【待实测】** | 用 dirty set；无状态节点不写回 |
| 快照 | ≤全部活动节点 + 每单位 4 个 RNG 字 | ≤1.50 ms **【建议值】【待实测】** | 仅检查点 / 存档执行，不逐帧执行 |

最坏同屏按 `tech/05` 的 24 个单位估算：完整物化为 `180×24=4,320` 节点；典型每单位 12 条、每条 10 穴、重合 40%，约 `10×12×60%=72` 个活动节点，即 `72×24=1,728`。一轮所有单位各出一招的路线热路径最多 `18×24=432` 节点访问；一次 AI 对 12 招全预览最多 `18×12=216`。因此决定性优化顺序是：

1. 初始化时把路线 `ap_*` 编译成连续整数索引，不在热路径查字符串 Map；
2. `NodeRuntime` 使用结构化数组或紧凑 typed array，静态容量 / 流畅与动态伤势分离；
3. 只物化路线并集和被外部点穴的节点，未触及节点读只读基底；
4. `water` 用本次路线 scratch 保存，只有 backlog / 迟滞 / 胀损 / 点穴变化才标 dirty；
5. `tick` 遍历 dirty set；没有 backlog 的节点不做“减 1”空写；
6. preview 缓存键包含实例 `stateVersion`、路线、有效层数与 Buff 版本；任一提交即失效；
7. 批量 AI 预览在 Worker 运行，但最终命令仍回 Core 重验并提交。

若所有 4,320 节点都必须进快照，按每节点 8 个 32 位槽粗估裸数据 `4,320×8×4=138,240 B`，未计 JSON 键开销；生产存档应用紧凑数组和稀疏节点，JSON 只用于调试 / golden。不得以“性能模式”跳过敌人模块、卡住判定或改用浮点近似，否则同录像会分叉。

### 11.9 敌人模板生成

敌人不逐个手配 180 穴，只填下列少量参数；生成器按 `unitIndex` 与穴位 ID 全序展开。Boss、精英、普通敌人走同一公式，差别只来自参数和 06 控制抗性。

| 参数 | 普通默认 | 精英默认 | Boss 默认 | 作用 |
|---|---:|---:|---:|---|
| `effGrade/effLayer` | 当界主力 −1 / 6 | 当界主力 / 8 | 首领表 / 9 | 容量、流畅、注水 |
| `mpRatioBp` | 9000 | 10500 | 13000 | 以 §2.3 平方根档影响容量 |
| `practiceBp` | 6200 | 7500 | 9000 | 卡住概率 |
| `capacityScaleBp` | 9000 | 10500 | 13000 | 模板个体差异 |
| `innerNature` | 武学主性质 | 武学主性质 | 显式配置 | 阴阳相性 |
| `openPolicy` | `routeOnly` | `schoolCore` | `fullTemplate` | 开穴集合 |
| 周天 / 九转 | 无 | 至多小周天 | 显式里程碑 | 只能使用 15 已有里程碑 |

生成步骤：汇总行动表路线 → 应用 `openPolicy` → 用模板参数派生节点基底 → 套单位固有装备 / Buff → 清零动态量。普通敌人的同 archetype 可以共享**只读基底**，但进入战斗后必须复制动态数组和 RNG 状态；任何写时共享都违反 §1.5。召唤物由召唤定义选模板；武学型环境行动者至少给 `routeOnly`，纯落石 / 火场等非武学事件不创建实例。

### 11.10 异常与降级

- 路线引用未知 / 未开通节点：内容构建失败；运行时拒绝命令，不悄悄缩短路线。
- 快照协议不匹配：拒绝继续战斗并回到兼容检查点；不能丢掉经脉态续跑。
- Worker 超时：采用最近完成的 preview 结果或合法待机；Core 规则不降级。
- UI 动画来不及：缩短 / 跳过动画，但 CT、RNG、伤势照常提交。
- 低内存：丢弃 preview 缓存，保留实例与回放；仍不足则安全中止战斗并保留战前存档。
- 内容尚无路线：仅迁移期挂 2 段默认短路并记录告警；正式发布门禁禁止默认路残留。

### 12.4 存档、录像与 golden

| 载体 | 必存字段 | 不应保存 |
|---|---|---|
| 战斗存档 | 每单位 snapshot、战斗 tick、命令序号、内容 / 规则 / RNG 协议 | UI 展开态、preview 缓存 |

### 12.5 版本迁移

`meridian-route.v1` 的数组顺序、取整点或 RNG 消费规则变化，必须同时提升 `rulesProtocol`，保留旧 runner 重放旧战斗。新增可选展示字段不必提升玩法协议；改变默认路线、调息优先级或点穴阈值则必须提升。存档在战斗外可直接用新规则重新初始化；战斗内只允许由明确迁移器转换，不能混跑。

## 13. AI、UI 与渐进教学

### 13.1 AI 路线效用

AI 仍归 `design/09` 的 Utility AI；本文只提供可确定预览特征。每个合法候选招式计算：

```text
expectedRouteBp = Σ(arriveProb[i] × passProb[i] × qualityBp[i])
                  × routeCapBp(n) / (n×10000²)
ruptureRiskBp   = 10000 - Π(10000-nodeRuptureChanceBp[i]) / 10000^(n-1)
routeUtility    = expectedDamage
                - flowCt×ctValue
                - ruptureRiskBp×ruptureValue/10000
                - pointExposure×sealValue
```

实现可以逐段更新整数到达概率，不得用浮点乘积。`preview` 返回至少：预计 Z3、完整 / 卡住分位 CT、首个硬封节点、各段卡住率、胀损率、调息后可恢复量。AI 不读取未来随机数，也不能通过重复 preview 挑出“下一抽最好”的路线。

### 13.2 选招与调息门槛

| 情况 | 默认行为 | 说明 |
|---|---|---|
| 可击杀且路线风险 <20% | 优先能完成击杀的最短路线 | 不为溢出伤害走长路 |
| 绝招可形成关键击破 | 若效用最高且无硬封则用 | 气势 / 冷却仍由 05 / 09 管 |
| 任一核心路线胀损 | 提高调息权重 | 有其他安全路线时可先出招 |
| 预计胀损率 ≥35% | 非拼死标签时拒绝该路线 | Boss 阶段脚本可放宽到 55% |
| 点穴 ≥7 且命中 2 条以上主路线 | 优先解穴 / 换短路线 | 9 级且禁止自行调息时求援 / 道具 |
| 调息可恢复 ≥2 个关键节点 | 调息效用 +20% **【建议值】** | 避免只为极小 backlog 空耗行动 |
| 擒拿 ≥7 | 优先挣脱或徒手可用招 | 9 级只走被控回合逻辑 |

防抖规则：同一单位连续两次非强制调息后，第三次调息效用 ×5000 bp，直到它完成一次攻击或位移；这只影响 AI 选择，不削弱玩家调息效果。Boss 的阶段脚本可以要求保留绝招，但不能绕开实例状态、封路或 CT。

| 层级 | 默认展示 | 交互展开 | 禁止 |
|---|---|---|---|

| 神雕 | 多路线管理、胀损与反制组合 | 全 1–9、逆催、AI 详细预览 | 无 |

新手默认用“稳 / 衡 / 险”三档替代概率墙；长按才显示 bp 与算式。首次卡住给一次不耗资源的教学回退，仅教学战有效且必须写入规则开关，正式战绝不悄悄回滚。敌人第一次使用 7 级以上控制前给可见意图与解法提示，避免无预警锁死。

### 13.5 可观测事件

Core 至少发出 `route.previewed`（仅诊断、不入玩法 hash）、`route.committed`、`route.jammed`、`node.ruptured`、`point.applied`、`grapple.applied`、`breath.completed`。玩法事件只带整数输入 / 输出、来源 ID 与 command sequence；日志脱敏后用于统计路线选择率、卡住率、调息占比和首次流失点，不反向改变当局概率。

## 14. 完整数值算例

除特别说明，伤害只展示路线对 04 Z3 的增量，`damage=floor(baseDamage×(10000+routeZ3Bp)/10000)`；其他 Z3 来源取 0。算例均由 `meridian_flow_sim.py` 的固定输入或同式手算得到。

### 14.1 短路线：半步崩拳

我方 9 品、8 重、调和内功，2 段路线各 70 CT，节点风险各 100 bp，基础伤害 849。节点平均质量使：

```text
cap = floor(1200×2/(2+6)) = 300 bp
routeZ3Bp = 126 bp
flowCt = 70+70 = 140
damage = floor(849×10126/10000) = 859
```

收益为 `+10`，只多 140 CT；适合补刀、低熟练或已迟滞状态。它验证“普通攻击也吃经脉，但短而稳”，不是零路线攻击。

### 14.2 长路线绝招：十八掌连环

同一我方走 10 段、每段 80 CT、固定无卡住；基础伤害仍用 849 便于对比：

```text
cap = floor(1200×10/(10+6)) = 750 bp
routeZ3Bp = 472 bp
flowCt = 10×80 = 800
damage = floor(849×10472/10000) = 889
```

相对短路再多 30 伤害，却多 660 CT 且暴露十次卡住检查。绝招价值还来自 05 自身的 power / 效果 / 气势兑现；经脉路线不能单独把它变成无条件最优。

### 14.3 熟练与生疏的卡住概率

设某段 `incoming=800`、`capacity=1000`、迟滞 2000 bp、无点穴、固有风险 500 bp：`loadBp=8000`，过载项为 0。

| 使用者 | `practiceBp` | 算式 | 卡住率 |
|---|---:|---|---:|
| 熟练 9 重 | 9000 | `500+(10000-9000)/8+2000/4` | 1125 bp = 11.25% |
| 生疏 3 重 | 5000 | `500+(10000-5000)/8+2000/4` | 1625 bp = 16.25% |

若装载升到 `incoming=1100`，`loadBp=11000`，再加 `(11000-9000)/4=500 bp`，两者变为 16.25% / 21.25%。熟练降低风险但不能抵消过载与旧伤。

### 14.4 第四段卡住并减威

普通敌人走 8 段生疏路线；尺泽预置迟滞 4000 bp、backlog 600，第 4 抽强制为 0。黄金结果：

```text
attempted=4, completed=3, flowCt=4×75=300
cap(8)=685 bp, routeZ3Bp=144 bp
damage=floor(849×10144/10000)=861
尺泽：backlog=1220, stagnation=6534 bp, ruptureDamage=816
```

若错误地只按前三段重新归一化，上限会被当作 400 bp，奖励失败；正确做法始终以配置 8 段作分母，所以卡住仅得 144 bp，并留下胀损。

### 14.5 胀损与调息恢复

强催六段在第 3 段云门遇到预置 `stagnation=6000 bp, backlog=1100` 并卡住：结果为 `attempted=3, completed=2, flowCt=255, routeZ3=105 bp`，云门 `backlog=1708, stagnation=8504 bp, ruptureDamage=1304`，后续路线被封。

12 品 10 重调和档案的单次战斗调息：

```text
relief = min(2500, floor((500+100×12+80×10)×10500/10000)) = 2500 bp
repair = floor((120+24×12+18×10)×10500/10000) = 617
云门 ruptureDamage: 1304→687；stagnation: 8504→6004
本次总计 backlog -252；CT=1000；额外内力成本=0
```

一次尚未修通，第二 / 第三次继续按优先级处理，直到 `ruptureDamage=0` 才可重新过路。战外同档乘 15000 bp，修复更快但不在战斗中免费发生。

### 14.6 九级点穴封路

我方太渊被施加 9 级点穴；10 段长路第 5 段经过太渊。选招预检发现 `sealPenalty=10000 bp`：

```text
attempted=0, completed=0, flowCt=0, routeZ3Bp=0
disabledReason=point_seal_9, blockedAt=4
```

因此不扣招式资源、不抽卡住 RNG；同时 9 级禁止自行调息，须队友解穴、道具或 Buff 自身到期。玩家仍可改用不经过太渊且合法的短路线。

### 14.7 擒拿升级与挣脱

目标先中 4 级，后再中基础 3 级且施加检定优势达到升级条件，严重度只升为 5，不做 `4+3=7`。5 级时移动 / 臂力 / 身法 / 闪避均为原值 60% / 75% / 75% / 75%，下一行动收招 +250；再次命中最高只升一级，避免连段瞬间跳 9。

若现为 6 级，目标臂力 70、身法 65，来源臂力 75、擒拿 70，目标内功有效品阶 8，首次挣脱：

```text
p = clamp(5000 + 40×((70+65)-(75+70)) + 150×8 - 650×6, 500, 9500)
  = clamp(1900, 500, 9500) = 1900 bp
```

失败一次后加 500 bp，下一次为 2400 bp；队友解控和 06 的控制递减另算。对 Boss 先走效果命中与硬控递减，最终 9 级至多映射为短时强控，不能永久无法行动。

### 14.8 四类单位独立实例与伤害

固定种子下，我方、普通、精英、Boss 各自创建模块；其节点 Map 与 RNG 都不是同一对象。显式使用不卡住 roll 的黄金结果为：

| 单位 | 路线 | 路线 Z3 | 基础伤害 | 接入后 | 说明 |
|---|---|---:|---:|---:|---|
| 我方 | 2 段短路 preview | 126 bp | 849 | 859 | preview 后 RNG / 节点不变 |
| 我方 | 10 段长路 commit | 472 bp | 849 | 889 | 只改变我方实例 |
| 普通敌 | 2 段短路 | 158 bp | 849 | 862 | `capacityScale=9000` |
| 精英 | 10 段长路 | 541 bp | 950 | 1001 | 7 品 8 重阴性相合 |
| Boss | 10 段长路 | 401 bp | 2574 | 2677 | 高容量使当前注水填充率更低 |

Boss 路线加成并非必然最高：容量很大但本招注水没有同比增长，填充率较低。这让“高容量更安全”与“更容易打满增益”形成取舍，也防止只堆容量同时获得安全和最高伤害。

### 14.9 TTK 锚点核对

使用 04 当前锚点，行动数一律向上取整：

| 敌人 | HP | 基础伤害 / 团队等价 | 接入前 | 接入后伤害 | 接入后 | 目标 |
|---|---:|---:|---:|---:|---:|---|
| 普通 | 3970 | 849 / 10000 bp | `ceil(3970/849)=5` | 862 | 5 | 3–5 |
| 精英 | 8000 | 950 / 10000 bp | `ceil(8000/950)=9` | 1001 | 8 | 6–10 |
| Boss | 170773 | 2574 / 31000 bp | `ceil(170773×10000/(2574×31000))=22` | 2677 | 21 | 12–25 |

这只是隔离路线加成的回归，不包含卡住、调息消耗行动、点穴与擒拿；这些因素总体会把真实时间拉回而非继续缩短。现有 `damage_sim.py --check` 仍必须 40/40 通过，证明未改 04 旧流水。

## 15. 敏感性、退化策略、成长与 TTK

### 15.1 敏感性方法

`meridian_flow_sim.py` 以固定种子族运行 64 个我方实例，每个最多尝试 18 次 10 段长路；迟滞合计 ≥3000 bp 或任一点胀损就调息。一次只改一个参数 ±20%。`TTK×100` 用 `ceil(3970×100/平均伤害)`，攻击频率是每 1000 CT 可出招次数的 bp 表示，调息占比按“调息行动 / 全部行动”。结果用于方向判断，不替代完整 09 战局模拟。

### 15.2 敏感性结果

| 参数 | −20%：TTK×100 / 频率 / 调息 | 基准 | +20%：TTK×100 / 频率 / 调息 | 解读 |
|---|---|---|---|---|
| 容量 | 449 / 5135 / 2330 | 451 / 5450 / 1192 | 454 / 5469 / 1111 | 低容量更易填满但调息激增；高容量更安全、增益略低 |
| 卡住固有风险 | 451 / 5463 / 1090 | 同上 | 451 / 5446 / 1219 | 主要改变维护频率，不显著改平均伤害 |
| 调息强度 | 451 / 5418 / 1299 | 同上 | 451 / 5465 / 1131 | 强调息减少维护行动，伤害不被直接放大 |
| 路线上限 | 454 / 5450 / 1192 | 同上 | 448 / 5450 / 1192 | 只改变 875 / 881 / 888 平均伤害 |
| 单段 CT | 451 / 5899 / 1192 | 同上 | 451 / 5063 / 1192 | 是出手频率最敏感旋钮，不改单次伤害 |

表内频率和调息均为 bp。容量 −20% 看似 `TTK×100` 略降，是因为较小容量提高填充率，却以调息占比从 11.92% 升至 23.30% 为代价；不能只读单击伤害。调参优先级应是：先把单段 CT 与调息占比稳定，再微调 1200 上限，不要用伤害上限掩盖节奏问题。

### 15.3 退化策略与防刷

| 退化 / 滥用 | 为什么可能最优或令人挫败 | 抑制规则 | 验收指标 |
|---|---|---|---|
| 永远只用短路线 | 低风险、低 CT，可能压过重招 | 短路 cap 仅 300 bp；绝招机制 / 范围仍在 05；敌人防御迫使换招 | 同练度长路在安全状态期望效用应高，但补刀短路应优 |
| 永远只用最长路线 | cap 随长度增，容易误以为越长越好 | 上限递减且 <1200；每段加 CT / RNG / 堆积；18 段硬上限 | 10→18 段 cap 只 +150 bp，CT 至少 +320 |
| 故意卡住刷伤害 | 若失败段被重新归一化会套利 | 分母固定配置总段数；卡住段不计质量；保留 CT 与伤势 | 强制第 4/8 段只得 144 bp，不高于完整短路设计收益 |
| 反复调息拖时 | 可等待 Buff / AI 失误 | 调息 1000 CT、可被打断；不自然回满；AI 连续三次降权；战斗目标可施压 | 正常样本调息占比约 11.92%，长期 >25% 告警 |
| 调息刷内力 | 旧调息本可回内，若再低成本循环 | 本文不另加 mp 收益；完全沿用 09 的回内上限与行动成本 | 净资源 / CT 不得超过 09 原调息 |
| 点穴链控 | 多人轮流封核心穴可永久禁招 | 同穴取高不相加；持续按自身行动；硬控递减；解穴 / 换路 / 道具；Boss 保护 | Boss 不能被 9 级永久维持；至少留一个可回应窗口 |
| 擒拿锁死 Boss | 9 级跳行动可无限控 | 先过 04 / 06 命中与 Boss 递减；同源刷新受限；失败挣脱逐次 +500 bp | 连续控制收益递减，Boss 必有行动窗口 |
| 多次 preview 探 RNG | 若预览消费 / 泄露 roll 可择优 | preview 无副作用且只返回概率；未来 RNG 不可读 | 调用 1 / 100 次后 snapshot 与提交结果一致 |
| 切换招式洗掉淤积 | 若状态挂在招式而非穴位可规避 | backlog / 迟滞挂单位穴位；共享穴位的所有路线都受影响 | 换招经过同穴仍读取同状态 |
| 敌方省略模拟 | 会造成玩家被风险约束而敌人白拿加成 | 每独立武学行动者强制一实例；构建期查漏 | 普通 / 精英 / Boss golden 均有独立输出 |
| 召唤海拖垮性能 | 大量单位 × 180 穴 | 路线并集稀疏化；全场单位上限沿用 09 / tech/05；非武学环境不实例化 | 24 单位最坏预算通过真机门禁 |

额外规则：路线收益只在成功提交的当前招生效，不可预先蓄存到下一招；battle tick 清 `water`；战斗结束清临时堆积，不可故意自伤换永久成长资源。任何奖励“因胀损而变强”的内容都必须另走 05 / 06 预算，本文不提供隐含狂战乘区。

### 15.4 高、中、低武书界与外来压制

经脉实例必须使用 13 / 05 已结算的 `effGrade`、`effLayer`，所以外来压制同时降低容量、流畅、注水、熟练与调息，而不只是伤害面板。

| 书界 | 典型表现 | 玩法重心 | 防失控措施 |
|---|---|---|---|
| 高武 | 天 / 地武学接近真实品阶，长路稳定，多绝招可选 | 选择瓶颈、主动点穴、长短路节奏 | 上限 <12%、CT 与堆积制约连发 |
| 中武 | 外来武学 −2 小品、层上限 9；本界武学较顺 | 换成本界短中路线，靠调息维持外来绝学 | 使用有效值初始化；本地路线给可见替代 |
| 低武 | 外来武学 −4 小品、层上限 8、下限黄下 | 外来绝学仍强但更易堵；本界技法稳定快速 | 不允许永久成长绕过压制；普通敌人仍非高控制墙 |

天书之力若临时抵消压制，应在 Buff 生效 / 失效边界更新派生基底，但不得重置 backlog、迟滞、胀损或点穴。容量变化时保留绝对动态量，再以新容量重算装载；为避免突然超阈，Buff 失效当 tick 只标“临界”，到下一次注水才检查胀损 **【建议值】**。这保持“预告即所得”，也避免 Buff 消失瞬间无动作自爆。

### 15.5 与冲穴、周天、九转的成长衔接

| 15 的永久里程碑 | 本文投影 | 收益性质 | 上限保护 |
|---|---|---|---|
| 穴位开通 | 路线可合法经过该节点 | 解锁选择 | 不直接加 Z3 |
| 经脉全通 | capacity +100，flow +400 bp | 稳定性 | 最终 capacity ≤2600、flow ≤10000 |
| 小周天 | capacity +50，flow +200 bp | 前期维护改善 | 同上 |
| 大周天 | capacity +100，flow +400 bp | 长路稳定 | 同上 |
| 十二经周流 | capacity +100，flow +400 bp | 多路线通用 | 同上 |
| 九转每转 | capacity +20，flow +100 bp | 小步长期成长 | 只计 0–9 转；路线 cap 不变 |

成长只提高“能否稳定接近 cap”，不抬高 `routeCapBp`。因此后期全通九转也至多取得路线自身 <1200 bp 的 Z3，且仍支付 CT；不会把永久成长乘进新的独立乘区。战斗调息只修临时态，不增加开穴、周天或九转进度，防止在安全战反复调息刷成长。

### 15.6 上线观测与回调阈值

首三个书界按敌方档、路线长度、有效品阶分桶观察：完整通过率、卡住率、胀损率、调息行动占比、硬封后可回应率、平均 flow CT、战斗 TTK。若普通战调息占比连续样本 >20%、玩家因无合法路线跳行动 >2%、或路线机制使任一 TTK 档越出 04 区间，先回调 `segmentCt/riskBp/injectBp`；只有全档一致偏差才改全局 1200 常数。所有回调必须重生成 golden 并复跑旧伤害模拟。
