## 0. 结论先行与阅读顺序

1. 一次直接伤害严格按 `Z0 → Z1 → … → Z10 → settle`。Z0 只确定命中、招架、暴击与开关；伤害只在 Z1–Z10 计算一次。
2. C01 定稿：Z1 的实际武学威力只除一次攻方 `P_ref(Ld, tier)`。这样品阶和层数仍有收益，又不会因全程 `G × L(n)` 增长约 6.5 倍而让后期同级战缩成约 1.5 击。
3. 数值核心使用整数万分点：`BP = 10000 = 100%`；每个乘区结束向下取整。概率以整数 bp 比较，资源消耗按 `MPREF` 四舍五入。
4. Z2 是比值型减伤；Z3、Z4 各自先加法合并，Z4 正向减伤上限 75%；Z5 由资质独立乘子与相性/破 X 加算池组成。
5. 直接伤害先扣护体、再扣气血；完全被护体吸收时，不施加 `injury` / `bleed`。DOT 是否绕盾由其 `bypassShield` 决定。
6. 随附模拟器采用解析期望而非蒙特卡洛；十四书界全部节奏检查通过，无已知偏差。

## 1. 符号、单位与整数化

### 1.1 符号表

沿用 `design/03` §12，不为同一概念另起名字。

| 符号 | 含义 | 来源 / 范围 |
|---|---|---|
| `Ld` / `Lr` | 显示等级 / 真实等级 | `design/03`；1–70，伤害只读取 `Ld` |
| `tier` | 当前书界境界 | `HIGH` / `MID` / `LOW` |
| `g_eff` / `layer_eff` | 经外来压制后的有效品阶 / 有效层数 | `design/02`、`design/05` |
| `G(g)` | 品阶系数 | 基准 §4；1.00–3.50 |
| `L(n)` | 层数系数 | `0.5 + 0.1n`，n=1–10，见 `design/05` §3.1 |
| `P_ref(Ld,tier)` / `τ(tier)` | 攻方等级期望威力指数 / 境界系数 | `design/03` §3.5；`τ=1.00/0.80/0.75` |
| `MPREF(Ld)` | 耗内基准 | `STD(Ld).mpMax`，见 `design/03` §3.5 |
| `r_in` | 招式内劲比例 | 0–1；数据字段 `wIn`，`wOut=1-r_in` |
| `ATK_mix` / `DEF_mix` | 按 `r_in` 合成的攻 / 防 | §4.1–§4.2 |
| `P_hit` / `P_parry` / `P_crit` / `P_eff` | 命中 / 招架 / 暴击 / 效果施加概率 | §3 |
| `apFactor` / `A_ap` / `artFactor` | 资质 / 技艺强度系数 | `design/03` §7.4；0.80–1.20 |
| `res_eff` | 经品阶对抗后的有效抗性 | `design/03` §6.3；−50%–75% |
| `Dk` | 完成 Zk 后的非负整数伤害 | `D1`…`D10` |
| `D_hit` | 触发位移的单段 `D10`，尚未扣护体 | C11 撞击基数 |
| `BP` | 万分点 | 10000 bp = 100%，1% = 100 bp |

### 1.2 百分比到 bp

- 配表小数在构建时换算：`bp = roundHalfUp(x × 10000)`；例 `0.1234 → 1234 bp`，`12% → 1200 bp`。内容数据不得把 `12` 同时解释为 12% 与 12 bp。
- PCT 属性以百分点存储时，进乘区先乘 100：`critDmg=154 pp → 15400 bp`。
- 同一加法池先以 bp 求和并钳制，再乘伤害；不同乘区不合并。负项保留符号。
- 运行时不得用显示到小数点后一位的 UI 数值回算；日志和录像保存整数 bp 与各区整数结果。

### 1.3 取整点

非负伤害使用 `mulBp(x,b)=floor(x×b/10000)`。顺序如下：

1. `design/03` 面板属性在属性表的最终边界四舍五入为整数；`MPREF`、招式内力消耗也按非负数四舍五入；正成本最低 1，显式零成本保持 0。
2. `ATK_mix`、穿透后的 `DEF_out/DEF_in`、`DEF_mix` 均向下取整。
3. `D1` 至 `D10` 每个乘区结束各向下取整；一个区内部先合并其加法项。禁止只在结算末尾取整。
4. 护体吸收、气血伤害、吸取、反震、DOT/HOT、环境伤害分别在各自公式末向下取整。
5. 概率运算保留整数 bp；最终乘法后向下取整并钳制 `[0,10000]`。若使用随机数，统一判定 `rng.nextInt(10000) < chanceBp`。

这回答 `tech/01` §8.3 D4 与其待决 P2：玩法核心可只用整数乘除重放每个边界。

### 1.4 快照与顺序

一次攻击开始时快照攻方面板、招式有效品阶/层数和攻方乘区；每段命中前读取守方仍有效的闪避、招架、防御、减伤、抗性和护体。多段导致破盾或触发 Buff 后，后段按最新守方状态结算。完整 P1–P8 事件顺序见 `design/06` §5.3，反应队列见 `design/09` §6.1。

## 2. 总公式与输入契约

对一段直接伤害，先做 Z0，再以命中的分支运行：

```text
D1  = floor(ATK_mix × 1.24 × P_actual / P_ref(Ld_attacker,tier))
D2  = floor(D1 × F_def)
D3  = floor(D2 × clamp(1 + sumZ3, 0.50, 2.00))
D4  = floor(D3 × (1 - clamp(sumZ4, -0.50, 0.75)))
D5  = floor(D4 × A_ap × (1 + clamp(affinity + breakX + synergy, -0.30, 0.50)))
D6  = crit ? floor(D5 × critDmg/100) : D5
F7  = floorBp(F_dir × F_height × F_terrain)
D7  = floor(D6 × F7)
D8  = floor(D7 × (1 + clamp(0.015 × (Ld_attacker-Ld_defender), -0.15, 0.15)))
D9  = parried ? floor(D8 × F_parry) : D8
D10 = floor(D9 × variance), variance ∈ [0.95,1.05]
```

其中 `P_actual = G(g_eff) × L(layer_eff) × move.power × Mod_armed × Mod_special`。`1.24` 是用合法 `STD(L)`、上游敌人模板与基准 §5 节奏校准的全局常数**（原创扩展）**；它不是品阶加成，不因等级或阵营变化。

伤害类型只影响所选攻防与机制标签，不改变区序。`direct` 跑完整管线；`dot` 走 §6.5；`true` 与环境伤害只跑其明确列出的区；`reflect`、`redirect`、`mirror`、`counter` 带来源旗标，防循环规则见 `design/06` §5.3.1。

### 2.1 单段输入与输出契约

`calcDamage` 的最小结算单位是“一名来源对一名目标的一段伤害”，而不是整招。范围招式先由 `design/09` 展开目标，多段招式先按 §7.1 拆分威力，再逐段调用本文管线。这样反震、破盾、击倒与中途移除目标都能发生在正确的段边界。

| 类别 | 必需输入 | 读取时点 | 说明 |
|---|---|---|---|
| 攻方快照 | `Ld`、四项攻防中的攻击侧、资质、判定评级、`critDmg` | 整招 P1 | 后段不因攻方本招自增益追溯改值；明确写“即时读取”的效果例外 |
| 招式快照 | `g_eff`、`layer_eff`、`powerBp`、`wInBp`、伤害标签、判定开关 | 整招 P1 | 外来压制必须在进入 04 前完成；本文不保存绝对品阶的第二份结果 |
| 守方即时值 | 防御、闪避、招架、韧性、Z4、抗性、护体、当前气血/内力 | 每段 P3/P5 | 前段破盾、驱散或倒地会影响后段；已经离场的目标不再接收后段 |
| 几何上下文 | 来源格、目标格、六向朝向、高度差、地形修正 | 每段 P3 | 方位枚举由 09 给出，04 只接受 `front/side/back` 与数值修正 |
| 已决结果 | `hit`、`parried`、`crit`、`varianceBp` | 对应判定后 | 正式结算由 RNG 产生；查询/预览可枚举，不得消耗 RNG |
| 来源旗标 | `direct/dot/reflect/counter/...` 与事件链 ID | 创建伤害段时 | 用于阻断同类递归，并让日志能追溯母事件 |

输出至少包含 `DamageTrace`、`Settlement`、四类判定结果和事件链 ID。未命中仍输出 Z0 结果，但不伪造全零的 Z1–Z10 trace；整招被作废则记录作废原因。命中且实际伤害为 0 与未命中是不同结果，前者仍可触发明确允许的 `onHit`。

## 3. Z0 · 判定 `judge`

### 3.1 概率公式与上下限

采纳 `design/03` §4.2 建议式：

```text
P_hit   = clamp(0.85 + 0.004 × (hit_eff - eva),       0.40, 0.99)
P_parry = clamp(0.12 + 0.004 × (parry - pierce),      0.00, 0.60) × F_dir_parry × targetParryMult
P_crit  = clamp(0.10 + 0.004 × (crit - tough),        0.02, 0.75)
P_eff   = clamp(baseChance × clamp(1+(effHit-effRes)/100,0.3,2.0)
                × (1-res_eff) × extraFactor,          0.00, 1.00)
```

`hit_eff = hit + move.hitMod + heightHit + cover.hit + LOS.hitPenalty`。高差命中每级 ±4 点、封顶 ±12；遮蔽、冠层、烟雾值引用 `design/08` §3、§5.5–§5.6。拿穴等专门强度（例如 `seal`）作为 `extraFactor`，不得同时改 `effHit`。

`resGrade(tag)` 的来源与下限归 `design/03` §6.3，穿透系数归 `design/06` §3.5.0；进入本文效果命中或 DOT 前，必须完整执行以下衔接，不能把原始 `res_X` 直接当 `res_eff`：

```text
Δr = effectGrade - resGrade(tag)
ρ(Δr) = 0                                  , Δr <= 0
ρ(Δr) = min(0.90, 0.15 + 0.15×Δr)          , Δr >= 1
res_eff = res_X                             , res_X <= 0
res_eff = res_X × (1-ρ(Δr))                 , res_X > 0
```

所以 `Δr=1/2/3/4/≥5` 时 `ρ=30%/45%/60%/75%/90%`；负抗性不被高品阶削弱。例：原始抗性 40%、效果品阶 8、`resGrade=5`，则 `Δr=3`、`ρ=60%`、`res_eff=40%×40%=16%`；若基础概率 60% 且 `effHit=effRes`，最终施加率为 `60%×(1-16%)=50.4%`。

### 3.2 开关、乘数与六向方位

| 输入 | 解析 |
|---|---|
| `mustHit` | 命中率置 100%；仍可被明确的整招作废机制拦截 |
| `mustCrit` / `noCrit` | `noCrit` 优先；否则 `mustCrit` 置 100%；普通公式最低 2% |
| `skipParry` 或 `parryable=false` | 招架率置 0，Z9 不生效 |
| `ignoreDef` | Z0 只记旗标，Z2 将有效防御置 0 |
| `asBack` / `asHigh` | Z0 只覆写几何标签；伤害分别到 Z7 的方位 / 高差项 |
| `targetParryMult` | 多来源取最小值，钳制 0–100%；再乘方位招架系数 |

AR-12 六角格下，守方朝向六邻方向之一：攻方位于正后方 1 向为背击、侧后 2 向为侧击、正前与侧前 3 向为正面；格距、远距离射线归类与方向细则由 `design/09` 定义。本文倍率为：正面 `F_dir=1.00/F_dir_parry=1.00`，侧击 `1.10/0.75`，背击 `1.30/0.50`。

### 3.3 判定顺序

每段固定按：

1. 目标合法性、援护与 Z0 开关合并；
2. 命中；失败立即结束该段；
3. 命中后整招反制 / 破招；若作废则伤害 0；
4. 招架；记录结果但不在 Z0 扣伤害；
5. 暴击；记录结果但不在 Z0 乘倍率；
6. Z1–Z10；
7. 结算后，对附加效果逐个做免疫、品阶穿透与 `P_eff`。

因此招架与暴击可以同时发生：先在 Z6 乘暴击，再在 Z9 减免。预测浮窗应枚举 `{未中, 普通, 招架, 暴击, 暴击且招架}`，多段组合算法见 `design/09` §10.4。招架成功时招式 `buffs` 的 `extraFactor=0.50`；完全吸收对伤势/流血的特殊阻断见 §6.2。

### 3.4 Z0 的整数实现

下式是 §3.1 的 bp 等价写法；评级均为整数，`clampInt` 两端都包含。`resEffBp` 允许为负，负抗会放大效果率。

```text
hitBp   = clampInt(8500 + 40×(hitEff-eva),        4000, 9900)
parryBp = clampInt(1200 + 40×(parry-pierce),         0, 6000)
parryBp = floor(parryBp × dirParryBp × targetParryMultBp / 10000²)
critBp  = clampInt(1000 + 40×(crit-tough),         200, 7500)
ratingBp = clampInt(10000 + 100×(effHit-effRes),  3000, 20000)
effBp   = clampInt(floor(baseBp × ratingBp × (10000-resEffBp)
                   × extraFactorBp / 10000³), 0, 10000)
```

开关在公式外按 §3.2 覆盖：`mustHit` 可把 9900 的普通上限改成 10000；`mustCrit` 可把 7500 改成 10000；`noCrit` 最后覆写为 0；`skipParry` 最后覆写为 0。实现不得先把评级差截为正数，否则弱势方的概率下限与负抗收益都会错误。

随机比较统一使用半开区间：产生 `roll∈[0,9999]`，当且仅当 `roll<chanceBp` 成功。0 bp 永不成功，10000 bp 必定成功；这也是录像重放和测试夹具的边界定义。

## 4. Z1–Z10 逐区定义

### 4.1 Z1 · 基础伤害 `base`

```text
ATK_mix = floor(((10000-r_in_bp)×atkOut + r_in_bp×atkIn) / 10000)
P_actual = G(g_eff) × L(layer_eff) × move.power × Mod_armed × Mod_special
P_ref(Ld,tier) = G(gMain(Ld)) × L(lref(Ld)) × τ(tier)
D1 = floor(ATK_mix × 1.24 × P_actual/P_ref)
```

`τ(HIGH/MID/LOW)=1.00/0.80/0.75`。严格执行 C01：分母取攻方显示等级与当前书界境界，且全管线只除一次；不得取实际武学威力作分母。模板敌人按 `design/03` §10.6 直接令 `P_actual=P_ref×tmplPower`；具名 `full` NPC 用真实 `g_eff/layer_eff`。典型 `P_actual/P_ref` 约 0.6–1.5，合法极端由数据校验控制在 0.25–3.0。

内力不足不额外降低威力：能否施放由 `design/05` 的耗内校验决定，内力不足则换普攻；避免在 Z1 对同一资源重复惩罚。

### 4.2 Z2 · 防御减免 `defense`

先按外/内各自穿透，再合成：

```text
DEF_out_eff = floor(defOut × (1-clamp(pierceOut,0,0.60)))
DEF_in_eff  = floor(defIn  × (1-clamp(pierceIn, 0,0.60)))
DEF_mix     = floor((1-r_in)×DEF_out_eff + r_in×DEF_in_eff)
K           = 1.20 × ATK_mix
F_def       = K / (DEF_mix + K)
D2          = floor(D1 × F_def)
```

通用穿透同时加进 `pierceOut` 和 `pierceIn`；同一侧加法合并，上限 60%（`design/06` §11.1）。`ignoreDef` 令 `DEF_mix=0`，故 `F_def=1`；它不与穿透重复获益。典型同级 `F_def≈0.55–0.75`；理论范围 `(0,1]`。

### 4.3 Z3 · 增伤 `dmgUp`

攻方所有适用的“伤害 +X%”先相加：`F3=clamp(1+ΣdmgUp,0.50,2.00)`，再得 `D3=floor(D2×F3)`。加成上限 +100%、减益下限 −50%，采用 `design/06` §11.1。合击、情缘、战阵、天书、招式条件与群攻破阵均明确落此区。典型 0.90–1.35。

`modZone Z3` 的 `filter` 只决定该来源是否进入 `ΣdmgUp`，不新开乘区：`hidden` 仅匹配暗器类攻击，`combo` 仅匹配 09 已成立的合击段，`sword` 仅匹配剑类招式，`sect` 必须携带明确的 `sect_*` 参数并匹配该武学归属。武学类别与门派归属分别引用 `design/05`、`design/17`，不得用显示名或武器外观猜测。多个通过过滤的来源仍在 Z3 加算并受同一上下限。

### 4.4 Z4 · 减伤 `dmgDown`

守方所有适用的“受到伤害 −X%”加法合并：

```text
R4 = clamp(ΣdmgDown, -0.50, 0.75)
D4 = floor(D3 × (1-R4))
```

正值减伤硬上限 75%，负值是易伤，最低 −50% 即最多承受 ×1.50。按伤害标签筛选的减伤只在匹配时进入本池。典型 `R4=0–0.30`。

### 4.5 Z5 · 资质与相性 `affinity`

```text
apFactor(ap) = 0.80 + 0.004×ap
A_ap = (1-r_in)×apFactor(ap_cat) + r_in×apFactor(apInner)
F_aff = 1 + clamp(natureAdd + breakAdd + synergyAdd, -0.30, 0.50)
D5 = floor(D4×A_ap×F_aff)
```

杂学主动以 `artFactor=0.80+0.004×value` 替代 `A_ap`；音功按 `apInner`，详见 `design/03` §7.4。`A_ap` 范围 0.80–1.20。

内力性质完全采纳 AR-02 与 `design/05` §5.3：阳主运对阳/阴招 `+12%/−12%`，阴主运相反；调和主运对阳/阴 `+6%`、调和 `+12%`、中性 `+2%`；无主运为 0。三运同源的同性质招式另 +4%。

“破 X”匹配、品阶对抗和 `poBonus(g,n)` 取 `design/05` §9.4；只取生效来源中的最高 `breakAdd`，不叠加，加入本区加算池。其破招架效果则在 Z0 乘 `targetParryMult`，不在 Z5 重复。典型 Z5 总倍率 0.70–1.45，硬边界由上式为 0.56–1.80。

### 4.6 Z6 · 暴击 `crit`

暴击时 `D6=floor(D5×critDmg/100)`，否则 `D6=D5`。`critDmg` 已由 `design/03` 钳制 120–300 pp；`tough` 只抵消 Z0 暴击率，不二次削减暴击伤害。`mustCrit` 仍受 `noCrit` 克制。典型暴击倍率 1.50–1.70。

### 4.7 Z7 · 方位与地形 `position`

```text
F_dirBase = 正面 1.00 / 侧击 1.10 / 背击 1.30
F_dir     = F_dirBase + ΣdirectionAdd
F_height  = 1 + heightAdd
F_terrain = 1 + clamp(attacker.dealt + defender.taken + cover.dmg, -0.30, 0.30)
F7 = floorBp(F_dir×F_height×F_terrain)
D7 = floor(D6×F7)
```

`directionAdd` 是“方位系数 +X”的 Z7 加法池：先由几何确定 `F_dirBase`，再加总所有适用项；例如侧击受金蛇秘笈 `+0.05` 得 `F_dir=1.15`，终卷破绽方位 `+0.15` 也在此处相加。它不是 Z3 增伤，也不分别相乘。`floorBp(a×b×c)` 表示三个 bp 系数先精确相乘，再向下取整回 bp；先合成唯一 `F7`，再只在 Z7 的伤害边界取整一次。近身每级高差 ±5%，封顶 ±10%；远程/投射每级 ±4%，高处封顶 +16%、低处封底 −12%，采纳 `design/08` §5.5。三项彼此相乘；整体安全钳制 0.50–2.00。`asBack` 令方向视为背击；`asHigh` 缺省视为攻方高 1 级，若效果明确给级数则取其值。

战斗为六角格、六向朝向。本文只定义倍率；方位解析与范围模板格集合归 `design/09`。范围、多段、溅射中的每个目标都按“该伤害段来源格 → 该目标朝向”独立计算 Z7。

### 4.8 Z8 · 境界差 `realmGap`

```text
gapAdd = clamp(0.015 × (Ld_attacker-Ld_defender), -0.15, +0.15)
D8 = floor(D7 × (1+gapAdd))
```

每级 ±1.5%，封顶 ±15%；读取双方显示等级，含 `design/02` 明确标记的超限 Boss 自身显示等级。属性评级已含对称等级项，Z8 是唯一额外等级压制。此函数也供 DOT 使用。

### 4.9 Z9 · 招架 `parry`

普通攻击被招架：`D9=floor(D8×0.50)`；绝招被招架：`D9=floor(D8×0.75)`，即采纳 `design/05` §4.8 的“招架减免减半”。未招架则 `D9=D8`。`skipParry`、不可招架或整招被破不可再进本分支。

### 4.10 Z10 · 浮动 `variance`

`varianceBp` 均匀取整数 `[9500,10500]`，`D10=floor(D9×varianceBp/10000)`。期望分析固定 10000 bp；实际战斗只从 `battle` RNG 流取一次。多段每段独立取值；回放记录随机结果而非浮点数。

## 5. Z0 期望值与预测

单段命中后的条件期望为：

```text
E[D | hit] = Σ(parry∈{0,1}, crit∈{0,1}) P(parry)P(crit) × D10(parry,crit,variance=1)
E[D]       = P_hit × E[D | hit]
```

招架与暴击使用独立随机掷骰；所有改变判定的钩子在对应掷骰前解析。展示最小/最大伤害时以 Z10 0.95/1.05 分别计算，不把“未命中=0”混进伤害区间；命中率另列。多段击倒概率应枚举各段结果，不能用总威力一次掷骰近似。

## 6. 伤害后结算

### 6.1 结算总序

一次命中段按 `design/06` §5.3 的 P5–P8：

1. 无敌、挪移、伤害上限等 `onBeforeHurt` 机制；
2. 护体吸收；
3. 以气御伤等资源代扣；
4. 扣气血；
5. 气血 ≤0 时走锁血、诈死、复活、倒地；
6. 以**实际气血伤害**触发吸血、伤害型吸内、反震；
7. 判定附加效果；
8. 该段结束；一招最后一段后再处理缺省“每招一次”的 `buffs`，全招后才进入连击、位移和反应队列。

### 6.2 护体、气血与附加效果

```text
shieldBlocked   = min(shield, D10)
shieldSpent     = min(shield, floor(D10×shieldDmgMult))
postShield      = D10-shieldBlocked
uncappedHpDamage = postShield
hpDamage        = min(hp, uncappedHpDamage)
overkill        = uncappedHpDamage-hpDamage
shield'         = shield-shieldSpent
hp'             = hp-hpDamage
```

护体不改变“命中/暴击/招架成功”事件，但若 `hpDamage=0`，本次攻击附带的 `injury`、`bleed` 不施加；其他标签仍按各自规则判定。若仅部分穿盾，伤势/流血可施加且其概率不按穿盾比例缩放。`shieldDmgMult≥1.00` 只放大对护体资源的消耗；`shieldBlocked` 始终只取原 `D10` 能被当前护体挡下的部分，因此破盾倍率不能放大穿透后的气血伤害。普通攻击 `shieldDmgMult=1.00` 时，`shieldBlocked=shieldSpent`。

护体之后若有 `mpGuard{pct,ratio}`，取最高优先级的一项：`guardWant=floor(postShield×clamp(pct,0,1))`，`mpSpent=min(mp,ceil(guardWant/ratio))`，`guardedHp=min(guardWant,floor(mpSpent×ratio))`，`uncappedHpDamage=postShield-guardedHp`，最终 `hpDamage=min(hp,uncappedHpDamage)`、`overkill=uncappedHpDamage-hpDamage`。`ratio` 表示每 1 内力抵消的气血伤害；“以气御伤”固定 `ratio=2`，玄/地/天阶 `pct=25%/30%/35%`，内力不足部分照扣气血（见 `design/06` §8.4）。

### 6.3 吸血、吸内与反震

- 吸血：`healSelf=floor(hpDamage×drainHp)`，多来源合计上限 25%，再受自身缺失气血上限；只认实际气血伤害，不认护体伤害、过量伤害、DOT 或反震，除非条目明确。
- 伤害型吸内：`mpDrain=min(target.mp,floor(hpDamage×drainMp))`。北冥/吸星/化功的特殊基数、去向、Boss 系数以 `design/06` §8.3 为准，不用本通式覆盖。
- 反震：`D_reflect=floor(hpDamage×reflectPct×(1-attackerZ4))`，合计上限 40%；不可闪避、招架、暴击，不过 Z1/Z2/Z3/Z5–Z10，但计原攻击者对 `reflect` 的 Z4。带 `reflected`，不能再反震，也不触发吸血、吸内、连击、反击。
- P7 触发器按 `priority`、再按实例 ID 稳定排序；资源恢复钳制上限。

### 6.4 治疗与护盾

```text
healRaw    = base × healPower/100 × target.healRecv/100
healActual = min(target.hpMax-target.hp, floor(healRaw))
shieldRaw  = floor(healRaw × 1.20)
shield'    = min(shieldMax, shield+shieldRaw)
```

`base` 由招式的 `targetHpMax×pct` 或 `casterMpMax×pct` 给出。直接治疗在施放时读取施治者当前 `healPower` 与目标当前 `healRecv`；HOT 在施加时快照施治者 `healPower`，每跳读取持有者当前 `healRecv`。标准单体治疗为目标 `hpMax×18%`，护盾以治疗量 ×1.2 等价，引用 `design/05` §4.2。治疗不能暴击，除非招式明确新增机制；过量治疗不转护体。护盾叠加与 `shieldMax≤50% hpMax` 见 `design/03`、`design/06`。

### 6.5 DOT / HOT

DOT 不走 Z0–Z10，不命中、不招架、不暴击、不浮动：

```text
raw     = Buff 条目的快照表达式
resPart = 1-clamp(res_eff(tag),-0.50,0.75)
z4Part  = 1-clamp(0.5×Z4_general + Z4_dot,-0.50,0.75)
dot     = floor(raw×resPart×z4Part×Z8(snapshot.Ld,holder.Ld)×bossF)
bossF   = 比例型伤害：普通 1.00 / 精英 0.50 / Boss 0.25 / 守卷人 0.15
```

同一持有者每自身行动 DOT 合计 ≤12% `hpMax`，按 `design/06` §5.3.2 的 priority 从后向前削减。`bypassShield:true` 直接扣气血；毒、蛊、内伤、寒毒通常如此，流血和灼烧通常先扣护体。战斗内默认可致死，战斗外最低留 1 气血。HOT 走 §6.4，合计 ≤8% `hpMax`；自身内功被动的施治系数为 1。

### 6.6 结算事件的数值口径

一次命中必须区分以下数量，禁止把 UI 上的“伤害数字”反推为机制输入：

| 字段 | 定义 | 主要使用者 |
|---|---|---|
| `incoming` | Z10 后、任何资源吸收前的本段伤害 | 撞击的 `D_hit`、伤害上限前的调试日志 |
| `shieldBlocked` | 当前护体从 `incoming` 中实际挡住的伤害；不受破盾倍率放大 | 伤害守恒、双色飘字 |
| `shieldSpent` | 本段实际扣除的护体资源 | 破盾触发、护体条表现 |
| `guardedHp` | 护体之后由内力等资源抵消的气血伤害 | 以气御伤表现与资源守恒 |
| `uncappedHpDamage` | 资源吸收后、当前气血/锁血/阶段门截断前的伤害 | 伤害守恒、过量伤害计算 |
| `hpDamage` | 钳制到目标现有气血后的实际损失 | 吸血、伤害型吸内、反震、受伤阈值 |
| `overkill` | `max(0, postGuard-target.hp)` | 仅统计/演出；不得增加吸血、反震或击杀次数 |
| `displayDamage` | UI 组合数字，可拆为护体/气血两色 | 纯表现，不得返回核心参与后续结算 |

资源守恒断言为 `incoming = min(incoming,shieldBefore) + guardedHp + uncappedHpDamage`；`shieldDmgMult` 只改变 `shieldSpent`，所以护体资源可能比第一项消耗得更快，但不能改变 `postShield=max(0,incoming-shieldBefore)`。气血锁定、剧情阶段门会再把 `uncappedHpDamage` 截为 `hpDamage`，被截掉的部分视同 `overkill`，不参与 P7。

无敌、转移和单击伤害上限可能在 Z10 与资源吸收之间先改写本目标待结算量。实现层可把该中间值命名为 `settledIncoming`，并以 `settledIncoming = shieldBlocked + guardedHp + uncappedHpDamage` 做内部守恒；它是 `tech/05` core 内部派生量，**不加入**本文公共 `Settlement`。被归零、转出或截下的份额必须另记 `prevented/redirected/capped` trace，跨包若要公开该字段须先修改本文接口契约。没有这些机制时 `settledIncoming=incoming`，上式退化为前述公共守恒断言。

同一段产生的事件按 `DamageResolved → ShieldChanged/MPChanged/HPChanged → Downed/PhaseGate → Drain/Reflect → EffectApplied` 稳定发出；没有变化的资源事件可省略，但 `DamageResolved` 必须保留。事件命名由 tech/05 最终落地，语义顺序不得改变。

## 7. 特殊伤害情形

### 7.1 多段、溅射、连锁与区域持续

| 情形 | 规则 |
|---|---|
| 多段 | `hits=N` 时将整数 `powerBp` 商与余数稳定分配：前 `powerBp mod N` 段各多 1 bp；每段独立 Z0、Z1–Z10、护体与 P7；总威力守恒，但总伤因逐段取整可能略低。招式 `buffs` 缺省最后一段后每目标判一次 |
| 溅射 | 主目标全额；其他格按 `splashMult` 生成独立伤害段，各自读取距离、方位、高差、地形与守方属性 |
| 连锁 | 每跳是独立目标段；若条目给衰减，第 k 跳把衰减乘入 `Mod_special`；已命中过的单位能否再次命中由招式定义 |
| 区域持续 | 入格 / 停留触发的 Buff 按 `design/06` DOT；直接爆发区才跑完整管线 |
| 六角范围 | 命中格数、环/面/60°或120°扇形由 `design/09` 的六角范围模板返回；04 不重算格集合 |

范围每个目标独立命中、招架、暴击；同一个范围招式只消费一次行动和招式资源。友伤规则引用 `design/05`。

### 7.2 反击、连击、追击与合击

- 通用反击 `Mod_special=0.50`，连击追加段 `=0.50`，追击 `=0.40`；特殊 Buff/招式按 `design/09` §6 标注值。它们都重新走完整攻击管线，但带相应旗标且不能递归触发同类反应。
- 连击沿用原攻击快照，单段、不再耗内，Buff 施加率 ×0.5；被招架的末段不能触发。
- 合击的两段分别结算完整管线；两段各自 Z3 加 `10%+5%×(羁绊等级-bond.min)`，封顶 +25%，情缘另 +10%；段 1 命中则段 2 `mustHit`。行动、集气与反应限制引用 `design/09` §6.7。
- 战阵单位被格数 ≥3 的范围命中时，群攻破阵 ×1.5 落 Z3；战阵人数输出 `Z3 += 0.1n-0.5`，引用 `design/09` §9.3。

### 7.3 绝招、代价型武学与外来压制

- 绝招仍走同一管线；通常 `move.power=3.00`，第 10 重强化直接乘入 Z1 招式倍率；被招架时只减伤 25%（Z9 ×0.75）。气势、耗内、霸体与收招见 `design/05` §4.8、`design/09` §5.9。
- `hpCost` 在 Z0 前按 `floor(self.hpMax×hpCost)` 扣除，不能被护体、减伤、吸血或反震改写；不足支付时不可施放。若条目标 `canDownSelf` 才可付至 0，否则至少保留 1。未命中也不退款；明确的 `refundHpCostOnKill` 在全招击杀后执行。七伤等以 Buff 表示的长期代价引用 `design/05` §9.1，不重复扣 `hpCost`。
- 外来武学先由 `design/02` 求 `g_eff/layer_eff`，再进入 `P_actual`。例：天上 10 重外来武学进入低武，普通压制 −4、层数上限 8，成为地中 8 重：`P_actual=G(8)×L(8)=2.20×1.30=2.86`；只与低武 `P_ref` 比较一次。

### 7.4 环境伤害

| 类型 | 公式与结算 |
|---|---|
| 撞击 | C11：撞墙单位 `floor(0.20×D_hit)`，被撞单位 `floor(0.10×D_hit)`；每次位移至多一次，不重跑 Z0–Z10、不触发反击/再次击退，正常扣护体；无伤位移基数为 0 |
| 坠落 | 完整公式归 `design/08` §5.3：`floor(hpMax×fallPct×landMul×qgMul×pctFactor)`；不跑 Z0–Z10，先扣护体，不触发反震/吸血 |
| 火势 | 环境火施加 `bf_zhuoshao`，后续按 DOT；品阶、蔓延、天气、油渍与六角相邻格由 `design/08` §7.5 定义 |
| 溺水/流沙 | `design/06`/`08` 的比例型 DOT，通常绕盾，仍受普通/精英/Boss/守卷人系数 |

同次位移若发生坠落，不再额外结算落地撞击；免疫击退则既不移动也无撞击。

### 7.5 群体、批次与同时结算

范围模板返回的是六角格集合，不是额外伤害倍率。`aoe_*` 的格集合、最大可命中六角格数 `Nmax` 与范围系数 `AF(Nmax)` 的唯一公式均归 `design/09` §5.3.3；`design/05` 只消费 `AF` 做招式预算，本文对每个合法目标只运行其应有的独立伤害段。

普通范围伤害按 `target.unitIndex` 升序逐个结算；同一目标的多段再按 `segmentIndex` 升序。前一目标触发的光环消失、施法者倒地或战场机关改变，可影响后一目标，这属于顺序结算。只有招式显式标记 `simultaneous` 时，才先快照全部目标的 Z0–Z10 与资源前值，再统一应用结果。

`simultaneous` 仍按稳定顺序派发事件和判断胜负，但同批目标互不读取批内先前结果。共享护体、代伤者内力、复活次数等批内稀缺资源先建立 reservation ledger，再按目标 `unitIndex` 升序预留；同一目标内按 `segmentIndex` 升序。已被前项预留的份额不能被后项重复消费，统一应用阶段只兑现预留结果。若同批双方同时归零，胜负规则交 `design/09`。批内反震在原批应用完后排入反应队列，不能中途取消尚未落下的同批伤害。

`dealDamage` 且 `dmgType:true` 的规则伤害不伪装成普通招式：其 `amount` 是已确定的真实伤害原始量，不跑 Z0–Z10，因此不进入 Z8；是否绕护体、能否致死及单次上限只读条目的 `bypassShield`、`canKill` 和明确 cap。故 `sqj_12`“恩仇了断”按 `design/13` §7.8 的 30% 回账与本卷气血 8% 上限取值后直接进入结算，不再因双方显示等级差缩放。

溅射、连锁、地面持续区不默认拥有 `simultaneous`。连锁必须逐跳结算，因为前跳击倒、位移或生成的新目标会决定下一跳是否合法；地面持续区按触发者行动与 06 的 S/A/E 段顺序处理。

## 8. 完整算例

以下均使用 10000 bp、各区向下取整；未特别说明时 Z3/Z4/相性/地形为空、Z10 固定 1.00，数据由 `tools/balance/damage_sim.py` 同模型核算。为展示单个分支，例 1–5 均假定已命中，且仅在例 5 强制暴击。

### 8.1 同级普通战：Lv35 主角打天龙普通敌人

`ATK_mix=floor(0.65×1095+0.35×939)=1040`，`DEF_mix=floor(0.65×633+0.35×561)=607`；`P_actual=P_ref=2.88`。Z0：命中 99.0%、招架 13.6%、暴击 17.2%。

| 边界 | 算式 | 结果 |
|---|---|---:|
| Z1 | `floor(1040×1.24×2.88/2.88)` | 1289 |
| Z2 | `floor(1289×(1.2×1040)/(607+1.2×1040))` | 867 |

### 9.4 报表解读与敏感性

校准时按以下顺序定位偏差，避免为了一个具名战扭曲全管线：

1. 所有等级、类型同向偏离：检查 `DAMAGE_SCALE_BP=12400` 与 03 的攻血成长比。
2. 只在高防目标偏离：检查 Z2 的 `DEFENSE_K_BP=12000` 与防御模板，不先改 Z1。
3. 只在某境界偏离：检查 `τ`、有效品阶/层数和该境界的遭遇系数。
4. 只在普通/精英/Boss 一类偏离：检查该模板耐久与队伍折算。
5. 只在具名 Boss 偏离：写入具名遭遇覆盖并登记理由，不回写全局角色属性。

表格显示到一位小数，`--check` 使用未格式化的内部值，所以显示 10.0 的精英行仍可能非常接近但不超过 10。修改公式或上游数值后必须先看失败的原始范围，再重新生成整张表；不得手工把显示值改进目标区间。
