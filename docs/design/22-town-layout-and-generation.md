## 0. 结论先行：一张城不是一张图

城镇采用“历史平面图约束下的确定性程序生成”，不再让图像模型一次生成整张不可拆城图。美术只生产无缝地表、河岸 / 墙体部件与透明建筑单体；代码从手写城市规格生成坐标、通行与遮挡，再合成可行走的斜 45° 2.5D 场景。

### 0.1 五步管线与文件契约

| 步 | 责任 | 输入 | 输出 | 主要消费方 |
|---:|---|---|---|---|
| 1 城市规格 | 关卡 / 考据手写历史骨架 | `design/19` 城市事实、历史平面图、本文建筑目录 | `docs/design/town/city_<city>__<chNN>.yaml`（`CitySpec`） | TOWN-render |
| 2 生成布局 | 固定版本算法与种子求解 | `CitySpec`、`schema.yaml`、建筑占地目录 | `generated/town/layout_<city>__<chNN>.yaml`（`TownLayout`） | 校验、渲染、玩法导入 |
| 3 贴片底图 | 栅格化地面 / 道路 / 水 / 岸 / 桥 | `TownLayout.ground_cells`、TOWN-tiles 图集 | `generated/town/<city>__<chNN>/ground.webp`、分层 PNG 与索引图 | 合成器、`tech/02` 区域构网 |
| 4 贴建筑 | 依实例锚点与深度序合成 | `TownLayout.buildings`、TOWN-buildings 透明 PNG / GLB | `buildings.webp`、碰撞 / 遮挡数据 | 预览、运行时 |
| 5 输出 | 打包、检查并提供审阅层 | 前四步产物、风格 manifest | `preview.png`、`debug.svg`、`walk-layer.json`、运行时 `RegionMap` 派生物 | TOWN-assemble、`tech/04/06` |

`generated/` 是后续工具默认输出名，不要求本任务建目录。任何预览 PNG 都是数据的派生物；修改城市必须先改 `CitySpec`，再重跑生成，禁止在成图上手修坐标而不回写源。

### 0.2 两个首批场景

| 城市 | 规划切片 | 运行时分片核算 | 视觉 / 密度结论 | 规格源 |
|---|---:|---:|---|---|
| 大理国都（羊苴咩城） | `96×96 m` | 六角轴框 `131×96`；按 q 分 2 个标准街区场景，18 个本地 chunk 容量位 | 土面 / 草地多，低密院落、本地植物与佛教元素多；不做满铺青砖 | `town/city_dali__ch01.yaml` |
| 临安府（行在） | `160×160 m` | 六角轴框 `219×160`；按 q×r 分 3×2 个标准街区场景，54 个本地 chunk 容量位 | 南端皇城、御街、河渠桥市；商铺与摊位显著更密，体现繁华 | `town/city_hangzhou__ch02.yaml` |

两城尺寸是离线**规划切片**，不是 `design/11` 的六角轴槽场景，也不是历史城垣的一比一复原。规划方格不能按 `96÷32` 冒充运行时 chunk；§1.3 先转六角，再按 32×32 `(q,r)` chunk 和 `≤96²/≤160²` 轴槽上限拆成街区场景。正式 `sc_*` 由 `design/11` 登记，本文只输出局部分片键，避免越权新造玩法 ID。

### 0.3 与既有系统的边界

- 全国地图仍是不可行走导航层；本文从 `city_* + chNN` 进入一座可行走城镇，符合 `design/11` §0.1 与 `design/19` §10.4。
- `CitySpec` 只决定物理布局候选；城是否开放、NPC / 势力 / 营生当前状态仍由时代层和章节数据决定。
- 本文的 1 m **正方规划格**服务道路宽度、矩形建筑占地与 64×32 拼贴；运行时战斗 / 探索规则仍使用 `tech/02` 的 pointy-top `HexCoord`。转换只从米制掩膜采样六角中心，不建立第二套玩法坐标。
- 建筑 PNG 是 45° 合成资产；需四向旋转或精确遮挡的主体仍以 `tech/07` §5.5.2 的 GLB 套件为权威运行时形式。两者使用同一占地、锚点与资产 ID。

## 1. 网格、坐标与画幅

### 1.1 规划格与边界

`grid.width × grid.height` 个 1 m 正方格使用**规划坐标**：原点为西南角，`+x_p` 向东、`+z_p` 向北。上游 `tech/02` 世界坐标则是 `+x_w` 向东、`+z_w` 向南，故不可直接传值；以规划切片西北角为世界原点，顶点转换为 `x_w=x_p, z_w=H-z_p`。格 `[x,z]` 指规划半开区域 `[x,x+1)×[z,z+1)`；矩形同样 `min` 含、`max` 不含。

墙多边形以格点表示，最后一点自动连回首点。生成器用“格中心在多边形内或边界上”决定城内格；城门净宽、道路和建筑碰撞均在规划格求解。数组仍按规划 `z_p` 后 `x_p` 的行主序：`index=z_p×width+x_p`。格中心 `(x+0.5,z+0.5)` 映射为 `(x_w,z_w)=(x+0.5,H-z-0.5)`；入口格与任意采样点用同式，顶点则不加 `0.5`。

### 1.2 64×32 菱形与 `tech/02` §1.6

基础贴片为透明边界内的 `64×32 px` 菱形，即每个 1 m 轴步投影为：

```text
x_p 向东一步：(+32,+16) px
z_p 向北一步：(+32,-16) px
地面锚点：diamond center；贴片透明画布 64×32 px
```

代入 `tech/02` §1.6 的世界轴（`+z_w` 向南），并取 `k=32√2≈45.2548 CSS px/m`，可得上述规划步长。含高度的屏幕变换必须先做 `z_w=H-z_p`，再沿用上游公式：

```text
px = cx + k·(x_w-z_w)·√2/2
py = cy + k·((x_w+z_w)·√2/4-y·√3/2)
```

因此无裁切地面菱形的理论包围框为：

- 大理：宽 `(96+96)×32=6144 px`，高 `(96+96)×16=3072 px`；
- 临安：宽 `(160+160)×32=10240 px`，高 `(160+160)×16=5120 px`。

它们是母版合成尺寸，不是浏览器常驻纹理要求。TOWN-render 应按 chunk / 可见视口切片并由 `tech/06` 转 KTX2 / WebP；不得把整张 10240×5120 作为手机常驻单纹理。

### 1.3 规划格转运行时六角

规划格只做离线 authoring。TOWN-render 在上游世界系枚举 `tech/02` 六角中心 `hexCenter(q,r)`，再以 `x_p=x_w,z_p=H-z_w` 反变换取样米制掩膜：

1. 计算候选六角中心 `(wx,wz)`，范围覆盖 `[0,width]×[0,height]`；
2. 以 `floor(x_w),floor(H-z_w)` 找规划格；中心恰落北 / 东半开边界或越界即删除六角；
3. 读取地面、建筑碰撞和水 / 桥掩膜；中心落建筑实碰撞或非桥水面则不可走；
4. 对六角六个顶点追加保守碰撞：任一点越界或落入不可走掩膜（墙、实体建筑、无桥水面）均不可走，避免边缘穿墙 / 穿岸；
5. 生成`runtime_hex_walkable`与`RegionMap`，世界坐标保持米，不将方格索引冒充`(q,r)`。六顶点偏移固定用`(√3/3,1/3),(0,2/3),(-√3/3,1/3),(-√3/3,-1/3),(0,-2/3),(√3/3,-1/3)`，每点先反转z再查掩膜；距离整数≤1e-9的分量先归整再floor，避免临界点受三角函数噪声影响。

六角外接圆半径沿用 `tech/02` 的 `R=2/3 m`，中心 `x_w=2√3/3·(q+r/2),z_w=r`。规划半开边界令 `r=1..H`，每行 `ceil(-r/2)≤q<√3·W/2-r/2`。大理轴框为 `q=-48..82,r=1..96`（131×96），临安为 `q=-80..138,r=1..160`（219×160），不是 218。§13.2 给出枚举核算。

大理按 q 切为 `66×96 + 65×96` 两个标准街区场景；临安按 q×r 切为 `73×80` 的 `3×2` 个标准街区场景，均不越 `design/11` 的 `96²` 标准上限。各街区从自身 q/r 下界归零分 chunk，容量分别为 `(ceil(66/32)+ceil(65/32))×ceil(96/32)=18` 与 `3×ceil(73/32)×2×ceil(80/32)=54`。这是轴框容量，空槽不生成地形；9 / 25 仅是离线 32 m 规划切片数。保留全局 `(q,r)` 作玩法坐标，局部槽仅作寻址；跨街区邻边照常连通，不重新起六角原点。

旋转先在规划系执行：0° 为目录原向；绕占地中心顺时针旋转，北边 90° 后成为东边。记目录未旋转占地为 `w0×h0`，局部点 `(u,v)` 的变换为 0° `(u,v)`、90° `(v,w0-u)`、180° `(w0-u,h0-v)`、270° `(h0-v,u)`，再加旋转后实例左下角 `(x,z)`。90° / 270° 的实例 `w,h=h0,w0`，其余为 `w0,h0`；入口边与偏移同步变换。

入口必须先在未旋转占地选局部格：N=`(floor((w0-1)/2),h0)`、E=`(w0,floor((h0-1)/2))`、S=`(floor((w0-1)/2),-1)`、W=`(-1,floor((h0-1)/2))`。对该格中心 `(i+0.5,j+0.5)` 施上述变换、加 `(x,z)` 后逐分量 `floor`，得到实例 `entrance_cells`；**禁止旋转后在新边上重新取中点**。缓冲由该入口格沿旋转后的门外法向逐格延伸，含入口本格。14×11的S门局部中心 `(6.5,-0.5)` 经180°变为 `(7.5,11.5)`；实例 `(9,52)` 得入口 `(16,63)`，而非 `(15,63)`。

上游 yaw 从 `+x_w` 转向 `+z_w`，故局部北向的 `worldYawDeg=(rotation_deg+270)%360`；这不是建筑正门朝向。目录 S 门 / 正面南向模型的世界正面角为 `(rotation_deg+90)%360`。入口格中心、顶点与锚点均先按上述局部旋转，再反转 z；禁止只转图片。例：H=96，格(10,20)中心→世界(10.5,75.5)，顶点(10,20)→(10,76)；S门在0/90/180/270°分别朝南/西/北/东。

### 1.4 行走层、遮挡层与锚点

| 层 | 数据 | 规则 |
|---|---|---|
| 地面层 | `ground_cells` | 每格恰一条；水格默认不可走，桥格覆盖为可走；高度单位 m |
| 碰撞层 | 建筑 footprint、墙、栏杆、不可穿物 | 与地面分离；建筑的纯阴影不得写入碰撞 |
| 行走层 | `planning_walkable` + `runtime_hex_walkable` | 道路不等于唯一可走区；院落可走，建筑实体不可走；与 `design/08` 的地形能力再求交 |
| 遮挡层 | 建筑 / 树冠的 `occluder` 和 `fade_group` | 由相机深度缓冲处理；屋顶靠 `tech/02` §3.5 聚焦淡出，不烧进地面 |
| 交互层 | `poi`、`business_ref`、入口格 | 入口必须紧邻可走道路；交互 ID 仍归 `design/11/12/16` |

建筑图锚点固定为“未旋转占地的底面中心在地平面的投影点”；PNG 透明画布的锚点元数据记录像素 `(anchor_px_x,anchor_px_y)`，不能用透明包围框底边猜。旋转后先变换 footprint，再把中心映射到世界。

### 1.5 相机与旋转

- 默认正交、俯仰 30°、偏航 45°；`135/225/315°` 仍是 `tech/02` 的可选预设。
- 只提供一张 45° PNG 的建筑不得随镜头旋转；该场景须 `allowRotation=false`，或补齐四个 90° 视图。运行时 GLB 建筑可随相机保持正确透视。
- 64×32 是基础画幅，不改变 `tech/07` 的 64/96/128 px/m 运行时质量档；后者由母版缩放 / 转码派生，必须验证锚点不漂移。

## 2. 按年代的城市布局规则

### 2.1 共通判据：不用朝代标签替代城市个性

程序先读城市自己的固定骨架，再读年代套件的默认倾向。年代规则只能填缺省值，不能覆盖史图明确的墙、门、河、桥、宫城和主街。每条 `basis` 必须说明属于项目事实、原著、地方志 / 舆图、考古、学术研究或**（原创扩展）**。两城已打开资料、证据强度、年代差与坐标取舍分别登记于 `town/history/dali.md`、`town/history/linan.md`；未读全文或未见图面继续标明限制，不以“有网址”代替核实。

“里坊制”与“街巷制”在生成器里是两种地块拓扑，不是互斥的朝代开关：

- `ward`：墙 / 院界围成的大地块，入口少，内部支路不自动贯通；适合宫城、官署、军营、寺院和保守残留坊。
- `street_lane`：主街切块后，以 2–4 m 巷道递归分割，小店可直接朝街；适合宋以后商业住宅混合区。

宋代城市普遍发生由封闭里坊向开放街巷、沿街设市的转变，但不能写成某日全国同时拆尽坊墙。该判断据城市史 / 考古综述，属网络资料，待核原始报告。

### 2.4 元末（`ch04`）

- 大都 / 路城优先正交干道、较规整坊块与明确宫城—皇城—市井层级；驿路、马市、仓场靠城门和水陆节点。依据为元大都考古与城市史综述，**网络资料，待核**。

- 王府与行省 / 路府衙门必须是不同 `zone_kind`；蒙古营帐只在城外 / 军事边缘区使用，不塞入江南密集街心。**（原创扩展）**
- 镖局作为玩法设施可在商路节点出现，但“镖局”称谓与成熟组织形态的年代适用性**（待考）**；若考据不稳，外观用货栈 / 护运号，不改 `biz_*` 玩法引用。

### 2.5 明（`ch05–07`）

- 都城与府城倾向较规整城垣、城门瓮城、官署轴线；北京皇城居核心，南京 / 普通府城按自身史图，不复制同一棋盘。依据为明代城图、城墙考古和地方志，**网络资料，待核**。
- 街巷制延续；会馆、商帮、镖局、当铺与市场沿干道 / 水陆转运节点分布。后四类若作为可交互玩法，仍须引用章节既有 `biz_*` 或普通设施，不在本文造新玩法 ID。
- 王府为封闭大院，宜邻官署但避开最高密商业；寺观可嵌入居民区或山门轴线，须按具名城市资料覆写。
- 江南城河桥密、商住混合；北方城道路更规整、院落更深，只是套件倾向，不作为气候或文化刻板模板。

### 2.6 清初（`ch08–09`）

- 北京等都城必须区分宫城 / 皇城 / 内外城或旗民空间；具体边界读历史图，不用一张通用清城模板。依据为清初都城图、档案与考古，**网络资料，待核**。

## 3. 功能建筑清单

### 3.1 字段与读法

表中占地 `w×h` 对应建筑 `rotation=0` 时东西 × 南北的 1 m 规划格；旋转 90° / 270° 后交换二者。入口边按未旋转局部边记 `N/E/S/W`，实例旋转后同步旋转。数量是**每个相应分区**的生成范围；城市规格中的 `building_quotas` 可收紧。

“对应”只建立物理建筑到既有系统的引用，不重定义玩法：`biz_*` 的 `casino/escort/manor`、`job_xingjiao/jiaotou/keqing` 见 `design/16` §8；普通设施不计 280 个营生硬预算。机构只引用 `sect_*`，空值表示不应凭建筑推断经营者。

外城门按 `CitySpec.gates` 固定生成，映射到 §4.3 的完整 `tex_town_<era>_city_gate` 门楼贴片；不从本节建筑配额随机抽取，也不另造 `bld_*`。当前两城共15个旱门，大理2、临安13；临安水门仅在史料文档登记，现契约不允许门楼压水。皇城门楼仍是下表独立地标，城门守舍仍是普通建筑，三者不混计。

## 4. 贴片清单与自动拼接

### 4.1 通用规则

- 每格母版 `64×32 px`；跨格对象以 `n×64` 宽、`n×32` 高的菱形逻辑范围出图，透明画布可为阴影 / 高度外扩，但 metadata 必须保留格锚。
- `tex_town_<时代>_<名>` 是本文的城镇贴片资产 ID。`时代` 取 `song_dali/song_southern/yuan/ming/qing_early`；同纹理可通过 manifest alias 复用内容哈希，但 ID 不伪装成另一时代考据结论。
- 地面中心可不透明；菱形四角必须 alpha=0。河岸、墙角、树丛、桥和贴花必须 RGBA 真透明，不接受棋盘格或白底。
- 无缝地面至少 4 个色差 / 裂纹变体；变体由 `hash(seed,x,z,type)%N` 选择，不使用运行时 `Math.random`。

## 5. 数据格式

`docs/design/town/schema.yaml` 是字段、单位、范围和示例的机器可读设计契约；它不是 JSON Schema 方言文件。TOWN-render 应从它生成或手写等价的 JSON Schema / Pydantic 校验器，但不得改变字段语义。三份 YAML 均限制为 JSON-compatible 数据形状：map、list、string、number、boolean、null。

| 字段 | 类型 | 单位 / 范围 | 示例 / 说明 |

### 5.4 编码与兼容

- 集合按 `(z,x)` 排序；map 键按字典序；浮点最多 4 位小数；建筑排序见 §6.8。
- RLE run为`[start_index,length,value]`，索引`z×width+x`；完整覆盖W×H无洞、无交叠/越界、相邻等值合并。ground的value不含at（从索引派生），zone的value为boolean；walk_layer仍用显式数组。
- 未知字段报错，避免拼写错误被静默吞掉；新增可选字段升 minor，改变含义升 schema major。
- `null` 表示“明确没有引用”，缺字段表示“不符合 schema”；二者不可混用。
- `source_spec.sha256` 对原始 `CitySpec` 字节计算；生成器版本、RNG 名和 seed 都进入重放指纹。

## 6. 从 `CitySpec` 到 `TownLayout` 的确定性算法

### 6.1 随机与稳定顺序

使用 PCG XSH-RR 64/32（下称 PCG32）**【建议值】**；所有整数运算无符号模 `2^64` / `2^32`，`uniform(n)`要求整数`1≤n≤2^32`。UTF-8字节、不含BOM；标签用字面NUL `0x00`分隔，空局部键写`-`：

```text
FNV1a64(bytes): h=14695981039346656037; each b: h=(h XOR b)*1099511628211 mod 2^64
root = uint64(seed) XOR FNV1a64(UTF8("town.v1\0"+city_id+"/"+chapter_id))
label = stage+"\0"+(zone_id or "-")+"\0"+(type or "-")
initstate = FNV1a64(LE64(root) || UTF8(label))
initseq   = FNV1a64(UTF8("town.stream.v1/"+label))
state=0; inc=(initseq<<1)|1; next(); state+=initstate; next()
next(): old=state; state=old*6364136223846793005+inc
        xorshifted=uint32(((old>>18) XOR old)>>27); rot=old>>59
        return rotr32(xorshifted,rot)
uniform(n): limit=2^32-(2^32 mod n); 重取 next() 直至 v<limit；return v mod n
```

参考向量：标准初始化 `initstate=42,initseq=54` 的前 6 个输出为 `a15c02b7 7b47f409 ba1d3330 83d2f293 bfa4784b cbed606e`。本项目 `city_dali/ch01/109301` 得 `root=6a461730c6982b98`；`stage=roads,zone=-,type=-` 子流前 4 个为 `a903fdf0 cc58feb9 0215efc9 1cbf99c4`。实现必须先通过两组向量。

### 6.2 阶段 A：规范化和硬约束

1. 解析 schema、枚举、ID 引用、尺寸和多边形；检测自交 / 零面积。
2. 墙 / 分区点为格顶点；街 / 河 `points` 与桥 `at` 为格索引，折线实际经过 `(x+0.5,z+0.5)`。中心线用 supercover（触边两格都收、触角四格都收），按有向段膨胀，交接处取并集；同距离平局按 `(priority desc,id)`。
3. 为固定地标旋转占地，验证在允许范围、footprint互不重叠；预排三塔作为整体地标组，固定塔净空允许互叠，合并净空仅约束后续生成建筑，不豁免塔本体碰撞。
4. 任一硬错误立即失败，不尝试“修好”历史输入；报告精确路径和坐标。

桥矩形以 `at` 所指格为锚点。0/180°时世界规划跨度为 `(width,length)`，90/270°为 `(length,width)`；`min=(at.x-floor(span_x/2),at.z-floor(span_z/2))`，`max=min+span`，半开取格，偶数向负轴多一格。例如at=(20,30)、长6宽4、0°覆盖`x=18..21,z=27..32`。桥面全矩形可画，`bridge_cells`只导出矩形与水格的交集；每座桥必须覆盖其道路/河流交叉分量且两端接陆路。全部道路与全部水面的交集必须被桥覆盖，否则报`TOWN_ROAD_WATER_UNBRIDGED`，不能靠截掉道路解决。

城门 `at` 必须落在墙顶点折线supercover格集，且全城恰有一门`primary=true`。门楼与通行孔分别采用GateSpec的局部尺寸：以at格中心为旋转中心，局部整数偏移`x=-floor((w-1)/2)..ceil((w-1)/2),z=-1..2`；偶数沿+x多一格，0/90/180/270°偏移依次为`(x,z)/(z,-x)/(-x,-z)/(-z,x)`。先分别合并所有门的孔掩膜为P、门楼掩膜为G，再以`(墙栅格−P)∪(G−P)`作为实体碰撞；不能逐门恢复整墙。跨孔梁楼只遮挡、不封孔；门净宽/方向必须匹配素材，门墩不得压固定地标。

可行走域为墙内格中心集合加P，再扣上述实体、建筑及非桥水。道路只在墙边裁到此域（城门处以净宽裁口），墙外方帽不导出；其余城内道路必须保留全宽。城门通过P获得墙退距通行例外，建筑仍不得侵入G。阶段A即验证每门P跨墙且与road_ref的城内道路4邻相接；空城采样后没有合法六角城门入口时报`TOWN_GATE_HEX_UNREACHABLE`。

### 6.3 阶段 B：主轴街

按 `class=main_axis`、`priority desc`、`id` 栅格化。对每段supercover格集先作Chebyshev半径`floor((w-1)/2)`膨胀（端点为方帽）；偶数宽再合并一次向右平移1格的副本。右向取主轴垂向：`abs(dz)>=abs(dx)`时为`(sign(dz),0)`，否则为`(0,-sign(dx))`；折点取相邻段并集。河宽同算法，墙另按顶点线supercover处理。

本阶段只检查主门接入主轴：按§6.2开门与裁墙后，令`R_B=∪main_axis格集`，要求`primary=true`城门at∈R_B；否则报`TOWN_ROAD_PRIMARY_DISCONNECTED`，不移动手写线。此时允许主轴有多个分量，不检查目标分区可达；次级街尚未铺设。临安原规格的`R_B`为850/1013格两个分量，主门位于850格分量，须允许进入阶段C。

### 6.4 阶段 C：次级街网

先铺手写 `secondary` 与 `alley`，按§6.2开门与裁墙后令 `R=∪roads[id]`（包含已铺路的桥格，排除其他可走空地）。枚举R的4邻连通分量，以主门at所在分量为M；根不在R立即报`TOWN_ROAD_PRIMARY_DISCONNECTED`。**先连接全部道路分量，再处理无邻路分区**：

1. 每个非M分量取相交原街的最小键`(class顺序main_axis/secondary/alley,priority desc,id)`，再以分量最小`(z,x)`排序，先修首个。每补一条后重枚举R与M，不沿用旧分量编号。
2. 起点集合取该分量的边界道路格（至少一个4邻不在本分量），按z/x排序；目标集合为M的全部格。使用多源A*，状态为`(x,z,来向)`，初始来向为哨兵4；`h=min(到M各格的曼哈顿距)`。队列键为`(g+h,h,源z,源x,z,x,来向N/E/S/W/哨兵)`；相同状态只保留较小`(g,源z,源x)`，完全相同保留先到项，邻居固定N/E/S/W。首个出队的目标即终点，按父链逆序还原中心链；不消费RNG。
3. 每步中心格代价为道路1、空地4、低优先区8、garden20；低优先区相对于出发分量覆盖分区的最高priority，无分区按0。新增宽2 m巷、surface=`dirt_road`、`reason=road_component_disconnected`、`zone_ref=null`，按实际生成顺序分配`gc_0001…`。全宽检测沿用下文；已有道路可穿宫禁，新增格不得占宫禁、固定footprint/净空、墙、非桥水或画幅外。既有桥仅允许其已声明矩形内的通路。
4. 搜完整城域仍无路径时报`TOWN_ROAD_COMPONENT_DISCONNECTED`，附出发分量格数/代表街、M格数与阻挡类别；不删孤路、不把空地BFS当作成功。成功后必须满足`components(R)=1`，否则不进入阶段D。

随后按 `(priority desc,id)` 处理无道路格相邻的分区。起点取胜出格中心平均值最近的可走格（平方欧氏距，平局z/x）；目标仅从已接主门的R中按main_axis/secondary/alley、最近曼哈顿距、road id、z/x选择。先搜起点16格曼哈顿半径，再扩大到全城，均用A*补路：

- 4 邻方格，代价依次为既有道路 1、空地 4、低优先区 8、受保护绿地 20；
- 水 / 地标 / 宫禁 / 墙为不可过；过河只允许预声明桥位；
- 平局按 `f=g+h`、`h`、`z`、`x` 排序，邻居按 N/E/S/W 枚举；`h` 为到目标的曼哈顿距离。输出 `GeneratedConnector`，中心链写 `cells`，膨胀后的格集合写 `roads[connector.id]`；不得输出未定义布尔标记。

找不到路时报`TOWN_ZONE_UNREACHABLE`；本阶段未放随机建筑，无可清空的建筑预留。不得临时挖桥或穿墙。代价“低优先区”指比出发区priority低的其他胜出区；garden为受保护绿地，其余空地代价4。

所有补路（含阶段E入口接驳）在搜索中按“当前位置+来向”扩展状态，逐段验证§6.3膨胀后的全宽及折点并集；任一格侵硬阻挡即拒绝该边。不能只检查中心链，再在导出时裁窄2 m巷。平局在既定键后追加来向N/E/S/W；入口候选全宽接驳失败则顺序尝试下一候选，不撤销此前已提交建筑。每条补路必须与目标R相交，完成后断言道路只有主门分量；阶段D以此时最终R建立可建掩膜和密度分母，后续补路格从可用位置扣除。

**目标分区可达性在本阶段末验收**：候选为`kind∈{palace,princely,commercial,market}`的分区，只保留最高priority（同优先级任一可达即可）。胜出格中至少一个4邻不属于本区的格为边界；主门的最终道路分量M须与某候选边界相交或4邻相接。无候选或全部不可达时报`TOWN_ROAD_PRIMARY_DISCONNECTED`；道路分量补接本身失败仍先报`TOWN_ROAD_COMPONENT_DISCONNECTED`。旧临安规格回归曾在铺完次级街后得到3773格单分量并接皇宫边界；这是阶段顺序的历史示例，当前完整道路格数见§8及TOWN-layout报告。

### 6.5 阶段 D：地块划分

从墙内格扣除道路、水、桥、固定地标、地标净空、墙内退距和已预留入口缓冲。分区重叠按 `priority desc,id` 逐格选择唯一胜者；没有胜出的格不进入任一区密度分母。**先保留完整可建掩膜，阶段E先放固定地标与功能建筑，再沿街填通用建筑。** 功能建筑不受中位数小地块限制，不可先切成6×6再宣告寺殿无位置；剩余空地切块用于导出和检查，不阻断沿街填充。

余地按4邻分量处理，从 `(z,x)` 最小格起取最大空矩形，同面积取较小 `z,x`、较宽 x。目标宽高取允许目录中去除固定地标后每一 `(type,rotation)` 的 `w/h` 序列中位数（0/180也分别计入）；偶数项取中间两数之和整除2，分别钳到宽6..24、高6..20。超大矩形从西南角按目标切出并重算；放不下最小footprint及入口缓冲的余块保留院地。

密度分母冻结为阶段D开始时“分区胜出格扣路水桥、墙距、固定净空与固定入口缓冲”，**保留固定地标占地**；生成后入口不再改变分母。分子为全部已放footprint（含固定地标）。`density`改为软视觉目标，超出时报warning，不截断通用填充：功能建筑先放已可能用完某分区旧密度预算。当前规格的`min`仍由校验器检查；通用下限按稳定贪心结果留余量后写入源规格，不能由生成器静默降低。

### 6.6 阶段 E：放固定与功能建筑

固定地标先放，并计入同 `type + zone_ref` 的配额。通用建筑为未绑定`business_ref/institution_ref`且type后缀为`house/courtyard/shop/shop_1f/shop_2f/market_stall/warehouse`的民居、院落、商铺、摊棚、仓屋；其余为功能建筑。配额按`通用在后、required优先、占地面积降序、type`排序，先保衙门、宫殿、寺塔、镖局、客栈、酒楼、赌场、码头等功能建筑，再沿街贪心填通用建筑，不回溯。required功能建筑目标为min，非required功能建筑在通用填充前试至max。通用类型按同序轮流每类放一栋，至max或候选耗尽；min不参与候选排序或停止条件，避免下调验收下限反而改变布局。候选枚举整区可建掩膜，评分：

```text
score = 1000*entranceTouchesRoad
      + 40*sameZoneCells - 25*distanceToPreferredRoad
      - 80*waterOverlap - 80*buildingOverlap
      - 10*blockedEntranceCells + seededJitter(0..9)
```

候选按 `(score desc, entranceRoadId, zone_id, rotation_deg, z, x)` 取首项；`entranceRoadId` 空值排最后。`seededJitter=uniform(10)` 每个按 `(zone priority desc,zone_id,type,rotation,z,x)` 排好的画幅内矩形候选恰消费一次对应type子流，淘汰候选也消费；首次建候选表缓存抖动，后续不重抽。distance取入口到最近道路格的曼哈顿距离（平局road id）；sameZoneCells、overlap、blocked均计格数。硬冲突候选永不因高分而放行。

硬条件优先于评分：footprint全属于同一胜出分区，不重叠、不压水 / 桥 / 道路 / 墙；基线建筑硬碰撞按footprint，屋檐不额外扩大硬占地。按§1.3先从目录未旋转 `w0×h0` 选局部入口格中心，再旋转并转为实例格坐标；多入口按目录未旋转N/E/S/W逐一试，以评分和旋转后入口边字典序决胜。入口缓冲、6步接街路径和六角映射均从该结果重新计算，不复用旋转后边中点。入口在6步4邻可走路径内接道路才合法；路径中除已有道路外的格预留为入口接驳。

先用最多6条边的4邻BFS寻找入口接驳，邻居N/E/S/W；到道路平局依次按步数、road id、终点z/x、整条路径的`(z,x)`序列取最小。入口接不上时自动寻路补完整2 m步道，再复验最终入口6步接路；固定塔群在其他建筑前初始化接驳，允许穿自身净空。所有新增路写入`generated_connectors`，不得穿建筑、墙或无桥水；可进入源建筑自己的宫区，其他宫禁仅可复用既有道路。校验器按接驳生成顺序复核新增全宽格，入口接驳的from须对应同zone_ref建筑入口。入口缓冲、路径和六角净空纳入预留，失败候选的临时预留撤销；已有道路与共用接驳不排他锁定。

**六角接入是候选硬条件**：每次试放即按§1.3重采样。建筑入口候选六角中心距入口格中心≤1.5 m，中心到入口中心的supercover线不穿硬阻挡；按平方距离、r/q排序取首个与主门连通的六角，写`entrance_hexes`，与`entrance_cells`一一对应。城门的六角入口取距at格中心≤4 m、中心在墙内且位于road_ref∪P的合法六角，按距离、r/q取首个；主门取根，其他门须接入根分量。六邻路径用BFS、邻居按r/q升序，等长取完整`(r,q)`序列字典序最小。

提交候选前检查已放建筑、固定地标、所有城门与显式poi入口仍接根分量；为新入口六角的中心/六顶点取样格预留净空，后续建筑不可占。固定地标在其他建筑前也做此检查；空城加固定地标仍无法接通时报`TOWN_HEX_DISCONNECTED`并定位。候选失败仅撤销本次临时碰撞、接驳、六角预留和入口映射，继续下一候选，不回溯此前已提交建筑。

墙退距采用“候选每格四顶点均在闭合墙内，且到任意墙边线段最短欧氏距≥inside_margin_cells”；墙门通行格是墙退距的通行例外，不可建楼。三塔净空是footprint四向外扩3格的矩形，扣掉塔本体后作为禁建环。普通入口外1格、衙门外4格（宽1格、沿门外法向）不得压建筑 / 非桥水 / 墙距 / 塔净空，但可叠道路；宫禁3格指皇殿 / 宫门与非palace建筑间至少留3格空带，不对宫区内部额外做边沿退距。固定地标的自身入口可穿自身净空，只许步道与低矮地表，不许另一座建筑。住宅距仓厩硬footprint至少1格；码头仅岸外占地且至少一边4邻接可航水格。

单行quota数量跨`zone_refs`合计，目录每区上限仍适用，目录下限以城市quota为准。功能建筑放不下时报`TOWN_REQUIRED_NO_SPACE`，调整分区或固定地标后重跑；通用建筑能放多少放多少，未达当前required.min时同样明确报出，由规格维护者下调到稳定可放数并留余量后重跑。2026-09-30第九次裁定授权本轮同步两城通用下限；不再运行容量证明、DFS或节点预算，也不把贪心失败解释为几何无解。

### 6.7 阶段 F：道路连通与修复

先独立复核`R=∪roads[id]`的4邻分量，主门at必须在R且全部R格都在其分量，桥上只计实际道路格；不能把其他可走空地纳入这次BFS。道路分量修复在阶段C、入口补路在阶段E完成，本阶段只作最终断言；若仍断路报`TOWN_ROAD_COMPONENT_DISCONNECTED`，不以入口可达豁免孤立街段，不移动固定几何。

再以主城门入口格为规划可走层BFS根，4邻连接；桥面是水上的可走节点。以下目标必须可达：全部 required 建筑入口、固定地标入口、其他城门与显式 `poi`。这是第二项独立不变式，不能替代上述道路格集合检查。

仍不连通则失败并报告不可达目标，不为增加数量撤楼或重放整城，不把水改地、删墙、凭空加桥或把不可达POI标成可达。全城规划层可保留不可进入的装饰小岛，R自身与“主路 + required入口”各自分量必须恰为1。

### 6.8 阶段 G：地表、植被和导出

v1只接受 §4.4 的7类陆生植物，临安palette已移除莲荷；`cluster_rule` 仍只描述美术意图，不扩展候选域。输入含清单外或水生资产时报 `TOWN_VEGETATION_PALETTE_INVALID`，不得将其随机落在陆地或自动解释为盆栽。

1. `ground_mix`是总和100的整数权重，按ground key字典序累计，用`uniform(100)`抽取；按`(z,x)`遍历，派生`stage=ground,zone=胜出区,type=-`；无分区空地用rammed_earth不消费RNG。道路、水、桥依优先级覆盖，不重抽。
2. 河岸 mask 从 8 邻水格生成；道路 mask 同理；桥面先写水格语义、再写可走覆盖。
3. 植被候选限城墙内部且当前行走层可走的陆地格，每格一次，按`(z,x)`排序；排除建筑 / 水 / 桥 / 塔净空 / 入口接驳及已放植物，并排除距道路Chebyshev距离小于`avoid_road_cells`的格。排除项不消费RNG，其余用`stage=vegetation,zone=-,type=-`的流以`uniform(10000)<floor(density×10000)`命中；命中后按palette字典序用一次`uniform(count)`选种、再取`2+uniform(4)`为簇目标（含首株2–5株）。以首株八邻N/NE/E/SE/S/SW/W/NW序补同种，邻格仍需全部合法，不再抽样；不足则保留实际数量。输出`decorations`，这些植被为可穿的视觉层；硬阻挡树需后续另定碰撞契约，不偷偷改行走层。
4. 重新采样最终六角行走层并复查§6.6所有入口。候选提交时已维持连通，本步只作最终断言，不增加随机抽样；若仍断连报`TOWN_HEX_DISCONNECTED`并定位，不能仅把可走空地标成道路或跳过行走层校验，不移动固定地标、墙、水或桥。
5. 建筑实例稳定排序：固定地标按声明序，其他按 `zone.priority desc,type,z,x`；补路按 `id`；编号 `bi_0001…`。
6. 建筑抖动用`stage=buildings,zone=候选区,type=候选type`；补路不抽随机数。贴片变体用`FNV1a64(LE64(root)||UTF8("tile\0"+x+","+z+"\0"+type)) mod N`。输出canonical YAML、SHA-256、校验摘要和调试SVG；同版本同输入须逐字节相同，不写时间戳或绝对路径，耗时只写独立统计。

### 6.9 复杂度与超时

道路 / 水栅格和单次BFS是`O(W×H)`，矩形候选枚举为`O(types×rotations×W×H)`；接驳与六角复验另计。采用候选缓存和沿街贪心，不做组合搜索。桌面目标为单城几秒内结束 **【建议值】**，超过10 s须在执行报告说明原因；不能用放松碰撞或跳过校验换取速度。

## 7. 渲染与合成规则

### 7.1 离线贴片绘制顺序

从后到前按以下固定 pass：

1. 城外留白 / 草地与墙内基础地面；
2. 分区地表、道路中心、路缘；
3. 河床、水面、水面动画索引；
4. 河岸边缘；
5. 桥墩（远侧）→ 水面 → 桥面 → 单位可穿行层 → 近侧桥栏；
6. 地面贴花、低矮草石；
7. 城墙、城门、建筑、树木等高度对象；
8. 角色与动态物；
9. 屋顶淡出 / X 光剪影、天气、后处理；
10. 调试 SVG（仅开发态）。

若使用真实 3D 网格，第 7–9 步交 `tech/02` 深度缓冲和渲染队列；离线 `preview.png` 才用排序合成。不得把建筑永久烘焙进 ground，避免无法淡屋顶、换时代状态或做遮挡。

### 7.2 autotile 与桥叠放

- 同一 pass 内先算所有 mask，再绘制，禁止绘制顺序影响邻接判断。
- 河岸由“中心是水、邻格非水”的边生成；道路边由“中心是路、邻格非同路面”的边生成。路与桥交叉时桥面胜出，但底层仍保留 water 标记。
- 桥轴须垂直河流局部切向的主方向；误差超过 45° 或桥头没有道路即校验失败。
- 船、倒影和水草不写进水面基础贴片；它们属于物件 / 动效，避免相位重复。

### 7.3 建筑远近排序与锚点

对 45° 静态合成，建筑实例的深度键取旋转后占地四角的最远格：

```text
world_corners = [(x_p, H-z_p) for rotated footprint corners]
far = max(x_w + z_w for world_corners)
sort_key = (far, anchor_world_z, anchor_world_x, instance_id)
```

按键升序从远到近绘制；墙段、树与建筑使用同一键。该规则只用于离线画家序和透明软边；真实运行时不替代 `tech/02` §3 的深度缓冲。锚点为底面中心投影，模型枢轴为底面中心；素材阴影不得改变排序锚点。

### 7.4 光源、阴影与色彩

- 默认风格遵循 `STYLE.md`：写实古风、符合城市与年代；建筑地图件保持 45°，不用水墨 / 卡通 / 微缩模型感。
- 首批统一暖中性日光从屏幕左侧略朝观者；投影短、软、向屏幕右侧略上。该方向沿用已生成 building-map 候选的目标契约；候选本身未全部通过几何验收，不能反过来覆盖本规格。
- 透明建筑只保留紧贴基座的接触影；大范围投影由运行时统一生成或作为独立 shadow pass，不烘进 RGBA 主体。
- 大理使用灰瓦、土墙、木石与低饱和绿色，砖铺装克制；临安使用维护更好的木构、灰瓦、石板 / 青灰砖和更密店铺陈设。具体历史材质仍逐类**（待考）**。

### 7.5 调试 SVG

`debug.svg` 与母版同画幅 / viewBox，必须可独立开关：

- `g#grid`：每 8 格细线、每 32 格 chunk 粗线；
- `g#zones`：分区半透明填色、边界、`zone id` 与 priority；
- `g#roads-water`：道路中心线 / 宽度、河、桥、城门；
- `g#buildings`：footprint、入口箭头、实例 ID / type、冲突红框；
- `g#walk`：规划不可走格和运行时不可走六角；
- `g#validation`：不可达路径、越界、重叠、缺素材提示。

中文显示名由代码写入审阅用 SVG 和俯视 PNG；正式底图与建筑素材 PNG 不生成文字 / 匾额，避免图像模型伪字。

另有面向布局审阅的 `tools/town/plan_view.py <spec> <layout> -o <plan.svg>`，同时输出同名 PNG。平面图北向上，直接消费同一规格与布局的坐标、路水掩膜、建筑占地，中文名称由代码读取 `basis` 中的“图名：名称；”说明；该约定不新增 schema 字段。图中编号与侧栏对应墙门、街道、水系、分区和固定地标；两城实图见 `town/history/*_plan.svg`。45° PNG 仍由 `render_town.py` 对相同坐标变换产生，两者均不得手绘改位。

## 9. `tools/town/check_town.py` 规格

TOWN-render 已实现此脚本；本轮两城按此契约校验通过。CLI 示例：

```bash
python3 tools/town/check_town.py --spec docs/design/town/city_dali__ch01.yaml
python3 tools/town/check_town.py --layout generated/town/layout_dali__ch01.yaml --assets assets/default --release
```

### 9.1 规格与布局 schema

| 代码 | 级别 | 检查 |
|---|---|---|
| `TOWN_SCHEMA_*` | error | 必填、类型、枚举、范围、未知字段、版本 |
| `TOWN_ID_REF_*` | error | `city/chapter/biz/sect/poi/type/asset` 外键存在且归属正确 |
| `TOWN_SOURCE_*` | error | 递归提取`sources`以外所有`basis`中的`src_[a-z0-9_]+`；未知键报`REF_MISSING`，重复来源键报`DUPLICATE`，未被任何basis引用的来源报`UNUSED`；`supports/note/title`自述不算引用 |
| `TOWN_GEOMETRY_*` | error | 点越界、多边形自交 / 零面积、矩形反向、重复局部 ID |
| `TOWN_PROJECTION_*` | error | 1 m、64×32、pitch30、合法yaw；轴槽分带求和、边界反向和32²chunk容量（尾块可不满） |
| `TOWN_REPLAY_*` | error | 同输入连续生成两次 canonical bytes / SHA-256 相同 |
| `TOWN_SCENE_REF_MISSING` | release error | 正式运行时发布须回填design/11登记的sc引用；null仅允许离线预览 |

### 9.2 空间与玩法不变式

1. 建筑旋转后 footprint 两两不重叠，不压墙、水、桥和道路；固定地标同样检查。
2. 建筑占地和入口均在墙内退距；v1没有城外例外字段，禁止静默裁剪越墙区框。
3. 每个建筑入口至少一格，入口不在碰撞内，并在 6 步内通过可走格连接道路；按§6.6平局规则复算入口路径及一一对应的`entrance_hexes`，六角中心与六顶点均无碰撞。
4. 阶段B只检查主门at∈`R_B=∪main_axis格集`，不提前要求目标区可达；阶段C铺完次级街并补接后，按§6.4检查主门到最高优先级目标分区边界可达，失败报`TOWN_ROAD_PRIMARY_DISCONNECTED`。最终布局令`R=∪roads[id]`，独立4邻BFS要求主门at∈R、道路分量恰为1；不计非道路空地，失败报`TOWN_ROAD_COMPONENT_DISCONNECTED`并列各分量格数/街ID。再检查primary到全部required入口、其他城门和POI在规划层、六角层都可达；required连通分量各恰为1。道路补接复查全宽掩膜/占地/配额；六角阻挡须按真实碰撞重采样，不能仅改道路标签。
5. 桥格是水格子集且可走；按桥矩形锚点与偶数偏置复算，每座桥两端各有陆地 / 道路；所有道路∩水面均有桥覆盖。无桥水面不可走。
6. 行走层必须等于“城内可走地表 − 建筑 / 墙 / 硬物 + 桥覆盖”再与 `design/08` 门禁求交；禁止渲染可走而逻辑阻挡或反之。
7. 每项 required quota 数量在 `[min,max]`；`business_ref` 的 kind 与建筑功能匹配，不能让赌场绑定 escort。
8. zone 实际覆盖只含墙内可分配格，重叠胜者符合 `(priority desc,id)`。
9. 城门锚点在墙栅格，完整门楼asset_type/方向/尺寸/净宽匹配，P⊂G、孔跨墙且接指定路；墙从P挖孔、两侧门墩为硬碰撞，梁楼不堵孔。门楼/孔均不得压水，全部15个旱门入口必须纳入连通检查；不得以旱门模型替代历史水门。
10. quota.max不得超过所列允许分区的目录上限之和；临安民居最多`24×2=48`。临安河埠外观不得实例化`port`、poi或旅行入口。

### 9.3 素材完整性

- 每个建筑 `type` 必须在所选风格包 manifest 有资产或明确占位；`--release` 要求 status=`approved`，S/A 级不接受 placeholder。
- 贴片 ID 必须覆盖该城出现的 ground / edge / wall / gate / bridge / vegetation；尺寸、alpha、锚点、四向 / GLB 能力与 metadata 一致。
- 植物逐项核对 §4.4：先验palette为7项白名单的非空无重复子集，再验每个 `DecorationInstance.asset_id` 属于来源palette，metadata / v01 / v02文件均可解析；不得用同名树丛贴片替代 `prp_*` 登记。缺文件报 `TOWN_ASSET_MISSING`，metadata域/尺寸/锚点或运行时 `prop/model` 类型错误报 `TOWN_VEGETATION_ASSET_INVALID`；release须两变体均approved。每个at及簇补点须满足 §6.8 的陆地候选域，否则报 `TOWN_VEGETATION_DOMAIN_INVALID`；实际素材生产与图像验收由下游执行。
- 建筑、城门楼、树丛等独立物件 PNG 检查完整轮廓与透明留白：非接缝轮廓触画布报裁边错误。64×32地面菱形、河岸 / 路缘、墙段等拼接贴片允许在 metadata 声明的接缝触边，不对接缝套用独立物件留白规则；菱形逻辑范围外仍须透明。
- 地面无缝检查按完整 autotile 邻接表拼接至少2×2格，检测接缝 alpha 是否出现非设计孔洞、端点色彩 / 纹理是否连续；有意边缘过渡须由对应 mask 声明。正常64×32地面触边应通过，屋檐被裁或接缝出现透明裂缝应分别失败。
- 锚点越界、底面轴斜率未满足 `±0.5` 容差、光向反转均报错；斜率容差默认 `±0.03` **【建议值】**。城门还须逐门匹配 `asset_type/rotation_deg/width_cells` 变体和 `footprint_cells/passage_cells`，缺完整楼体或可视孔与通行孔不符均失败。
- 输出统计：建筑 type 已用 / 缺失 / candidate / approved 数，贴片 mask / 城门变体覆盖数，非接缝裁边和接缝裂缝数，母版和每 chunk 像素预算。
