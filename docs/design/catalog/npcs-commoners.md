# NPC 名录 · 路人甲生成规则

> 归属：`design/18-npc-and-companions.md` 的路人甲（L-D / D1）分层名录；本文定义生成、招募与持久化候选数据。
> 上游：AR-04、AR-09，`design/02` 的时代，`design/03` §10 的 `template` 管线，`design/09` 的 AI 人格，`design/11` 的城市接口。
> 引用而不重定义：战斗数值归 `design/03` / `09`；城市人口与地域名归 `design/11`；工资锚归 `design/10` / `16`。
> 标注：本文的词素均为内容池示例 **（原创扩展）**，不是原著人物。辽、西夏、大理、西域等专名在语言 / 历史校审前只使用职业称谓，不伪造人名。

## 0. 目标与边界

路人甲要让街巷、村镇、驿路与野外有生活感，也落实“NPC 都可成为同伴”。其可招募不等于必然适合战斗：商贩、孩童、老人、病患和文职人员可以作为营地、旅行或经营同伴，`combatEligible=false` 时不占战斗编组位。

路人只用 `template` 数值管线。与玩家发生以下任一事件后转为持久 NPC：已招募、羁绊 ≥20、持有未结任务、被玩家伤害 / 救助、欠薪 / 借物、见证关键选择。否则可在离开视野 30 个游戏日后回收。

## 1. 稳定生成算法

```text
seed = hash(saveSeed, chapterId, cityId, districtId, spawnWeek, slotIndex)
candidate = {
  nameToken, region, culture, occupation, ageBand,
  temperament, rumor, need, schedule, combatEligible
}
runtimeId = stable_uuid(namespace, hash(seed, identityRevision))
```

- 相同存档、同一周、同一槽返回同一人；读档不会刷姓名、特质或招募价格。
- `runtimeId` 是由固定命名空间与内容哈希派生的稳定运行时 UUID（实现可采用 RFC 9562 UUID v5 或等价确定性方案，见主文 §12.4），不写入静态名录；一旦持久化，此 ID 永不复用，即使角色死亡或离开。若未来需要可读前缀，采用主文 §15 的 `npcg_*` 基准提案，而不是自行登记。
- `spawnWeek` 只影响未持久池。已持久者按日程移动，不随每周刷新复制。
- 生成顺序固定：地域 / 文化 → 姓名或职业称 → 年龄 → 职业 → 性情 → 需求 → 谣言 → 战斗资格 → D1 条件。
- 禁止让生成角色占用静态 `npc_*` 的姓名 + 别号组合；冲突时重抽，不给静态人物加后缀。

## 2. 汉语姓名池示例

> 下列仅作为程序最小池，用于宋至清汉语环境的普通角色；历史时代的使用频率、女性名、行次称谓仍 **（待考）**。正式内容须扩充并由语言 / 历史校审，不能把现代人口排名当古代频率。

### 2.1 姓氏词素

| 池 | 词素 | 使用限制 |
|---|---|---|
| 高频单姓 | 赵、钱、孙、李、周、吴、郑、王、冯、陈、褚、卫、蒋、沈、韩、杨、朱、秦、许、何、吕、张、孔、曹、严、华、金、魏、陶、姜 | 只给分布候选，不声称各时代频率相同 |
| 次频单姓 | 戚、谢、邹、喻、柏、水、窦、章、云、苏、潘、葛、范、彭、郎、鲁、韦、昌、马、苗、凤、花、方、俞、任、袁、柳、鲍、史、唐 | 与静态主线人物全名去重 |
| 复姓 | 欧阳、司马、上官、诸葛、夏侯、皇甫、尉迟、公孙、慕容 | 低权重；`慕容` 在天龙时代需避免误导为姑苏慕容家属 |
| 无姓显示 | 阿 + 单字、小 + 单字、排行 + 郎 / 娘、职业称 | 仅在地域 / 社会身份适合时；规则待考 |

### 2.2 名字词素

| 语义池 | 字 / 组合示例 | 禁用检查 |
|---|---|---|
| 德行 | 仁、义、礼、信、安、宁、和、诚、敬、善 | 不与称号拼成嘲弄语 |
| 山水 | 山、川、江、河、松、柏、兰、竹、泉、溪、云、月 | 不直接复用名宿全名 |
| 志向 | 志、远、达、成、兴、昌、文、武、勇、杰 | 官职 / 性别表达不由名字强推 |
| 家常 | 大郎、二娘、三郎、五娘、小七、阿福、阿顺 | 行次不得超过已生成家庭子女数；无家庭时只作俗称 |
| 手艺称 | 老周铁匠、陈家嫂、阿林脚夫、何郎中 | 职业称可替代未经校审的名字 |

组合权重：单名 55%、双名 25%、行次 / 小名 15%、纯职业称 5% **【建议值】**；同街区显示名重复时优先改用职业称，不重掷身份和需求。

## 3. 多地域命名闸门

| 地域 / 文化 | 校审状态 | 当前生成策略 | 禁止事项 |
|---|---|---|---|
| 宋、明、清汉语城市 | 最小池可用，频率待考 | §2 姓名池 + 职业称 | 不把同一频率表跨 700 年硬复用 |
| 大理各族群 | 待语言 / 历史校审 | “大理马夫 / 苍山采药人 / 王府译语人”等 | 不以随意汉字音译造名 |
| 契丹 / 辽 | 待校审 | “契丹骑手 / 辽商 / 上京译语人”等 | 不从皇族姓名拆字拼接普通人 |
| 党项 / 西夏 | 待校审 | “兴庆商人 / 西夏驿卒”等 | 不伪造党项姓氏与官号 |
| 蒙古诸部 | 待校审 | “漠北牧人 / 蒙古骑手 / 幕府译语人”等 | 不借历史名人名号随机拼装 |
| 回部 / 哈萨克 / 西域绿洲 | 待校审 | 地域 + 职业称 | 不混同现代民族称谓与清代行政语境 |
| 藏地 / 吐蕃 | 待校审 | 地域 + 僧俗职业称 | 不杜撰法名、活佛号或真实宗教职阶 |

如果专名池没有通过校审，生成器必须返回职业称谓，不能悄悄回退到汉名池。这是构建警告而不是阻断可玩性的错误。

| `wanderer` 行脚 | 驿路、客栈 | 青至老年 | `tmpl_normal` | 七人格按经历抽取 | 地域随机专长 | 好感 20 或交换同行目的 |

## 5. 年龄、家庭与伦理限制

| 年龄段 | 生成权重【建议值】 | 招募规则 | 战斗资格 |
|---|---:|---|---|
| `child` | 5% | 不进入付费招募池；仅护送 / 家属同行 | 固定否 |
| `youth` | 12% | 需监护 / 师长同意或独立生计事实；不签高危短约 | 默认否，原著 / 专属任务例外 |
| `young_adult` | 24% | 标准 D1 | 按职业 |
| `prime` | 34% | 标准 D1；检查工作与家属 | 按职业 |
| `mature` | 16% | 标准 D1；检查照护责任 | 按职业 |
| `elder` | 7% | 默认只作营地 / 旅行顾问 | 默认否，人物画像可覆写 |
| `venerable` | 2% | 不进随机付费池；只经个人事件邀请 | 默认否，宗师不得由路人池生成 |

权重和为 `5+12+24+34+16+7+2=100%`。这是全局初值；战争、疫病、商埠、门派驻地等城市标签可调整，但儿童与高龄者保护规则不变。

家庭生成先创建 `householdId` 再创建成员。招募主要照护者时必须提供安置选择：家属随迁到据点、预付生活费、或拒绝长期同行。不得把家属自动当作赠品同伴。

## 6. 性情、传闻与需求

| 维度 | 候选 | 作用 |
|---|---|---|
| 性情 | 豪爽、谨慎、热心、寡言、机敏、固执、圆滑 | 映射 `design/09` 已有 AI 人格，不新建人格 ID |
| 传闻可信度 | 真、半真、误传、刻意隐瞒 | 决定线索检定；不能改写主线事实 |
| 当下需求 | 盘缠、寻人、送信、治伤、护送、找工、避祸、还物 | 形成 1–3 节点短事件 |
| 拒绝理由 | 家属、职业、伤病、门禁、路线、品德冲突 | 必须给可读原因；硬约束不能用钱消除 |
| 同行目的 | 同路、受雇、报恩、学艺、避难、调查 | 决定短约期限与离队地点 |

谣言文本只能指向已配置事件 / 地点；无内容承接时不得生成假线索。对真实族群、疾病、贫困和犯罪的描述不得作为人格负面随机词。

## 7. D1 招募与数量

### 7.1 条件

满足一条软门槛并通过全部硬门槛：

- 好感 ≥20【建议值】；或
- 支付 `design/18` §9.1 的 D1 日佣，合同 3–30 日【建议值】；或
- 完成救助事件，获得一次免软门槛邀请；或
- 同乡 / 同业 / 当前门派关系通过口才检定。

硬门槛包括：不是儿童战士、家属已有安置、当前没有不可离岗任务、路线可达、玩家未对其家庭犯下未修复恶行。检定失败只冷却 1 游戏日；明确拒绝不得靠重复点击重掷。

### 7.2 数量与卸载

| 池 | 上限【建议值】 | 处理 |
|---|---:|---|
| 同时有效 D1 短约 | 6 | 新签前结束或续转旧契约 |
| 单街区未持久路人 | 12 | 远处以群像 / 剪影表现 |
| 单城市未持久路人 | 48 | 分街区与班次加载 |
| 全存档持久路人 | 无硬上限 | UI 按时代 / 地点 / 关系分页；存档预算由 `tech/05` 实测 |

未持久路人离开视野 30 游戏日后可回收；已招募、羁绊 ≥20 或有未结事实者永不自动删除。若性能超预算，只卸载外观与寻路缓存，不删除身份、关系、生死和契约。

## 8. 持久化记录

```ts
interface GeneratedNpcState {
  id: string; // 运行时 UUID；不与静态 NpcId 混用
  seed: string;
  identityRevision: number;
  chapterId: string;
  bornYear: number | null;
  ageBandAtSpawn: string;
  culturePool: string;
  nameTokens: string[];
  publicLabel: string;
  occupation: string;
  home: { cityId: string | null; districtId: string | null; householdId?: string };
  scheduleKey: string;
  combatEligible: boolean;
  persistentReasons: string[];
  recruitment: { state: string; contractUntilDay?: number; wageDue?: number };
  lifeState: 'alive' | 'dead' | 'unknown';
  companionSnapshot?: unknown; // 具体类型见 design/18 §7.3
}
```

出生年在首次生成时由 `appearanceYear − sampledAge` 计算并锁定；不能每次加载按年龄段重抽。进入后世书界时与具名人物使用同一健在判定；普通人不因曾被招募而获得超自然长寿。

## 9. 校验用例

| 编号 | 输入 / 操作 | 预期 |
|---|---|---|
| COM-01 | 同存档、同周、同槽连续加载 3 次 | `stable_uuid` 对相同命名空间与哈希输入生成相同 `runtimeId`；姓名、职业、年龄与需求也完全相同 |
| COM-02 | 不同存档种子加载同槽 | 可不同，但都通过禁名与地域闸门 |
| COM-03 | 路人好感升至 20 后离开 31 日 | 仍保留；不得被回收或换人 |
| COM-04 | 未互动路人离开 31 日 | 可回收；旧 `runtimeId` 永不分配给新人 |
| COM-05 | 生成 `child` + `guard` 冲突组合 | 修正为非战斗家属 / 学徒，不能生成儿童战士 |
| COM-06 | 契丹专名池未校审 | 显示职业称，构建给警告，不生成伪音译名 |
| COM-07 | 命中静态人物同名同姓 | 重抽显示名；不得添加数字冒充另一静态人物 |
| COM-08 | 招募唯一照护者 | 要求家属安置；拒绝时保留可读原因 |
| COM-09 | 14 段书眠后检查 D1 旧同伴 | 按实际出生 / 死亡判定；不得冻结年龄或自动复活 |
| COM-10 | 年龄权重求和 | 恰为 100%；城市修正后重新归一化 |
