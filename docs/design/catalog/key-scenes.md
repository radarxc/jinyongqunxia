# 各书重要场景情景图名录

> 归属（基准 §18）：剧情插图（`cg_`）的选景、画面瞬间、构图、身份参考与生产门禁名录；剧情事实仍归各书 `design/story/NN-*.md`，资产流水线仍归 `tech/07-asset-generation.md`。
>
> 上游：`docs/decisions/author-requirements.md` AR-26、AR-29、AR-30、AR-36、AR-39；`design/story/00-yuenv.md` 至 `14-xueshan.md`；`design/chapters/00-yuenv.md` 至 `14-xueshan.md`；人物层级与身份立绘来自 `assets/default/prompts/characters/**` 及对应 manifest。
>
> 引用而不重定义：回目、锚点、改命结果与人物生死只引用各书 story；`npc_*` 的生卒、招募与外貌归 `design/18`；`por_*`、`cg_*` 的格式与生产状态归 `tech/07`。本文不把候选插图当成运行时场景 `sc_*`。
>
> 标注约定：**（原创扩展）** = 原著没有的内容；**（待考）** = 须以三联 / 广州修订版逐字核对；**（待核实）** = 技术事实尚未联网确认；**（待实测）** = 需真机或真账号验证；**【建议值】** = 依赖其他文档的暂定值；**（生产门禁）** = 提示词可用，但须等指定立绘通过审核后才可出图。

## 0. 使用口径

1. 本名录是**候选清单**，不等于入库清单：初版为 `4 + 14 × 7 = 102` 个规划行，主角精修两轮又只追加 6 行，故当前共 **108** 行。正式书每书保留不少于 7 个候选；候选多少不直接推导入库或最终采用数。
2. AR-36 后，正式插图改由 codex 主角精修任务按书制作并配古风题字，目标为巨作每书 8–10 幅、其他作品每书 4–6 幅；所有生成结果依 AR-39 落库。入库统计只认 `assets/default/scene/chNN/manifest.yaml`：截至 2026-10-03，ch01–ch14 共 `8+8+8+8+8+5+5+8+5+3+3+5+5+3=82` 幅，均为 `status: candidate`；序章尚无 scene manifest。
3. 资产 ID 使用 `tech/07` §1.4 已登记的 `cg_`，格式为 `cg_chNN_<语义>`。Canon §12 已废止旧 `scn_*`；运行时 `sc_*` 只表示章节相位 / 关卡实例，不用于本名录。
4. 每张为 1536×1024、3:2 横幅源图，服从本任务直接要求。若进入运行时 16:9 CG 管线，必须另做安全区裁切验证，见文末依赖。
5. `reference_upload` 按同 ID 提示词 frontmatter 记录精确 `por_*` asset_id 与参考图顺序；AR-36 / AR-39 生产批次允许使用已落库的 `status: candidate` 人物立绘作身份参考，不再以 `approved` 为前置条件。参考图只锁定本人面容、成年年龄、发式与本场适用服饰，不复制姿势、背景或光线。
6. 全体人物按一眼可辨的成年样貌表现。原著早年 / 童年事件只以成年化追忆、远景剪影或改选成年阶段处理，不生成幼态主体；不复刻真人、演员或剧照面容。
7. 打斗强调关系、阵势与动作方向，不表现血腥特写。亲昵或玩闹强调诙谐与心动，衣着完整，不做性化处理。
8. 下表“文字外貌”只服务本场出图，不重定义人物名录。`status: ready` 只表示提示词已完成；缺少可映射的 `por_*`、人物阶段不符或跨书一致性未解决时仍须记录生产门禁，但 `candidate` 状态本身不构成失败。

## 16. 本文新增术语与 ID

- 当前登记 108 个 `cg_chNN_<slug>` 剧情插图候选资产 ID：初版 102 个，主角精修两轮追加 6 个；完整清单即 §1–§15 表格首列。前缀 `cg_` 已由 `tech/07` §1.4 定义，本文只登记具体资产，不新造前缀。
- **身份参考**：同 ID 提示词 frontmatter“参考图顺序”中的 `por_*` 资产；允许使用已落库的 `status: candidate` 立绘，只锁定该人物面容、成年年龄、发式与本场适用服饰，不锁姿势、背景、机位或光线。
- **生产门禁**：`status: ready` 只表示提示词可执行；缺少可映射的 `por_*`、引用文件不可读、人物阶段不符或跨书一致性未解决时，不得进入正式生产。`candidate` 状态本身不是门禁。

## 17. 数据校验规则与测试用例

1. 数量：当前候选行核算为 `102 + 6 = 108`；序章现有 4 行，正式书每书规划行不少于 7。候选数不等于成品数；各书实际入库数只从 `assets/default/scene/chNN/manifest.yaml` 统计，并与 §1–§15 标题中的“入库 N”一致。
2. ID：场景 ID 全局唯一并匹配 `^cg_ch(0[0-9]|1[0-4])_[a-z0-9_]+$`；提示词文件名、`asset_id`、`output` basename 必须相同。
3. 参考图（规划阶段）：`reference_upload` 中作为人物身份参考的每个 asset_id 必须能映射到现有 `por_*` 人物资产；名录精确 asset_id 与路径 basename / 参考图顺序一致。`status: candidate` 合法，白马候选也可使用完成唐代化的人物立绘。
4. 参考图（正式出图阶段）：执行前逐条解析人物登记与对应 manifest，要求引用文件可读、哈希与登记一致、人物及年龄阶段吻合；缺图、未登记、哈希不符或阶段不符才触发生产门禁。生成结果必须按 AR-39 写入对应 scene manifest，入库状态可为 `candidate`。
5. 提示词：每份恰含一个中文 `text` 代码块，明确 3:2、人物动作 / 站位、参考图顺序用途、统一画风与排除项。
6. 安全：所有人物一眼成年；禁止真人 / 剧照复刻、幼态、性化、血腥特写；绿柳庄只用中景，足部不得成为视觉中心。
7. 测试：正式书规划行少于 7、重复 ID、参考 asset_id 无法映射现有 `por_*`、名录 / frontmatter 不一致、生成结果未写入 scene manifest、字段缺失或输出非 1536×1024，均判失败；引用文件缺失、不可读、哈希不符或人物阶段不符也判失败。不得仅因参考或成品为 `candidate`、或白马场景使用唐代化参考图而判失败。
