# NPC 名录 · 城市与设施

> 归属：`design/18-npc-and-companions.md` 的设施 NPC 分层名录；招募难度、生卒 / 年龄、同伴状态与价格换算由主文定义。
> 上游：AR-04（统一地图与历史城市）、AR-06（营生）、`design/02`（时代）、`design/10` §13.5（时收入锚点）、`design/11`（区域玩法）、`design/16`（营生契约）、`design/19` 与 `design/map/cities.yaml`（正式城市 ID）；本文只给设施 NPC 生成模板与仍需实测的 **【建议值】**。
> 引用而不重定义：城市坐标 / 时代名称归 `design/19`；区域探索归 `design/11`；赌场、镖局、山庄职位和报酬归 `design/16`；商店货池归 `design/10`；任务 DSL 归 `design/12`。
> 标注：`city_*` 必须解析到 `design/map/cities.yaml`；`facilityKey` 是城市记录内局部键；“某姓掌柜 / 某行脚”等是生成槽，不是虚构原著人物，也不建立静态 `npc_*`。
> 版本：v1.2；全局审计（2026-09-26）。

## 0. 设施 NPC 的生成单位

一个营业场所由 `facility instance + role slots + shift` 组成。场所开关取时代城市层；角色身份取稳定种子。营业场所易主时，不覆盖已招募者的 NPC 状态，而给空缺角色槽生成接班人。

| 字段 | 规则 | 示例 |
|---|---|---|
| `facilityKey` | 所属城市记录内局部键，不注册全局前缀 | `kedian_01`【建议值】 |
| `cityRef` | `design/map/cities.yaml` 已登记的正式 `city_*` | `city_kaifeng` |
| `roleKey` | 场所内局部键，不是全局 ID | `keeper`、`clerk_01` |
| `runtimeId` | 已互动后固化为运行时 UUID；未固化只保留生成种子 | UUID（不占静态 `npc_*` 命名空间） |
| `ageBand` | 从场所允许的年龄段权重抽取 | `prime` |
| `shift` | `dawn/day/evening/night`；同一槽不可在两个地点同时出现 | `day` |
| `recruitment` | 设施角色默认 D2；杂役可 D1，具名剧情人物回主线 D4/D5 | 好感 + 跑腿或日佣 |
| `replacement` | 死亡、退隐或易主后生成新 NPC；原 NPC 记录只读保留 | `successor_01` |

### 0.1 D2 通用对话树

1. **初识**：先问本地行情 / 来路 / 禁忌；解锁场所服务，不直接展示招募按钮。
2. **熟客**：好感达到 20 后开放一条 5–15 分钟的小任务；任务主题必须来自场所日常，不强迫犯罪。
3. **受托**：完成任务或签雇佣契约后开放短约同行；非战斗岗位可选择营地 / 探索支援。
4. **共患难**：好感达到 60 且无未结工资，允许转长期同伴；若其有家属 / 师门，先安置或取得许可。
5. **离职**：结清工资、归还场所信物并完成交班；恶意欠薪触发离队与城市口碑下降。

### 1.1 角色槽数量与换班

| 设施规模 | 常驻槽 | 同屏上限【建议值】 | 换班 | 可被招募后最低留守 |
|---|---:|---:|---|---:|
| 小摊 / 乡店 | 1–3 | 3 | 日 / 夜二班可省略 | 1 |
| 普通场所 | 4–8 | 6 | 日 / 夜两班 | 2 |
| 总号 / 大庄 / 大赌场 | 9–20 | 8 | 三班 + 事件班 | 4 |

“同屏上限”只是场景呈现 **【建议值】**，不限制场所实际名册；超出者在后台、院落或异班。场所被招空时必须由替班 / 接班槽补齐服务，防止招募系统锁死商店与旅行入口。

## 2. 雇佣价与结算

引用 `design/18` §9.1 与 `design/10` §13.5：

```text
I_hour(ch) ≈ 2 × P(主武器, g_mode) × chapterIncomeMul
D1日佣 = I_hour × 0.25h × skillMul
D2日佣 = I_hour × 0.50h × skillMul
D2定金 = 3 × D2日佣
```

`skillMul`【建议值】：学徒 0.8、熟手 1.0、名手 1.5。每日跨过子时结算；不足一日按一日计，主动遣散返还尚未开始的整日预付款。任务强制离队不没收预付款。

### 2.1 天龙书界核算例

`I_hour≈20 两/时`：

| 熟练度 | D1 日佣 | D2 日佣 | D2 三日定金 | 算式 |
|---|---:|---:|---:|---|
| 学徒 0.8 | 4 两 | 8 两 | 24 两 | `20×0.25×0.8`；`20×0.50×0.8×3` |
| 熟手 1.0 | 5 两 | 10 两 | 30 两 | `20×0.25`；`20×0.50×3` |
| 名手 1.5 | 7.5 两 | 15 两 | 45 两 | `20×0.25×1.5`；`20×0.50×1.5×3` |

设施提供食宿可将现金日佣降低最多 20% **【建议值】**，但必须把等值食宿写入契约；不得以“包吃住”降到零。危险任务按 `design/12` 任务难度追加报酬，本文不重定义倍率。

## 4. 地域与时代命名规则

### 4.1 姓名组成

```text
displayName = surname(region, culture, era) + givenName(genderPresentation, era)
publicLabel = displayName + roleTitle
```

- 姓氏与名必须来自经语言 / 历史校审的地域时代词库；不把现代高频榜直接投到所有朝代。
- 宋地普通人可用“姓 + 行次 / 小名 / 职业称”作公共显示，但不能冒充真实历史人名；姓名史细节统一标 **（待考）**。
- 辽、西夏、大理、西域人物不得用汉名池一键覆盖；在专名词库未核定前，显示“契丹译语人”“大理采药人”等职业称，不伪造音译姓名。
- 避免与所有静态 `npc_*` 的姓名、别号重名；若随机同名，重抽名或附真实职业称，不附随意数字给玩家看。
- 店号使用“地名 / 吉祥词 + 行业”，但屏蔽现实品牌、低俗谐音和原著具名场所；未考据店名标 **（原创扩展）**。

### 4.2 时代替换

城市换时代后：保留场所功能槽，不保留经营者本人；先做生卒判定，再按继承、转让、停业三种状态处理。同一店号跨数百年继续存在必须有传承任务依据，否则换新 `facilityRef`。

## 5. 其余城市的生成规则

| 城市类型 | 必选设施 | 候选设施 | 每城建议槽数 |
|---|---|---|---:|
| 都城 / 陪都 | 客栈、市集、医馆、驿站 | 酒楼、赌场、镖局、武馆、官办教场 | 32–56 |
| 商埠 / 水陆枢纽 | 客栈、市集、镖局 | 酒楼、赌场、车马行、船行 | 24–40 |
| 门派驻地城镇 | 客栈、医馆、武馆 | 山庄、药铺、香烛铺 | 18–32 |
| 边关 / 军镇 | 驿站、行旅店、医棚 | 马市、铁匠铺、军需市 | 16–28 |
| 县城 / 普通州府 | 客栈、市集、医馆 | 武馆、镖局、茶肆 | 16–28 |
| 草原 / 沙漠营地 | 商队、马队、医者帐 | 向导帐、临时酒食摊 | 8–20 |

生成步骤固定为：读取城市时代状态 → 选城市类型 → 生成设施集合 → 展开角色槽 → 排除静态具名人物重名 → 绑定班次 → 生成 D2 小任务 → 运行服务不可被招空校验。赌场、镖局、山庄是否必有由 `design/16` 最终裁定；本文不把 AR-06 的“若干场所”误写成每城三类全有。
