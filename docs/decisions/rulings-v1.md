## 1. C01–C23 逐条裁定

### C01 · Z1 威力只归一一次

- **冲突**：`design/03` §3.5 要求以 `P_ref` 归一；`design/05` §2.7、§3.1 给出绝对威力；`design/02` §2.4、§2.7 E1–E11 仍按 `0.5 + 0.05n` 核算。基准 V11-22 已采纳归一，但旧算例未同步。
- **裁定**：`Z1 = 攻击合成 × G(effGrade) × (0.5 + 0.1 × effLayer) × move.power × Mod_armed × Mod_special / P_ref(Ld_攻方, tier)`。`P_ref = G(gMain(Ld)) × (0.5 + 0.1 × lref(Ld)) × τ(tier)`；`τ` 高/中/低为 **【建议值】** `1 / 0.80 / 0.75`。其他乘区不再除 `P_ref`。伤害常数须用合法 STD 配装校准，不能把旧常数与新归一重复叠用。
- **需修改**：`02` §2.4、§2.7 及九阳成长轨迹改层数系数并重算；`05` §2.7 显式写唯一归一入口；`03` §3.5 与新 `04` 使用同一参考函数。举例：天上十重 `3.5×1.5=5.25`，普通中武 `2.8×1.4=3.92`，普通低武 `2.2×1.3=2.86`；这三项均尚未除 `P_ref`。
- **理由**：遵守基准 §9；防止后期攻击、武学、等级三次放大，以及重复归一。

### C02 · 耗内基准与合法典型配装

- **冲突**：`03` §3.5 明定 `MPREF = STD.mpMax`；`05` §4.1 与 §17.2 D1 虽已采用该名称，Lv35 仍写 4,559，而 `03` 同版为 4,697。`03` 的 STD 又给常规衣、鞋等配置天级品阶，与基准 V11-31 冲突。
- **裁定**：`MPREF(Ld) = STD(Ld).mpMax`；不是裸装 `MP_LV`，也不是施招者自己的 `mpMax`。耗内按 `max(1, round(mpCost × MPREF × 耗内修饰))`。STD 装备仅允许基准 §14 的 12 件天级名器，其他槽位最高地上 9；参考主武器如用天级必须指定名录 ID。
- **需修改**：`03` §3.5、§9.3、§10 的参考装备和派生表重算；`05` §4.1、D1 暂引用 `03`，删除重复写死的 4,559。4,697、Lv70 28,887 及约 2.1/2.4 倍只保留为旧版**【建议值】**，R03 合法配装重算后一次同步 `04/05/09`，不得声称已校准。
- **理由**：`MPREF` 是招式定价基尺；让回内使用个人内力、耗内使用典型内力，才能区分人物内功成长。

### C03 · 回内上限为 6%

- **冲突**：`03` §4.8 与 `05` §5.5 的内功回内合计曾使用不同上限；基准 V11-19 已明确 6%，需清理旧预算及解释。
- **裁定**：`mpRegen = clamp(1 + Σ(内功回内贡献 × innerScale × 主辅比例) + 其他百分点修饰, 0, 6)`，每次自身行动开始回复 `floor(真实 mpMax × mpRegen / 100)`，资源不超过上限；封内力等暂停规则仍按 `06`。
- **需修改**：`05` §5.5 及示例内功、图鉴贡献预算与 `03` §4.8 同步；`04` 模拟用真实 `mpMax` 回复、`MPREF` 耗内。删除“6% 上限保证任何招式都净耗内”的结论：典型角色 5% 招式确可被 6% 回内覆盖，应以连续高耗招式和整战资源曲线验收。
- **理由**：基准已定上限；两个不同分母不能直接用百分数相减证明所有招式净耗。

### C04 · 突破点服从显示等级

- **冲突**：`02` §2.5 的跨界保留描述可读成高修为分配全生效；`03` §2.8 的 `realmAlloc` 按突破等级启用。
- **裁定**：保留全部真实等级、突破分配和洗点记录，只启用 `突破等级 ≤ Ld` 的点。普通 `Ld=min(Lr, chapterCap)`；被登记的超限 Boss 为 `min(Lr,70,chapterCap+δ)`，高/中/低 `δ=3/4/6`，每书界至多 2 名，不豁免武学品阶、层数与修为门槛。
- **需修改**：`02` §2.5、压制示例和 `03` §9.2 统一表述；章节 Boss 配置登记超限名额；旧待决改“已解决：按基准 §3、§5 生效”。例：普通真实 70 入鹿鼎只显示 44，Lv51/61 突破点暂不生效；洪安通若登记超限，至多显示 50。
- **理由**：基准 V11-09、V11-14 已定；保留记录与当前生效是两件事。作者体验选项见决策单 P36。

### C05 · 满级经验与武学积蕴分别处理

- **冲突**：`02` §2.5 描述到书界上限仍累积真实等级经验；`13` §2.6–2.7 转为修为余韵；`02` §2.4 的武学截断文字又容易误伤历史层数或修为瓶颈经验。
- **裁定**：角色到 `chapterCap` 后的新增角色经验按 `13` 的既有兑换率转余韵，不再提升真实等级；一次发奖跨阈值时，先扣升至上限所需经验，再转换余量。武学真实层数不回退：只被 `gateCap` 或来源上限卡住而未达到书界层数上限时，保留 `sxp`；达到书界层数上限后的新增武学经验才转 `latentExp`。既有兑换率不在本裁定重定。
- **需修改**：`02` §2.4–2.5、`05` §3.3–3.4、`13` §2.6–2.7 加入阈值分段和两类瓶颈用例。天龙 Lv35 的天级八重仍未到高武十重上限，后续 `sxp` 不提前转积蕴；鹿鼎到八重后才按其规则转积蕴。
- **理由**：遵守 V11-10、V11-11 和 A2.R；避免强制遗忘已经练成的层数。

### C06 · 经验与难度已部分解决，保留追溯

- **冲突**：`TODO.md` C06 称 `09` 自拟公式与 `13` 不同；实查 `09` §11.2、§12.1 已与 `13` §2、§5.1 对齐。旧待决记录仍需收束，不能按摘要改回旧稿。

### C07 · 九阳不附送毒免与内伤免疫

- **冲突**：`02` §2.7 E1 泛称外来九阳免疫毒与内伤；`05` §9.2、§13.4 定义六重寒免、十重缩短毒持续；`06` 的免疫逐标签、逐品阶判定。
- **裁定**：有效六重解锁 `bf_mian_han`，覆盖 `cold` 标签并按 `06` 品阶对抗；不自动赋予 `bf_mian_du` 或 `bf_mian_shang`。十重大成的 `poisonDurMult=0.5` 仅在第十重被动当前可用时生效，不等于毒免、内伤免疫或根治特殊毒。
- **需修改**：`02` E1 改为“达到六重时免疫不高于自身有效品阶的寒类新效果；高品依穿透规则处理”；中武普通九重不能使用十重毒时长减半。`05` / 图鉴补被动解锁条件，`06` 的寒毒根治继续走专用解法。
- **理由**：免疫、抗性、缩时和根治不能互换。原著“百毒不侵”的具体表述保留**（待考）**，不据此新增系统免疫。

### C08 · 战后和休息清理采用跨战斗表

- **冲突**：`03` §5.6 写战后清除回合制减益、休息清低层毒伤；`06` §5.4.2 规定中毒、剧毒、内伤等跨战；`09` §7.4 已给战后阶段顺序。
- **裁定**：战末依次 `onBattleEnd → 清非 persist → 跨战实例转 world → 倒地者按伤势后上限恢复 10% 且本场伤势+1 → 调息 hp+10%、mp+30% → 奖励`，每次回复封顶。中毒地阶起跨战：休息品阶≤8清除，否则减3层；剧毒全部跨战，休息降1品；内伤玄阶起跨战，休息减3层。寒毒、异种真气、走火、情花/蛊/受制没有“休息一律清空”。
- **需修改**：`03` §5.6 删除独立清减益表，引用 `06` §5.4.2；`09` §7.4 第四步写清先确定伤势导致的新 `hpMax` 再取 10%；`08/10/11/12` 的旅宿、疗伤入口只发同一休息事件。每场倒地一次或多次均只加一层伤势。
- **理由**：持续类型不等于是否跨战；避免战末顺序不同导致治疗收益、毒伤状态不同。

### C09 · 猬刺、刀枪不入允许压制后实例

- **冲突**：`06` §8.4 的 `bf_weici` 仅列10，§8.9 的 `bf_daoqiang` 列10–12；`10` 带入后须生成较低品阶实例。但06 §2.1已说明 `gradeRange` 约束原生配置、压制后低于下限合法，因此任务摘要“生成不了”仅在校验器误把该字段当运行时范围时成立。
- **裁定**：采纳目录原生允许范围 **4–12**，便于明确登记较低品阶的同类护体来源；这不新增天级名器。装备触发用当前 `effGrade`，按06公式缩放与品阶对抗。构建检查原生配置范围；运行实例仍允许因压制/削品降至1–3，不报越界、不钳回4，也不保留原始天级威力。
- **需修改**：`06` §8.4、§8.9 与构建校验改范围；`10` §5 的软猬甲等触发模板给出带入低武用例；`02` 装备示例只引用。
- **理由**：原生配置范围与运行有效品阶分开；扩大目录范围不能代替修正错误的运行校验。

### C10 · 轻功算例使用合法鞋和有效层数

- **冲突**：`03` §4.5.1–4.5.2、§9.3 用“天中鞋”；`10` §3.2、§4.1 与基准 §14 均不允许天级鞋；天龙凌波例又使用被 `05` §3.3 禁止的十重。
- **裁定**：鞋主属性 `Q_eq=2.5×gUse`，普通鞋绝对品阶≤9；强化不放大鞋轻功。轻功武学项严格为 `QS(effGrade)×(0.40+0.06×effLayer)`。天龙 Lv35 凌波最高有效八重，不以十重判门禁。
- **需修改**：`03` §3.5、§4.5、§9.3 及 `08` §4.6 全书界表重算。可复算的无 Buff、无负重例：天龙 `agi=73, apLight=55, 凌波11品8重, 本土8品鞋, 主运8品8重`，`Q=10.75+10.5+152×0.88+8.25+20+3×2.2×0.8=188.54`，仅 qg4；再加10点仍为198.54。倚天 `agi=87, apLight=80, 9品轻功10重, 本土9品鞋, 主运12品10重`，`Q=14.25+21+120+12+22.5+10.5=200.25`，为 qg5。
- **理由**：沿用 `03` 现行公式的合法输入，不能证明所有实际路线必然达到这些属性。天龙 qg5 只可安排经合法加值单独证明的可选路线，不把无条件到达 qg5 写成主线前提。

### C11 · 疲惫只用一个恢复阈值，撞击只算一次

- **冲突**：`03` §5.3 为体力恢复20%解除疲惫；`06` §8.11 为50%，另附速度和开场CT惩罚；`08` §4.1 Q6 又拆成动作20%/门禁50%。`05` §4.5 撞击是本招单段伤害×0.2，`06` §8.7 却是 `hpMax×2%×G` 并自动眩晕。
- **裁定**：体力到0获得 `bf_pibei`，统一恢复至 `sta≥ceil(0.20×staMax)` 即移除；疲惫期间 `eva flat −15`、`mov flat −1`（仍受移动下限）、禁疾行/纵跃/轻功门禁动作，不再附额外 `spd−10%` 或 `ct−200`。恢复行为引用 `03` 体力恢复率。
- **裁定**：撞击采用 `floor(0.2×D_hit)`，被撞单位为 `floor(0.1×D_hit)`；`D_hit` 为触发位移的那一段已走完伤害乘区、尚未扣护盾的结算伤害。每次位移最多一次撞击，不再过暴击/招架/防御乘区、不触发反击或再次击退；正常扣护盾。免疫击退则不移动也无撞击；无伤害的位移令 `D_hit=0`，纯地形推动只有配置了环境伤害段才有撞击基数。
- **需修改**：`03` §5.3、`06` §8.7/§8.11、`08` §4.1/§5、`05` §4.5 同步；删除“撞击必眩晕”。要眩晕须独立声明 `bf_xuanyun` 并通过招式预算、控制免疫和 Boss 抗控。坠落另走 `08`；同次位移不重复结算落地撞击。
- **理由**：20% 延续属性文档的快速恢复默认；伤害驱动撞击能复用武学预算，避免纯推人技能额外获得按 Boss 总血量计的伤害与免费硬控。

## 4. Reqs 新字段与 dualWield 草案

本节为C16/C17的可执行接口，R05合入 `05` §2.4、§2.9、§7.3、§9.3.2 后作为唯一归属；R03同步属性类型。新图鉴从本轮起按此填写，旧提案条目改为“已解决：见本裁定 §4”。

### 4.1 字段、范围与前置逻辑

| 字段 | 类型 / 范围 | 判定与迁移规则 |
|---|---|---|
| `reqs.skills` | 技艺ID→整数下限，0–100 | 键只允许 `med/poi/antidote/forge/alchemy/formation/music/art/chess/speech`；与基准 §6 十项一致。省略某键＝无该项门槛，0也是合法下限 |
| `reqs.prereq` | 前置条件数组 | 外层各项AND；空数组＝没有武学前置。元素是单项 `{skill,layer}` 或OR组 `{anyOf:[{skill,layer},…]}` |
| `skill` / `layer` | 已注册 `sk_*` / 整数1–10 | 须已学会且当前可用；以该武学的 `effLayer` 判定，无须装配。只有图鉴记录、残篇或尚未忆起的武学不满足 |
| `anyOf` | 至少2个不同武学的单项前置 | 任意一项达到层数即通过；不支持组内嵌套、混入AND对象、自依赖或同一ID重复。作者简写的纯ID列表必须展开并明确层数，正式数据不默认猜层数 |
| `reqs.hard` | 合法条件路径数组，可省略 | 省略与显式列表的区别见 §4.2；未知路径、拼错技艺、负数/小数层数均构建失败 |
| `learnSources[].reqsOverride` | 门槛字段补丁，可省略 | 只对这一条来源生效；合并及删除语义见 §4.3，不改变其他来源或武学本体 |

`lore` 是江湖属性，仍用 `reqs.lore`，不是技艺；医术不写 `medicine`，毒术不写 `poison`。不增加 `cook`、不把水性塞进技艺；若某途径要求会游水，在事件的探索条件中检查 `swimLevel`。所有前置还须通过章节来源可达性检查，不能用“存在ID”代替“本界有合法取得路径”。

```ts
// ArtId直接复用design/03的十项联合类型，不新增第二套技艺ID类型。
type SkillPrereq = { skill: `sk_${string}`; layer: number };
type PrereqClause = SkillPrereq | { anyOf: SkillPrereq[] };
// number在内容schema中约束为整数：技艺0..100，前置层数1..10。
// 沿用Reqs原有attrs/attrsMax/aptitude/morality/sect/level/lore/vow字段。
interface ReqsExtension {
  skills?: Partial<Record<ArtId, number>>;
  prereq?: PrereqClause[];
  hard?: string[]; // 仅接受4.2白名单中的顶层键或条件路径
}
```

### 4.2 hard、软门槛计数与迁移

1. **省略 `hard`**：沿用05默认，`sect/prereq/vow/morality/attrsMax/lore.max` 为硬；`attrs/aptitude/level/lore.min/skills` 为软。默认只作用于实际存在的条件。
2. **显式 `hard`**：它是完整的硬条件选择列表，不再额外并入默认列表；`hard: []` 表示本 `Reqs` 中全为软。列表中的顶层键覆盖所有子项，可细选 `attrs.wis`、`attrsMax.wis`、`aptitude.apInner`、`skills.med`、`lore.min`、`lore.max`、`prereq.0` 等。`sect/morality/vow/level` 各作为一个条件，只接受顶层键；OR组不可选择到某个分支内部。
3. **条件原子**：`attrs/attrsMax/aptitude/skills` 每个实际键各计一项，`lore.min/max` 分别计项；`sect` 的身份与职级共同算一项，`morality` 区间一项，单项前置或整个OR组各一项。OR两支都不满足只计**一个**缺项；外层AND两项都不满足计两个。
4. **惩罚沿用05**：硬项失败不可学；软缺项数为k时，修炼倍率 `max(0.3,0.7^k)`，突破走火概率 `clamp(0,1,0.05×k×(1−wil/150))`，数值变化后重算，不额外发明技艺惩罚。k=2时倍率0.49，wil=50时概率 `0.1×(1−50/150)=6.67%`。
5. **全局规则不属于可软化的Reqs**：`maxLayer=0` 的只见闻来源、残承品阶/来源上限、书界层数上限、修为门槛和断尘等专属解锁规则仍独立执行；显式空 `hard` 不能绕过它们。

迁移时按旧条目明确写出的“硬/软”补全列表；不要只看到 `hard:[sect]` 就给该条目另加本来允许软学习的前置。六脉保留 `hard:[prereq]`，纯阳保留 `[sect,prereq]`；五绝碧海潮生曲补 `skills:{music:50}` 但维持软门槛，倚天屠龙功补 `art:40` 同理。其余图鉴有原数值的沿用原数值，只有自然语言而无门槛数字的条目可不给门槛，不能批量补成40。

### 4.3 来源覆写与依赖校验

- 基础是武学的完整 `reqs`。`reqsOverride` **只按顶层字段合并**：未出现的字段继承；非null值整体替换该字段，包含对象与数组；null删除该字段。例：`{sect:null}` 仅解除门派，`{prereq:[]}` 清除前置；`{skills:{music:40}}` 会替换整张技艺门槛表，不暗中保留旧 `art`。需要保留的键必须一并写出。
- `hard` 未覆写时继承原有模式；若原值省略，应用补丁后再计算默认硬条件。继承显式列表时，删除条件对应的路径一并剔除；覆写 `hard` 则整表替换。替换 `prereq` 数组而使用 `prereq.N` 路径时必须同时重写 `hard`，防止数组顺序变化偷换硬条件；可优先用顶层 `prereq`。
- 例：基础 `hard:[sect,prereq]`，羁绊来源 `{sect:null}` 的有效硬列表为 `[prereq]`；再加 `{prereq:[]}` 才会成为无前置。接受哪条来源，就按该来源的有效门槛计算软惩罚；后续接受另一条合法来源时重新计算，不因全局模板仍有门派项而补罚已经豁免的角色。
- 旧 `special.altPrereq` 必须迁入对应的一个OR组并删除活跃旧字段，不将两支并列成AND；旧 `prereq:[{sk_xxx,5}]` 展开为带 `skill/layer` 的对象。
- 构建期拒绝未知ID、自依赖、空OR、重复分支、嵌套OR及没有任何入口的闭环。可达性按“某来源硬条件成立，AND各项可得，OR至少一支可得”的最小不动点计算；所有路径都互相等待的闭环失败，有独立入门来源打破闭环的关系不误报。章节验证须把身份互斥、来源覆盖、书界上限与前置层数一起计入。
