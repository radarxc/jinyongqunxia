## 至少包含（一级小节按此顺序）

0. **阅读指引与剧情总览**：一张 Mermaid 流程图，显示正线、邪线、选择节点、汇合点、锚点与结局；正邪线的定义：不是开局锁定的阵营，而是由关键选择与品德 `morality` 累积决定的立场，可在选择节点切换但有代价。
1. **原著重要剧情与走向清单**：按原著顺序列 30–60 个关键事件（回目、人物、地点、结果），每条标注在本作中的去向：正线 / 邪线 / 双线共有 / 选择节点 / 锚点 / 支线（交书界文档）/ 不采用（说明原因）。给出**覆盖率表**：原著主要情节 100% 有去向。
2. **主角定位与开局**：穿越者以何身份进入故事（与书界文档"穿越开局"一致，若尚未写成则由本文先定并登记待同步）、与主角团 / 反派的关系起点、首个选择节点在何处。
3. **正线**：8–14 幕（ID `q_{{nn}}_main_z_NN`）。每幕固定字段：标题、原著对应事件（回目）、地点（城市 / 区域，用当时的历史名）、参与 NPC（`npc_*`，来自 design/18）、目标与流程（3–8 步）、关键战斗（对手、强度档位：普通 / 精英 / Boss，机制引用 09，不写数值）、幕内小选择、幕末状态变化（旗标、品德、声望、门派、同伴加入 / 离开）、失败与时限。
4. **邪线**：同样 8–14 幕（ID `q_{{nn}}_main_x_NN`），与原著反派或灰色势力同行，覆盖原著重大事件的"另一面"，有自洽的、完整可通关的走向（不是惩罚性坏结局）；写清与正线共享的幕（ID `q_{{nn}}_main_c_NN`）与分岔点。
5. **选择节点** ≥ 6（ID `dc_{{nn}}_NN`）：位置（在哪一幕之后）、选项（2–4 个）、条件（品德、声望、门派职级、同伴在场、前置旗标、时机窗口）、后果（进入 / 切换正邪线、锚点走原著或改命、NPC 生死、门派关系、天书线索）、是否可逆、汇合点。给一张"节点 × 后果"总表。
6. **锚点事件与改命**：与 `design/01` 锚点总览逐条一致：原著结果 / 改命结果 / 触发条件 / 对后续幕与后书界的影响（与 design/18 的 NPC 生卒一致：改命救下的人物在后书界健在）。
7. **结局**：正 / 邪 × 原著 / 改命至少 4 个结局摘要；天书取得条件（引用 13 的 `tsp_{{nn}}_*`）；书眠过场引子（引用 02 §4）；对下一书界的传承 / 彩蛋钩子。
8. **NPC 与门派清单**：本剧情用到的全部 `npc_*`、`sect_*`（引用 18 / 17；缺的列"待补"并给一句设定）；同伴加入 / 离开时机表（含招募等级与任务门槛）。
9. **原著考据备注与原创扩展清单**；数据结构（幕、选择节点的 YAML 示例，字段与 design/12 的任务 DSL 兼容）；数据校验规则与测试用例（每个原著关键事件有去向、每条主线可从开局到结局连通、选择节点条件可满足）；本文新增术语与 ID；待决事项 / 依赖。
