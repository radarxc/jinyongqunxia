## 要做的事

1. **ID 检查**：运行 `python tools/lint/check_ids.py`，逐项处理：
   - 未定义的引用：补定义，或改用已有 ID；
   - 重命名表中的旧 ID 残留：替换；
   - 拼写近似：确认后统一；
   - 套装成员与 `setTags` 不对称：修正。
   脚本本身有误报的，修正脚本（`tools/lint/**`）。
2. **冲突落实**：逐条核对 C01–C23 的裁定是否已在所有相关文档中落实。报告里给出核对表：冲突 / 文档 / 位置 / 状态。没落实的，直接改。
3. **基准同步**：核对基准 v1.2 变更记录中的每一条都已同步到下游（依据 A3 报告第 6 节）。
4. **数值链抽查**：03 锚点 → 04 模拟（运行 `python tools/balance/damage_sim.py --check`）→ 05 招式预算 → 09 战斗节奏 → 各书界文档的 Boss 数值；02 / 13 的等级上限与经验；10 的装备数值与 04。
5. **归属检查**：同一概念在非归属文档中被重新定义的，改为引用归属文档（基准 §18）。
6. **修改尺度**：以小改为主。需要大改（整节重写）的，列入报告"遗留问题"，不要动手。
7. **跨文档同步收尾**：跨文档同步的第一轮已由 F1a / F1b / F1t / F1n 完成（读它们的报告第 7 节处理总表与"遗留"）。本任务处理：(a) 它们的遗留中属于小改的；(b) 在它们之后才合入的报告——`C3`、`CX*`、`C2`、`H1`、`E3`、全部 `D*` / `D*.R`、以及 F1b 开跑后才审校完成的 `P*.R`——第 6 节"需同步到其他文档"的条目；(c) `tools/agents/reports/_coordinator-notes.md` 中所有条目的最终状态（在报告里给一张 CN 编号 / 处理任务 / 状态表；该文件本身不在你的写权限内，不用改它）。
8. **作者新增需求核查**：逐条核对 `docs/decisions/author-requirements.md` AR-01…AR-13 的"归属与影响"：归属文档是否按要求定义、受影响文档是否只引用不重定义、`author-decisions.md` 追加表中的作者决定（AR-01a…AR-13b）是否落实。报告里给 AR 编号 / 归属文档 / 状态（已落实 / 本次修正 / 遗留）表；小改直接改。
