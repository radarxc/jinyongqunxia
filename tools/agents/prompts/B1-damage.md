# 本任务：撰写 `docs/design/04-damage-formula.md`（伤害公式），并实现 `tools/balance/damage_sim.py`

这是全计划中优先级最高的一篇：03、05、06、09 都在等它。基准 §9 固定了乘区 Z0–Z10 与结算的名称和顺序；基准 §18 规定"伤害 / 治疗 / 命中 / 招架 / 暴击 / 效果命中公式"唯一归属本文。上游各文档已经以【建议值】给出了大量输入，见各文档"待决事项"中归属为 design/04 的条目（例如 `design/03` §14.1 的 D-01、D-04、D-17、D-21）。先把这些条目全部找出来：`grep -rn "design/04" docs`。

## 必须采纳

- **C01**：Z1 威力项按攻方等级期望 `P_ref` 归一（`design/03` §3.5、§10.6）。否则 05 的 `G × L(n)` 全程涨约 6.5 倍，而攻击与气血之比恒定，后期同级约 1.5 击毙命。
- **C02**：耗内基准 `MPREF(L) = STD(L).mpMax`，即典型配装内力，以 03 的定义为准。
- **C03**：`mpRegen` 上限 6%（与 05 内功预算一致）。
- `docs/decisions/rulings-v1.md` 中涉及 04 的其他裁定（如 C11 撞击伤害）。

## 文档至少包含

1. **符号表**：沿用 `design/03` §12 的符号，不另起名字。**取整点与整数化**：结算在哪些乘区边界取整，百分比如何换算为万分点（bp）。`tech/01` §8.3 D4 与待决 P2 要求由本文定义取整点。
2. **Z0 判定**：命中、招架、暴击、效果命中的概率公式（采纳或修订 03 §4.2 的建议），判定顺序、判定开关与判定乘数（在 Z0 生效）；上下限。
3. **Z1–Z10 逐区**：公式、上下限、典型取值区间。Z1 招式威力（品阶 G × 层数 L(n) × 招式倍率 × 攻击合成 × `1/P_ref`）；Z2 比值型减伤（含破防、无视防御）；Z3、Z4 加法合并，Z4 上限 75%；Z5 资质 `apFactor`、内力性质相性 ±12%（05 §5）、兵器克制"破 X"；Z6 暴击倍率；Z7 背击 / 侧击、高低差、地形（与 08 §7 对齐）；Z8 境界差；Z9 招架减免；Z10 浮动 0.95–1.05。
4. **结算**：护体真气吸收顺序；气血；附加效果（内伤、流血、Buff 施加）；吸血 / 吸内；反震；DOT / HOT（06 已定 `bypassShield`）；治疗公式（`healPower` / `healRecv`）；护盾公式；护体完全吸收时不施加 `injury` / `bleed`（03 D-21）。

6. **完整算例 ≥ 6 个**，逐区写出中间值：同级普通战；越级挑战；Boss；低武书界中被压制的外来武学；暴击 + 背击 + 高差；DOT 与护体交互。

   - 单招耗内占 `mpMax` 的比例；
   - 与基准 §5 节奏目标逐项对比。
8. 与其他文档的接口；数据校验规则与测试用例；本文新增术语与 ID；待决事项 / 依赖。待决事项中要**逐条回应** 03、05、06、09 里指向 04 的条目：采纳 / 修改 / 驳回，并写理由。

## `tools/balance/damage_sim.py` 要求

- 只用 Python 3 标准库（兼容 3.9+）。参数放在文件顶部常量或同目录 `params.json`，每个参数用注释标明来源（文档 §）。
- 实现本文的完整管线。Z0 可以用期望值法，也可以用蒙特卡洛；用蒙特卡洛就固定种子，保证结果可复现。
- 主角按 03 的典型配装 `STD(L)`；敌人按 03 §10 的模板，以及 02 中各书界的出场等级带与 `enemyStatMul`。
- `python tools/balance/damage_sim.py --report`：输出 Markdown 表（即第 7 项的内容）。
- `python tools/balance/damage_sim.py --check`：按基准 §5 断言以下各项，全部通过时退出码 0；否则打印不达标项，退出码 1。
  - 普通敌人：主角 3–5 次命中击杀；敌人 8–12 次命中击杀主角；
  - 普通战斗 3–5 轮；精英 6–10 轮；Boss 12–25 轮（按主角行动次数计）；
  - 单招耗内为内力上限的 5%–15%（绝招除外）。
- **调度器会在你结束后运行 `--check`，不通过即视为任务失败。** 先迭代公式与参数，直到通过。如果某项在设计上确实不应满足（例如洪安通这类刻意的难度峰值），在 `--check` 中登记为"已知偏差"并附理由，同时在文档中说明；已知偏差不得超过 3 项。
