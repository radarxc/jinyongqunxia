## 至少包含

1. **同伴系统规则**：招募难度 D1–D5（D1 路人甲：好感 / 银两；D2 设施 NPC：好感 + 小任务或雇佣；D3 门派 NPC：门派职级 / 掌门许可 / 门派任务；D4 有名 NPC：专属任务链 + 品德 / 声望 / 时机窗口；D5 主线核心人物：主线关键幕后、原著线 / 改命线分支限定，部分时段不可招募；给出"永不可招募但可结盟"的名单提案）；有名 NPC 的专属任务链模板（与 12 的任务 DSL 对接）；好感 / 羁绊与 09 合击的衔接；队伍 ≤ 6 与据点 / 客栈留守；离队、死亡（原著命定死亡是否可改命：与 01 / 13 的改命规则一致，给默认）、背叛。
2. **生卒年与年代**：`born` / `died` 字段规范（史实 / 推算 / 待考 / 年龄段）；年龄段 → 能力段的换算（少年 / 壮年 / 老年对属性与武学层数的修正，用 03 §10 的模板表达）；各书界年代对照（引用 02）。
3. **长生诀与跨书界同伴**：沉睡年数表（14 段，引用 02；书眠的机制名为《长生诀》）；苏醒后同伴健在判定（`died` > 苏醒年份，或原著明确在世）；重逢任务模板；能力合并规则（离队快照 + 按新书界原著形象新增能力 / 功力，只增不减）；给 ≥ 3 个算例，选原著中确实跨书的人物（如张君宝 → 张三丰、少年杨过 → 神雕侠、周伯通、黄药师 / 郭靖跨射雕 → 神雕等）；未曾加入的跨书 NPC 按新书重设；已故者的传承 / 遗物 / 后人（原创扩展）。
4. **NPC 数据结构**：YAML 示例与 TS 类型（ID、姓名、别号、出现书界、生卒年、门派与职级、所在城市 / 场所、层级 D1–D5、招募条件引用、武学与品阶、数值模板、AI 人格、羁绊、跨书界标记）；数据校验规则与测试用例（ID 唯一、生卒年与出现书界一致、D4 / D5 必有任务门槛、每部主线 NPC ≥ 20）。
5. **名录（按此顺序撰写，表格压缩）**：
   - ① **主线重要 NPC**：14 书界各 20–40 人（ID、原著身份、生卒年、门派、层级、招募要点、能力要点、跨书界标记、出处回目）；
   - ② **门派 NPC**：按 `design/17` 的门派 × 时代列掌门、长老、亲传与史实人物（标（史实）+ 参考）；
   - ③ **设施 NPC**：店铺 / 赌场 / 镖局 / 山庄 / 客栈 / 武馆 / 医馆等的模板（职能、对话要点、招募难度 D2、雇佣价）、命名规则（按地域与时代）、各主要城市的实例表（至少覆盖天龙时代的 6–10 城作为范例，其余城市给生成规则）；
   - ④ **路人甲**：模板与随机生成规则（姓名池、职业、年龄段、D1 招募条件与数量上限）。
6. 与其他文档的接口（12、09、11、16、17、13、tech/04、tech/05）；本文新增术语与 ID；待决事项 / 依赖（对基准的修改提案：§3 队友跨书界、§1 长生诀术语、§12 前缀；需作者拍板：永不可招募名单、改命可否救回原著命定死亡的同伴）。
