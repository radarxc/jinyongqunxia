# 本任务：城镇程序化生成 · 设计文档、数据格式与两座城的城市规格

## 背景

作者放弃了"整张城镇图纯生图"的做法，改为程序化生成。作者原话（2026-09-29，逐字）：

> 城镇 - 城镇参考对应年代的城镇平面图，生成道路和建筑的坐标，将商业区、住宅区、镖局/衙门区、王府/皇宫 等区域分配到坐标区间内，然后填入功能性建筑。然后按照素材贴图（代码实现），渲染整个城镇的底图（道路，河流，桥梁等）。再根据坐标，贴对应的建筑图（建筑图逐一生成）。

早先的两条作者要求仍然有效：「城市图要45度视角（主角要能在城市地图上移动）」「建筑分两种， 一种是类似立绘，另一种是要拼到城市地图上，第二种要45度」。

协调者把这条管线拆成五个任务，本任务是第一个，产出设计文档、数据格式和两座城的城市规格；后续任务按本任务定的格式做贴片素材（TOWN-tiles）、建筑单体素材（TOWN-buildings）、生成与渲染代码（TOWN-render）和最终组装（TOWN-assemble）。所以本任务写下的每个字段、每张清单都会被代码和素材任务直接消费，要写到能照着实现的程度。

## 要做的事

1. **写设计文档 `docs/design/22-town-layout-and-generation.md`**，章节至少包括：
   1. 结论先行：管线五步（城市规格 → 生成布局 → 贴片底图 → 贴建筑 → 输出）、各步的输入输出文件、与 tech/02 / design/11 的衔接。
   2. **网格与画幅**：沿用 1 m 格；基线城镇场景尺寸给默认值并说明取舍（默认：大理 96×96 标准场景、临安 160×160 大型场景，体现作者说的"大理没有那么发达"），2:1 菱形贴片的像素规格（默认每格 64×32 px，建筑与贴片都按此比例出图），坐标系与 tech/02 §1.6 的换算关系，行走层与遮挡层的约定。
   3. **按年代的城市布局规则**：至少覆盖北宋 / 大理国（ch01）、南宋（ch02–03）、元末（ch04）、明（ch05–07）、清初（ch08–09）；区分里坊制与街巷制，城墙 / 城门 / 主轴街 / 河道与桥的常见格局，皇宫 / 王府 / 衙门 / 镖局 / 商业 / 住宅 / 寺观 / 市场 / 码头等分区的典型位置关系。每条规则给历史依据（写明来源类型，网上资料标"网络资料，待核"）。
   4. **功能建筑清单**：每类建筑一条：`type` ID（形如 `bld_kit_song_yamen`、`bld_kit_song_biaoju`、`bld_lm_ch01_chongshengsi_pagoda`）、中文名、所属年代套件、占地格数 `w×h`（1 m 格）、允许旋转、所属分区、出入口在哪一边、生成时的数量范围、与 design/11 §3.4 / design/16 的营生 / 机构 ID 的对应关系。宋套件（大理、临安要用的）必须完整，其他年代先列骨架。
   5. **贴片清单**：底图贴片种类（夯土地、青砖地、石板路、土路、草地、水面、河岸八向边缘、桥、城墙段与城门、树丛等），每种的 ID（`tex_town_<时代>_<名>` 或你按 tech/07 §1.4 定的前缀）、需要的变体与自动拼接（autotile）规则、像素规格、透明底要求。
   6. **数据格式**（机器可读，另存 `docs/design/town/schema.yaml`）：
      - **城市规格 `CitySpec`**（手写，源自历史平面图）：书界、城市 ID（沿用 `city_*`）、年代套件、网格尺寸、城墙多边形与城门、主轴街与次要街的折线、河道折线与桥位、分区框（类型 + 矩形 / 多边形 + 优先级）、地标建筑的固定坐标（如崇圣寺三塔、御街）、随机种子。
      - **布局 `TownLayout`**（生成器输出）：每格地面类型与行走性、道路 / 水面 / 桥的格集合、建筑实例列表（`type`、左下角格坐标、`w×h`、旋转、所属分区、可选 `poi` 引用）、分区实际覆盖范围、校验摘要。
      - 每个字段写类型、单位、取值范围与示例。
   7. **生成算法说明**：从 `CitySpec` 到 `TownLayout` 的确定性算法（同一种子同一结果）：主轴街 → 次级街网 → 地块划分 → 按分区填功能建筑（数量范围、朝向朝街、出入口临路、不重叠、不压河）→ 道路连通性保证 → 行走层导出。写清楚每一步的规则和失败处理，让 TOWN-render 能直接实现。
   8. **渲染规则说明**：贴片绘制顺序、河岸 / 道路 autotile、桥的叠放、建筑按远近排序（按占地远角 `x+y`）与锚点、阴影与光源方向的统一（与 STYLE.md 及已通过的建筑基线一致）、调试叠加层（分区框、坐标、建筑 ID 的 SVG）。
   9. **两座城的城市规格文件**：`docs/design/town/city_dali__ch01.yaml`（大理国都羊苴咩城，约 1093，苍山在西、洱海在东，崇圣寺三塔在城西北；作者要求：多本地植物、不全铺青砖、多佛教元素、整体不如临安发达）与 `docs/design/town/city_hangzhou__ch02.yaml`（南宋临安，约 1220 年代，御街、坊巷、河道与桥、商铺密集；作者要求：更繁华）。按 §3 的规则和历史平面图手写，每个分区框、地标坐标都给依据。
   10. 需作者确认的事项（默认值列出）、待考项、与其他文档的同步清单（design/11、tech/02、tech/07、tech/06、STYLE.md）。
2. **校验脚本的规格**：在文档里写明 `tools/town/check_town.py` 应检查的项目（规格与布局的 schema、建筑不重叠、不压水、在城墙内、道路连通、每种 `type` 都有素材、行走层与建筑占地一致），供 TOWN-render 实现。
3. 通用：每次写入不超过约 150 行；文首引用块、文末待决事项按规则；不新造玩法 ID（`city_*`、`sc_*`、`poi_*` 沿用既有）。
