# 本任务：把 `docs/00-canon.md` 修订为 v1.1

基准是所有下游代理都会读的唯一事实来源。各初稿累计提出了约 40 条基准修订提案（汇总在 `TODO.md` §4），另有几条跨文档冲突需要在基准层面定下来。本任务审定这些提案并合入基准。

## 输入

- `TODO.md` §4（提案汇总）、§3（冲突表，其中 C04、C05、C15 等与基准直接相关）、§2（已定结论）。
- 各文档中的"对基准的修改提案"小节：`grep -rn "对基准的修改提案" docs`，逐篇读原文（提案编号、理由、上下文），不要只看 TODO 里的摘要。

## 做法

1. 逐条审阅提案。以下类别直接采纳（TODO 已建议先批准）：
   - §12 ID 前缀（03、06、02、05、10、08、13 提出的全部新前缀）；
   - §6 次级属性 `hpRegen` `mpRegen` `rageGain` `shieldMax` `staRegen` 与水性 `swimLevel`（0–3）；
   - §3 截断语义（有效层数截断、真实层数保留、超出部分转为积蕴）；
   - §3 等级封顶后经验转为"余韵"。
2. 其余提案：与现有基准不矛盾、理由充分的，采纳。有争议或影响面大的（例如高武原生天级上限改为 ≤ 16、越女剑法定级、自创武学的外来压制减半、Boss 超出书界等级上限的幅度），写出你的推荐并按推荐值写入正文，同时在变更记录中标"⚠️ 待作者确认"。
3. 同一概念有多份提案且彼此不一致时，选一个并说明理由；不要把两种写法都放进基准。
4. 在文首引用块之后加：
   - 版本行：`版本：v1.1（{{date}}）`；
   - "变更记录 v1.1"表：编号 / 章节 / 变更 / 来源（文档 § 或 TODO 条目）/ 状态（已采纳 / ⚠️ 待作者确认）；
   - "未采纳的提案"表：提案 / 来源 / 理由。
5. 保持基准的风格：精炼、表格化，只放定义和硬规则，细则留给归属文档（§18）。基准正文预计增加 60–150 行，不要写成长篇论述。
6. 需要下游同步的改动写进报告第 6 节，按文档分组（这是后续修订代理的输入）。
