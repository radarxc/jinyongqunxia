## 3. 关键结论与数值

### 3.1 定稿结论

- 资源品级保持作者决定：天地玄黄四阶，每阶一品最高、九品最低，共 36 级；`resourceLevel=9T+(10-rank)`，材料映射为 `materialGrade=3T+1+floor((9-rank)/3)`。穷举结果为 1～36 各一次。
- `design/11` 的十四界预算逐行原样复用：103 个开放区域、229 个资源点时代实例、280 个赌场 / 镖局 / 山庄时代实例。
- 家丁默认不上场、不占六人编组；同一 NPC 的家业岗位与活动 / 留守同伴状态互斥。
- 客卿全存档同时最多一份活动合同；合同集合与 `activeKeqingContractId` 必须双向一致，签约和解约均在同一事务。教头可签多处，但日程块不可重叠。
- 资源点、营生、门派和赌场从同一 `I(ch)×H` 总盘分桶，不叠加新钱；转仓、买卖、封装与本金返还不重复创造经济价值。
- 书眠清空银两、资源库存、资源点状态、家丁合同、职位、门派身份 / 公账和家业设施；成就只记里程碑，不恢复资产。

### 3.3 数据契约修正

- 资源价值区间由错误的 `Vbase` 区间改为类别中值 `Vref=Vbase×C(category)` 的区间，避免类别倍率只影响中值却不影响上下界。
- 资源预算改为整数文 `B_resWen=floor(0.08×I×H×1000)`；维护、工资、现金报酬才走 `round10`，消除预算和账期的重复取整。
- 增加 `ResourceLocation` 与 `transfer_resource`，点仓必须带 `pointRef`；转仓保留原 provenance lot，搬运收据不进入库存，栈数量必须等于 lot 数量之和。
- 家丁 YAML 补 `contract.servantRef/state`，并将 `assignment` 按 TS 契约嵌入合同；`assign_servant` 可指向资源点、场所或门派。
- 将场所门槛的 `localMartialGrade` 改用独立 `MartialGrade` 类型，不再借用语义不同的 `MaterialGrade`。
- 将 `estateValueCreated` 明确为整数文 `estateValueCreatedWen`，并统一 `createdAtWorldTick`、`SectLedger.treasuryWen` 等字段名。
- 客卿唯一键补成集合与索引的双向不变量，并增加损坏存档拒绝和并发签约测试。
