## 3. 关键结论与数值

| 主题 | 结论 / 数值 | 推导或依据 |
|---|---|---|
| 更新模型 | `Command → validate → apply → DomainEvent[] → state`；拒绝命令零写入、零 RNG、零领域事件 | 单命令 journal 事务；成功后一次提交版本、RNG 与事件 |
| 状态 | 单一版本化 JSON 树；事务内原地更新并 journal 回滚；外部仅深只读快照/裁剪投影 | 兼顾移动端分配预算与原子性 |
| 随机 | `sfc32`，由 `splitmix32` 派生 `battle/loot/world/ai/qiyu` 五流；整数区间用 rejection sampling | 沿用 `tech/01` D1–D9，避免 `% n` 偏差与流间相互扰动；表现随机不得进入 core 状态 |
| 算术 | 安全整数与 `10000 bp`；跨乘区中间值用瞬时 BigInt，按 `design/04` 指定边界取整 | 状态不存 BigInt；Node/WebKit golden 校验逐步哈希 |
| 探索 tick | **10 Hz = 100 ms/tick**；后台、暂停、停时对话均不补跑 | 终结 `tech/01` P3；只由已提交 tick 推进世界日历 |
| 世界换算 | `WORLD_TICKS_PER_SHICHEN=3000`【建议值】；`3000 × 0.1 s = 300 s = 5 min/时辰`，`12 × 5 = 60 min/日` | 等待 `design/11` 定稿 |
| 六角格 | pointy-top 轴坐标 `(q,r)`，立方 `s=-q-r`；距离 `max(|dq|,|dr|,|ds|)`；稳定序 `(r,q)` | AR-12、`design/08/09`；范围为点/环/面/扇形 |
| 战斗时序 | 首轮按有效轻功全序，随后事件驱动 CT；反应 FIFO、嵌套深度 ≤3、来源位继承 | 覆盖招架、反击、连击、合击、阵法、环境行动者 |
| 伤害 | 每目标每段按 Z0→Z10 执行，在归属公式规定位置取整；每段可输出 `DamageTrace` 与 `Settlement` | 可定位每个乘区的输入、输出、取整与来源 |
| Buff DSL | 构建期编译为受限字节码；接入 59 hooks / 约 50 原语；按 `(priority,iid)` 派发 | 热路径复用 bucket/scratch，普通攻击目标为零临时数组/闭包（待实测） |
| DSL 护栏 | 每段 ≤256 指令、事件深度 ≤32、每根命令 ≤4096 ops【建议值】 | 等待 fuzz 与最大 Buff 基准回填 |
| 周期产出 | 只按逻辑日历边界补结算，使用 `lastSettledPeriod` 幂等；禁止墙钟 | 覆盖资源点、家丁、营生职位与门派月钱 provisional 状态 |
| 同伴 | 当前周目跨书保存离队能力快照；先判健在，再以快照为下限合并后世能力；新周目重置运行态 | 对齐 AR-09 与 `design/18`，避免把跨书误作跨周目 |
| AI | Utility AI + Boss 阶段机；确定性 `workBudget` 决定搜索边界，5/15/40/80 ms 仅为 host SLO | 设备差异可改变选招，但最终命令入录像，core 结算仍可复放 |
| 回放 | 开局封闭快照 + 全部已接受战斗命令 + RNG/协议/内容版本 + 终局 SHA-256；每 10 命令中间 hash【建议值】 | 重放不重跑 AI；战后世界写回另以收据原子提交 |
| 性能 | 探索 tick P95 0.5 ms、所在帧峰值 2 ms、预测 ≤8 ms、活动逻辑单位 ≤24 | 均为设计预算；须按 `tech/03` 真机矩阵实测 |
