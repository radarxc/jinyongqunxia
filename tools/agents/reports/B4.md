## 3. 关键结论与数值

1. **任务契约**：任务只允许 `main / side / faction / bond / qiyu`，ID 为 `q_<两位书界号>_<类型>_<两位序号>`。条件编译为无副作用白名单 AST，动作先生成命令再由 core 重验；持久效果 ID 为 `<questId>/<stageId>/<effectLocalId>`，不得使用数组下标。
2. **完整夹具**：提供主线分支、门派晋升、D4 招募、跨书重逢、走镖 / 护院、资源点 / 家丁事件、限时奇遇 7 个完整任务夹具；7 个任务 ID 全仓无冲突。正文另给 `QuestDef`、`QuestInstance`、`NpcInteractionBinding`、`SectProgressionPolicy` 与门派存档示例。
3. **经验与现金**：任务经验只用 `design/13` 的战斗当量；直接现金为 `I(ch)×expectedHours×cashShare(kind)`，其中 `I=2×P(主武器,g_mode)×chapterIncomeMul`。笑傲 30 分钟支线为 `94×0.5×0.70=32.9` 两，配表 33 两。
4. **NPC / 同伴边界**：D1–D5、R0–R6、好感 / 羁绊、生卒、编组、成长和 U0–U5 重逢均读 `design/18`；活动编组仍 ≤6。AI 仅可用 `propose_effects` 提议最多 3 项，每项好感 −1..+1、每段累计绝对值 ≤3，或设置当前节点预登记旗标，其他持久效果全部拒绝。
5. **五级门派**：统一 L1 外门、L2 入门 / 内门、L3 亲传 / 闭门、L4 长老级、L5 掌门级。贡献下限为 0 / 300 / 900 / 2,400 / 6,000，声望为 100 / 100 / 300 / 800 / 1,600，年资为 0 / 3 / 10 / 30 / 90 日；月钱与资源只传 1–5 档。每书界最多一个 L5。
6. **组织汇总**：完整列出 `design/17` 的 99 个 `sect_*`，含 O/H 投放、正邪倾向、加入 / 对抗、武学图鉴、全局 `city_* / rg_*` 驻地和原著依据索引；与权威 99×14 六态矩阵、`map/sects.yaml` 城市及 `design/11` §2.4 区域均一致。
7. **正邪与声望**：`morality` 为跨书界 −100..100，`fame` 为当界 0..9,999；书眠以幂等事务先累加 `fameTotal` 再清零。邪派任务通常 `morality≤−10` 可接触，正式入门通常 `≤−40`，允许图鉴 / 条目显式例外。
8. **经济**：`1 枚铜钱=1 文`、`1 两=1,000 文`；价格为 `P=P0×2.2^(g−1)`。十四界按 11.5 小时横向基线展开收入与 60%–80% 支出目标；收入来源仍为任务 / 战利品 / 掉钱 / 其他 = 50% / 30% / 15% / 5%，营生、资源、家丁和月钱必须纳入既有篮子，不能成为额外无上限收入。
9. **生活技能**：十项技艺用 `T(g)=8g−4`、`gMax=min(12,floor((a+4)/8))`、`Pcraft=clamp(0.60+0.04×(a−T(g)),0,1)`；0→20 / 60 / 92 / 100 分别需 130 / 630 / 1,261 / 1,450 次成功操作。烹饪不读 `alchemy`、不新增 `cook`，采用每菜谱 1–10 的 `recipeMastery`。
10. **质量闸门**：正文定义 QST-V01–V22 与 QST-T01–T30，覆盖引用闭合、任务图、分支互斥、单掷 RNG、幂等、门派身份、书眠、AI 权限、经济与技艺金标准。
