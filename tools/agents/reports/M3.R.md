## 1. 摘要（3–6 行）

已完成 M3 全量审校并直接修正：最大问题是原始路线质量未按同等级 / 同用途 / 同路线 STD 归一，导致不同路线的“标准对标准”不能稳定保持 10000 bp。

五档对战、防守路线、两类护体击穿、四类伤害、同档 / 强者 / 封路 / 受擒速度均与黄金数据一致；旧 `damage_sim.py` 仍为 40/40。

## 3. 关键结论与数值

### 3.1 审校修正

| 位置 | M3 原值 / 口径 → M3.R 定稿 | 依据 / 复算 |
|---|---|---|
| §3.4 完成质量 | `completionBp=routeQualityBp` → `floor(routeQualityBp×10000/STD.routeQualityBp)`，钳 0–18000 | 标准短路原始质量 4230；`floor(4230×10000/4230)=10000`，否则标准档会被误判为 4230 |
| 模拟器强度输入 | 直接加权 → 气量 / 容量 / 流畅逐项钳 4000–18000，完成质量钳 0–18000 后加权 | 极端输入 `(0,99999,0,99999)` 得 `(30×4000+25×18000+25×4000+20×18000)/100=10300` |

| 护体输出名 | `hpDamage` / `hpDamageBeforeMpGuard` → `damageBeforeMpGuard` | 该值仍须进入既有 `mpGuard`，不是最终气血损失；维持例为 0，击穿例为 1000 / 600 |
| 护体流畅输入 | 未说明原始 / 归一 → 明定 `MeridianProfile.flowBp` 为相对 STD 的 4000–18000 分量 | 标准档 `10000×10000/100000=1000` 容量，与黄金相等 |

## 7. 审校结论

**有条件通过。** M3 的文档、参考实现与黄金数据已达到可交后续 owner 接入的质量；条件是基准 v1.3 正式采纳提案、下游按 §18.6 接线，并完成纸本考据与真机性能验证。

### 阻断

- 已处理：无遗留阻断。标准归一缺失会破坏“标准对标准中性”，现已在文档、脚本、黄金、作者解读和基准提案中统一修正。
- 已处理：原 `qualityReach` 在弱势时读取弱方自身完成度，出现属性增长反而使攻击乘区下降的反例；现统一由当前强度优势方的完成质量兑现差距，并以双向、四分量、四路线长度扫测锁住单调性。

### 重要

- 已处理：护体剩余量曾被命名成 `hpDamage`，可能绕过既有 `mpGuard`；现统一为 `damageBeforeMpGuard`。
- 已处理：擒拿曾同时进入 `combinedSpeedBp` 与经脉闪避差，可能重复惩罚闪避；现闪避差只读纯经脉速度，擒拿倍率由 04 / 06 另算一次。
- 已处理：速度在综合 Profile 已含完成质量后又按原始路线质量向中性混合，极弱档存在质量 3→4、速度 `10000→9999` 的反向台阶；现删除二次输入，直接查单调速度曲线，并补精确反例与四分量扫测。
- 已处理：黄金嵌套键与 TypeScript 契约不一致，且缺逐段 `trace`；现统一 camelCase，并为所有路线向量输出 / 校验 trace。
- 已处理：敏感性分析把原始质量直接当相对 Profile；现按同路线 STD 6302 归一并更新表值。

### 一般

- 已处理：明确偶数敌人时的中位数算法、补齐 TypeScript 最小类型、逐输入钳制与受擒强者黄金用例。
- 已处理：主文档追加“审校 M3.R（2026-09-27）”；§18.6 已逐项覆盖 03 / 04 / 05 / 06 / 08 / 09 / 13 / 14 / 15 / 图鉴 / tech/05 与 Canon。
