# ENG-12d-clip-perf 报告 · 游戏工程 · 动作原型 P9 补：片段驱动 rig 的 CPU 优化（100 人片段模式低负载 P95 ≤ 0.5 ms；接口、金样与阈值不变）

## 1. 摘要（3–6 行）
- 完成片段投影共享缓存、采样间隔投影/affine 复用及无脏数据快速返回；公开接口不变。
- 100 人片段门禁 min P95 从基线 0.764 ms 降至 0.299 ms；另一次较低负载实跑为 0.288 ms，达到 ≤0.5 ms 目标。
- Python 投影金样最大误差仍为 0 px @128 ppm；程序步态快照、2 draw call 与现有门禁阈值不变。
- 缓存和热路径使用预分配 typed array；测试覆盖命中以及偏航、clip、滞回历史、切片和淡出边界。

## 2. 产出（文件、行数、主要章节）
- 运行时：`project.ts` 257 行（共享投影/FK 缓存、三角函数复用），`character.ts` 456 行（affine generation），`instance-buffer.ts` 115 行（无脏快速返回）。
- 测试：`project.test.ts` 164 行、`clip-player.test.ts` 121 行、`character-clip.test.ts` 104 行；新增命中与全部失效路径回归。
- 工具：`clip-perf.bench.ts` 83 行，本地独立分项 benchmark，不进入 `pnpm check`。
- 契约：`packages/render/CLAUDE.md` 125 行；本报告登记结果与下游接入约束。

## 3. 关键结论与数值
- 分项口径均为 100 人、120 帧预热、3×600 帧取 min P95；前后系统负载不同，数值用于定位瓶颈而非统计置信区间。
| 分项（ms） | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 播放器投影 | 0.440 | 0.075 | -83% |
| 角色 update（含投影） | 0.531 | 0.142 | -73% |
| batch sync | 0.105 | 0.104 | -1% |
| update + sync 总计 | 0.641 | 0.245 | -62% |
- 最终 `check:perf`：loadavg 13.86/11.10/10.04、12 CPU；20 人 / 100 人程序 / 100 人片段 min P95 = **0.072 / 0.356 / 0.299 ms**。
- 较低负载复测：loadavg 8.60/8.75/9.16、12 CPU；三项 min P95 = **0.075 / 0.367 / 0.288 ms**。
- 金样：64 个帧-方向样本 × 4 关节，最大误差 **0 px @128 ppm**（门槛 ≤2 px）；`clip-map.yaml` 无差异。
- draw call = **2**；`projectionAllocations = 0`；每 clip/RigSet 预分配 `32×776 = 24,832 B` typed-array 载荷（不含对象开销）。

## 4. 开放问题（附默认值）
- 未遇到完全空闲的机器窗口；默认接受已在 1 分钟 loadavg 8.60/12 CPU 下达到 0.288 ms，发版前仍按既有流程在更空闲窗口复跑并登记。
- 未做浏览器 heap profiler 精确 B/帧采样；默认以固定输出身份、预分配缓存、`projectionAllocations=0` 和代码审阅作为稳态零分配证据。
- 未新增外部版本、API、价格或限额事实，联网核实不适用。
