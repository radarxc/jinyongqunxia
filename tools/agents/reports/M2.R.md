## 3. 关键结论与数值

### 3.1 定稿口径

| 主题 | 结论 |
|---|---|
| 名称与归属 | 正式称“绝招”，复用 `MoveDef.ultimate`；15 拥有 20 脉 / 180 穴与战外成长，21 只拥有战内动态投影 |
| 实例与随机 | 每个可独立武学行动者一份状态实例；所有提交按战斗事件全序消费 `BattleSession.battleRng`，preview 不改状态也不抽 RNG |
| 路线上限 | `floor(1200n/(n+6)) bp`；1 / 2 / 6 / 10 / 18 段 = 171 / 300 / 600 / 750 / 900 bp，1–64 段严格递增且 `<1200` |
| CT | `flowCt=Σ实际尝试段 CT`，作为 09 的 `Σrec_flat`；最终 `rec_eff` 钳在 500–2000，配表要求基础收招 + 满路线 CT ≤2000 |
| 控制标签 | 擒拿属于主标签 `cc`、子标签 `cc.bind`；现行主标签 `bind` 留给豹胎易筋丸、生死符等长期受制，不混用 |
| 调息 | 合并 09 的 1000 CT 调息；顶级调和档 `relief=2500 bp`、修复 617；9 级点穴在战内外都禁自行调息 |
| TTK | 同一我方攻击者接入前后：普通 5→5、精英 9→9、Boss 22→21，均在 04 的 3–5 / 6–10 / 12–25 区间 |
| 敏感性基准 | 平均伤害 880、`TTK×100=452`、攻击频率 4925 bp、调息占比 1258 bp；单段 CT −20% / +20% 时频率为 5282 / 4879 bp（加长端受 2000 钳制） |

## 7. 审校结论

**结论：有条件通过。** 文档和参考实现已达到可交给下游实现的质量；条件是未越权代做的 v1.3 采纳、其他 owner 文档同步、纸本考据与真机 / TypeScript 验证。

| 严重度 | 发现的问题 | 处理方式 / 状态 |
|---|---|---|
| 阻断 | 每单位自持 RNG 与 tech/05 唯一全局 `battle` 流冲突；多单位 golden 未真实共享提交序列 | 改为 Core 注入同一 RNG，单位快照不含 RNG；普通→精英→Boss→自解穴固定推进；已解决 |
| 阻断 | 18 段等路线加 CT 后超过 09 的 `rec_eff≤2000`，会产生免费段 | 路线缩至 9–10 段并增加构建门禁；已解决 |
| 阻断 | 把 `bind` 长期受制标签误用为擒拿，导致所有 Boss 被错误免疫 | 改为 `cc.bind`；Boss 1–8 级限 1 行动、9 级走硬控递减，终局免疫；已解决 |
| 重要 | 精英 TTK 使用敌方实例增益且算成 8，和“同一我方攻击者”比较口径不一致 | 统一用我方 472 bp，精英 9→9、Boss 22→21；已解决 |
| 重要 | 调息解穴由门槛自动成功，未按 04 效果体系消费 RNG；空调息不推进版本 | 门槛只开放尝试，按 `releaseBp` 抽唯一 `battle` 流；合法调息均推进 `stateVersion`；已解决 |
| 重要 | 敏感性曾把禁路记零伤攻击，随后又漏用基础收招 / CT 钳制 | 改为下个决策槽调息，攻击采用 `clamp(1200+flowCt,500,2000)`；正文全表重算；已解决 |
| 重要 | 3 条图鉴游戏化名称被计作小说招式，现实来源 URL / 用字有误 | 分为 41 条小说候选 + 3 条扩展名；修正公开来源与“安身炮”用字，存疑均标（待考）；已解决 |
| 一般 | 半步崩拳、路线 YAML、算例与脚本段数不一致；下游建议另造了一套招式数量范围 | 统一为 2×70 CT，补字段 / 校验，并恢复引用 05 §3.5 唯一数量规范；已解决 |
| 一般 | README 工具行数与扩充后的 golden 不符 | 按最终 `wc -l` 更新为 4 文件 3,400 行；已解决 |
